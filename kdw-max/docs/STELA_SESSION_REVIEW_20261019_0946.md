Три серверных отмены `new_speech` не являются тремя barge-in: это приветствие до начала звука и две незавершённые обработки D. Единственное `playback.interrupted` — выход посетителя (`audio_close`) на последнем ответе.

## Доказанная ошибка после продолжения речи

Цепочка UTC 06:46:35 (МСК +3):

1. 35.129 — новый речевой ход отменяет обработку «Ум, серьезно?».
2. 35.411 — приходит response.created старого хода; посылается один response.cancel.
3. 35.682 — cancelled response.done содержит **incomplete** function_call `call_76663b72dbed4eef88d25826`.
4. Сразу после этого persistent.cjs посылает function_call_output для отменённого незавершённого вызова.
5. 35.953 — Qwen отвечает `Unknown function call id: call_76663b72dbed4eef88d25826`; закрывается D-канал, следующий текущий ход теряется.

Это один исходный сбой, отражённый provider.error/provider.failed/request.failed, а не три независимые ошибки. Место в коде: PersistentTurn после response.done вызывает resolve(CANCELLED), а resolve отправляет output для всех calls, не фильтруя terminal status вызова. Старый отменённый вызов повредил обработку следующего хода. Для исправления нужны регрессия incomplete-cancelled tool и явное владение подтверждённым вызовом; простого повторения запроса или уменьшения паузы недостаточно. **Эта неисправность не исправляется сменой системного промпта и остаётся отдельной задачей.**

D восстановился новым соединением на следующей реплике; ещё одна ротация после четырёх ответов плановая. TTS переподключился после отменённого приветствия с drain750, дальнейшие ответы используют тёплый канал.
