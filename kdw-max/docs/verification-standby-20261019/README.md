# Настоящий standby вместо тестового меню — 19.10.2026

**[Публичная игра](https://futuronika.pro/df/max-game-client/)** обновлена. Выпуск VPS `20261019T080842Z`, web release `c0d5499504e1a1329442`, portable bundle `23bf67dad8708624ba015c13719ebbb1fc71a35c8cef5b2f6fb23e4b84d91c94`.

## Причина и исправление

Управляемый стенд показывал `createIdleMenu` по контексту внешнего host. Автономная адаптация обходила этот контекст и попадала в тестовую ветку controller menu с крупными карточками/сбросом/покрытием. Веб-вход дополнительно автоматически выбирал отдельный touch UI на телефоне. Эти варианты ошибочно оставались основными.

Теперь локальный menu подключает **тот же** стендовый `journey-v5-idle-menu.mjs`, исходный `idleLayout` и тот же TV-ролик. Иконки берутся из первых заданий четырёх миссий, а не из mission-card. [Неизменность двух стендовых модулей и шесть адаптаций базы](lineage.json). Основное меню не копируется заново средствами CSS.

При выборе иконки существующее ядро получает SELECT_MISSION. Для сохранённого задания renderer сразу продолжает presentation через resume; второго нажатия на телефон не требуется. После reload открывается standby без recovery-диалога, данные сохранены. «Назад» возвращает в standby. Явный debug=1 остаётся техническим просмотром, в обычном сценарии его нет.

Одна сцена на всех размерах окна; отдельный телефонный интерфейс исключён из веб-сборки. Общий план резервирует 4096×1280 и все миссии до первого кадра, поэтому масштаб не меняется при переходе из standby в задание. Фон продолжает обновляться и в idle-ветке.
