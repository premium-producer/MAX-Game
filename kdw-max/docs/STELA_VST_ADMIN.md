## Работа оператора

1. Завершить разговор, открыть панель. Положить целые Windows x64 VST3 в `apps/stela/plugins/`, сохранив имя bundle/ресурсы, нажать «Перечитать».
2. Добавить эффект во входную или выходную цепочку. По кнопке «Открыть родное окно» сначала сохраняется текущий порядок/bypass/универсальные параметры, затем на этом ПК открывается штатный HWND-редактор плагина.
3. Настроить плагин. «Сохранить и закрыть» в браузере/родном окне и крестик родного окна сохраняют полный VST3-пресет. «Отмена» оставляет состояние до открытия окна; сохранённые перед открытием порядок/параметры цепочки не откатываются.
4. Начать новый разговор. Эффекты используют сохранённое состояние. Универсальные регуляторы остаются доступны для плагинов без собственного редактора; явные изменения регуляторов накладываются после восстановления полного состояния.
5. «Экспорт полного комплекта» сохраняет один JSON с конфигурацией и бинарными пресетами обеих цепочек. Для импорта выбрать JSON; полный комплект применяется после проверки. Старый JSON без вложенных пресетов загружается как черновик и требует «Сохранить настройки».

Изменения действуют со следующего сеанса; прослушивание в реальном времени через панель не добавлено. Редактор работает в режиме обслуживания, без подключения микрофона/колонок. Пока открыт редактор или выполняется импорт, новый голосовой сеанс запрещён. Начатый голосовой сеанс, включая пустую FX-цепочку, запрещает редактирование. Можно открыть одно родное окно за раз. Кнопка «Перечитать» доступна и при блокировке.

## Полное состояние

Хост сохраняет стандартный `.vstpreset` с component/DSP chunk и controller chunk, если плагин предоставляет последний. Это включает данные, которые не представлены нормализованными параметрами: внутренние режимы, кривые, собственные настройки интерфейса и прочее, что сериализует изготовитель. Положение внешнего окна хоста отдельно не сохраняется. Внешние библиотеки/IR и лицензии не становятся частью пресета автоматически.

При восстановлении вызываются `IComponent::setState`, `IEditController::setComponentState`, затем `IEditController::setState`, если controller chunk существует. Только после этого применяются явные универсальные overrides. Используется SDK PresetFile; [официальная последовательность Steinberg](https://steinbergmedia.github.io/vst3_dev_portal/pages/Technical+Documentation/API+Documentation/Index.html#persistence). Native HWND подключается через `IPlugView::attached`, `IPlugFrame` обслуживает resize, `IComponentHandler`/Handler2 принимают редактирование и dirty-состояние. Все обращения к VST выполняются на STA/message-loop потоке отдельного worker; браузер не встраивает чужое окно в HTML.

Новая сохранённая запись эффекта в `data/audio.local.json`:

```json
{
  "path": "Example.vst3",
  "enabled": true,
  "parameters": {},
  "state": {
    "sha256": "64 lowercase hex characters",
    "classId": "32 uppercase hex characters",
    "pluginSha256": "64 lowercase hex characters",
    "bytes": 1234
  }
}
```

Файлы: `data/audio-presets/<sha256>.vstpreset`. Ссылка не содержит абсолютного пути. Перед загрузкой проверяются структура/размер/SHA/class и SHA Windows-бинарника плагина. Изменённый бинарник не получает старое состояние молча: оператор восстанавливает прежний файл или явно сбрасывает пресет. Обновление версии плагина требует отдельной проверки; автоматическая миграция между версиями не заявляется.

## Сохранение и конкуренция

Редактор создаёт временный файл в `data/audio-work/`. После успешного сохранения сервер проверяет пресет, добавляет неизменяемый файл состояния, затем атомарно меняет конфигурацию. Предыдущая конфигурация копируется в `audio.local.json.backup`. При сбое плагина, некорректном пресете, отмене или конфликте ревизий прежняя ссылка остаётся действующей. Неиспользуемые пресеты автоматически не удаляются, чтобы не разрушать резервные ссылки. Экспорт содержит только текущие состояния.

Панель использует хеш-ревизию конфигурации: устаревшая вкладка получает `AUDIO_CONFIG_CONFLICT`. Пока открыто родное окно, другая вкладка не может перестроить цепочку. Админ-панель доступна локально; POST требует точного Origin, server проверяет Host. Это не удалённая панель и не система пользовательских паролей.

Ограничения: до8эффектов на направление, до1024 универсальных overrides на эффект, пресет≤8МиБ, совокупные данные пресетов одного экспорта≤32МиБ. Входящий JSON импорта ограничен примерно48МиБ. Native load/save и содержимое пресетов не записываются в журнал. Окно ограничено30минутами, старт worker —10секундами, закрытие через панель —10секундами. Рабочий DSP сохраняет прежние deadline/очереди.

## Перенос

Для своего целевого Windows x64 ПК переносить:

- папку приложения с `launcher/`/`runtime/`/`www/`;
- целые плагины и необходимые ресурсы в `plugins/` с прежними относительными путями;
- `data/audio.local.json` и `data/audio-presets/`, либо импортировать полный JSON в приложении с уже скопированными плагинами.

API-ключи/профиль Василисы — отдельные частные настройки; JSON аудиокомплекта их не включает. Сами непрозрачные пресеты могут содержать пути или сведения изготовителя, поэтому не публиковать их как открытые ассеты. Штатная статика не выдаёт `data/`. Активация плагина, внешние IR/библиотеки и право передачи определяются изготовителем. Обычный `.vstpreset` не обходит активацию и не гарантирует перенос внешних абсолютных путей. «Полное состояние» означает полное состояние, которое предоставляет plugin API.

Собственная UTF-8 обработка пути bundle перед вызовом SDK исправляет обнаруженную загрузку из папки с кириллицей; SDK vendor-файлы не менялись. Проверен перенос на этом ПК в другую папку с кириллицей/пробелами; физический второй ПК отдельно не проверялся.

## Сохранённый аудиотракт и диагностика

48кГц float32, mono/stereo с последующим моно, прежние ресемплеры, AEC/Silero/512мс, очередь/epoch/reset, VST-tail и фейды сохранены. При ошибке восстановления полного пресета поток закрывается по прежнему fail-closed пути; параметрический fallback не подставляется. Редактор не добавляет параллельный звук мимо опорного WebRTC.

События `audio.editor.opened/saved/cancelled/failed`, `audio.bundle.exported/imported`, `audio.fx.configuration_saved` сохраняют направление/индекс/имя, идентификатор редактора, SHA/размер/class, где применимо. В журнал не попадают chunks, содержимое экспорта, vendor stdout/stderr и данные лицензии. Native UI/экспорт не выполняют вызовов Qwen.

Пока поддерживается первый audio-effect class VST3-модуля. Shell-пакеты с выбором нескольких классов, динамическая смена IO/reload по команде плагина и универсальный сбор внешних ресурсов не реализованы. Нет фирменного GUI — остаются универсальные параметры; совместимость и активацию каждого стороннего эффекта необходимо проверять отдельно.

Реализация и проверочные квитанции: [отчёт](verification-20261020/stela-vst-admin/README.md).
