# INVALID_SAVED_SESSION после удаления ready

Воспроизведение: пройти старую регистрацию до `business.platform.ready`, завершить её, перейти к каналу, перезапустить регистрацию, закрыть и открыть сессию. RESTART_TASK очищал ответы по текущему списку экранов; после удаления ready его старый ответ оставался при replay, хотя историческая квитанция его удаляла. Это приводило к строгому отказу restoreMissionModel и INVALID_SAVED_SESSION.

Исправление в `kdw-development.mjs`: очистка ответа retired-экрана при перезапуске. `catalogForBusinessReceipt` отдельно сохраняет поведение принятой квитанции промежуточной версии с оставшимся ответом. Это не ослабляет сравнение квитанций и не изменяет уже принятые записи.
