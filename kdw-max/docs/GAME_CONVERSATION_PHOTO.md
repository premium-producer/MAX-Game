## Один исходный портрет и кадрирование

Входной формат — ориентированное вертикально фото **1080×1920**, 9:16. С 21.10.2026 по запросу пользователя тестовый портрет взят из предоставленного `фотодок.png`, сохранённого в `apps/max-game/source/fixtures/visitor-photo.png`. Он имитирует входное фото со стелы. Генератор применяет EXIF-ориентацию и центральное кадрирование до 1080×1920 без растяжения и дополнительного зеркалирования. Производный Full HD WebP занимает 164 216 байт, отдельная SVG-обёртка доступна в runtime как `assets/kdw-native/conversation/visitor-placeholder.svg`. SHA исходного снимка и подготовленного WebP записываются в манифест.

`VISITOR_CAPTURE` в `apps/max-game/source/client/src/kdw-conversation-photo.mjs` задаёт размер кадра и круг маски. Текущий **предварительный** круг: центр (540, 960), радиус 500 px. Маска стелы ещё не реализована и физически не согласована; её окончательные параметры должны стать общими для съёмки и игры.

- Для кружочков и обоих аватаров берётся один квадрат (40, 460, 1000, 1000), затем применяется круглая маска. Лицо не растягивается и не меняет положение между этими поверхностями.
- Для звонка используется прямоугольное окно с отношением сторон 132:200, максимально вписанное в исходный кадр и центрированное по маске, с ограничением границами фотографии. Скругление остаётся из макета.
- У аватара истории сохранено исключение под кнопку «+». Подпись «Вы», смена камеры, дуги записи и выключенный микрофон взяты из SVG и рисуются поверх нового фото.

## Основа для будущего фото со стелы

`composeVisitorScreen(template, photo)` заменяет только помеченную фотографию и её окно кадрирования. `photo` содержит `{width, height, guide: {cx, cy, radius}, dataUri}`. Принимаются встроенные PNG/JPEG/WebP, размер URI меньше 6 МиБ; SVG/HTML/внешние URL не принимаются. Координаты относятся к уже ориентированному изображению. Поставщик фото должен заранее декодировать его, сверить реальные размеры, применить EXIF-ориентацию и согласованное зеркалирование один раз.

Сетевой приём, привязка к посетителю/назначению, сохранение и передача со стелы **не подключены**. Следующая интеграция должна загрузить и проверить фото до показа, подготовить все нужные варианты одного посетителя и атомарно сменить их в контексте актуальной сессии с защитой от запоздавших ответов. До этого игра использует только локальный шаблон. Камера не запрашивается, изображения посетителей не сохраняются.

## Подготовка и проверки

Оригиналы — `UI/new_screens/conversation/`. Воспроизводимая подготовка:

```powershell
node apps/max-game/source/prepare-conversation.mjs D:/job/production/FUTURONIKA/VK_DigitalProducts/artifacts/max-game/node_modules
node apps/max-game/source/prepare-visitor-details.mjs
node apps/max-game/source/build.mjs D:/job/production/FUTURONIKA/VK_DigitalProducts/artifacts/max-game/node_modules
```

Подготовка использует существующие Python stdlib и Sharp из указанного toolchain; при запуске игры они не требуются. SVG исходников не переносится целиком: из него выделяются маски/контролы. PNG-подложки сохраняются без перекодирования, чтобы не менять цвета полупрозрачных краёв. Манифест в `source/client/public/assets/kdw-native/conversation/manifest.json` хранит SHA обоих исходников и геометрию. Runtime проверяется по `kdw-conversation-assets.json`. Восемь ресурсов runtime суммарно около 9,91 МБ; в исходном наборе SVG было около 59 МБ.
