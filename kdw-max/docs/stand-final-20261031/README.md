# Финальный снимок production-стендов — 31.10.2026

Сняты фактические файлы обоих production-ПК, без установки новых версий и без остановки приложений. Локальный архив: `releases/stand-final-20261031/` в рабочем проекте. CHUWI не затрагивался.

## Точные версии и исходники

В GitHub каждого компонента — ветка `stand-final-20261031` и выпуск с тем же тегом. ZIP выпуска содержит фактические launcher/www, BAT и профиль app.json основного приложения с его профильного ПК. SHA всех файлов — в `runtime-max-game.json` / `runtime-stela.json`; те же манифесты включены в ZIP. Это архив приложения для существующей Windows-поставки с Electron, а не новый установщик с драйверами.

Рабочие исходники и материалы также зафиксированы в ветках. MAX: все 1034 установленных launcher/www совпадают с рабочим корнем. Стелла: 208 файлов совпадают, 10 служебных файлов на стенде старее рабочего корня, также остаются 5 исторических SVG. Точные отличающиеся файлы сохранены здесь в `installed-stela/` и в ZIP. Для точного восстановления использовать ZIP или приватный снимок, не пересобирать из более свежих общих исходников. Исходники не заменялись старыми файлами.

## Что сохранено локально

- Полные деревья `C:/KDW-Stand` обоих ПК: действующие и исторические releases, deploy и резервные копии, настройки, runtime, данные, журналы и crash dumps. Служебная папка создаваемых снимков исключена из рекурсии.
- Desktop/kdw-startup обоих пользователей.
- Все успешно прочитанные файлы проверены SHA-256. В приватном хранилище одинаковое содержимое хранится один раз; манифесты сохраняют исходные пути каждого ПК.
- Читаемые копии журналов и записей игр — `private/readable/<роль>/`.

Файлов захвачено: MAX 8398, Стелла 8246. На каждом ПК недоступна только открытая база Chromium `data/profile/Network/Cookies`. Она не относится к игровым журналам или статистике; ради неё приложения не останавливались. Снимок живой, пофайловый: записи ограничены размером файла на момент открытия, а не одной общей транзакцией. Уже удалённые штатным retention журналы восстановить нельзя. Ошибок чтения логов нет.

## Статистика

`statistics.json`, `events-daily-*.csv`, `screens-*.csv` содержат только агрегаты без идентификаторов посетителей, фотографий или расшифровок. Сырые данные остаются локальными.

В сохранённых данных: 451 уникальная запись игры MAX и 728 идентификаторов созданных сессий Стеллы. Эти числа включают тестовые и операторские сессии и не являются числом посетителей. Повторяющиеся строки исторических журналов устранены по содержимому. Стелла: счётчики screen_entered дедуплицированы по сессии/ревизии/этапу. MAX: счётчики экранов — наблюдения из сохранившихся логов, а не полный счётчик входов; эти метрики нельзя сравнивать напрямую. В исходных журналах 0 неразбираемых строк.

## Восстановление приватного снимка

Из локальной папки снимка, в НОВЫЙ каталог:

```powershell
python restore.py --device max-game-pc --destination D:/restore/MAX
python restore.py --device stela-pc --destination D:/restore/Stella
```

По умолчанию восстанавливается полный активный RC4-1 с обоими приложениями, runtime, настройками и данными соответствующего ПК. `--scope all` восстанавливает также всю историю и desktop/kdw-startup. Существующие каталоги не перезаписываются. Перед запуском на другой машине проверить аппаратные профили, пути и права, не переносить живые процессы/PID буквально.

Полные приватные архивы, секреты, фотографии и исходные журналы не публикуются в GitHub. Публичные ZIP сохраняют существующие data/settings при наложении; они не содержат индивидуальные настройки оборудования, Electron, VST и приватные ключи.
