# Однократный возврат в standby после ладони

Исправлено локально 28.10.2026. На стенды не отправлено.

Причина: тайм-аут переводит локальную сессию в menu и renderLocalStandby уже создаёт меню. Следующий существующий poll game-link подтверждает release, после чего transitionPortableSession повторно вызывал exit/dispose/clear и создавал тот же standby. Это отдельное пересоздание запускало уход и повторное появление.

Изменён только существующий адаптер: при терминальном menu-снимке запоминается уже показанный idleMenu. Если после подтверждения game-link нет новой активной игры, при смене сессии сохраняются DOM, видео, готовые GPU-ресурсы и прогресс появления этого standby. Если назначена новая игра, меню по-прежнему плавно уходит. Закрытие сессии, обновление каталога/политики, владелец ввода и наблюдение за следующими назначениями сохраняются. Новых production-компонентов нет, frozen stand-base не изменён.

Проверки: 175 тестов MAX, сборка и check:generated прошли. Один браузерный сценарий выполняет реальный тайм-аут ладони с production-политикой 2,5 с. С установленным ACTIVITY-WEBGL bundle воспроизводится повторное создание меню (before.json, replaced=true); с исправлением DOM не заменяется, повторного ухода нет, первое появление плавное, graphicsBootId сохраняется, из оставшегося меню запускается следующий посетитель (after.json). Ошибок JavaScript нет. Сценарий: ops/production-build/standby-return-browser.mjs.

Точная область относительно production-базы — scope.json. Профили, тайминги стенда, лидар и аппаратные службы не изменялись; короткий тайм-аут используется только в изолированном тестовом каталоге.
