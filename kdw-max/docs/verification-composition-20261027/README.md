## Уточнение: связанный игровой блок (установлено)

По последней правке устройство управляет одной композицией: иконки маршрута с подписями/бейджами, таймер, справка и переходящая кнопка масштабируются и перемещаются относительно общего центра устройства. Расстояния между элементами меняются тем же коэффициентом. Справка и кнопка сохраняют вертикальное центрирование общим блоком по устройству, заданное штатным transition layout. Стандартная геометрия каждой сцены и анимация устройства остаются источником раскладки.

В игровых настройках остался один раздел «Игровой блок»: X/Y/масштаб. Наследование всей игры / телефона / ПК / screenId сохранено. Старые независимые поля reference/button остаются в файлах для совместимости, но больше не влияют на отображение и не выводятся в форме. Сам файл профиля не переписывается при чтении. Standby сохраняет прежние три настройки.

Один affine-map используется для DOM, GPU, иконок/подписей и зон нажатия. Родитель и его потомки не трансформируются дважды. Учтён реальный pivot иконки в центре плитки, который отличается от центра блока с подписью; чтения и записи геометрии сгруппированы. Модуль kdw-composition-layout.mjs и форма source/operator/layout.* обновлены, build:max подготовил runtime-копии. Замороженный stand-base не менялся.

## Возможности первой установленной итерации

- Standby: X/Y и масштаб логотипа, видео и блока миссий. Блок миссий масштабируется вокруг общего центра вместе с подписями.
- Игра: X/Y и масштаб устройства, справки и переходящей кнопки. Кнопка следует перемещению/масштабу справки; её собственные поправки задаются отдельно.
- Наследование: вся игра → телефон/ПК → конкретный screenId. «Убрать исключение» возвращает наследуемые значения.
- Ползунки и числовые поля. Смещения задаются относительно исходного макета в пикселях дисплея 3072×1536, масштаб — 35–250%. Физическая зона лидара остаётся прежней.
- Живой игровой предпросмотр с направляющими. Начальные сцены: Standby, Цифровой ID, бизнес, общение, блогер. Далее можно проходить игру кнопками и настраивать показанный экран.
- Сохранение, отмена, исходный макет, импорт/экспорт JSON.

Это первая согласованная итерация: свободного перетаскивания, отдельного редактора маршрута, карточек постов/товаров и фонового слоя здесь нет. Устройства и их содержимое масштабируются целиком; перестановка внутренних элементов телефона не производится.

## Применение

Предпросмотр по умолчанию изолирован от игры: отдельный серверный токен на час, memory persistence, link=0, без production-таймеров/назначений/ACK/фото посетителей, звук отключён. Исходные фото и реальные данные в редактор не копируются. Обычный query-параметр без действительного токена не включает этот режим.

Переключатель «Предпросмотр на стене» создаёт временную настройку на 15 секунд с продлением каждые 3 секунды. Закрытие/сбой редактора возвращает сохранённый макет; renderer также проверяет срок локально, даже при недоступности API. Сохранение и показ на стене требуют отсутствия активного назначения MAX и выключенного ARM. Чужой активный предпросмотр защищён владельцем; параллельное сохранение — ревизией CAS.

Профиль хранится в apps/max-game/data/layout.local.json, резервная копия — .backup. Первое чтение не создаёт файл. При отсутствии профиля используется прежняя композиция. Настройки загружаются до запуска GPU-сцены; последующие изменения читаются раз в секунду без перезапуска игры. Установщик патчей добавляет этот файл в проверку сохранности настроек. Профиль находится вне публикационной синхронизации и переносится кнопками JSON.

## Геометрия и код

- apps/STARTUP/tools/layout-settings.cjs — схема, локальный API, сохранение, временный показ и preview-токены; копия launcher обновляется build:shared.
- source/operator/layout.* — редактор; build:max копирует его в www/admin.
- kdw-composition-layout.mjs — накладывает один affine-map после штатной анимации; GPU-координаты и DOM используют одинаковое преобразование. Нативные бизнес-кнопки выравниваются по перемещённой медиа-плоскости. Соединительные линии используют итоговые bounds.
- journey-webgl-ui.mjs снимает операторское преобразование перед подготовкой ресурсов, затем применяет его после motion. Текст справки получает тот же масштаб, что и её поверхность. Замороженный stand-base не менялся; вход генерируется через adapt-stand-main.mjs.
