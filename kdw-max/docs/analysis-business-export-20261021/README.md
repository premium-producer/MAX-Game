# Проверка выгрузки бизнес-экранов

Источник: `UI/new_screens/busines_no_sort/`. Дата: 21.10.2026. Сверка с текущими21screenId бизнес-миссии; новое прохождение использует19, два старых состояния витрины остаются для совместимости.

**Основной комплект полный.** После первичной сверки добавлены `экран.svg/экран.png`: это недостающая телефонная переписка с ботом о заказе и доставке (`business.bot.result`). Создание канала, платформа, заполненная форма бота и его готовая карточка также присутствуют. Основную страницу платформы можно переиспользовать в двух заданиях, отдельная копия для этого не нужна.

В папке **24 пары SVG/PNG, 48 файлов**. SVG действительно содержат отдельные векторные элементы; это существенно полноценнее прежних PNG-подложек. Однако во всех24 SVG **0 узлов `<text>`** — надписи переведены в контуры. В некоторых SVG вложены растровые телефонные preview: они не становятся векторными из-за внешнего SVG-контейнера.

## 3. Варианты одного экрана и несоответствия

- `Frame 2087330771/2087330780` — один этап выбора профиля с отличиями оформления/состояния. Это не два последовательных шага.
- `Frame 2087330772/2087330781` — почти одинаковая верификация: при сравнении PNG только3 пикселя отличаются больше чем на8 уровней в канале. Два экрана в маршрут не нужны.
- `Frame 2087330773/2087330782` — варианты главной страницы с уведомлением/разной подложкой. При интеграции выбрать согласованный вариант, не показывать оба.
- `busines-4/5` — сравнение PNG локализует различие в области кнопки сохранения. Это состояния неактивной/активной кнопки.
- В `4. number.svg` стоит **+7 915 123-44-55**, в `5. confirmRequest.svg` — **+7 912 000-00-00**. В игре по уточнению пользователя принят второй номер; при подготовке обоих SVG сохранить **+7 912 000-00-00**. Сейчас исходники не исправлялись.
- Не все поля можно подменить заменой текста SVG: названия, описания и handles находятся в контурах. Нужно выделить эти области и заменить их живым текстом, сохранив остальные элементы MAX.
- Новые размеры отличаются от текущих: например телефон360×794 вместо720×1588; форма723×452 вместо1445×903. Перенос требует сверки/нормализации горячих областей, а не простой смены URL картинки.

## 4. Вложенные телефонные preview

В `busines-2.svg` телефон содержит встроенный PNG1080×2349 с профилем «М-Банк | Поддержка». Поверх исходного PNG лежат векторные элементы, формирующие кофейный вариант. [Извлечённая растровая основа](embedded-bot-preview.png) показывает, что это не независимый редактируемый SVG телефона.

В `busines-4/5.svg` телефонный preview также растровый900×1956, уже с кофейными данными: [основа preview](embedded-settings-preview.png).

**Желательно, но не обязательно для продолжения:** отдельный SVG самого телефонного профиля бота, используемого в правой части формы. Это позволит менять названия/логотипы/описания без чистки растровых данных. При отсутствии такого экспорта можно подготовить чистую подложку и живые области локально. Переэкспортировать все24 файла ради обычного SVG-текста не требуется.

Фото посетителя не брать из этих демонстрационных профилей: существующий слот посетителя сохраняется отдельно. Логотип бизнеса и официальный аватар бота MAX — другие сущности.

## 5. Пригодность для подготовки ассетов

SVG суммарно **35 776 233 байта**, PNG-прототипы — **3 033 746 байт**. В SVG45 встраиваний растров, но уникальных изображений по SHA только14: суммарно4 837 062 байта исходных растров вместо19 566 905 байт повторных вложений. До оптимизации WebP это не оценка финального runtime-веса.

Внешних ссылок в `<image>` не найдено. При подготовке следует выделить повторяющиеся фон/фото/логотипы, описать динамические области, сохранить исходные SVG и не копировать полную35,8МБ выгрузку в каждый вариант бизнеса. SVG с текстом в контурах подходят как графическая основа; это ещё не готовые нативные формы.

**Обязательных дополнительных выгрузок больше нет.** Единственное пожелание — отдельный SVG телефонного профиля/предпросмотра бота из заполненной формы. Это необязательный компонент, не ещё один шаг миссии.

Новые спорт/цветы готовятся из этих общих исходников и пакетов данных, три полных копии всех экранов не нужны.

## Проверка и границы

Состав и SHA каждого SVG/PNG, размеры, количество контуров, текстовых узлов и вложенных изображений записаны в [files.json](files.json), скрипт проверки — [audit.mjs](audit.mjs). Первые23 пары просмотрены на обзорных листах, добавленный PNG — отдельно; листы пересобраны для24 пар. Два встроенных preview извлечены и просмотрены отдельно. Исходники не переименованы и не изменены. Каталог/runtime/сохранения/стела/VPS/GitHub не менялись. Это сверка материалов, игровая интеграция новых SVG не выполнялась.
