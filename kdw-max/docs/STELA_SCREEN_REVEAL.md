# Показ экрана после начала озвучки

**22.10.2026 — выбор голосом:** на audience окончание речи больше не скрывает интерфейс. Гистограмма/обработка продолжают реагировать на голос. Принятый выбор удерживает audience до окончания общего AnswerFlight; затем photo/result показывается сразу, а ready нового экрана разрешает озвучку. Для audience и перехода после вылета не применяется прежнее ожидание playback180мс. Остальные экраны/20с fallback сохраняются. [Сценарий и таймеры](STELA_SELECTION_FLIGHT.md).


## Стартовая заставка — 22.10.2026

Заставка находится в исходном index.html, вне React root; собственные inline CSS/JS и точный entry.svg. Статический градиент и три точки работают до инициализации React/WebGL. Портрет9:16 вписан в окно, геометрия logo совпадает со следующим entry — при fade не возникает скачка.

Root inert до завершения загрузки. MutationObserver ждёт serviceReady=true (шрифты/изображения), смонтированную и доступную brand-splash__logo и stellaRingState=ready либо error (штатная деградация рендера). Через два RAF начинается opacity1→0 за650мс; на700мс overlay удаляется, root становится интерактивным. Никакой минимальной искусственной задержки перед готовностью нет. Reduced-motion отключает точки/fade.

Через20с либо при ошибке script/runtime показываются сообщение и явная кнопка «Повторить» (reload). Пустой интерфейс не открывается. Observer продолжает ожидать: поздняя успешная готовность снимает заставку. После завершения очищаются observer/error listener/watchdog; заставка одноразовая и не возвращается при навигации/blur/reset сессии. data-stella-boot-state/ms позволяют проверить состояние/время в DOM. Это не процент загрузки и не ожидание соединения Qwen: голос по-прежнему стартует после явного действия пользователя. Штатное журналирование/защита звука не изменены.

Сборка переносит заставку в /stella/, /stella/pixels/, /stella/gradient/. Админпанель не изменена. Проверка launch verifyExpression теперь требует stellaBootState=ready. Не обещает показ до получения HTML браузером/старта локального HTTP-сервера.

FOUR-SCREENS-20261020 сохраняет эту развилку для entry/intro/audience/result; промежуточного goal больше нет. Все4миссии выбираются с одного audience. Нативные кнопки ждут загрузки оформления; при ошибке ресурса есть текстовый fallback. Это не ожидание нейросети. Контракт/тексты и порядок4вариантов описаны в дизайн-документе.

`MANUAL-AUDIO-20261020` уточняет прежние правила ниже: **нажатие не скрывает UI и не ждёт начала звука**. Серверный Controller сразу публикует новый экран с `presentation:manual`; после layout-ready запускается локальная запись. Логотип тоже открывает вступление с записью. Голосовой ввод переключает сессию в `presentation:voice`: прежние скрытая готовность, мягкое затухание, гистограмма→точки, playback+180мс и fallback20с сохраняются. Следующее нажатие сразу снимает ожидание/таймеры, отменяет старый ход и возвращает локальную озвучку. Epoch/generation/revision остаются общими для обоих источников. `voice=off` сохраняет бесшумный маршрут.

## Реализация

`ScreenRevealGate` отвечает только за видимость и ожидаемую озвучку. При касании, окончании человеческой реплики или новом snapshot интерфейс скрывается через opacity/visibility/inert/aria-hidden; React-компоненты продолжают готовиться. Логотип/кнопочный voice=off и сессия без доступного голоса не ждут несуществующий звук.

Готовность геометрии (`ready`, как прежде после анимации заголовка/подготовки вступления) отдельно подтверждается серверу, даже при скрытом UI. Сервер может сразу генерировать S; ожидание показа UI перед генерацией создало бы взаимную блокировку. `ready.hidden` также позволяет не считать скрытую миссию уже показанной. Отдельный `screen.visible` сообщает начало её видимого проявления, mission.displayed идемпотентен по revision.

Сигнал к показу — существующий `playback.started` локального проигрывателя, а не приход snapshot/audio-пакета, provider status speaking или окончание генерации. Через180мс начинается fade-in320мс; reduced motion убирает fade, сохраняя задержку. Часы playback.started — прежний RTC sender/audio-context clock, не физический датчик звука в колонке. Дополнительная акустическая/браузерная буферизация отдельно не измерялась.

В первоначальной SCREEN-REVEAL скрытый UI сопровождался кольцом из15light-влияний. WIDE-PIXELS-20261020 сохраняет gate/тайминги, но показывает3крупные независимые точки внутри широкого непрерывного кольца; после playback — крупную гистограмму реального output meter. Всего18влияний на прежних ячейках/одном canvas. Тени смонтированного скрытого UI теперь имеют нулевую силу и следуют opacity при проявлении. На gradient gate и прежние символы сохранены. Reduced motion останавливает декоративческое движение фигур. [Новая композиция и проверки](verification-20261020/stela-wide-pixels/README.md).

## Тайм-аут и отмена

Дедлайн20с запускается при начале ожидания и не откладывается из-за snapshot/ready. Если playback успел начаться до дедлайна,180мс завершаются даже за границей20с. Если звука нет, UI немедленно становится доступен на текущем выбранном экране, narration отменяется, локальный output generation/reset очищает очередь/реверб. Поздние audio-пакеты заблокированы до нового явного действия/новой человеческой реплики.

`ready.silent` подтверждает текущий экран без автоматического приветствия/озвучки и очищает pendingTouch/pending speech. Никакого back/restart/возврата к логотипу при таком fallback нет. Следующий выбор снова разрешает речь. Ошибка воспроизведения/соединения открывает доступные кнопки сразу, без бессмысленного ожидания20с.

session generation/epoch/revision и serial таймеров защищают от поздних callback. Новый epoch отменяет старый reveal; stop/reset/hidden/unmount убирают таймеры. Подтверждённое пользовательское перебивание снимает старое ожидание, существующие SpeechGate/AEC/Silero/duck/endpoint512/фейды и SOFT-VOICE профиль не перенастраивались.

## Диагностика

Добавлены разрешённые клиентские события ui.screen_waiting, ui.screen_audio_started, ui.screen_audio_ignored, ui.screen_revealed: epoch/revision, причина, waitMs, deadline/revealDelay, причины проигнорированного playback. Сервер различает ui.ready(hidden/silent), ui.visible и ui.silent_ready. Контракт событий по-прежнему фильтрует поля; аудио/SDP/ключи/содержимое пресетов в журнал не попадают.
