# Единая рабочая версия KDW-MAX

Каноническая версия — KDW-MAX-UNIFIED-20261025. На каждой машине работа ведётся в корне проекта: apps/max-game, apps/stela, apps/STARTUP, UI, docs, ops. Production Local Export больше не используется как рабочая папка. Изменения вносить здесь, а затем переносить в публикационные репозитории.

## Какие папки использовать

| Путь | Назначение |
|---|---|
| apps/max-game, apps/stela | Единственные рабочие исходники и сборки приложений |
| apps/STARTUP | Общие инструменты запуска и связь приложений |
| UI, docs, ops | Действующие ресурсы, документация и инструменты |
| github/MAX-Game, github/VK_Stella | По одной публикационной Git-копии каждого репозитория |
| production/* на Windows | Производные комплекты запуска, обновляются из рабочих apps; самостоятельную разработку здесь не вести |
| .sync/archive | Архив конфликтов и прежних рабочих копий с исходными путями и SHA; не источник для разработки |
| releases | Сохранённые контрольные выпуски; не текущая рабочая версия |

Актуальный синхронизированный снимок 28.10.2026 находится в ветке **2810** обоих GitHub-репозиториев; прежняя ветка kdw-max сохранена как история. MAX находится в MAX-Game/kdw-max, Стелла — в VK_Stella/apps/stela. Это два компонента одного проекта. Общий apps/STARTUP и документация публикуются из одного рабочего источника. Состав и ограничения: [SYNC-20261028](SYNC-20261028/README.md).

## Проверка перед синхронизацией

```sh
npm run check
npm run sync:check
```

Проверка пакетов относится к локальной полной поставке. Проверка синхронизации сравнивает каждый разрешённый файл рабочего корня с публикационными Git-копиями и проверяет общий sharedRevision. Список разрешённых путей хранится в ops/sync/paths.json. Новый файл добавлять в этот список осознанно; неизвестные файлы автоматически не публикуются.

После просмотра изменений команда npm run sync:prepare переносит разрешённые файлы в уже существующие публикационные Git-копии и обновляет SOURCE_MANIFEST. Она не создаёт экспортов, не коммитит, не выполняет push и не меняет основной ПК. Затем проверить diff, обе SOURCE_MANIFEST и Gitleaks, выполнить обычный commit/push. После переноса на вторую машину сверить SHA общего набора файлов; изменение целевого файла со времени аудита требует повторного сравнения.

## Допустимые различия

Стендовые app.json используют production=true; в производном dev-комплекте production=false. MAX использует pixel-map. Эти явные профили не являются конкурирующими версиями кода.

Пользовательские data/private/secrets, ключи pairing, настройки камер/микрофонов и голосов, runtime, VST и node_modules остаются локальными и не публикуются. package-manifest каждой полной Windows-поставки отражает её фактический состав; поэтому он может отличаться от манифеста очищенной Git-поставки. Эти локальные инвентаризации исключены из общего sharedRevision; sync:prepare сохраняет проверенную публикационную копию метаданных и не заменяет её инвентаризацией другой машины. SOURCE_MANIFEST проверяет именно Git-поставку. Windows runtime не является нативной программой для macOS.

Конфликтную копию нельзя выбирать по суффиксу (2)/(3) или дате. Перед заменой нужны сравнение содержимого, зависимости, проверенный эталон и резервная копия. Подтверждённые прежние копии выводятся из рабочих папок в архив; уникальное содержимое и незакоммиченная работа сохраняются.

## Новая машина

На существующих Mac/ПК общий рабочий корень уже собран. Только на новой машине создать пустую папку проекта и разместить два репозитория в github/MAX-Game и github/VK_Stella, ветка 2810. Загрузить LFS текущих компонентов и выполнить в каждом репозитории его verify-source.mjs. Оба SOURCE_MANIFEST должны иметь одинаковый sharedRevision. Синхронизация 28.10 проверяет текущий Windows-корень и production-ПК; отдельный Mac этим действием не обновляется.

Затем скопировать содержимое github/MAX-Game/kdw-max в пустой рабочий корень, а github/VK_Stella/apps/stela — в apps/stela этого корня. Общий apps/STARTUP уже входит в MAX-компонент; повторная копия не нужна. Git-каталоги остаются под github, текущие исходники — под apps/UI/docs/ops. Только после объединения доступны корневые npm run setup/build/sync:*. Runtime и приватные настройки устанавливать отдельно. На существующую рабочую папку такую первоначальную сборку поверх файлов не выполнять.
