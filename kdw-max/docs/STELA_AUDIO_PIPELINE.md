# Стела: резервный выбор и обработка речи

**Актуализация 20.10.2026:** на полном сценарии MAX добавлена [админ-панель с родным UI и полными VST3-пресетами](STELA_VST_ADMIN.md). Две цепочки/48кГц/моно/AEC/фейды ниже сохранены. Вступительные записи P1/Serena — история; текущая озвучка использует выбранную Василису. Перенос настроек включает data/audio-presets и audio.local.json либо полный JSON-комплект.

Итерация `KDW-MAX-STELA-OMNI-P1-SCREEN-TTS-20261018`, 18.10.2026. Основной S заменён на потоковый Qwen TTS Serena; D Omni, входной тракт, post-FX/post-gain reference, фейды, AEC/Silero и 512 мс сохранены. Серверный план содержит вопрос текущего экрана; прежний свободный резерв S ниже относится к CONTEXTUAL. При missing/changed reply SCREEN-TTS уточняет текущий вопрос без третьего inference. [Устройство и тесты](verification-20261018/stela-screen-tts/README.md).
Область — текущая голосовая ветка P1, `?voice=omni`. Бизнес, блог,
Цифровой ID и передача управления игре остаются прежним бэклогом.

Дополнение BARGE-DIALOGUE: во время озвучки кандидат сначала приглушает ответ; затем проверяется речь с допуском пауз и признаком совпадения с post-gain reference. Неподтверждённый кандидат возвращает громкость без нового inference. [Текущие параметры](STELA_AEC.md), [проверки](verification-20261018/stela-barge-dialogue/README.md).

Дополнение CONTEXTUAL: Firefox использует совместимый gain-ramp с интерполяцией текущего уровня и сохранением VAD-телеметрии при ошибке. Qwen D возвращает action и самостоятельно сформулированный reply; Controller получает только action, S озвучивает допущенный reply. Старый action-only остаётся совместимым, при отсутствии/смене/отклонении reply работает контекстный резерв с текущим ASR. ASR также используется в ограниченной памяти разговора при выключенной записи текста; пользовательская речь передаётся как данные, не как системная инструкция. Метаданные о воспроизведении не равны акустической записи. [Текущее устройство и ограничения](STELA_REACTION_ARCHITECTURE.md).

## Каскад выбора

1. Завершённый одиночный `resolve_turn` либо целый строгий JSON из Qwen
   разбирается прежним `decision.cjs`. Допустимый выбор для текущего этапа
   имеет приоритет над распознанными словами.
2. Если команды нет, Qwen выбрал `clarify` либо предложил выбор другого
   этапа, `fallback.cjs` рассматривает **только финальный ASR текущего хода**.
   Если ASR ещё нет, ожидание ограничено 350 мс. Дополнительного LLM-запроса
   для исправления формата нет. Тёплые D/S-соединения сохраняются.
3. Нормализация регистра/ё/пунктуации, границы слов и словарь текущего
   экрана: вступление — «начать/поехали/начнём»; первый вопрос —
   «личное/для себя»; первый/второй — «общение/общаться/близкими/связи».
   Есть отдельные правила назад/повтори/объясни/заново и явного завершения.
   «Для себя, общаться с близкими» выбирает конкретную цель общения.
4. Отрицания, вопрос, альтернативы/конфликты, недоступное направление,
   отсутствие совпадения или ASR приводят к уточнению. Простое «спасибо»
   не завершает сеанс; «спасибо, всё» завершает. Произвольный ответ модели
   и reasoning не становятся источниками ключевых слов.
5. Все команды проходят прежний Controller с revision/ready/idempotency.
   Пока ждём ASR, касание/новая речь/выход могут отменить ход; поздний ASR
   не переключает экран. Один decision обрабатывается один раз.

`command.fallback` содержит reason/rule/action/originalAction/waitMs;
`command.result.source` различает voice/keywords/local-clarify/touch.
ASR включён и при `KDW_OMNI_LOG_TEXT=0`, но текст тогда скрыт журналом.
Это изменение прежней политики «ASR только для диагностики» по поручению
пользователя. Распознавание может ошибаться; резервный разбор не исправляет
качество ASR и не должен угадывать по старым репликам. Дополнительных
LLM-ответов нет, но отключение записи текста теперь не отключает облачную ASR;
её биллинг следует сверять по данным провайдера.

## Аудиотракт

```text
Микрофон → WebRTC AEC → mono PCM16 16 kHz → входная VST3-цепочка
         → Silero/96 мс idle/duck-probe/пауза 512 мс → Qwen D

Qwen S PCM16 24 kHz → выходная VST3-цепочка → хвост эффекта
                   → огибающая/сглаживание стыков → WebRTC → колонки
```

Таким образом, опорный поток локального WebRTC содержит **обработанный
звук с фейдами**, включая реверберационный хвост. Входные эффекты работают
после AEC и перед Silero/отправкой в Qwen. Хвост и интервалы защиты не
обходятся через отдельный вывод звука. Не добавлять параллельное локальное
WAV-озвучивание в P1.

### VST3

Нативный `launcher/audio/kdw-audio-host.exe`, Windows x64, отдельный скрытый
процесс для каждой непустой цепочки. Сам хост статически связан с C++ runtime;
его зависимости — системные Windows DLL. Драйвер и внешняя DAW не требуются.
SDK Steinberg VST3 3.8.1 поставляется в исходниках с MIT-лицензиями и точными
ревизиями в `source/audio-host/vendor-manifest.json`. [Официальный SDK](https://github.com/steinbergmedia/vst3sdk),
[раздел лицензий](https://steinbergmedia.github.io/vst3_dev_portal/pages/VST%2B3%2BLicensing/Which%2Bfiles%2Bfall%2Bunder%2Bwhich%2Blicense.html).

Две независимые упорядоченные цепочки до восьми эффектов. Обработка 48 kHz,
float32, основные mono/stereo audio buses; стерео сводится в моно. PCM
16/24 kHz повышается линейной интерполяцией, на обратном преобразовании —
63-tap Hann-windowed sinc anti-alias FIR. Состояние DSP сохраняется между
кадрами; отмена делает deactivate/activate перед новой репликой. Поддерживается
первый audio-effect class модуля; инструменты, VST2, sidechain и динамическая
перестройка шин не поддерживаются. Совместимость выбранного плагина проверяется
отдельно. Заявленный latency/tail пишется в журнал; пользовательский эффект
может добавлять задержку независимо от времени вычисления хоста.

Страница [настройки звука](http://127.0.0.1:18751/stella/audio-settings.html):
добавление/удаление, порядок, enabled/bypass, универсальные слайдеры параметров
0…1, сохранение, JSON импорт/экспорт. С 20.10.2026 доступно родное HWND-окно
плагина и полный DSP/controller `.vstpreset`; основной адрес — `/stella/admin/`.
Пресеты сохраняются отдельно в data/audio-presets, проверяются по SHA/class/
бинарнику и восстанавливаются до overrides. Изменения применяются со следующего
сеанса; обслуживание и разговор взаимно исключены. [Контракт и ограничения](STELA_VST_ADMIN.md).

Плагины помещаются целиком в `apps/stela/plugins/`. Поддерживаются только
относительные пути внутри неё, в том числе проверяется realpath. Настройки —
`data/audio.local.json`, вне www и SHA-манифеста. В поставке обе цепочки пусты:
сторонние эффекты пользователь выберет позже. Тестовый ADelay находится только
в документационных fixtures. Для переноса выбранных плагинов нужны их файлы,
настройки и, если требует изготовитель, активация на новом ПК.

Local WebSocket защищён origin/host/короткоживущим токеном. Передача PCM —
только в оперативной памяти. Очередь ограничена, большие фрагменты дробятся;
лимит вычисления кадра 250 мс, клиентский deadline 350 мс. Отказ/краш/зависание
плагина закрывает FX-тракт и микрофон, отменяет ответ Qwen и показывает ошибку;
кнопки доступны. Не переключаться незаметно на необработанный микрофон.
Отключить проблемный плагин можно на странице настроек после завершения.
Сессия ограничена пятью минутами, закрытие вкладки освобождает процессы.

### Фейды

По умолчанию начало 12 мс, окончание 24 мс, прерывание 16 мс. Регулируются
на странице настройки; работают при пустых VST-цепочках. Начало применяется
один раз на реплику. Непрерывная огибающая удерживает последние 24 мс до
`audio.end`; после конца выходной цепочке подаются нули для хвоста (400 мс
по умолчанию, 0…2000 мс), затем фейд до нулевого последнего отсчёта. Для
стыков сетевых фрагментов используется коррекция разрыва на 32 отсчётах.
Нет периодического провала громкости на каждом чанке.

При перебивании gain текущей реплики плавно опускается, её источники
останавливаются после ramp; новая эпоха не получает старый хвост. AEC остаётся
в тракте во время ramp, сохраняются защитные 200 мс. Закрытие микрофона —
сразу, закрытие выхода — после короткого ramp. Фейды уменьшают краевые щелчки;
они не гарантируют исправление артефактов внутри синтезированного аудио.

## Диагностика и проверка

`audio.fx.chain_ready` — имена, latency/tail; `audio.fx.metrics` каждые 5 с —
число кадров, mean/max времени тракта; `audio.fx.failed/closed` — причины;
`playback.envelope` — применённые фейды и хвост. Нативные события привязаны к
clientId/attemptId и объединяются анализатором с visitor session. Не писать
PCM, входные/выходные WAV, vendor stdout, ключи или токены в рабочий журнал.

Проверки и ограничения — [отчёт](verification-20261018/stela-fallback-vst/README.md).
Физические акустические условия стенда, выбранные сторонние эффекты и второй
ПК требуют отдельной приёмки.
