# ТЗ на звук — стенд MAX + Стелла

Дата: 25.10.2026. Основа: текущая версия KDW-MAX-UNIFIED-20261025.

Документ описывает сцены, звуковые события и названия файлов для передачи звукорежиссёру. Раздел 3 сохраняет 16 имён существующего звукового набора MAX. Разделы 4–5 предлагают 21 новый звук для полного оформления сценария; эти события требуют отдельного подключения в приложениях. Создание этого ТЗ не означает, что новые звуки уже реализованы или воспроизводятся.

## 1. Общая задача

Звук должен поддерживать ощущение технологичного, лёгкого и дружелюбного интерфейса MAX. Короткие тактильные подтверждения, мягкие появления и перелёты, спокойный фон без навязчивого ритма. Речь Стеллы всегда должна оставаться разборчивой.

- Одно действие — одно основное звуковое подтверждение. Не накладывать одновременно клик, успех и завершение задания на одно нажатие.
- Похожие действия в разных миссиях используют один звук. Не создавать отдельные копии для каждого экрана.
- Ошибка выбора — мягкий нейтральный отклик, без тревоги, сирены и ощущения проигрыша.
- Истечение времени задания в production считается его завершением, а не поражением. Отдельный звук провала не нужен.
- Перезапуск, отмена, уход в standby и смена посетителя останавливают относящиеся к прежней сцене звуки.
- Видео, демонстрационные сообщения и речь могут иметь собственную дорожку. Новый эффект не должен дублировать уже слышимый звук из медиа.

## 2. Какие сцены есть

### 2.1. Общий маршрут MAX

| Сцена | Что происходит | Какие звуки использовать |
|---|---|---|
| Ожидание / standby | Логотип, видео и четыре миссии; экран свободен | `game_standby_loop`; звук видео учитывать отдельно |
| Выбор миссии | Миссия выбрана вручную либо получена от Стеллы | `game_mission_select` один раз на фактический выбор |
| Приглашение приложить ладонь | Ожидание старта, по умолчанию до 30 секунд | `game_transition_handscreen`; без постоянного тиканья |
| Удержание ладони | Посетитель удерживает ладонь; по умолчанию 0,8 секунды | `game_icon_hold_loop`, затем `game_palm_confirm` |
| Раскрытие маршрута | Появляются иконки заданий, связи и устройство | `game_transition_icons`, `game_icon_pop`, `game_enengy_stream_1`, `game_enengy_stream_2`, `game_phonescreen_activate` по фазам анимации |
| Задание | Посетитель работает с телефоном / ПК и выполняет действия | `game_ambience_loop`, общие клики, события из таблицы заданий ниже |
| Переход к следующему заданию | Завершение, упаковка текущей сцены и раскрытие следующей | `game_task_complete`, затем существующие переходы и `game_phonescreen_reactivate` по фактическим событиям |
| Финал миссии / QR | Миссия завершена, показан QR; по умолчанию 15 секунд | `game_mission_complete`, `game_qr_appear`; после этого спокойное удержание без повторных фанфар |
| Возврат в ожидание | Завершён QR, отменён вход или истекло бездействие | Плавно завершить текущие дорожки и вернуть фон standby; отдельный звук ошибки не нужен |

Тайминги указаны как текущие значения по умолчанию. Они настраиваются: звук не должен задавать длительность сцены или задерживать действие. При ручном входе и входе через Стеллу звуковой сценарий MAX одинаков.

### 2.2. Четыре миссии MAX и 15 заданий

Во всех заданиях обычные кнопки используют общий набор `game_button_click_1/2/3`. Успешное завершение логического задания — `game_task_complete`; завершение последнего задания миссии заменяется `game_mission_complete`.

| Миссия | Задание / ID | Что видит посетитель | Специальные события поверх общих звуков |
|---|---|---|---|
| Стать блогером | Канал — `blogger.channel` | Создание и оформление личного канала, название, тип, ссылка, подписчики | `game_action_success` при принятом значимом действии; не озвучивать каждую букву |
| Стать блогером | Общение с подписчиками — `blogger.comments` | Пост, поле ответа, отправка комментария и возвращение к посту | `game_message_send` после принятой отправки |
| Стать блогером | Статистика — `blogger.statistics` | Открытие статистики канала | Общий переход экрана; отдельная музыкальная тема не нужна |
| Все возможности с Цифровым ID | Создание ID — `digital-id.create-id` | Документы, подтверждение, быстрый доступ, биометрия и готовый ID | `game_action_success` при подтверждении; без непрерывного «сканера» под интерфейсом |
| Все возможности с Цифровым ID | Отель — `digital-id.hotel` | Прибытие, предъявление ID, результат | `game_action_success` при успешной проверке |
| Все возможности с Цифровым ID | Льгота — `digital-id.benefit` | Предъявление ID и подтверждение льготы | Тот же `game_action_success` |
| Все возможности с Цифровым ID | Возраст — `digital-id.age` | Предъявление ID и подтверждение возраста | Тот же `game_action_success` |
| Общение на максимум | Видеозвонок — `communication.call` | Чат, соединение, результат | `game_call_connect` при появлении соединения, если этот звук отсутствует в самом медиа |
| Общение на максимум | Голосовое / видеосообщение — `communication.message` | Начало записи, остановка, просмотр и отправка; затем видеоэтап | `game_record_start`, `game_record_stop`, `game_message_send`; содержимое записи не имитировать звуковым эффектом |
| Общение на максимум | Стикеры — `communication.reaction` | Выбор, предпросмотр и отправка стикера | `game_message_send` на отправке; для предпросмотра достаточно клика |
| Общение на максимум | История — `communication.story` | Подготовка, длительность, аудитория и готовая история | `game_action_success` при публикации |
| Продвижение бизнеса | Бизнес-аккаунт — `business.platform` | Выбор бизнеса, регистрация, профиль, проверка и финальная плашка | `game_action_success` при подтверждении; переход после плашки не должен получать второй идентичный сигнал успеха |
| Продвижение бизнеса | Канал и публикации — `business.channel` | Настройка канала и активность с выбором постов, ростом аудитории | `game_card_place` на приземлении принятой карточки; `game_action_soft_reject` для неподходящего выбора, если результат действительно отклонён логикой |
| Продвижение бизнеса | Чат-бот — `business.bot` | Создание и настройка бота, готовность и диалог | `game_action_success` при готовности; `game_message_send` только для реальной отправки в сценарии |
| Продвижение бизнеса | Мини-приложение / витрина — `business.store` | Панель инструментов, настройки и активность с товарами, ростом рейтинга | `game_card_place` на приземлении товара; мягкий отклик неподходящего выбора по подтверждённому результату |

Текущие варианты бизнес-миссии: **кофейня (`cafe`), цветочный магазин (`flowers`), авто (`auto`)**. Для них нужен один общий звуковой набор: механика одинакова. Исторический `sports` не заменять и не переименовывать в `auto`; отдельные отраслевые звуки в этот заказ не входят.

Справочно: финальный набор экранов содержит 69 уникальных экранных состояний заданий. Это не 69 отдельных звуковых сцен: переходы и действия переиспользуют общие эффекты. Точные ID состояний приведены в приложении A.

### 2.3. Маршрут Стеллы

| Сцена | Что происходит | Звуковое оформление |
|---|---|---|
| Загрузка / логотип — `entry` | Заставка загрузки, затем ожидание касания логотипа | Автоматическое приветствие и отдельный стартовый джингл не требуются |
| Вступление — `intro` | Приглашение выбрать персональную миссию, кнопка «Начать» | `stela_button_click`, мягкий `stela_screen_transition`; речь отдельно |
| Выбор — `audience` | Четыре карточки направлений | Клик при касании; без постоянных звуков плавания и hover |
| Вылет выбранных слов — AnswerFlight | Один анимационный переход после выбора; около 7 секунд в текущем темпе | `stela_selection_flight`, синхронный с анимацией; отменяемый |
| Фото: готовность — `photo.ready` | Камера и предложение сфотографироваться либо продолжить без фото | Клики; без зацикленного звука камеры |
| Фото: захват — `photo.capture` | Отсчёт, закрытие изображения декоративным полем и снимок | `stela_photo_countdown_tick` на видимых шагах; `stela_photo_shutter` один раз на фактическом захвате |
| Фото: просмотр — `photo.review` | Просмотр снимка, «Продолжить» или «Переснять» | `stela_photo_confirm` после принятого подтверждения; пересъёмка возвращает в фотоэтап |
| Итог — `result` | Одна из четырёх персональных миссий, направление к правой панели | Один общий `stela_mission_ready`; речь о выбранной миссии — отдельный канал |
| Передача в MAX / очередь | Подтверждённое назначение передаётся игровому экрану; может ожидать в очереди | `stela_handoff_confirm` только после фактического подтверждения доставки; без повторов при сетевых попытках |

При выборе «Без фото» отсчёт, затвор и подтверждение снимка не звучат. Состояния голоса «слушает / думает / говорит» не требуют трёх отдельных постоянных звуков: главное содержимое здесь — речь.

| `game_icon_grab_1.wav` | Захват интерактивной иконки, вариант 1 | One-shot, 0,1–0,3 с |
| `game_icon_grab_2.wav` | То же, вариант 2 | One-shot, 0,1–0,3 с |
| `game_phone_grab_1.wav` | Захват / начало перемещения устройства | One-shot, 0,1–0,3 с |

| `game_enengy_stream_1.wav` | Формирование основной связи / потока | One-shot, 0,5–1,5 с |

Наличие этих 16 слотов и медиафайлов не означает, что все они включены в каждом профиле запуска. V5-аудио имеет условия активации, а часть методов взаимодействия нуждается в проверке привязок. Нельзя обещать автоматическое включение новых или заменённых звуков одной только доставкой файлов.

Подгонка выполняется по актуальной анимации, не по произвольно выбранной длительности трека. Взаимодействие и готовность следующего экрана не должны ждать окончания звукового хвоста.

### Речь Стеллы — отдельный тракт

Диалог и ответы помощницы не заменять набором этих SFX. Не добавлять голос в клики, переходы или фон. Не генерировать новые реплики и не пересоздавать голос в рамках подготовки звукового пакета.

Существующие служебные записи `intro.wav`, `audience.wav`, `result-business-promotion.wav`, `result-blogger.wav`, `result-digital-id.wav`, `result-communication.wav` относятся к тестовому набору `manual-tests`. Они не являются шестью новыми файлами этого заказа и не должны перезаписываться. Формат того набора — WAV PCM 16 bit / 24 kHz / mono; он отличается от формата новых SFX-мастеров ниже.

## 6. Формат и организация передачи

### Имена

- Только латиница нижнего регистра, цифры и `_`; существующие имена из раздела 3 — без изменений.
- Одно событие — одно базовое имя. WAV, OGG и MP3 отличаются только расширением.
- Номер в имени используется только для предусмотренных вариантов клика и захвата. Версию пакета указывать в имени папки, не дописывать ко всем файлам.
- Не создавать вложенные дубли `audio/audio` и файлы вида `sound (2).wav`.

### Формат новых материалов

| Материал | Требование к сдаче |
|---|---|
| Мастер | WAV, PCM, 48 kHz, 24 bit; stereo. Для точечных интерфейсных SFX допустим mono, указать в cue sheet |
| Рабочая версия | OGG Vorbis и MP3, одинаковая монтажная длина с мастером; для MP3 ориентир 192–320 kbit/s |
| Начало / конец | Без случайной тишины и щелчков; аккуратные короткие fades там, где они не нарушают loop |
| Loop | WAV и OGG должны замыкаться без слышимого шва; MP3 проверить отдельно из-за возможного encoder padding |
| Громкость | Без клиппинга; предлагаемый потолок true peak −1 dBTP. Однотипные эффекты согласованы по воспринимаемой громкости, фон заметно тише речи |
| Пространство | Основные подтверждения слышны при mono downmix; без обязательной привязки только к левому или правому каналу |
| Обработка | Без жёсткого мастер-лимитинга и чрезмерной реверберации; оставить запас для итогового микса на стенде |

Громкости в приложении и приглушение фона под речь настраиваются при интеграции. Не компенсировать это постоянной «накачкой» исходного файла.

### Папки пакета

```text
kdw-max-sound-YYYYMMDD/
  masters/       # 37 WAV, если принят весь предлагаемый набор
  runtime/
    max/         # OGG + MP3: 16 существующих имён + 13 новых
    stela/       # OGG + MP3: 8 новых имён
  cue-sheet.md
```

В `cue-sheet.md` перечислить имя файла, событие, длительность, каналы, loop / one-shot, варианты, временные акценты и сведения о правах на использованные материалы.

Всего в полном предложении: **37 уникальных звуков** — 16 существующих имён MAX, 13 новых MAX, 8 новых Стеллы. При трёх форматах это 111 аудиофайлов. Служебные речевые WAV, звук существующих видео и дополнительные музыкальные темы в это число не входят. Если заказывается только замена существующего набора, объём — 16 звуков / 48 файлов.

Текущий путь воспроизведения существующих MAX-файлов: `apps/max-game/www/webgl-v5/audio/`. Это готовая сборка: передача пакета звукорежиссёром не должна означать ручную замену файлов прямо в ней. Подключение в исходниках, сборка и проверка манифестов — отдельный этап. Для новых SFX Стеллы автоматического каталога подключения сейчас не задано.

## 7. Приёмка звука после интеграции

1. Проверить все 37 базовых имён либо согласованный сокращённый объём; одинаковые имена во всех трёх форматах, без дубликатов версий.
2. Проверить циклы и короткие эффекты отдельно, затем в последовательности реальных сцен и в mono.
3. Пройти обе точки входа MAX и все четыре миссии; в бизнес-миссии проверить cafe / flowers / auto без размножения звуковых пакетов.
4. Проверить Стеллу с фото, пересъёмкой и пропуском фото; во время речи эффекты её не перекрывают и не создают ложное голосовое перебивание.
5. Успех, клики и переходы не дублируются; анимация карточек и прогресс не создают бесконечную очередь эффектов.
6. Отмена, повтор, смена посетителя и возврат в standby не оставляют старый фон или loop удержания. Повторная сетевая доставка не повторяет звук передачи миссии.
7. На реальном стенде отдельно проверить разборчивость, общий уровень, видео и акустическое взаимодействие Стеллы с микрофоном. Прослушивание файлов на ноутбуке не заменяет эту проверку.
