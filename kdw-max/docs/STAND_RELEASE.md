# MAX + Стелла — стендовый выпуск

Реальные приложения Windows x64: MAX в Electron с двумя Spout-потоками, Стелла в полноэкранном Electron без Spout. Общий runtime Electron 44.4.5 лежит в `runtime/electron`. Node, Python, CMake и npm на стенде не нужны.

**Решение 27.10.2026:** финальная Стелла — пиксельная, `/stella/pixels/`. Обычный `/stella/` тоже открывает пиксели; градиент доступен только явно через `/stella/gradient/`. Это не вариант `pixels-no-photo`: штатный фотоэтап сохранён. Оба стендовых ПК MAX/STELLA содержат обе сборки, роли выбираются отдельными ярлыками; заранее настроены оба направления связи. До следующего указания пользователя Стеллу на дисплеи не выводить.

## Запуск

1. Перенести папку целиком. `Start.bat` запускает оба приложения; `Check.bat` проверяет сервисы; `Stop.bat` останавливает принадлежащие этому комплекту процессы.
2. В TouchDesigner выбрать `KDW_MAX_BACKGROUND` и `KDW_MAX_CONTENT`. Оба 3072×1536, целевые 60 кадров/с. Фон непрозрачный; контент имеет premultiplied alpha. Композиция: `content.rgb + background.rgb * (1 - content.a)`. Не применять повторное умножение RGB на alpha.
3. Проверить изображение на физическом выводе, затем запустить `Arm-Output.bat`. До ARM игра не принимает ввод и не подтверждает визуальную готовность заданий. `Disarm-Output.bat` отменяет текущий контакт и закрывает визуальный допуск. После нового запуска MAX нужен новый ARM; старый файл не подходит к новому bootId.
4. `Status-Output.bat` показывает bootId, два счётчика кадров, GPU и состояние LiDAR. ARM — явное подтверждение оператора; автоматического обнаружения потери изображения в TouchDesigner здесь нет. Перед отключением приёмника выполнить Disarm.

Стелла выбирает портретный дисплей, при его отсутствии основной. Для закрепления дисплея создать `apps/stela/data/display.local.json` с `{"displayId":123}`. ID доступны в журнале `runtime.displays`; если закреплённый дисплей отсутствует, запуск завершается ошибкой вместо вывода на другой экран. Аудио/камера на новом ПК настраиваются отдельно в штатной панели Стеллы.

## OSC от лидара

Используется прежний HokuyoTracker2: UDP 9001, `/create` и `/update` с `,iff` или `,iffff` (ID, X, Y и два необязательных неиспользуемых float), `/delete` с `,i`. Это не TUIO. Парсер — osc.js 2.4.5, projective mapping — perspective-transform 1.1.3. Native touch события идут через Chromium в обычные игровые обработчики; OSC не вызывает команды прохождения напрямую.

Скопировать `examples/lidar.local.json` в `apps/max-game/data/lidar.local.json`. Указать реальный `sourceAddress`, локальный `bindAddress`, четыре измеренные `rawPoints` и соответствующие `targetPoints` в пикселях 3072×1536, в порядке TL, TR, BR, BL. После проверки центра установить `enabled:true` и перезапустить MAX. Сохранённая старая калибровка 4096×1280 не переносится автоматически. Без измеренных точек LiDAR выключен; пример не является калибровкой. Ввод за пределами x=560…2320 отбрасывается. Как в последней установленной версии, выбирается верхняя точка по экранному Y после калибровки. Смена физической точки продолжает один ID жеста, без повторного down; выбор выполняется после полного OSC-пакета. Watchdog 350 мс отменяет потерянный контакт; его значение проверить на реальной частоте неподвижной руки. После отмены требуется новый create. Firewall на стенде разрешать только для фактического IP отправителя, локального адреса, UDP-порта и Electron этого комплекта.

## Состав и обновление

- `apps/max-game` — реальная игра, GPU bridge и OSC-приёмник
- `apps/stela` — реальная Стелла, локальные голосовые и аудиосервисы
- `runtime/electron` — один общий runtime
- `archives` — два согласованных обновления приложений с SHA256 и общим sharedRevision; без runtime, `data` и VST-плагинов
- `release-set.json` и `release-manifest.json` — версии и точные хеши файлов

Полная локальная папка содержит приватный голосовой конфиг и пресеты. Она предназначена для доверенного локального переноса; целиком публиковать её нельзя. Архивы обновления формируются до копирования приватных файлов. VST и runtime переносятся один раз; последующие релизы обновляют код и ресурсы. `data`, фото, профили, настройки, ключи связи и калибровка сохраняются на стенде. Не распаковывать архив поверх работающего приложения. Оба компонента обновлять одним согласованным набором после остановки; не смешивать разные sharedRevision.

Для чистой установки из GitHub распаковать оба ZIP приложений и `stand-tools` в одну новую папку. `Install-Runtime.bat` докачает закреплённый Electron с проверкой SHA256; можно передать `-CachedRuntime` с ранее установленным runtime, чтобы не скачивать его повторно. После этого отдельно перенести приватные настройки и VST из доверенного локального комплекта. На уже работающем стенде сначала сохранить резервную копию и остановить оба приложения; файлы `app.json` и `settings/stand.json` сохранять как настройки оператора. Эти архивы не являются автоматическим обновлятором с откатом — старый рабочий комплект хранить до завершения приёмки нового.

При первой установке текущие голосовые настройки и полные аудиопресеты уже находятся в локальном комплекте. История посетителей, браузерные профили, старые игры, исходники, Git и node_modules исключены. Совместная локальная связь MAX/Стеллы создаётся штатным механизмом; ключи прежнего стенда не публикуются.

## Статус приёмки

RC2 установлен 27.10.2026 на PREMIUM-CHUWI (оба приложения), KDW MAX / DESKTOP-DBD624H и KDW STELA / DESKTOP-64J4BMN. Установки и проверочные запуски успешны, TLS-связь двух стендовых ПК проверена. Стелла оставлена закрытой по указанию пользователя; MAX работает без ARM/LiDAR. 60-секундный транспортный тест в DISARM: MAX около60FPS, CHUWI около52–53FPS. Подробности и ограничения: [отчёт установки](verification-stand-install-20261027/README.md).

Это production-компоновка реальных приложений. Маркировка RC сохраняется до аппаратной приёмки именно этих сборок на CHUWI: TouchDesigner, физический лидар и неподвижное удержание, дисплей Стеллы, камера, микрофон/VST, все миссии и три бизнеса, очередь посетителей и длительный прогон. Результаты прежнего синтетического Spout-прототипа не заменяют эту проверку.
