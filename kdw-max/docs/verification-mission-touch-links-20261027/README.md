# Линки и касания внутри миссии — 27.10.2026

Подтверждена ошибка общего масштабирования: createCompositionLayout.project возвращал x/y/w/h без scenePose.scale. Повторный projectBounds(local, projectedPose) давал NaN для плиток и подписей; их bounds использовались соединительными линиями. На production зарегистрированы повторные THREE.BufferGeometry.computeBoundingSphere(): Computed radius is NaN. Исправлено сохранение полей позы и умножение её scale на affine-коэффициент. Основной регрессионный тест теперь проверяет дочернюю плитку и конечные координаты, а не только внешний DOM-прямоугольник.

Нативные панели личного канала/бизнеса/постов/товаров находятся вне #circles и имели только обычные click-обработчики. При длительном едином контакте OSC касание не завершалось, поэтому click ждал отпускания. kdw-native-touch переводит настоящий touch-down/вход пальца в эти кнопки в их прежний click-обработчик. Учтены active, disabled, hidden/inert, уход из предыдущей области и подавление последующего browser click на отпускании. Стационарная рука не активирует новый экран под собой; мышь/клавиатура и обычные поля ввода не подменяются. Generated main изменён через адаптер, frozen stand-base сохранён.

Проверки: test:max149/149, test:layout13/13, build:max/check:generated PASS. Chromium: ПК75%/−80px и телефон60%/+40px; нативная кнопка реально активирована CDP touchStart до touchEnd; после отпускания экран не продвинулся повторно; у масштабированного телефона есть входящие линки, ошибок JavaScript/NaN нет. Дополнительно проверены перенос на другую кнопку и запреты на disabled/inert/неактивное/синтетическое касание. browser.json и before-errors.json рядом.

Установка подготовлена пакетом MISSION-TOUCH-LINKS-20261027-1. Первоначально автопроверка отклонила деплой без явного запроса; после отдельного ответа пользователя «Да, установить на оба ПК» запущена установка на обе production-машины. Финальный результат — ../stand-patches/MISSION-TOUCH-LINKS-20261027-1/. Физический проход рукой не имитировался.
