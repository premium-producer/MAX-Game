# Независимая доставка Стелла → MAX — реализация 27.10.2026

## Поставленный объём

- У каждого приложения свой локальный сервер. Стелла получает локальные настройки или сохранённый кэш/defaults сразу; удалённый запрос выполняется в фоне.
- Стелла сохраняет небольшую миссию в `data/link/outbox-v2/<gameId>.json`. Возврат с результата по локальному таймеру не зависит от ответа MAX.
- Подтверждённый JPEG сохраняется отдельно в `data/link/outbox-v2/photos/`. Миссии и фото доставляют независимые фоновые обработчики, с ограничением времени запроса и повторными попытками. Удалённый ответ не удерживает локальный HTTP API.
- MAX принимает миссию без фото. Позднее фото привязано к `gameId` и `voiceSessionId`, проверяется по SHA256, размеру и в Electron — декодированием JPEG. После локального декодирования renderer обновляет изображения без reload, новой сессии, сброса прогресса или изменения contentRevision.
- Нейтральные SVG остаются доступны даже при одновременной доставке фото и загрузке первоначального каталога.
- Повтор сообщения идемпотентен. Старый выбор не заменяет новый; отмена не останавливает игру после claim. Срок ожидания неполученной/неподтверждённой миссии — 120 секунд; начатая игра этим сроком не обрывается.
- Отдельные readiness-поля отражают доступность API, renderer, вывода, ввода и ARM. Приглашение не объявляется на основании одного ACK доставки: требуется готовый вывод и состояние scan. Физическая работоспособность LiDAR требует аппаратной приёмки.
- Фото в MAX хранится отдельным файлом, а не base64 в журнале. Верхний срок хранения фото — 24 часа; очистка выполняется при обслуживании записей. Отмена/истечение/замена удаляют связанный файл. История терминальных назначений ограничена 30 днями.

## Фактический контракт v2

Локальный API Стеллы: `POST /__kdw/link/v2/submit`, `/status`, `/photo`. Сохраняются проверки Origin и действующего токена/ревизии голосовой сессии. Фото передаётся бинарным JPEG, не в JSON миссии.

Между ПК: `GET /__kdw/link/v2/capabilities`, `/readiness`; `POST /missions`; `GET /missions/<gameId>`; `PUT /missions/<gameId>/photo/1`; `POST /missions/<gameId>/cancel`. Сохраняются привязанный TLS-сертификат и ключ пары. Старый v1-приёмник/отправитель сохранён для совместимости; новая Стелла не переключается скрыто на v1.

В этом выпуске подтверждается хранение фото на MAX (`stored`), но отдельного серверного ACK `applied` от renderer ещё нет. Повторное применение контролируется локально по SHA. Нет отдельного экрана управления очередью, автоматического capability-negotiation или нового протокола визуального ACK приглашения. Эти расширения в архитектурном документе остаются целевыми; не следует считать весь проектный контракт уже реализованным.

## Проверки

- 140 тестов MAX, 13 тестов game-link/async-link, 17 тестов Стеллы: пройдены; TypeScript, generated-source и сохранение профилей при сборке проверены.
- Retention-набор: 5000 синтетических записей; пройден.
- Общий browser audit: настоящее меню MAX 3072×1536, восстановление Стеллы после потери локального WebSocket, выбор миссии без фото → MAX → удержание ладони → первое задание, звук без ошибок. Результат: `../verification-audit-fixes-20261026/browser/results.json`.
- `browser.json`: настоящий JPEG, выдача SVG, позднее обновление, неизменность состояния/ревизии, обновление вновь появившегося изображения, отсутствие ошибок браузера. Проверено Chromium; это не измерение FPS на стенде.
- При первой общей проверке выявлены и исправлены недопустимый query-string в каталоге и обработка пустой активной игры. После исправления browser audit пройден повторно.

## Обновление стендов

Только production-роли `max-game-pc` (DR7) и `stela-pc` (DR2). CHUWI исключён. Готовый установщик: backup, проверка SHA до/после, сохранение конфигураций, восстановление прежнего режима запуска, rollback при ошибке.

Пакеты: `ASYNC-MAX-20261027-2` — 702 140 байт / 7 файлов; `ASYNC-STELA-20261027-2` — 150 404 байта / 4 файла. Сначала MAX на обоих ПК, затем Стелла на обоих. Машинные подтверждения установки — `../stand-patches/ASYNC-MAX-20261027-2/` и `../stand-patches/ASYNC-STELA-20261027-2/`.

Полный физический сценарий с камерой, LiDAR и TouchDesigner не следует подменять health-check или локальным браузерным тестом. ARM автоматически не включается.

### Итог установки и обнаруженная проблема вывода

Все четыре установки завершились `complete`; сохранено по 4 конфигурационных файла MAX и по 6 файлов Стеллы на каждом ПК. Передача каждого ZIP занимала 2,35–2,47 секунды. Основная Стелла восстановлена с окном, её запасная копия — server-only. MAX на DR7 первоначально восстановил оба Spout-слоя, запасная копия на DR2 — server-only.

В 12:13:49 UTC на DR7 MAX завершился с `Unexpected shared texture dimensions/handle`. Единственный повторный запуск в 12:16:15 UTC завершился с `Shared GPU texture unavailable`. Это сообщения существующего `stand-output.cjs`; этот модуль и native-мост данным патчем не изменялись. Причина изменения GPU-окружения пока не подтверждена. Текущая архитектура процесса MAX всё ещё завершает API вместе с фатальной ошибкой Spout; изоляция GPU-ошибок внутри самого MAX — отдельное незавершённое расширение.

Подтверждён v2 + pinned TLS по резервному направлению DR7 → DR2 (`max-game-pc-link.json`), локальные настройки ответили за 20 мс. Основное направление DR2 → DR7 сейчас не подтверждено: MAX прекращает обслуживать API из-за указанного GPU-сбоя. Нельзя считать аппаратную приёмку или основной канал передачи успешно завершёнными. Свидетельства: `max-stop.json`, `max-stop-latest.json`. Дальнейшие перезапуски, смена режима и включение ARM не выполнялись.

Дополнительная диагностика (`gpu-session.json`): активна локальная console-сессия DR7, RDP-сессии нет; два дисплея определяются активными; NVIDIA RTX 3080 и Intel UHD 770 имеют статус OK. Это не объясняет потерю shared texture; физическая причина остаётся неустановленной.

Обновление после следующего обращения: основной MAX восстановлен через интерактивную Scheduled Task, оба Spout-потока подтверждены независимым приёмником. Ошибка прозрачного standby до ARM исправлена; см. [проверку Spout](../verification-spout-idle-20261027/README.md). Предыдущий неудачный повторный запуск из SSH не являлся корректной аппаратной проверкой интерактивного GPU.
