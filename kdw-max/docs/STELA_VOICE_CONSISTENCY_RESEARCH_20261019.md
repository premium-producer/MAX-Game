Сначала провести небольшое сравнение с другим штатным голосом текущего движка. Один удачный пример и одинаковый voice ID не считаются доказательством постоянства.

## 2. Что фактически делает наш тракт

Проверены `launcher/voice/config.cjs`, `tts.cjs`, `persistent.cjs`, `dialogue.cjs`, клиентский `omni-audio.ts`, настройки и безопасные события журнала. [Локальная сводка](verification-20261019/stela-voice-research/audit.json).

| Параметр | Факт |
|---|---|

| Речь | qwen3-tts-flash-realtime, Serena |
| Язык | явно Russian; шесть TTS ACK за19октября сообщают russian |
| Звук | PCM24k; буфер браузера также объявляется24k |
| Ходы | один полный текст, append+commit на реплику; PCM-чанки принадлежат одному синтезу |
| Соединение | тёплое; после некоторых отмен создаётся новое с теми же параметрами |
| Эффекты | во всех четырёх проверенных клиентских запусках input/output VST выключены, фейды12/24мс |
| Управление стилем | инструкции D в TTS не передаются; TTS получает только утверждённый текст |
| Список голосов в нашем config | разрешены только Serena/Cherry; произвольный voice ID или другая TTS-модель сейчас не подключаются |

В журналах нет признака переключения Serena↔другой голос или автоматического выбора языка. Это **не** акустическое доказательство одинакового тембра: исходящее аудио в пользовательской сессии не записывается. По коду не обнаружено произвольного изменения playbackRate; межрепликовую вариативность синтеза считаю основной гипотезой, а не доказанной единственной причиной. Приглушение может менять воспринимаемую громкость, но не объясняет само по себе нерусские ударения.

Фраза «говори по-русски» в системном промпте D меняет содержание ответа. Она не становится акустической инструкцией нашего отдельного TTS. Сохранение WebSocket убирает handshake, но документация не обещает, что оно фиксирует все внутренние параметры генерации голоса.

## 3. Что подтверждают разработчики

### 3.1. Языковая поддержка и родной язык диктора различаются

В официальном **локальном** Qwen3-TTS CustomVoice Serena описана как голос с родным китайским языком. Авторы рекомендуют родной язык выбранного диктора для лучшего качества, хотя генерация других языков поддерживается. Они также описывают повторное использование одного clone prompt и схему VoiceDesign→эталон→Clone для постоянного персонажа. Это аргумент в пользу русского эталона, **не доказательство**, что облачная Serena имеет идентичные веса и поведение. [Официальный репозиторий Qwen](https://github.com/QwenLM/Qwen3-TTS#custom-voice-generate), [Voice Design then Clone](https://github.com/QwenLM/Qwen3-TTS#voice-design-then-clone).

Облачный список отдельно подтверждает русский у Serena и наличие Katerina. Имя Katerina и её описание не доказывают родной русский: её нужно прослушать на нашем тексте, а не выбирать по имени. [Облачный список голосов](https://www.alibabacloud.com/help/en/model-studio/qwen-tts-voice-list).

### 3.2. У текущего API нет универсального регулятора постоянства

Для Qwen3 realtime документированы явный язык, rate/pitch и commit целых предложений. Это полезно для качества и одинакового темпа, но не является гарантией одной личности диктора. В опубликованной схеме session.update не обнаружены seed/temperature/top_p: нельзя просто перенести эти поля из локального Transformers/vLLM. [Client events Qwen3](https://www.alibabacloud.com/help/en/model-studio/qwen-tts-realtime-client-events).

В SDK таблица относит instructions к **Instruct**-семейству, а не к обычному flash-realtime; языки самих инструкций — китайский/английский. Примеры той же страницы местами упоминают Omni вместо Instruct, поэтому одну скопированную строку примера нельзя считать проверенным контрактом. Нельзя обещать исправление Serena добавлением русского instructions в нынешний session.update. [SDK, параметры](https://help.aliyun.com/en/model-studio/qwen-tts-realtime-python-sdk).

### 3.3. Один созданный голос нужно переиспользовать

Облачный Voice Design создаёт voice_id и preview; документация предупреждает, что повторное создание по тому же описанию может дать другой голос. Для постоянной стелы выбирается и сохраняется один результат. Описание должно задавать конкретные слышимые свойства; поддерживаются английский/китайский, до500символов. Это операция создания, не инструкция заново «придумывать» голос перед каждой фразой. [Voice Design](https://www.alibabacloud.com/help/en/model-studio/voice-design-user-guide).

Voice Cloning привязывает созданный голос к target_model. Для новых Qwen-Audio моделей рекомендован чистый эталон10–20с, без музыки, других людей и выраженного реверберационного хвоста; от16кГц. Русский указан среди поддержанных языков референса. Выбираем запись носительницы русского в нужной манере; «три секунды достаточно» из описания локальной модели не следует считать нашим целевым качеством. [Voice cloning и требования](https://www.alibabacloud.com/help/en/model-studio/voice-cloning-user-guide).

## 5. Варианты для нашего стенда

| Вариант | Смысл | Решение |
|---|---|---|
| Serena + ещё один штатный голос, например Katerina | Минимальная переделка, сравнение на текущем протоколе. Нужно расширить наш allowlist в эксперименте. | Быстрая контрольная пара, без обещания качества русского. |
| Один русский эталон→закреплённый custom voice | Лучше соответствует требованию одного русского персонажа. Профиль не пересоздаётся между ходами. | **Предпочтительный кандидат для следующего прототипа**, после проверки доступности модели/региона. |
| Voice Design один раз→прослушивание→сохранённый voice_id | Возможность обойтись без выбранной дикторской записи. В локальном варианте — Design→Clone. | Второй путь к эталону; нужен русский preview, описание само по себе не доказывает акцент. |
| Отдельный TTS с русским исходным диктором | Сохраняем Omni D/Controller, заменяем только S. | Контроль качества, если Qwen-кандидаты не проходят русскую приёмку. |
| Локальный Qwen+SFT/свой GPU | Больше контроля над conditioning/генерацией, больше сопровождения и аппаратных требований. | Не первый шаг для переносимого Windows-комплекта. |

Для внешнего контрольного TTS подходит проверка SpeechKit: в официальном списке есть русские женские marina/dasha/lera с фиксированными ролями; отдельно документированы русские ударения и фонемная разметка. Это основания включить его в сравнение, **не измеренное превосходство** по нашему голосу/задержке. [Русские голоса](https://aistudio.yandex.ru/en/docs/speechkit/tts/voices), [разметка](https://aistudio.yandex.ru/en/docs/speechkit/tts/markup/tts-markup).

### Важная граница совместимости облака

Актуальная документация уже разделяет Qwen3-TTS и новые Qwen-Audio-TTS3.0/3.1. У новых моделей другой endpoint `/api-ws/v1/inference`, задачи run-task/continue-task и другие terminal/cancel события; нынешний адаптер использует `/realtime`, buffer.append/commit и response.done. Простая замена model или voice ID недостаточна. [Актуальный guide](https://www.alibabacloud.com/help/en/model-studio/realtime-tts-user-guide), [новый WebSocket-протокол](https://www.alibabacloud.com/help/en/model-studio/qwen-audio-tts-websocket-api).

Доступность конкретного clone/design model в нашем Singapore workspace и привязку voice_id нужно проверить отдельно: пример в Beijing не доказывает переносимость голоса в Singapore. Не использовать старые VC/VD названия из SDK как уже доступные модели аккаунта. Зафиксированный model alias не фиксирует скрытые веса облачного сервиса; если провайдер поддерживает snapshot, закреплять проверенный snapshot, иначе сохранять дату/API-ACK и выполнять регрессию.

## 6. Предлагаемый профиль и изменения следующей итерации

Целевой голос: взрослая женщина примерно30лет, носительница стандартного русского, тёплый средний регистр, чёткая артикуляция, спокойная естественная вопросительная интонация, умеренный постоянный темп. Без нарочитой детскости/шёпота/рекламных перепадов. Это предложение для выбора звучания, не уже утверждённая фонограмма.

Черновик английского описания **для создания голоса**, если доступен соответствующий API:

```text
A female native speaker of standard Russian, around 30 years old. Warm, clear mid-pitched voice, natural Russian stress and intonation. Calm, friendly exhibition assistant. Steady conversational pace, precise articulation, restrained expressiveness, consistent vocal character. No whispering, theatrical delivery or exaggerated pitch changes.
```

Сначала прослушать результат на русском. Одна и та же запись/voice_id применяется ко всему диалогу. Общий профиль хранит engine/model/voiceId/language/rate/style/version/referenceSHA. Он неизменен в пределах посетителя и восстанавливается после reconnect; сырой speaker embedding/референс в журнал не попадает. В журнале — fingerprint профиля, подтверждённые параметры и источники аудио. При отсутствии поля ACK оно unknown; язык сравнивать после нормализации регистра, не угадывать подтверждение по запросу. Сейчас язык логируется, но не входит в строгую проверку TTS ACK — это полезная небольшая будущая доработка.

Текст разделить на displayText и speechText: интерфейс сохраняет MAX; для звука отдельно проверить произнесение «Макс», числа, аббревиатуры, пунктуацию и корректную «ё». Нормализация ограничена произношением, не переписывает смысл ответа и не запускает новый LLM. Словарь ударений специфичен движку; синтаксис SpeechKit не копировать в Qwen. Логировать хеш/версию нормализатора и фактический submittedText с прежним text-off.

Повторяющиеся канонические вопросы можно заранее утвердить и хранить PCM того же выбранного профиля. Это даёт побайтово повторяемое звучание этих фраз и убирает облачное ожидание именно для них. Ключ кэша: текст/нормализатор/голос/модель/стиль/формат. Динамические ответы генерируются тем же голосом; старые WAV другого диктора не смешиваются с ним. И кэш, и поток идут через один VST→фейды→WebRTC/AEC reference/epoch/cancel. Эффекты применять после кэша; не обходить тракт отдельным проигрывателем.

Компрессор/эквалайзер могут выровнять уровень и окраску, но не возвращают русские ударения и не фиксируют идентичность генеративного диктора. Прослушивание сначала сухое, затем в стендовом тракте. Автоматический speaker-score полезен для offline QC, но не должен становиться платной перегенерацией после начала речи или единственным критерием на однословных ответах.

## 7. Проверка до смены рабочего голоса

Следующий эксперимент проводится отдельно от зафиксированной версии. Сейчас он **не запускался**.

1. Проверить возможности нужной модели/voice/региона двумя короткими синтезами. Если API не поддержан, не запускать большую матрицу.
2. Отсеять кандидатов на восьми одинаковых фразах × три жизненных цикла: свежий прогретый канал, тёплый повтор, reconnect. Случайный порядок и выровненная громкость, прослушивание носителем русского.
3. Для лучшего кандидата — двадцать фраз × три повтора, затем отмены до/после первого чанка, ожидание и возвращение после reconnect. Примеры: «Да», «Нет», «Привет», «Повторю», «Готовы начать знакомство с MAX?», личное использование/общение, объяснение MAX, исправление выбора, длинный ответ и названия миссий в кавычках.
4. Разделять ошибки чтения, ударений, нерусской интонации, тембра/личности и громкости. ASR проверяет слова, а не естественность акцента; F0 и speaker similarity — вспомогательные признаки. Приёмка: ни одной услышанной смены диктора/пола, все ключевые слова понятны, выбранная спокойная манера держится на вопросах и ответах. Ноль ошибок на60пробах не означает гарантированного нуля в эксплуатации.
5. Одновременно записывать firstPCM p50/p95, полный speech.end→playback, handshake/reconnect, отменённые задания и usage в единицах движка. Сравнивать с Serena на том же наборе/сети; прежние527/717мс — исторический ориентир TTS, не гарантия нового движка. Предлагаемый допуск — не ухудшать сопоставимый firstPCM более чем на100мс p50/200мс p95; окончательный порог после прослушивания.
6. Финал — живой разговор с колонками, тихим/коротким перебиванием и эффектами. AEC-reference должен содержать новый голос/фейды/хвост, старые чанки не оживают после смены epoch. Потом отдельно фиксируется принятый голос и чистый комплект; до этого SCOPE остаётся откатом.

Приоритет следующего действия: **короткая аудиопроба штатного кандидата и одного закреплённого русского эталона**, затем выбор по звучанию и стабильности. Полное обучение и миграция диалогового движка не требуются для такого сравнения.
