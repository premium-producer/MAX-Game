# Меню: восстановление после ошибки выбора

27.10.2026, установлен на оба production-ПК. CHUWI не затрагивался.

Патч кнопок/карточек CARD-PRESS уже присутствовал на обоих ПК в составе ALL-UPDATES. Это подтверждено совпадением всех четырёх SHA в preflight. Попытка его отдельной установки завершилась проверкой основы без замены файлов; после обнаружения совпадений повторная установка этого пакета не предпринималась.

До исправления: combined, armed/active=true, активного назначения нет; пакеты лидара выросли с 772 до 1442 без ошибок. Таким образом прежняя причина с выключенным ARM не объясняет этот эпизод. Старый renderer не журналировал состояние выбора, поэтому первоначальный код ошибки точно не установлен.

Найден дефект: createIdleMenu.select устанавливал selected=true; при ошибке manual fetch внешний код сбрасывал idleSelecting, но не selected. На следующем RAF все кнопки оставались inert. Кроме того, запрос не имел таймаута. Исправлено: таймаут 5 секунд, восстановление меню через restore(), безопасная публикация кода ошибки и запись в журнал.

Добавлена диагностика preload → output: раз в секунду текущий экран, состояние выбора, готовность меню, четыре области кнопок, последнее доверенное pointer-событие и счётчик. Вводимый текст и фото не собираются. Данные видны в operator/state, output-state.json и штатных runtime samples; ограничены 4096 байт. ARM не включается автоматически при обычном холодном запуске — при этой установке восстановлен прежний включённый режим.

Проверки: 157 существующих MAX-тестов, отдельный новый тест диагностики preload, 11 runtime, check:generated. Локальный настоящий production-сервер и полная GPU-сцена: первый HTTP 503, меню снова интерактивно, второе trusted touch запускает digital-id в scan; два запроса, без JS-ошибок. Результат browser.json. Повторяемый runner: node ops/production-build/menu-start-browser.mjs (изолированные данные .cache/menu-start-fixture-*).

После установки на основном стенде: armed=true, active=true, оба слоя готовы, реальные pointer-события зарегистрированы. Без искусственного назначения со стороны агента наблюдался экран digital-id.create-id.confirm в фазе task. Свежие снимки active-game-verified.json и operator-verified.json находятся в docs/stand-patches/MENU-START-MAX-20261027-1. Источник текущей реальной игры — stella, поэтому это подтверждает прохождение и касания, а не физический выбор в меню. Повторный manual-выбор после HTTP-ошибки подтверждён локальным production-прогоном; физический выбор на стенде ожидает пользователя. Точный первоначальный HTTP-код отказа не установлен.
