# Чистый idle при запуске и касания полей — 27.10.2026

Установлено на обоих production-ПК патчем IDLE-KEYBOARD-20261027-1; см. ../stand-patches/IDLE-KEYBOARD-20261027-1/README.md.

По прямому указанию пользователя новый запуск/перезапуск графического процесса MAX больше не продолжает прежний пользовательский сеанс. Supervisor перед созданием output запрашивает API через внутренний IPC reset-game-for-output; API вызывает сериализованный resetForStartup хаба. Старые active/queued/playing/completed/incomplete назначения становятся cancelled с endReason=startup-reset, активный указатель очищается; записи, подписи, claim и закреплённая политика сохранены для истории. Это явное изменение прежней политики восстановления активного посетителя при новом запуске. Обычная HTML-перезагрузка после выбора миссии не вызывает этот сброс. Повторный Start уже работающего MAX инициирует restart-output через штатный ограничитель перезапусков. Стелла и её сценарий этим условием не сбрасываются.

При отсутствии приглашения production-клиент создаёт отдельный idle.session вместо восстановления исторического общего webgl-v5 из IndexedDB. Новое назначение от Стеллы/экрана использует собственный gameId и штатное прохождение. Сброс хаба не доступен по LAN/HTTP — только доверенный IPC supervisor/API. Гонка повторного запуска во время reset блокируется флагом resetting.

Нативный touch-адаптер теперь поддерживает input/textarea: фокус с preventScroll, затем прежний click-обработчик открывает экранную клавиатуру сразу, без ожидания /delete. Запреты disabled/readOnly/inert/hidden и защита от повторного клика при отпускании сохранены. Кнопка «Создать канал» требует название длиной хотя бы два символа, как прежде; тест проходит после ввода названия.

Проверки: MAX151/151, link/runtime24/24, build:shared/build:max/check:generated PASS. Реальный Chromium прошёл касаниями путь blogger.chats → menu → name: открытие клавиатуры имени, ввод «Ко», открытие клавиатуры описания, ввод «д», нижняя кнопка → privacy. Затем production-игра дошла до task, выполнен тот же resetForStartup, перезагрузка показала idle без активного назначения, следующий посетитель смог выбрать новую миссию. Ошибок JS/NaN нет. Дополнительно проверены сохранность старых подписей/claim, отмена очереди, невозможность оживить старый gameId дубликатом и свежий idle-sessionId. Физический проход на стенде ещё не проверялся.

Канонические правки: apps/STARTUP/tools/game-link.cjs и runtime-main.cjs; MAX portable-server.cjs; client/src/kdw-game-link.mjs и kdw-native-touch.mjs. Shared launcher-копии синхронизированы build:shared. Замороженный stand-base не менялся.
