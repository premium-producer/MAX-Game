# Настройки production-стенда

Единственный источник — `max-game/settings/stand.json` в используемом комплекте MAX. Для одного ПК это `production/startup-one-pc/max-game/settings/stand.json`, для двух — `production/startup-max/max-game/settings/stand.json`. Stella получает публичные настройки от своего MAX через существующую связь, в том числе закреплённый TLS на двух ПК. Ключей, фотографий и VST в JSON нет.

1. Запустить комплект и открыть `Edit-Settings.bat`.
2. Изменить число, сохранить JSON без комментариев.
3. Запустить `Check-Settings.bat`: он показывает принятую ревизию, дату и значения или ошибку. Чтение и проверка происходят при запросе, без сборки и перезапуска. В standby MAX опрашивает версию примерно раз в 1,2 секунды; Stella читает её перед новым посетителем.

Активная игра хранит снимок настроек и абсолютные сроки. Смена JSON не перезапускает её таймеры. Новая миссия закрепляет конфигурацию при выходе из очереди на MAX. При неверном документе целиком сохраняется последняя принятая версия в `data/stand-settings.accepted.json`; она переживает перезапуск. При первом запуске с ошибочным/отсутствующим файлом используются эталонные значения с сообщением оператору. Stella при отключении MAX использует последнюю полученную версию, миссии сохраняет в outbox.

| Ключ | По умолчанию, секунды | Назначение |
|---|---:|---|
| `max.timings.palmWaitSeconds` | 30 | Ожидание подхода после появления ладони |
| `max.timings.palmHoldSeconds` | 0.8 | Непрерывный контакт внутри кнопки ладони |
| `max.timings.taskDurationSeconds` | 60 | Время каждого задания; смена внутренних экранов не сбрасывает |
| `max.timings.inactivitySeconds` | 120 | От последнего реального касания до standby |
| `max.timings.qrDisplaySeconds` | 15 | Показ декодированного финального QR |
| `max.timings.standbyAfterIdleSeconds` | 3 | Минимальный standby после бездействия перед следующей очередью |
| `max.timings.resultSeconds` | 0.8 | Интервал результата до следующего задания |
| `stella.timings.inactivitySeconds` | 30 | Бездействие Stella с сохранением защиты речи/съёмки |
| `stella.timings.deliveryRetrySeconds` | 2 | Повтор клиентской доставки; серверный outbox также сохраняется |
| `stella.timings.resultReturnSeconds` | 15 | Возврат Stella после подтверждённой доставки и окончания речи |

Допустимый диапазон таймингов: 0,1–3600 секунд; в JSON десятичная точка. Удержание ладони должно быть короче ожидания подхода. Неизвестные/пропущенные ключи, строки вместо чисел и нулевые значения отклоняются. `schemaVersion` всегда 1.

`max.entryMode`: `stella` — выбор только через Stella; `manual` — самостоятельный выбор иконкой; `combined` — оба входа с одной FIFO-очередью, ручной выбор только когда MAX свободен. `Start-Manual.bat` и `Start-With-Stella.bat` переключают этот параметр; обычный `Start.bat` сохраняет выбранный режим. Переход на manual не удаляет ранее принятые назначения, новые назначения Stella будут ожидать в её outbox до возврата режима.

`defaults` задаёт данные при автозачёте: `businessType` (`cafe`, `flowers`, `auto`), `channelName` (до 64 символов), `channelDescription`, `channelSlug` (4–32 латинских букв/цифр/`_`, первая — строчная буква), `commentReply`. Существующие введённые значения сохраняются. Непустые строки — до 160 символов, без управляющих символов. Это настройки содержимого, не доступ к диагностике.

Физическая «ладонь» в этой версии — удержание штатного touch-контакта, без биометрического распознавания формы. Реальные pointerdown/перемещение с контактом в разрешённой плоской области обновляют бездействие. Hover, синтетические события, автоматические переходы и касания скруглений — нет. Неподвижное длительное удержание не обновляет срок само по себе. На финальном QR касания не продлевают показ. Бездействие имеет приоритет перед автозачётом.

В production `Escape/F11/F12` и dev-команды закрыты. Выход оператора — `Ctrl+Shift+Q` или `Stop.bat`. `Calibrate-Pixel-Map.bat` — отдельный операторский запуск после остановки игры, перед обычным запуском его нужно закрыть. Исходные анимационные кривые, контент миссий, карта экрана, Qwen и VST редактируются прежними инструментами; их технические параметры не являются таймерами пользовательского сценария.

Обновление через `ops/production-build/update.cjs` сохраняет JSON и все `data`, меняет только файлы приложения с резервной копией изменённых файлов. Эталон JSON лежит в `apps/max-game/settings/stand.json`; после установки настроек `Check-Settings.bat` — основной способ проверки, поскольку операторские правки штатно меняют хеш конфигурации относительно поставки.
