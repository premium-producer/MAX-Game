# Production-комплекты — 23.10.2026

**Уточнение 27.10.2026:** актуальная финальная Стелла — пиксельная (`/stella/pixels/`), с сохранённым фотоэтапом. Для реальных MAX/STELLA теперь ставятся обе сборки на каждый ПК, чтобы роли можно было поменять. Текущая поставка описана в [STAND_RELEASE.md](STAND_RELEASE.md); приведённое ниже разделение startup-max/startup-stela — прежняя схема комплектов.

**Production-итерация реализована 23.10.2026.** Параметры находятся в runtime JSON; текущие решения и операторские действия — [STAND_SETTINGS.md](STAND_SETTINGS.md). Подробные результаты — [проверки](verification-stand-production-20261023/README.md). Физическая установка и проверка на стенде ещё не выполнены.

Готовая папка — `production/` в корне KDW-MAX. Четыре независимых каталога:

| Каталог | Назначение | Запуск |
|---|---|---|
| `dev` | Исходники приложений, UI, документация и готовые dev-приложения | `apps/STARTUP/Start.bat` |
| `startup-one-pc` | MAX и Стелла на одном Windows-ПК | `Start.bat` |
| `startup-stela` | ПК Стеллы | `Start.bat`, при первом запуске ввод IP MAX |
| `startup-max` | Игровой ПК, локальный экран и HTTPS-приёмник | `Start.bat` |

Каждый startup-каталог переносится целиком и не зависит от dev или исходного проекта. Source/toolchain в runtime-каталоги не включены. Встроены Electron, штатные ресурсы, точные VST3 и app-local CRT, текущие Qwen-конфиг/голосовой профиль и полные VST-пресеты. Старые `data/profile`, runtime.json, журналы, фото и игры не копировались. Разработческие копии браузерных профилей/кэшей также исключены из dev. Папка предназначена для внутренней передачи: действующие приватные настройки остаются внутри `data`, вне `www`.

Для одного ПК достаточно `startup-one-pc/Start.bat`. Для двух ПК:

1. Скопировать `startup-max` на игровой ПК, `startup-stela` — на ПК Стеллы. Оба ПК подключить к одной сети Windows с профилем «Частная».
2. На MAX один раз выполнить `Enable-Network.bat` от администратора, затем `Start.bat`. `Show-Address.bat` показывает IPv4.
3. На Стелле запустить `Start.bat` и ввести IPv4 MAX. Адрес можно изменить через `Configure-Link.bat`. `Check-Link.bat` проверяет HTTPS и ключ пары.

Ключ и сертификат одной пары подготовлены заранее именно для этих двух каталогов. Глобально устанавливать сертификат, Node или Python не требуется. MAX слушает отдельный TLS-порт18753; локальный UI/stop/фото API остаются на127.0.0.1:18752. Сетевой приёмник обслуживает только авторизованные status/ingest и публичную конфигурацию /__kdw/settings, отклоняет Origin и не публикует статику/администрирование. Стелла доверяет только сертификату своей пары и отправляет отдельный случайный ключ по HTTPS. Проверка сертификата не отключается; для локального IP проверяется закреплённый сертификат вместо DNS-имени. Firewall-скрипт разрешает только конкретный Electron runtime, Private-профиль и LocalSubnet; `Disable-Network.bat` отключает созданное правило. На этом рабочем ПК firewall-правила и системное хранилище сертификатов не изменялись.

Во всех режимах действует [общий протокол](GAME_STELA_LINK.md): один gameId/sessionId, подтверждённый чистый JPEG1080×1920 или явное отсутствие фото, миссия, durable outbox, FIFO после отключения, идемпотентный ACK, отдельные игровые сохранения, очередь и восстановление. Настройки двух режимов не смешиваются: one-pc находит соседний MAX, отдельная Стелла использует явно сохранённый IP/сертификат. Другие варианты комплекта одновременно на том же ПК не запускают: стандартные порты приложений общие.

Сборщик — `ops/production-build/build.py`. Новую папку создаёт build.py; существующую обновляет update.cjs, сохраняя data/JSON и резервируя заменённые файлы. Для новой поставки передать новый `--output`; OpenSSL нужен только на машине сборки для создания уникальной пары. Сборщик проверяет наличие кода handoff в клиенте Стеллы и SHA файлов при копировании, чтобы устаревший bundle или параллельное изменение файлов не выдавались за готовую поставку. В каждом каталоге есть `delivery-manifest.json` с SHA кода и ресурсов; изменяемые data исключены. Операторский JSON сохранён и учитывается при выпуске манифеста.

Проверки: [отчёт](verification-stand-production-20261023/README.md). Сетевой режим проверен двумя отдельными процессами встроенного runtime через HTTPS loopback, с реальным voice gateway и JPEG, без платной генерации. Физические два ПК/камеры отдельно не проверялись. GitHub/VPS этой подготовкой не обновлялись.


Для новой пиксельной карты используйте Start-Pixel-Map.bat в startup-one-pc/startup-max, Calibrate-Pixel-Map.bat показывает границы. Обычный Start.bat также открывает production pixel-map. См. [MAX_PIXEL_MAP.md](MAX_PIXEL_MAP.md).
