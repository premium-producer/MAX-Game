# Защита стелы от самоперебивания

Текущая итерация `KDW-MAX-STELA-OMNI-P1-SCREEN-TTS-20261018`. Только `/stella/?voice=omni`. Локальный WebRTC AEC, один маршрут P1, D Omni + S Qwen TTS и 512 мс сохраняются. Допуск BARGE-DIALOGUE заменил прежнее требование непрерывных 384 мс с вероятностью ≥0,75. При подтверждении перебивания локальная остановка/epoch не ждёт TTS terminal; drain ограничен750 мс. Успешный Firefox-тест с остаточным эхом и двумя перебиваниями использует усиленную тестовую речь; тихое короткое hello в отрицательном прогоне отклонено как эхо. Физическая акустика не принята. [Результаты и границы](verification-20261018/stela-screen-tts/README.md).

**Совместимость Firefox:** `GainRamp` проверяет наличие cancelAndHoldAtTime. Если метода нет или он выбрасывает исключение, применяются cancelScheduledValues и setValueAtTime с рассчитанным значением собственного незавершённого линейного ramp; затем новый linearRampToValueAtTime. Сохраняются 20 мс duck / 60 мс restore / cancel-фейд. Поле ducked меняется после успешной автоматизации. Ошибка gain записывается отдельно и не прерывает обработку VAD/её события. В Firefox 158 измерено реальное снижение gain до 0.12 и восстановление до 1; контролируемый browser-прогон описан в [отчёте CONTEXTUAL](verification-20261018/stela-contextual/README.md).

## Аудиотракт

Ответ Qwen PCM → очередь Web Audio → MediaStreamDestination → локальная пара RTCPeerConnection → принимающий audio-элемент → колонки.

Микрофон с echoCancellation/noiseSuppression/autoGainControl → встречное направление той же пары WebRTC → AudioWorklet → входные VST3 → PCM16/16 kHz → локальный Silero VAD/проверка эха → подтверждение речи → существующий WS-шлюз → Qwen.

Выходные VST3/фейды и gain приглушения стоят перед MediaStreamDestination, поэтому AEC и новая опорная ветка получают итоговый сигнал. Второй вход AudioWorklet собирает опорный mono PCM для worker, а не звук микрофона в колонки. [Эффекты и фейды](STELA_AUDIO_PIPELINE.md).

Оба RTC-пира находятся в одном браузере, iceServers пуст, внешнего STUN/TURN нет. Микрофонный поток в колонках не воспроизводится. Сырой PCM только в памяти. Облачный транспорт остался WebSocket, ключи и контроллер — на сервере. Это локальный WebRTC-медиатракт с браузерным AEC, **не прямое соединение браузера с Qwen WebRTC**. Сохраняются проверенные две Qwen-фазы и UI-ready. Эффективность удаления эха на оборудовании требует отдельного измерения.

## Детектор и параметры

Silero VAD v5: ONNX-модель из закреплённого @ricky0123/vad-web@0.0.30, ONNX Runtime Web 1.22.0 WASM. Собственный worker-адаптер; MicVAD из пакета не встроен. Ассеты/лицензии/SHA находятся в `source/artifacts/stella-prototype/public/voice/vad/`, сборка копирует их в www. При запуске CDN и установка пакетов не нужны. Один worker и один WASM-поток.

| Параметр | Значение |
|---|---|
| Рамка модели | 512 отсчётов / 32 мс, контекст 64 отсчёта |
| Ожидание речи | вероятность ≥0.60, подтверждение 96 мс |
| Кандидат перебивания | вероятность ≥0.65 без текущего признака эха |
| Предварительное приглушение | gain 0.12, ramp 20 мс; Qwen и очередь продолжают работать |
| Выдержка после приглушения | 128 мс для RTC/акустического хвоста |
| Подтверждение после приглушения | 128 мс кадров ≥0.55, из них ≥64 мс ≥0.70 в окне 384 мс |
| Допустимый провал кандидата | до 192 мс в probe, прежние 64 мс в idle |
| Предел probe / повтор | 896 мс / cooldown 256 мс после отказа |
| Признак эха | нормализованная корреляция ≥0.78; удержание 128 мс и сброс накопленных положительных кадров |
| Предварительный буфер | 1504 мс, сохраняет начало фразы |
| Конец реплики | 512 мс вероятности ниже 0.35, 16 рамок; операторский резерв 800 мс |
| Защита начала ответа | 200 мс |
| Хвост после отправки аудио | 180 мс, затем 200 мс акустической защиты |

До подтверждения ответ только приглушается. Неподтверждённый кандидат восстанавливает gain за 60 мс, без отмены Qwen и нового платного response. Подтверждение возможно от 256 мс, допускаются паузы между слогами. После подтверждения прежняя очередь прекращается коротким cancel-фейдом, шлюз отменяет старый ход с прежним terminal barrier. Касание/завершение используют ту же остановку. Речь внутри защитного окна может не приниматься; параметры требуют настройки на стенде.

`echo-hint.js` сравнивает вход с опорным сигналом в памяти: одинаковый двухкаскадный lowpass анализа перед decimation до 4 kHz, окно 32 мс, задержки 0…256 мс с шагом 0,25 мс, ring 2048 отсчётов. Абсолютная нормализованная корреляция переносит масштабирование/инверсию. Короткое удержание признака не позволяет слогам собственного голоса пройти при провале совпадения. Распознанное эхо в pre-roll заменяется тишиной, чтобы не добавлять его к пользовательской реплике в Qwen. Сами аудиосигналы и reference не сохраняются. Анализный фильтр не обрабатывает слышимый голос.

Это дополнительный признак, **не новый AEC и не идентификация говорящего**. Сильные изменения акустики/плагинов или тихий человек на фоне громкой колонки могут ухудшить разделение. Тестируемый остаточный echo loop — моделирование, не измерение физического стенда. Общая входная реплика с предварительным буфером ограничена прежними 20 с.

При неподтверждённом echoCancellation=true, сбое RTC/модели, задержке рамки >256 мс или очереди восьми рамок голосовой тракт закрывается и микрофон освобождается. Показывается ошибка, кнопки остаются. Возврата к старому RMS-режиму нет. Повтор — завершить диалог и нажать логотип.

## Журнал

События: aec.state/ready/stats, vad.ready/candidate/rejected/confirmed, audio.pipeline_error, playback.duck и playback.duck_error. В duck сохраняются mode (cancel_and_hold/cancel_and_set), durationMs, enabled и gain. В vad.level — вероятность, inferenceMs, speaking, echoScore/renderRms и число кадров с признаком эха. rejected сохраняет reason/durationMs/positiveMs, confirmed — фактические confirmationMs/positiveMs/reason. threshold относится к вероятности, RMS записан отдельно. Анализатор сводит probe/восстановления/подтверждения/причины отказа, способы/ошибки gain и источники ответов. В оперативном worker не добавлены облачные запросы или дисковая запись.

Раз в три секунды aec.stats сохраняет доступные агрегаты приёма для speaker/microphone: байты/пакеты/потери, jitter, накопленный jitterBufferDelay, jitterBufferEmittedCount, totalAudioEnergy, totalSamplesReceived, concealedSamples. SDP, ICE-адреса, сырое аудио и ключи не пишутся. Энергия принятого потока подтверждает прохождение медиаданных; физическую слышимость и качество AEC не доказывает.

playback.started — часы Web Audio **отправителя** RTC, mode=rtc_sender_clock; принимающий буфер добавляет задержку. Старые speechEndToPlayback нельзя выдавать за аппаратное измерение. playback.ended учитывает настроенный хвост. [Политика логов](STELA_LOGGING.md).

## Аппаратная приёмка

Проверить молчание во время полного ответа, короткий стук, речь посетителя поверх ответа, отключение микрофона после завершения, полный маршрут и постоянный журнал. Настроить громкость и положение микрофона/колонок. Программная совместимость Firefox проверяется отдельно; тестовое добавление речи/эхо после RTC и декларация fake-устройства не доказывают работу физического AEC. Автоматические тесты не заменяют акустику и второй физический ПК.
