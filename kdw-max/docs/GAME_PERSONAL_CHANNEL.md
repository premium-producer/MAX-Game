# Личный канал блогера — 20.10.2026

Локальная итерация `KDW-MAX-PERSONAL-SYNC-20261020`. Первые два задания блогера сохраняют исходные экраны MAX. После уточнения пользователя упрощённая нативная перерисовка отменена; разрешены только точечные изменения для собственного канала. Статистика использует прежние экраны/ассеты; новое оформление статистики и её персонализация в этот этап не входят по последнему поручению пользователя.

## Поведение

- Существующая сцена, телефон, маршрут, связи, таймер и общий масштаб сохранены. Неизменяемые области — точные PNG исходных макетов; HTML/CSS заменяет только пользовательские поля, аватары и название внутри текущего прямоугольника телефона. Экранная клавиатура выезжает поверх игры без перерасчёта масштаба/устройства.
- Название 2–64 символа, описание до 160. Аватары: хлопушка из нового макета и четыре прежних варианта — кот, игры, путешествия, сердце. Персональные фотографии не загружаются; контакты из исходников не превращены в варианты аватара.
- Профиль один для созданного канала, шапки поста и аватара канала в обсуждении. Имя/аватар из примеров «Таймкод» и «Фильмы и сериалы» не подставляются вместо пользовательских.
- Приватный/публичный маршрут сохраняет выбор типа. Публичная учебная ссылка: 4–32 символа, первая латинская буква, затем латинские буквы/цифры/подчёркивание. Проверка формата локальная, реальной регистрации/проверки уникальности в MAX нет.
- Во втором задании посетитель вводит свой ответ до 400 символов. После отправки он занимает то же поле ответа, что и в предоставленном макете; чужие сообщения и пост не переписываются. Возврат к посту показывает два комментария; затем доступна прежняя статистика.
- Пустая/заполненная форма и ввод/подготовленный ответ используют общие компоненты, сохраняя существующие логические шаги. В комментариях добавлен настоящий пятый шаг `blogger.comments.returned-post`.

## Целостность отображения при переходах

Устранена причина появления демонстрационного канала между состояниями. В прежней графической подложке оставались имя «Фильмы и сериалы», пример описания и аватар; native-слой скрывался по уже новому snapshot или фазе phone-exit. Теперь каталог использует генерируемые `underlay_*.svg` с исходной PNG и непрозрачными заменами только областей пользовательских данных. Ни старый пример, ни пример ответа не должны проступать при частичной прозрачности.

Native-слой читает displaySnapshot, остаётся на прежнем отображаемом экране до смены mediaReadyKey/sceneVersion, затем переключается целиком. Он следует общей прозрачности contentPresence/pathPresence и не исчезает отдельно на phone-exit. Подготовка собственного PNG включена в границу готовности контента и морфинга. На переходе старые действия inert; перед действием дополнительно сверяются run/task/screen с текущей сессией. Исходные PNG и оформления экранов не перерисованы.

## Отправка и закрытие клавиатуры — 20.10.2026

`KDW-MAX-PERSONAL-REPLY-20261020`: комментарий рисуется прозрачным textarea поверх очищенной исходной белой подложки 12/13. Для светлой части выставлен color-scheme light; рамки, тени, scrollbar и spellcheck не добавляют браузерное оформление. Во втором состоянии очищается вся область ответа, включая вторую строку. Сохранённые PNG-оригиналы не изменены.

Стрелка отправки — native button с исходной векторной иконкой: серая/disabled при пустом ответе, синяя при тексте. Старая нарисованная стрелка в подложке 13 очищена, двойной кнопки нет. Внешняя клавиатура при вводе комментария содержит «Отправить» вместо «Готово»; оба способа проходят через тот же pc.send → SAVE_INTERACTION → ACT, ядро не обходится.

Capture pointerdown на документе закрывает клавиатуру по мыши/касанию вне неё и полей; текст и черновик сохраняются. Действие под нажатием не поглощается. Нажатия внутри клавиатуры, поля и области открытия не закрывают её. Подписка снимается в dispose. [Полный прогон](verification-personal-reply-20261020/README.md).

## Постоянный выбор аватара и прямое подтверждение — 20.10.2026

`KDW-MAX-PERSONAL-DIRECT-20261020`: группа пяти аватаров постоянно присутствует на обоих логических состояниях формы. Выбор обновляет превью и aria-pressed без повторного render и замены полей. Кнопка крупного аватара переводит фокус к выбранному варианту. Крестик — отдельный native button с z-index выше аватара, 44×44 logical px областью нажатия и исходным размером видимого кружка 24×24; он сбрасывает аватар на «Кино», не закрывая выбор. Нарисованный в PNG крестик очищен в GPU/native-подложке 4, исходный PNG сохранён.

Прежний pc.create выполнял две ACT подряд: name → filled → privacy. Обе формы визуально одинаковы, а очередь анимации честно показывала каждую. Аналогичные пары существовали для ссылки и ответа. Теперь personal.channel.create / personal.channel.save-public-link / personal.comments.send добавлены в текущий каталог и, где требуется, вложенный task catalog. Они валидируют сохранённый черновик и создают профиль/ссылку/ответ сразу в одном принятом переходе. Нет временного UI-флага, скрывающего промежуточное сохранение. Незаполненные данные отклоняются, повтор commandId идемпотентен; старые действия, экранные ID и квитанции не переписаны. Нативный «Назад» из ранее сохранённых filled/public-filled/reply пропускает только эквивалентную форму ввода.

[Выбор аватара](verification-personal-avatar-20261020/README.md), [переходы и регрессии](verification-personal-direct-20261020/README.md). Локальная разработка, серверная версия не обновляется.

## Плавная клавиатура — 20.10.2026

`KDW-MAX-KEYBOARD-MOTION-20261020`: открытие панели использует translate3d + лёгкий scale(.985→1), 520 мс cubic-bezier(.16,1,.3,1), opacity 280 мс. Закрытие — 280 мс/opacity 200 мс, visibility скрывается после ухода; inert/aria-hidden и запрет pointer-events применяются сразу. Закрытая клавиатура не блокирует игру. Геометрия телефона/маршрута не меняется.

Главная причина прежнего скачка — refreshKeyboard заменял всю сцену вместе с панелью. Теперь общий kdw-keyboard-ui.mjs сохраняет внешнюю панель, меняет содержимое лишь при изменении разметки клавиш, переключает dataset состояния на существующей сцене. Набор/раскладки не запускают повторный выезд; повторное открытие во время закрытия перенаправляет ту же CSS transition. SVG-шеврон заменяет символ «⌄»; кнопка имеет область 56×44 logical px. Клавиатура расположена выше «Пропустить», чтобы игровая кнопка не проступала поверх клавиш. Reduced motion отключает переходы и для отдельного personal-channel слоя. Тексты, сохранение, отправка и закрытие нажатием снаружи сохраняют прежние пути.

[Покадровые проверки](verification-keyboard-motion-20261020/README.md). Изменения локальные.

## Данные и совместимость

`SAVE_INTERACTION` сохраняет черновик `progress.blogger.interactions['blogger.channel']` с schemaVersion 2, name/description/avatar/visibility/slug. Ядро проверяет контекст, владельца, поля и допустимые значения. `channel.create` создаёт `progress.blogger.personalChannel` с теми же полями, стабильным id и created. Настройка типа/ссылки обновляет тот же профиль. Изменения поля сохраняются после 200 мс; перед переходом/выходом ожидается flush. При отказе/ошибке черновик остаётся доступным для повтора. Пользовательский текст экранируется, не интерпретируется как HTML/SVG.

Ответ: взаимодействие `blogger.comments` с schemaVersion 1 и reply. Принятое действие отправки создаёт `personalComments` с channelId/reply/submittedAt. Нельзя отправить пустой ответ или прислать чужой screen/task. Повтор команды обрабатывается прежним ядром receipts.

Данные прежнего канала name/description/avatar читаются в новом интерфейсе без удаления и без обязательной записи новой версии при загрузке. При редактировании сохраняется v2. Старые принятые завершения комментариев из четырёх экранов воспроизводятся с прежним исходом; новые завершения идут через пятый экран. Исключение replay ограничено квитанциями без новых данных профиля/ответа. Испорченные состояния не принимаются как сохранённые.

Перезапуск комментариев удаляет только ответ и его черновик, сохраняя канал. Перезапуск создания предлагает сохранённый профиль для редактирования и сохраняет его id; соседние завершённые задания не сбрасываются. Полный RESTART_MISSION/RESET_PROGRESS сохраняет прежнюю семантику удаления всего прогресса миссии.

## Исходники и ресурсы

- `apps/max-game/source/client/src/kdw-personal-channel-model.mjs`: каталог, профиль, валидация и совместимость receipts.
- `kdw-personal-channel.mjs/.css`: неизменяемый слой исходного экрана, прозрачные области действий и точечные поля/аватары/название, клавиатура.
- `kdw-personal-channel-assets.mjs`: генерируемый реестр проверенных ресурсов.
- `source/prepare-personal-channel.mjs`: копирует подготовленные images/icons с проверкой SHA и 15 исходных PNG (всего 1 453 697 байт); фиксирует их SHA в реестре. Генерируются также 15 лёгких SVG-подложек для GPU, со встроенной PNG и локальными масками только персональных полей. Тяжёлые пользовательские SVG и инструменты подготовки в runtime не копируются.
- Runtime-ресурсы: `assets/kdw-native/personal-channel/`. WebP/иконки загружаются компонентами по фактическому использованию, без включения всех картинок в первоначальную загрузку каталога. Каталог содержит SVG-подложки исходных экранов с очищенными областями персональных данных; верхний слой использует исходные PNG с нативными полями. Контракт PNG/SVG не расширялся ради WebP. Меню/контакты/приватность/подписчики показываются целиком без придуманного содержимого. Форма использует оформление заполненного макета с настоящими полями вместо демонстрационных значений; клавиатура остаётся поверх игры.

Форма 360×800 следует живому прямоугольнику устройства, без отдельного центра/масштаба. Статичные подложки сохраняют GPU-рамку/анимации; дублирующие внешние кнопки скрыты на время нативного задания.

Переносимость: локальный build копирует новые ресурсы из source/client/public в www вместе с JS/CSS. Исходный UI-каталог, Python и инструменты подготовки на целевом ПК не требуются.

## Проверка и границы

[Актуальный покадровый прогон и пиксельная сверка](verification-personal-channel-sync-20261020/README.md): ядро/сохранение/старые данные и браузерный путь от standby через создание, публичную ссылку, собственный ответ, пятый экран, перезагрузку IndexedDB и выход в статистику. Отдельно проверены экранная клавиатура, сохранение масштаба, resize 1200×800, читаемость светлой темы и безопасный вывод пользовательского имени. Неизменяемые области сверены с PNG при 360×800, исключены только явные прямоугольники персональных данных/ввода.

Изменения локальные. VPS/GitHub/stable не обновлялись; физический стенд, мобильные устройства и визуальная приёмка точного соответствия всем SVG не выполнялись. Статистика ожидает отдельной итерации. Периодический прежний сбой входа в «Канал», отложенный пользователем в другом поручении, не объявляется исправленным этим изменением.
