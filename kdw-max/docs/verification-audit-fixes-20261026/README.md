# Исправления аудита — 26.10.2026

Объект — канонический рабочий корень `apps/UI/docs/ops`. Основание: [аудит](../GAMEPLAY_AUDIT_TASKS.md) и запрос «реализуй исправления». Исходные файлы сохранены в `.sync/archive/audit-fixes-20261026-before`. Этот отчёт описывает программные проверки на Mac; физическую приёмку Windows-стенда он не заменяет.

## Принятые правила

- До подтверждения ладони новый выбор того же посетителя заменяет старый. Остальные посетители сохраняют FIFO; новая миссия занимает место по времени нового выбора. После подтверждения ладони активная игра не отменяется: Стелла показывает, что она уже началась. Claim и замена выполняются последовательно в одном приёмнике; промежуточный журнал восстанавливается после сбоя.
- Технический отказ не отменяет назначение и не выдаёт заново полный бюджет. Renderer получает до трёх попыток восстановления за пять минут, затем видимую кнопку повтора. Подготовка сцены дольше 60 секунд показывает независимый от WebGL экран восстановления. Отсутствие heartbeat 90 секунд отображается как недоступность экрана; запись остаётся для восстановления.
- Завершённые квитанции relay и явно отпущенные production-сессии хранятся 30 дней. Живая очередь, активные/старые нераспознанные сохранения не удаляются. Прежний срок фотографии и ожидания недоставленной миссии — 24 часа — сохранён. Очистка не обещает абсолютный лимит диска для неизвестных старых данных.
- Внутри процесса время не идёт назад. После перезапуска валидная цепочка квитанций сохраняет прежний deadline при небольшом откате часов. Отклонение более суток требует исправить часы (`CLOCK_CORRECTION_REQUIRED`). Перевод вперёд может завершить уже истёкший этап; новый бюджет не выдаётся.
- 30/60/120/15 секунд, графика, frozen stand-base, ручные WAV, устройства и ключи не менялись.

**Итог программного прогона:** 140 тестов MAX, 7 тестов очереди/восстановления, 9 тестов Стеллы, TypeScript, обе сборки, проверка dev-профиля, очистка 5 000 записей и браузерный проход — PASS. В успешном браузерном проходе нет ошибок JavaScript/загрузки.

Строковый адаптер всё ещё нужен для принятой графики. Полный перенос его визуальных замен в новую архитектуру не выполнялся; безопасный первый этап AUD-11 завершён. История receipt внутри одной живой сессии не сжимается: это сохраняет replay и идемпотентность.

## Как повторить

Требуются Node.js 24+ и Python 3 только для существующего упаковщика Windows.

```sh
npm run setup
npm run setup:browser
npm run build
npm run test:audit:all
```

`test:audit` запускает генерацию-проверку, MAX, очередь/восстановление и Стеллу с TypeScript. `test:audit:profile` собирает временное приложение и сравнивает app.json побайтно. `test:audit:retention` использует временные файлы и fake-indexeddb. `test:audit:browser` запускает реальные launcher-серверы на 18781/18782 с чистыми временными данными и закрывает их после проверки. Порты должны быть свободны. Playwright закреплён в корневом lockfile; можно передать `PLAYWRIGHT_MODULE_PATH` для установленного внешнего toolchain.

Qwen/облачный inference не вызывается, камера Chromium синтетическая, пользовательские данные не копируются. Браузерные проверки пишут только отчёт/скриншоты в эту папку. Дополнительный smoke штатным клиентом develop-web-game сохранён в `skill-smoke`; он снимает первый canvas, который у многослойного MAX не представляет готовый экран. Для визуальной оценки используются полные кадры из `browser`.

## Покрытие и ограничения

- Автотесты ядра покрывают 4 миссии/15 заданий, принятые тайминги, replay и бизнес-ветки cafe/flowers/auto. Это проверки логики, не запись полного прохождения человеком.
- Обычное меню снято при 3072×1536; функциональный проход MAX выполняется при 1536×768 и reduced-motion. В SwiftShader на 3072×1536 анимационные часы заметно отстают от реального времени: программный GPU не годится для оценки темпа стенда. Chromium проверяет реальный интерфейс Стеллы на трёх обрывах WS, ручной выбор без фото, передачу миссии, меню MAX, ладонь и начало задания. Он не подтверждает прохождение всех экранов тачем, голосом и камерой на стенде.
- [Нагрузочный отчёт](retention-load.json) измеряет файловый outbox и fake-indexeddb на 5 000 синтетических записей. Он не измеряет дисковый IndexedDB в Chromium, FPS, размеры реальных JPEG или Windows I/O.
- Полная аппаратная матрица остаётся отдельной приёмкой: VST/микрофон, реальное фото/пересъёмка, физический тач, Windows GPU/crash, QR, акустика, три человека на двух ПК, длительный прогон. Непроверенное не обозначается PASS.
- [Восстановленные отчёты](restored-reports.json) датированы 20–23.10 и не доказывают работоспособность кода 26.10. Перенесены тексты/проверочный скрипт и один JSON; связанные исторические изображения, профили и приватные данные не копировались.
