## Воспроизведённый дефект

activity-input записывал карточку в hand.seen до результата select. activity-controller ограничивает товары одной pending-командой. Пока предыдущий выбор ожидает подтверждения, нажатие следующей карточки отклоняется, но она уже считается обработанной до pointerup/cancel. После освобождения pending повторные движения этой же руки игнорируются. Это подтверждённый дефект, согласующийся с симптомом, но без истории точных нажатий нельзя утверждать, что он объясняет каждый пропуск на стенде.

Теперь controller явно возвращает false при отказе и true при принятии. Input запоминает только принятый выбор; временно отклонённый контакт остаётся доступен при следующем движении. Дедупликация успешного выбора, поколения экранов, блокировка настоящих контролов, порядок перекрытий и ограничения числа pending сохранены.
