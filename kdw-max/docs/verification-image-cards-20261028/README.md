# Карточки-картинки: новая WebGL-итерация

Локальные исходники MAX. На production-стенды не устанавливалась.

В потоке постов и товаров показывается только изображение со скруглёнными углами. Заголовки, описание, цены и подпись публикации не рисуются и не загружаются как отдельные текстуры падающих карточек. Полные данные остаются в каталоге и доступны после добавления в устройство; скрытые подписи для доступности сохранены.

Нажатие плавно проявляет голубую каёмку за 140 мс. Изображение тормозится за 320 мс с сохранением входящей скорости, затем за 850 мс летит к позиции фотографии внутри устройства. После посадки за 420 мс раскрываются элементы полного поста/товара. Порядок слоёв остаётся постоянным. Изображение при начале перелёта не дублируется на старом месте; текстовая оболочка вне устройства отсутствует.

Размер hit-area равен размеру изображения, включая скругления. Высота потока рассчитывается по пропорциям фотографии в целевом посте/товаре. Масштаб из админки, правый диапазон появления, таймеры, правила выбора и оценки сохранены. Старый WebGL-вариант доступен с `activityCards=full`; новый — по умолчанию или с `activityCards=images`. Для обычного браузера также нужен `activityRenderer=webgl`; явный DOM-режим остаётся предыдущим резервным вариантом.

## Проверка

- 15 тестов input/model/runtime/falling-card-layout прошли
- `node ops/activity-webgl/check-selection-feedback.mjs`: реальные WebGL-посты и товары, совпадение пропорций hit-area с изображением, принятие выбора, перелёт, сохранение одной карточки, отсутствие pageerror
- `node ops/activity-webgl/check-selection-feedback.mjs --full`: предыдущий вариант полных карточек
- Снимки и JSON-отчёты находятся в `images/` и `full/`; изображения новой итерации визуально проверены
- В новой итерации для кофейни 30 GPU-ресурсов постов (~40,7 MiB) и 24 товаров (~36,3 MiB), без fallback-изображений

Браузерная проверка собирает актуальные исходники в памяти, не перезаписывая общий production bundle. Временный сервер и браузер закрываются после проверки. Spout и физический лидар с новой итерацией пока не проверялись. Отдельный обнаруженный дефект повторного входа через админку не исправлялся этой визуальной итерацией.
