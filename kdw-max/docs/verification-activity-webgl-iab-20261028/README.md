# Плавность WebGL-активностей во встроенном браузере Codex

## Результат

Локальные канал и витрина прошли измерение. Это реальный встроенный браузер Codex, не headless Chromium. Во время каждого замера штатным указателем выбрана падающая карточка; подтверждённая публикация/товар появилась в телефоне. Во втором сценарии после замера также принят повторный выбор.

## Файлы и методика

- [motion-summary.json](motion-summary.json) — сводные метрики
- [iab-posts-exact.json](iab-posts-exact.json), [iab-store-exact.json](iab-store-exact.json) — исходные кадры, позиции, время renderer, перелёты, ошибки, длительные задачи
- [console.json](console.json) — финальная выборка предупреждений и ошибок консоли IAB; пуста
- [posts.png](posts.png), [store.png](store.png) — скриншоты после выбора карточек
- `iab-posts.json` — предварительный замер по времени наблюдателя, без точных меток renderer; не использован в итоговой таблице

Диагностический сервер `ops/activity-webgl/serve-motion.mjs` поднимает отдельный memory-предпросмотр на 127.0.0.1:19784 и upstream 19785. Он подключает тестовый `motion-probe.js`, который записывает 20 секунд после появления интерактивных карточек. Наблюдатель читает DOM-диагностику; в production-сборку этот скрипт не входит. `activityDebug=1` дополнен точным временем кадра и положениями перелётов. В обычном режиме эти данные не сериализуются.

Проверки траектории нормированы по ширине к 3072 единицам: недопустимы движение назад более 0,25 px, горизонтальный скачок более 2 px и изменение скорости более 0,035 px/ms между соседними кадрами одной карточки. Вход/выход карточек и смена поколений не сравниваются как один объект. Для перелётов записаны позы; их геометрическое начало/завершение отдельно покрыто unit-тестом. Критерий кадров: p95 ≤ медиана × 1,2 + 1 мс, отсутствие интервалов >50 мс. Это локальный диагностический критерий, не SLA стенда.

## Повторение и тесты

```powershell
node ops/activity-webgl/serve-motion.mjs
# Во встроенном браузере открыть один из адресов ниже, дождаться журнала
node ops/activity-webgl/analyze-motion.mjs
node --test --test-isolation=none ops/activity-webgl/analyze-motion.test.mjs
npm run test:max
npm run check:generated
```

Адреса:

```text
http://127.0.0.1:19784/webgl-v5/client.html?backend=local&view=pixel-map&interaction=posts&test=memory&activityRenderer=webgl&activityDebug=1&audit=iab-posts-exact
http://127.0.0.1:19784/webgl-v5/client.html?backend=local&view=pixel-map&interaction=store&test=memory&activityRenderer=webgl&activityDebug=1&audit=iab-store-exact
```

Повторный запуск с тем же audit перезапишет соответствующий журнал: для сравнения использовать новый суффикс. Во время замера не запускать сборки/тесты и не скрывать вкладку.

Проверено после изменения диагностики: сборка MAX успешна; 174/174 unit-теста MAX; 4/4 теста анализатора (нормальное движение, движение назад, горизонтальный скачок, длинный кадр/ошибка); generated entry соответствует адаптеру. Первоначальный запуск анализатора с изоляцией процесса был запрещён sandbox (spawn EPERM); повторён штатно с `--test-isolation=none`, все проверки прошли.

Полный ранее выполненный аудит всей системы не считается зелёным: в его сценариях Стеллы были HTTP 409, см. [предыдущий отчёт](../verification-activity-webgl-20261027/README.md). Здесь проверялись именно MAX и плавность новой WebGL-ветки.

## Границы проверки

Измерено движение после готовности ресурсов, включая выбор и перелёт одной карточки в каждом 20-секундном окне. Холодная загрузка, длительный прогон, вывод 3072×1536 в Electron, два Spout-потока, TouchDesigner и физический лидар в этом замере не проверялись. Полное прохождение активностей, три бизнеса и восстановление GPU проверялись в предыдущем локальном браузерном наборе; текущий IAB-прогон не повторяет все его сценарии.

Новая ветка остаётся включаемой через `activityRenderer=webgl`. Стенды и их профили не обновлялись, ввод лидара не изменялся.
