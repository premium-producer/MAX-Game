# Василиса в стеле MAX

20.10.2026. Итерация `KDW-MAX-STELA-VASILISA-20261020`. Пользователь выбрал Василису и отдельно разрешил повторно передать сохранённый эталон в Qwen для создания клона Omni 3.8.

## Голос и модель

Василиса — пользовательский клон, не штатный голос из списка Qwen. Эталон взят из предыдущего проекта только для регистрации; работающая стела не зависит от его каталога. SHA256 эталона: `c2373e077f70f07ce8902b2bb6045a9aa09d55d6bb25e49dfeae28fb1a496f18`.

Ранее голос был зарегистрирован для `qwen3-tts-vc-2026-01-22`. При проверке 20.10 HTTP SSE этой модели и WebSocket `qwen3-tts-vc-realtime-2026-01-15` вернули `InvalidParameter / Model not exist`, включая прямой Singapore endpoint. Успешная регистрация голоса не доказывает доступность синтеза. Не утверждаем глобальное закрытие этих моделей: зафиксирован ответ с текущими учётными данными и проверенными endpoint.

Рабочий профиль зарегистрирован для **`qwen3.8-omni-flash-realtime`**, `voice_clone_mode=normal`. Voice ID привязан к модели, поэтому старый TTS ID не подставляется в Omni. Это соответствует [официальному контракту клонирования Omni](https://www.alibabacloud.com/help/en/model-studio/qwen-omni-voice-cloning).

## Выполнение и защита

- D остаётся постоянным Omni-каналом распознавания/решений с прежними tools, Controller, контекстом и ограничением истории.
- S использует существующий постоянный Omni-канал чтения утверждённого текста с одним фиксированным клоном. История ограничена прежними 4 ответами / 8192 входными токенами / 1,92 МБ. Модальности D не переключаются; новые сокеты на обычную реплику не добавляются.
- Для выбранного клона отсутствие утверждённого `replyText` — ошибка, а не свободная беседа. Qwen S получает только `serverReplyText`; вопросы и допустимые действия остаются серверными. Генеративный S всё равно требует наблюдения: транскрипция провайдера сравнивается с текстом после ответа, доозвученное отклонение этим не отменяется.
- S проверяет подтверждённый сервисом `audio.output.voice` после каждого `session.update`. Несоответствие закрывает канал с `PROVIDER_VOICE_MISMATCH`. D сохраняет прежний встроенный voice в своей текстовой конфигурации, клон получает только S.
- Epoch / response ID / отмена и очередь остаются прежними. PCM24k поступает в прежний VST3 → фейды/duck → WebRTC reference/playback. AEC, Silero и endpoint512 не меняются.
- Журнал сохраняет логическое имя `Vasilisa`, SHA профиля, подтверждение голоса, транскрипции по прежней политике, usage и задержки. Voice ID дополнительно включён в redaction. Анализатор выводит `speechVoices`: подтверждения/несоответствия профилей и сравнения текста. Аудио, ключи и приватный ID не записываются.

## Настройки и перенос

На этом ПК `data/omni.local.json` выбирает `"voiceProfile": "vasilisa"`. Временное переопределение: `KDW_OMNI_VOICE_PROFILE=vasilisa`. Профиль находится в **`apps/stela/data/voice-profiles/vasilisa-omni.json`**, ключ — в прежнем операторском конфиге. При запуске ничего не клонируется.

Загрузчик проверяет статус регистрации, модель, SHA эталона, workspace fingerprint и SHA профиля. URL из профиля не используется. Отсутствующий/повреждённый выбранный профиль отключает AI, кнопочный сценарий сохраняется; скрытой подмены голоса нет. В чистом комплекте без частных настроек остаётся встроенная Katerina.

Для переноса выбранного голоса на свой ПК нужны подходящие учётные данные и соответствующий частный профиль внутри `data/`. Эти файлы не входят в Git/чистую поставку/SHA-манифест и не публикуются. На другом workspace/model потребуется отдельная регистрация с разрешения пользователя. Старые профили сохранены, не выбираются автоматически.

Откат: `KDW_OMNI_VOICE_PROFILE=builtin` и `KDW_OMNI_SPEECH_ENGINE=tts`, затем перезапуск. Постоянный вариант — `voiceProfile: "builtin"`, `speechEngine: "tts"`, `ttsVoice: "Katerina"` в операторском конфиге. Текущие `speechEngine`/`ttsVoice` при выборе клона не перезаписываются.

## Ограничения и измерения

Omni S расходует текстовые и аудиотокены; прежний Qwen TTS учитывал символы отдельно. Сравнивать эти единицы как один тариф нельзя. Usage — полученные поля провайдера, не счёт; отменённые незавершённые запросы могут иметь неизвестный расход.

Проверка фиксированного текста: 7 полных реплик, включая четыре миссии, совпали с транскрипцией; 1 отмена после начала PCM и следующая реплика прошли. Первый PCM: 0,87–3,94 с; медиана полных реплик около 1,10 с. Это не полная задержка до колонок. Историческая проверка Katerina дала медиану 416 мс в других условиях: новая озвучка не объявляется столь же быстрой. Одно имя/SHA/ACK обеспечивают одинаковую конфигурацию, но не доказывают одинаковое субъективное звучание каждой фразы.
