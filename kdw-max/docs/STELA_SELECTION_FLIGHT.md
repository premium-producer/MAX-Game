# Стендовый вылет перед фотографированием

## Голосовой выбор — 22.10.2026

Голос и кнопки теперь используют один HybridSelection/AnswerFlight. Пока Qwen слушает или решает на audience, карточки остаются видимыми; VoiceVisualModel продолжает переключать гистограмму/обработку на фоне. Принятое решение сервера сразу фиксирует photo/result, но клиент удерживает показанный audience и новый snapshot отдельно. 

HybridSelection получает voiceChoice с уникальной парой epoch/revision, запускает прежний один вылет четырёх слов и при завершении вызывает callback вместо повторной команды. Только после этого клиент применяет snapshot, монтирует photo/result и отправляет ready. Новый ready служит барьером для генерации/воспроизведения финальной реплики. Параллельно хранить или проигрывать PCM заранее не нужно. Дополнительного запроса Qwen эта синхронизация не создаёт.

На переходе audience→photo голосовая реплика выбора закрывается без озвучки: камера визуально ведёт посетителя; голосовое подтверждение/пропуск фото озвучивает result. Нажатия по-прежнему используют локальные тестовые WAV, без нового Qwen TTS. В pixels-no-photo результат появляется только после того же вылета, без создания камеры.

На время вылета новый микрофонный turn не отправляется, проигрывание останавливается, запоздалые audio chunks не воспроизводятся. Защита SpeechGate/AEC, постоянные соединения и endpoint512мс остаются прежними вне этой короткой фазы. Уточнения без принятого выбора говорят на audience и не запускают вылет.

Повтор pending revision игнорируется; смена snapshot/сессии очищает pending. У сценического watchdog остаются16с активного времени; внешний deadline24с освобождает целевой экран при зависшем renderer, сервер ожидает ready до28с только для такого выбора. Reduced motion завершает переход сразу. Остановка/размонтирование очищают таймер; ошибка/разрыв во время вылета освобождает авторитетный snapshot с прежней обработкой ошибки соединения.

Новые события ui.voice_choice_deferred/released дополняют ui.selection_flight_* и серверные ui.ready/voice.continuation. Для тихого перехода к камере есть voice.selection_deferred. Текст/PCM/фото не добавляются в события. Транспорт может доставлять пакет клиентского журнала после серверного ready: порядок сравнивать по clientElapsedMs и epoch/revision, а не только порядку строк файла.

Это заменяет нижеописанное историческое поведение, где голосовая навигация отменяла вылет. [Проверки](verification-20261022/stela-voice-selection/README.md).


**22.10.2026 — оптимизация частиц:** после step4 прекращаются DOM-записи градиента/blur/transform исчезнувших слов; размеры для scatter читаются группой до записи стилей. Частицы используют4кэшированных растровых образца40×40 с прежними цветами/радиусом скругления вместо roundRect/fill на каждую частицу/кадр. Холст соответствует отображаемому размеру×DPR (ограничение .25–2 от authored1080), а не минимум1080×1920; ResizeObserver/window.resize пересчитывают размер и перерисовывают текущий кадр даже на паузе. Dispose отключает observers/listener и освобождает sprites. Seed, количество, траектории, нити/шлейфы, clock/1.5×/guards/журнал сохранены. ## Актуальный ритм FINAL-DESIGN —21.10.2026

По новому запросу движения ускорены в1,5раза: playbackRate1,5 задаёт длительность Motion clock без изменения его пути/частиц/тайминга отдельных фаз относительно одних часов. Дополнительно STELA_PACE наследует AUTHORED_PACE, сокращая только lead.5→.35,idle1.2→.9,encodedHold1→.85,scatterDelay1→.8,rest.6→.35. Значения ненулевые; после ускорения реальные ожидания ещё делятся на1,5. Общая длительность драйвера10,01/1,5=6,673с; уход остальных240мс+stagger16,667мс даёт примерно7с до photo (проверено7,009–7,053с). Было11,5с.

Одна группа четырёх слов, нити/кодирование/MAX_CELLS/единый fade выбранной карточки/отмена/reduced-motion/watchdog16с/одна команда после сцены сохранены. AUTHORED_PACE остаётся неизменным эталоном; приведённые ниже11,06с описывают исходный ритм, а не текущую скорость. [Финальные проверки](verification-20261021/stela-final-design/README.md).


Исходное решение — KDW-MAX-STELA-STAND-TRAILS-20261021. Пользователь отклонил ранний WAAPI Choreographer: нужен эффект финальной стелы со стенда, **один вылет четырёх слов без второй группы**. Это заменяет прежнюю реализацию двух групп от21.10; её отчёт остаётся историей, не визуальным эталоном.

## Сценарий

Невыбранные карточки, заголовок и back уходят за360мс со stagger25мс; выбранная остаётся и продолжает прежнее независимое плавание. После ухода остальных один TagDissolve запускает четыре плашки от краёв реально показанной карточки. Геометрия берётся из текущих DOM bounds с переводом в логические1080×1920, включая её плавание. Плашки располагаются вокруг неё по свободным зонам нового интерфейса.

Нити рисуются на прозрачном Canvas2D1080×1920 поверх живого фона. На концах — светящиеся головки; плашки имеют вращающуюся градиентную рамку. Читаемые слова превращаются в код, распадаются на квадратные частицы MAX, собираются и ускоренно уходят за правый верхний край. Тени/импульсы LumiCells остаются подключены. Механизм работает и на градиентной странице.

Единственная группа из существующих metadata:

| Карточка | Слова |
|---|---|
| Развитие бизнеса | клиенты, продажи, автоматизация, продвижение |
| Личное общение | чаты, видеозвонки, голосовые, файлы |
| Уникальные возможности | Цифровой ID, идентификация, документы, льготы |
| Ведение блога | канал, контент, аудитория, публикации |

Исходный MAX-ритм одной сцены11,06с: вход начинается0,5с, последняя плашка приходит2,75с; кодирование с3,95с; распад4,95–5,31с; выбранная карточка исчезает вместе с облаком к9,71с; последние частицы уходят к10,46с; затем пауза0,6с. Вместе с начальным уходом остальных карточек получается около11,5с. Второй цикл не создаётся.

TagDissolve единолично управляет fade выбранной карточки и её влиянием на фон. HybridSelection не запускает поверх него прежний fade420мс при leaving: это проявило бы уже исчезнувшую карточку заново. Фотографирование монтируется и запрашивает камеру только после завершения сцены и отправки одной команды выбора. Серверные stages/version4, фото/review/retake/confirm/skip, финальные экраны, общий PCM/FX/AEC и локальные тестовые записи не меняются. Генераций Qwen нет.

## Жизненный цикл

Фазы клиента: idle → retiring → flying → leaving. Синхронный pending-guard блокирует повторное нажатие, другие карточки и back. Голосовая навигация/смена серверного экрана отменяют локальный driver, часы, Canvas и влияния; отложенная команда не отправляется. TagDissolve.dispose возвращает карточку при прерванной сцене. При остановке сервиса часы и watchdog приостанавливаются. Reduced motion пропускает сцену сразу.

Watchdog увеличен с10до16с активного времени: прежние10с обрывали бы исходную11-секундную сцену. При зависании он журналирует ANIMATION_TIMEOUT и освобождает photo. Голосовой playback+180мс/20с fallback остаётся отдельным механизмом. Это принятое пользователем исключение из немедленной manual-навигации только для карточек audience; логотип/«Начать»/фото управляются по прежним правилам.

Журнал сохраняет ui.selection_flight_started/revealed/leaving/completed/cancelled/failed, action/index/revision/epoch/durationMs и корреляцию сессии. Новое начало явно указывает batches=1, count=4, mode=stand-max-cells. Аудио/фото в журнал не попадают.
