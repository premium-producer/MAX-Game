# Настройки карточек канала и мини-приложения

Локальная сборка 28.10.2026. На production не устанавливалась.

## Поведение

В существующей админке MAX, «Игра и тайминги», добавлены шесть параметров для обеих игр:
- Пауза таймера задания на этапе карточек (по умолчанию включена)
- Появление 800 мс, показ 2000 мс, исчезновение 800 мс
- Максимальное суммарное перекрытие площади карточки 15% (диапазон 0–15)
- Минимальная прозрачность для нажатия 15% (диапазон 0–100)

Порог включительный: при 15% нажатие принимается, ниже — нет. Учитывается фактическая прозрачность вместе с общей видимостью сцены. Нулевые/полностью исчезнувшие карточки не активны даже при пороге 0.

Настройки сохраняются через прежний settings API с CAS, проверкой Origin и резервной копией. Они фиксируются для следующей игровой сессии; текущая не переписывается. Старый stand.json без cardActivity валиден. Старые версии сохранённых активностей сохраняют прежние тайминги и replay.

Пауза относится только к countdown: общий clock карточек, анимации, вход лидара и STAND_TOUCH/STAND_IDLE продолжают работать. Пауза снимается при выходе из этапа, переходе оператора, завершении миссии и возврате в меню; QR и следующие задания получают штатный таймер.

Размещение резервирует полный диапазон вертикального движения и ограничивает суммарные пересечения каждой карточки. Уже размещённые цели не перестраиваются после выбора соседа. Если свободного места нет, новая цель пропускается до следующего появления; лимит не обходится уменьшением или перекрытием соседей. Летящая после выбора фотография является анимацией подтверждения, а не новой целью размещения.

Для команды выбора предусмотрен ограниченный запас доставки 500 мс после окончания её временного окна. UI при этом строго проверяет порог прозрачности. Добавлены lastCommand (тип/результат/код), arrived, remainingMs и timerPaused в существующие activityMetrics.

Предыдущие локальные правки сохранены: ручной скролл витрины отключён, автоматическая прокрутка сохранена; «Отправить» удалена из клавиатуры ответа, отдельная кнопка у поля остаётся.

## Разбор последнего канала

В прочитанном фрагменте performance.jsonl 28.10.2026 в 15:50:02–15:50:12 (UTC+3) последний канал начал с published=0, затем зарегистрировал 2 публикации и 2 перелёта непосредственно при переходе в phone-exit. Это не отсутствие входных касаний: счётчик принятых попаданий вырос с 17 до 19. До ухода сцены перелёты не завершились. Общий таймер канала расходуется и на предшествующих экранах; отдельного полного бюджета при входе в карточки раньше не было. Это вероятное объяснение раннего ухода, но в ограниченном фрагменте нет команды EXPIRE, поэтому точную причину перехода по нему не утверждаем. Новые метрики сохраняют остаток и состояние таймера для следующего разбора.
