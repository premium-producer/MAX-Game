## Что реализовано

- Тот же экран/renderer всех миссий, один телефон по центру. Иконки, справка, связи и прежняя обходная кнопка скрываются; масштаб сцены не меняется. По завершении обычные элементы возвращаются.
- Карточки падают в двух полосах по сторонам телефона. Нажатие фиксирует карточку и отправляет PUBLISH_POST; после commit — перелёт фотографии в зарезервированную публикацию и скролл ленты.
- Хорошие посты: лайк/+120 подписчиков. Плохие: дизлайк/−100/пояснение. Исходная аудитория 14628, цель чистого прироста +300. Пропуск без штрафа. Это баланс прототипа, не окончательное решение.
- Используются оставшиеся 60 секунд всего задания business.channel. Внутренний переход на активность не даёт ещё одну минуту. При таймауте действует прежнее истечение задания.
- Восемь смысловых публикаций на каждый бизнес. Кофейня — извлечённые фотографии; отель и театр — собственные тексты и векторные иллюстрации вместо подмены фотографиями кофейни. До публикации реакции нейтральные.
- Очередь детерминирована; повтор уже опубликованного postId не начисляет аудиторию. Независимые commandId/spawnId, проверка контекста/owner/дедлайна и цель находятся в ядре. Клиент не присылает величину прироста.
- Модель, реакция, история и аудитория сохраняются одной транзакцией общего SessionPort/IndexedDB. Полёт не участвует в сохранении. Сбой commit не выдаёт успех; повтор после согласования snapshot/owner безопасен.
- Старые принятые receipts завершения канала восстанавливаются без навязывания новой цели; уже завершённые задания не отзываются. Старый незавершённый последний шаг получает активность при входе.
- Ручной скролл ленты отключает автопрокрутку; новая публикация отмечается кнопкой возврата вниз. Reduced motion оставляет по одной статичной доступной карточке в полосе и отключает перелёт.

## Проверки

[30 Node PASS](node-tests.tap): все локальные KDW-тесты, включая прежние 15 заданий/четыре миссии, геометрию рамки/связей/масштаб, новые состояния публикаций, три бизнес-банка, good/bad, повтор команды и поста, поддельную аудиторию, pause/deadline, возврат/возобновление, строгий restore/подмену состояния, старые завершённые и незавершённые сохранения. Отказ хранилища имитировался на PersistencePort: после ошибки нет публикации/начисления, согласование owner/revision и повтор дают один commit, повтор принятой команды идемпотентен, новый экземпляр authority восстанавливает историю.

[7 Chromium-сценариев PASS](checks.json), Electron 44.4.5 с реальными pointer events, отдельным тестовым профилем и HTTP-сервером на 18777:

1. Общая сцена, один центральный телефон, скрыты иконки/справка/исходная кнопка. Центральная позиция проверена по реальным bounds.
2. Нажатие публикует пост, обновляет аудиторию и ленту; перелёт просмотрен на снимке. Проекция не меняется.
3. Resize 1920×1080 → 1280×720 → 1920×1080 сохраняет центральный телефон и публикацию.
4. Плохая публикация получает дизлайк, уменьшение аудитории и объяснение.
5. Хорошие публикации восстанавливают рост, лента скроллится, достигается цель без изменения масштаба.
6. Завершение возвращает обычные иконки/справку и следующее задание; полёты удалены.
7. Синтетический принятый журнал импортируется штатным механизмом в настоящий IndexedDB изолированного браузера. Через обычный standby открыт сохранённый канал; новое реальное нажатие и перезагрузка сохраняют две публикации и точное число подписчиков.

## Уточнения, найденные при проверках

- У локальной сессии server-only clockStale не является источником времени. Активность использует свой presentation clock на общих checkpoints; иначе старт блокировался.
- Кнопку прежнего result нужно скрывать и в DOM, и в WebGL. Проверка снимка выявила её оставшийся GPU-слой; исправлено.
- Общая authority сравнивает дубли до validator. Для двух новых команд сохранён порядок wire keys, чтобы идентичный повтор совпадал с receipt; историческая нормализация остальных команд не менялась.
- После отказа persistence authority при восстановлении делает безопасную паузу и меняет revision. Повтор сначала согласует owner/snapshot; тест это проверяет, а не обходит старую revision.
- В harness перед CDP focus нужен загруженный about:blank. Для standby включена такая же autoplay policy, как в штатном launcher. Форматированный счётчик в тесте нормализуется до цифр; первоначальные сбои этих настроек не считались успешной приёмкой.
