# Профили, live-композиция и ручной калибратор — 27.10.2026

Установлено на обоих production-ПК патчем PROFILES-LIDAR-20261027-1; см. ../stand-patches/PROFILES-LIDAR-20261027-1/README.md. Вход: MAX → Композиция. Кнопки «Композиция» и «Калибратор лидара» переключают правую рабочую область редактора.

## Профили и изменения на стене

Сохранено прежнее наследование настроек: вся игра → тип устройства → экран. Добавлено до 24 именованных профилей. Новый профиль копирует текущую композицию, включая несохранённый черновик; его можно назвать и затем сохранить кнопкой «Сохранить профиль». Переключение профиля отменяет несохранённые правки предыдущего и сразу включает сохранённый вариант выбранного. Выход без сохранения оставляет сохранённую версию активного профиля. Активный профиль переживает перезапуск приложения.

Режим «Редактировать прямо на стене» явно отключает ARM и применяет изменения с debounce 100 мс. Геометрия отправляется renderer через SSE /__kdw/layout/events, без перезагрузки сцены и без секундного ожидания polling. При обрыве SSE сохраняется fallback-poll; черновик имеет lease 15 секунд и не перезаписывает сохранённый профиль. После закрытия редактора / отмены / истечения lease возвращается сохранённая композиция. При переключении ожидается окончание предыдущего запроса, чтобы запоздалый черновик не попал в другой профиль.

Правки при выключенном ARM разрешены и при сохранённом назначении игры: layout API не отменяет назначение и не очищает прогресс. Для работы с настоящей стеной нужен запущенный графический вывод; режим сервера сам по себе изображения не создаёт. ARM после настройки включается вручную.

Файлы: data/layout-profiles.local.json — библиотека и activeId; существующий data/layout.local.json мигрирует в «Основной» при первом сохранении и остаётся совместимым зеркалом активного профиля. CAS проверяется отдельно для библиотеки и значения композиции, старые клиенты остаются совместимыми. Профили сохраняются только явно, черновики — временные. Оба файла исключены из Git и защищены проверкой сохранности установщика.

## Уточнение: четыре угла и курсор (установлено)

Следующая итерация после установленного PROFILES-LIDAR-20261027-1: верхняя левая → верхняя правая → нижняя правая → нижняя левая → центр. Координаты по умолчанию (1000,500), (1880,500), (1880,1036), (1000,1036), (1440,768). Бывший заводской ромб заменяется при чтении только при точном совпадении с заводскими значениями. Пользовательские мишени и измеренная карта не переписываются; «Расставить по углам» строит прямоугольник в пределах текущих четырёх точек, сохранить его нужно явно.

Розовый прицел текущего касания виден в KDW_MAX_CONTENT во время калибровки независимо от ARM и переключателя игрового курсора. Он также виден на схеме редактора (опрос 100 мс во время калибровки / 500 мс вне её, без параллельных запросов). До четырёх фиксаций используется сохранённая измеренная карта, после четвёртой — новое преобразование, даже до проверки центра. На экране указано, какая карта используется. При касании за экраном маркер остаётся у края с явной подписью и фактическими координатами. Отпускание/отмена контакта и отсутствие свежего сигнала 350 мс убирают курсор. Курсор ничего не нажимает и не подменяет сырые измерения.

Если предыдущей карты нет, до четырёх углов показаны сырые координаты и объяснение отсутствия экранной позиции; выдуманная позиция не отображается. Независимый центр, удержание, отпускание между точками и явное сохранение остаются обязательными.

Проверки этой итерации: build:max, check:generated; test:layout 10/10; operator + spout-resilience 11/11; Chromium layout-browser — PASS, ошибок JS нет. Проверено переключение на новую карту, исчезновение устаревшего курсора, отсутствие перезаписи измерений, отрисовка курсора preload при выключенном игровом курсоре и курсор в реальной странице админки. ## Мишени лидара в установленном PROFILES-LIDAR-20261027-1

Пять точек: левая → верхняя → правая → нижняя → центр. Значения по умолчанию: (1000,768), (1440,500), (1880,768), (1440,1036), (1440,768). Они находятся ближе к середине вместо прежних углов на Y=160/1376. Мишени перетаскиваются на большой схеме 3072×1536 или задаются численно. Допуск координат учитывает центральную зону X=560…2320 и отступ 64 px; четыре точки образуют выпуклую фигуру, центр должен лежать внутри.

На стене через прежний operator-overlay показывается текущая мишень, имя точки и прогресс удержания. По умолчанию устойчивое касание 0,8 секунды фиксируется автоматически. После фиксации требуется убрать руку; один непрерывный контакт не захватывает несколько точек. Ручная фиксация также доступна. Центр независимо проверяет найденное преобразование с прежним пределом ошибки 60 px. Ошибка/дрожание/неполная последовательность не позволяют сохранить новую калибровку.

Позиции мишеней — data/calibration-targets.local.json. Фактическое измерение — прежний data/lidar.local.json с rawPoints/targetPoints. Калибровка общая для физического ПК и не меняется при выборе профиля композиции. Старое измерение сохраняется до успешной проверки и явной команды сохранения; отмена возвращает прежнюю карту, ARM выключен. Менять расположение мишеней во время активной калибровки нельзя. Настройки UDP/OSC и физическая интерактивная зона не переписываются.
