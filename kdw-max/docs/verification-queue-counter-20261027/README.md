# Счётчик очереди рядом с таймером

Реализовано локально, на стенды не отправлено.

Слева от таймера ожидания ладони и слева от таймера задания показана плашка «очередь: n». Использует существующий материал v5-device-timer, его масштаб, общую композицию и значение плавного появления. Не принимает касания.

n — количество ожидающих назначений в существующей FIFO-очереди MAX, без текущего активного игрока. Поле queueCount возвращается существующим GET /__kdw/link/active и обновляется существующим опросом (1200 мс). Нет отдельного запроса или нового компонента. При отсутствии свежих данных более пяти секунд отображается «очередь: —», а не вымышленный ноль. Старый managed-режим получает количество из своего существующего monitor.queued и теперь сохраняет его также во время задания.

Проверено: 166 тестов MAX и 15 тестов game-link/async-link; сборка; check:generated. Браузер проверил обе плашки, положение слева на одной высоте, одинаковое значение opacity, отсутствие перехвата касаний и обновление 3 → 1 без перезагрузки. Отдельный серверный тест проверяет 0 → 2 → 1 и исключение текущего игрока. Скриншот и JSON рядом.

Канонический game-link изменён в apps/STARTUP/tools, выполнен build:shared. Основной вход изменён только через adapt-stand-main.mjs. Frozen stand-base не изменён. Существующий journey-v5-device-timer.mjs расширен для чтения очереди вне scan; его имя явно добавлено в список разрешённых адаптаций сборки.

Ранее подготовленные локальные GRACEFUL-UI-*-20261027-4 не включают эту правку очереди. Для будущей установки следует подготовить пакет из текущих runtime-файлов, включая launcher/game-link.cjs.
