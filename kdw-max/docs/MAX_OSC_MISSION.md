# MAX — OSC состояния и номера миссии

Установлено на диск production MAX 30.10.2026 в 13:43 МСК без перезапуска. Новый канал начнёт работать после следующего полного запуска MAX/API. См. docs/stand-patches/MISSION-OSC-MAX-20261030-1/README.md.

Получатель: UDP 127.0.0.1:9000 на ПК MAX. Два независимых OSC-адреса, аргумент int32 (тип ,i):

- /max/state — прежний канал: 0 меню, 1 ладонь, 2 игра/результат задания, 3 финальный QR
- /max/mission — выбранная миссия по таблице ниже

| ID | Миссия | Внутренний идентификатор |
| --- | --- | --- |
| 0 | Миссия не выбрана, idle / главное меню | null |
| 1 | Все возможности с Цифровым ID | digital-id |
| 2 | Продвижение бизнеса | business / business-promotion |
| 3 | Стать блогером | blogger |
| 4 | Общение на максимум | communication |

Нумерация закреплена по порядку иконок главного меню, не зависит от сортировки каталога. Каждая величина отправляется при изменении и повторяется раз в секунду. Номер миссии появляется при готовом видимом экране ладони, сохраняется во время игры и финального QR. На готовом меню отправляется 0, даже если публикация содержит старый missionId. Переходы, загрузка, потеря публикаций и восстановление изображения сохраняют последние известные значения; до первой достоверной публикации канал молчит. Неизвестный или отсутствующий missionId вне меню не выдаётся за idle. UDP не гарантирует доставку или одновременное получение обоих каналов; получатель хранит последнее значение каждого канала, heartbeat восстанавливает потерянные обновления.

Диагностика: /__kdw/health → stateOsc.mission: missionId, sent, errors, lastError, lastSentAt, address, port. Прежние поля stateOsc сохранены. Событие API osc-mission-changed.

Для TouchDesigner: тот же OSC In, отдельный канал max/mission (точное представление адреса зависит от настроек оператора). Сеть TD этим патчем не менялась.

Изменён один runtime-файл apps/max-game/launcher/game-state-osc.cjs. При последующей установке нужен перезапуск API/MAX; обычная смена миссии не загружает код заново. Патч восстановления лидара — отдельный, уже установлен на диск и ожидает полного перезапуска.

Проверка: node --test --test-isolation=none ops/production-build/game-state-osc.test.cjs ops/audit-fixes/max-screen-api.test.cjs — 6/6. Реальный локальный UDP: оба адреса, int32, повтор, смена миссии без смены stage, возврат в idle, сохранение на QR/при потере связи и прекращение после close. Получатель TouchDesigner на стенде не проверялся.
