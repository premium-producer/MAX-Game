## Что выяснили

В журнале production `runtime.sample` метрики падающих карточек существовали,
но frame/update/resources содержали `[depth]`: общая очистка журнала отсекала
даже скалярные числа на шестом уровне вложенности. Эти прошлые значения утрачены.
Исправлено сохранение скаляров с сохранением ограничения глубины объектов,
размера коллекций и удаления секретов. Общая исправленная библиотека скопирована
в оба приложения через `npm run build:shared`.

Два локальных замера posts/store в Chromium при 3072×1536, по 18 секунд:
максимальный интервал около 16,8 мс, длинных задач и скачков координат не найдено.
Результаты `before-*-summary.json` относятся только к локальному браузеру,
не доказывают плавность Electron/Spout на production и не устанавливают причину рывков.

## Постоянная диагностика

MAX пишет `data/runtime-logs/performance.jsonl` раз в секунду и при обнаруженной
смене экрана. Журнал содержит UTC-время, boot ID, экран/этап, возраст UI-снимка,
готовность игры, состояние LiDAR, кадры двух Spout-слоёв и очередь GPU.
На существующем renderer tick собираются реальные интервалы и Long Tasks;
дополнительного RAF или покадрового IPC нет. В main process отдельно измеряются
интервалы paint, прихода IPC, задержки GPU completion, monitor и записи output-state.
GPU completion включает задержку опроса, это не чистое время работы GPU.
Существующие метрики activity включают CPU update, ресурсы и количество карточек.

Интервал >50 мс маркирует slow-frame, но не объявляется автоматически причиной
визуального рывка: загрузка и переходы тоже могут давать такой интервал.
Смена экрана определяется по UI-снимкам, не является полным событийным replay.
При зависании renderer журнал main продолжает сохранять возраст последнего UI.
Сбой всего процесса по-прежнему покрывают supervisor/output/crash журналы.

Запись асинхронная, очередь максимум 8 строк, кольца максимум 120/240 значений.
Переполнение отмечается dropped; ошибки диска не останавливают игру.
16 МиБ × 8 файлов (основной + 7 ротаций), до примерно 128 МиБ; срок истории
зависит от активности, после заполнения удаляется самая старая часть.
Внезапное завершение процесса может потерять текущую секунду и очередь записи.
Изображения, голос и тексты посетителей намеренно не записываются.

Для анализа скопированного журнала без участия посетителя:

```powershell
node ops/activity-webgl/read-performance-history.cjs <папка-runtime-logs> [от-ISO] [до-ISO]
```

Читает все ротации потоково, выводит статистику и последние 30 инцидентов.
Например, время с явным смещением: `2026-10-28T09:00:00+03:00`.
Последние записи также включены в существующий runtimeLogTail.
