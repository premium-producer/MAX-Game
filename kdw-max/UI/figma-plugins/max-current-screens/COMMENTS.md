# Комментарии Figma → экраны MAX

Обновление 23.10.2026. Используется тот же плагин и та же папка `max-current-screens`. Для анализа комментариев не нужно заново собирать экраны или выбирать пакет PNG.

## Как пользоваться

1. Перезапустите плагин. Если Figma не подхватила новые сетевые разрешения, повторно импортируйте **manifest.json из этой же папки** через Plugins → Development → Import plugin from manifest.
2. Выделите общий фрейм **«MAX · Финальные скриншоты · 3072×1536»**. Поддерживается также один экран, созданный этим плагином. Переименование или перемещение фрейма не мешает: используются сохранённые метаданные, а не имя и не старая сетка.
3. Раскройте **«Комментарии → экраны · JSON / MD»**.
4. Выберите источник:
   - **Figma API:** вставьте ссылку/ключ текущего файла и Personal Access Token с разрешением `file_comments:read`; нажмите «Загрузить комментарии Figma и сопоставить». Токен должен иметь доступ к этому файлу. При наличии ключа в Plugin API поле заполняется автоматически.
   - **JSON:** выберите сохранённый ответ `GET /v1/files/:key/comments` вида `{"comments":[…]}` и нажмите «Сопоставить с выделенным фреймом». Принимается и сам массив комментариев. Лимиты — 10 МБ и 5000 комментариев.
5. Если комментарии содержат только абсолютные координаты без привязки к узлу и без `page_id`, подтвердите их принадлежность текущей странице отдельным флажком **только если это известно**. Иначе плагин покажет кандидатов, но оставит такие ветки на проверке. Координаты разных страниц могут совпадать.
6. Скачайте **JSON** для машинного разбора и/или **MD** для чтения правок по экранам. Эти файлы можно передать в чат для следующего прохода по текстам.

При перемещении экранов повторите сопоставление: геометрия считывается заново при каждом запуске. Для абсолютных координат старый JSON должен соответствовать текущему расположению; если с момента выгрузки макет перемещался, получите свежие комментарии из API. Относительные координаты привязанных комментариев пересчитываются по текущему узлу.

## Как определяется экран

- Из выделения читаются реальные `absoluteTransform`, размеры и метаданные каждого кадра: `fixtureId`, `screenId`, `missionId`, `taskId`, `sector`, `variant`.
- Прямая привязка комментария к экрану или его вложенному слою имеет приоритет.
- Привязка к общему контейнеру: `node_offset` переводится в абсолютную позицию, затем проверяется попадание в экран.
- Абсолютная точка: проверяется попадание в фактический прямоугольник экрана с учётом поворота/масштаба.
- Комментарий-область: учитываются размеры и `comment_pin_corner`. Область на нескольких экранах считается неоднозначной; частично выходящая за экран требует проверки.
- Ответы наследуют экран корневого комментария. Сохраняются авторы, время, текст, ID, порядок ветки и статус закрытия.
- Комментарии, привязанные к другому набору или странице, не назначаются выделенным экранам даже при совпадении координат.
- Промежутки между кадрами не назначаются ближайшему экрану автоматически. Пропавшие узлы, недостающие родители ответов и некорректные координаты отмечаются отдельно.

Это геометрическая привязка, не интерпретация смысла правки: комментарий «так же на всех экранах» остаётся прикреплённым к своему экрану, а расширение области действия требует редакторского разбора.

## Что находится в отчёте

JSON: схема `max-screen-comments/v1`; сведения о файле, странице и выделенном фрейме; геометрия экранов; ветки комментариев; причины сопоставления и кандидаты; локальная позиция, нормализованные координаты и позиция в исходном кадре **3072×1536**.

| Статус | Значение |
| --- | --- |
| `matched` | Однозначная привязка к экрану |
| `review` | Нужно подтвердить страницу абсолютных координат или проверить область, частично выходящую за кадр |
| `ambiguous` | Точка/область относится к нескольким экранам |
| `unmatched` | Промежуток, недоступный узел, отсутствующая позиция или неполная ветка |
| `outside` | Узел принадлежит другой странице или находится вне выделенного набора |

Markdown содержит разделы по `fixtureId` и отдельный раздел для веток без однозначной привязки. Исходные формулировки не считаются командами на автоматическую правку игры.

## Доступ и ограничения

Plugin API не предоставляет комментарии файла. Для чтения нужен REST API или готовый JSON. Единственный разрешённый сетевой адрес — `https://api.figma.com`; запрос только `GET`, без cookie и перенаправлений. Токен существует в UI на время запроса, затем поле очищается; он не передаётся в основной код плагина, не записывается в pluginData/clientStorage, экспорт или исходники. Ошибка API не выдаётся за отсутствие комментариев.

Плагин не публикует ответы, не закрывает и не удаляет комментарии, не меняет экраны или тексты. Отсутствие `file_key` в JSON и недоступность `figma.fileKey` ограничивают проверку принадлежности файлу: загружайте JSON именно текущего документа.

Проверено на синтетических данных и в Chromium iframe; живой доступ к конкретному аккаунту/файлу Figma в разработке не использовался. Отчёт: [verification-plugin-comments-20261023](../../../docs/verification-plugin-comments-20261023/README.md).

## Обновление кода без пересъёмки игры

`node source/update-plugin-only.mjs` обновляет `code.js`, `ui.html` и `manifest.json` из исходников, сохраняя уже поставленные каталог, `content-index.json` и `screens.maxscreens`. SHA пакета проверяется до/после. Полная пересъёмка по-прежнему проходит через `final-prepare`, `final-capture`, `final-merge` и `package.mjs` с проверкой production-происхождения.
