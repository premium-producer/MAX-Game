# KDW-MAX — рабочий проект

[Архитектура устойчивости production](docs/PRODUCTION_RESILIENCE_ARCHITECTURE.md) — разделение API и графики, восстановление Spout/renderer, резервный экран и критерии длительной приёмки; подготовлена к реализации.

[Архитектура независимой Стеллы и MAX с фоновой доставкой фото](docs/STELA_MAX_ASYNC_ARCHITECTURE.md) — основной обмен реализован; фактический объём и ограничения см. в [отчёте](docs/verification-async-link-20261027/README.md).

Рабочая структура находится в корне, как на основном ПК. Изменения приложений делать в `apps/`, ресурсов — в `UI/`, документации — в `docs/`.

Финальная Стелла — **пиксельная**, штатный вход `/stella/pixels/`; `/stella/` также использует пиксели. Градиент оставлен только как явно выбранный альтернативный просмотр. На обоих стендовых ПК должны быть обе сборки, с отдельным запуском MAX и Стеллы для смены ролей. Фотоэтап этим решением не отключается.

**Роли production-ПК с 27.10.2026:** MAX — `DESKTOP-64J4BMN / DR7` (`max-game-pc`); Стелла — `DESKTOP-DBD624H / DR2` (`stela-pc`). Исторические SSH aliases не переименованы. [Таблица ролей и порядок обновления](docs/STAND_FAST_ITERATION.md).

Этот README и package.json описывают объединённый рабочий корень с обоими приложениями и двумя публикационными Git-копиями. В GitHub каталог MAX-Game/kdw-max содержит только MAX-компонент. Для отдельного MAX использовать `npm --prefix apps/max-game/source/client ci --ignore-scripts` и `node apps/max-game/source/build.mjs`; команды общего корня требуют также Стеллу. [Сборка общего корня на новой машине](docs/sync/WORKSPACE.md#новая-машина).

## Разработка

Нужен Node.js 24+; версия указана в `.nvmrc`. Команды выполняются из этого корня:

```sh
npm run setup
npm run build
npm run check
```

`setup` устанавливает зависимости обоих приложений по lock-файлам. `build` обновляет исходники и сборки, но не переутверждает SHA-манифесты автоматически. После осознанных изменений просмотреть diff и обновить манифест только затронутого приложения штатным `check-package.mjs --app … --seal`, затем повторить проверку.

Отдельные команды: `npm run build:max`, `npm run build:stela`, `npm run test:max`, `npm run test:stela`. Для разработки начинать с [AGENTS.md](AGENTS.md), последних записей [WORKLOG.md](WORKLOG.md) и [дизайн-документа](docs/DESIGN_DOCUMENT.md).

Единая версия и порядок обновления: [docs/sync/WORKSPACE.md](docs/sync/WORKSPACE.md). `npm run sync:check` показывает расхождения публикационных копий; `npm run sync:prepare` обновляет их из рабочего корня по явному списку разрешённых файлов, без создания нового экспорта и без автоматического push.

[Архитектура тестового стенда PREMIUM-CHUWI](docs/STAND_EXPORT_ARCHITECTURE.md): MAX в Electron с отдельными Spout-потоками фона и контента, полноэкранная Стелла, поставка и откат выпусков. [Изолированный GPU-прототип](apps/max-game/source/spout-prototype/README.md) собирается отдельно и доставляется через GitHub Releases; полная интеграция игровых экранов и совместный обновлятор MAX/Стеллы остаются следующими этапами.

Включённый Electron и native audio host относятся к Windows. Перенос структуры на Mac сохраняет исходники и готовые файлы; нативный запуск приложений на macOS требует отдельной адаптации. Windows BAT/PowerShell-команды сохранены в корне.

## Синхронизация

Текущая рабочая копия — этот корень. Для следующих синхронизаций брать код из `apps/`, `UI/`, `docs/`, `ops/`; промежуточный переносимый экспорт для работы не нужен. Корень проекта, как и на ПК, объединяет два приложения; Git-история находится в отдельных репозиториях `github/MAX-Game` и `github/VK_Stella`.

[Доступ к основному ПК и правила GitHub-синхронизации](docs/DEVELOPMENT_AND_SYNC.md).

Папка прежнего переносимого экспорта разобрана. Его контрольные документы и исходный SHA-манифест сохранены в `.sync/archive/export-20261024/`; второй полной копии приложений не создано. [Квитанция переноса](.sync/workspace-migration-20261025.json).

## Исправления и регрессии 26.10

[Аудит и список задач](docs/GAMEPLAY_AUDIT_TASKS.md), [реализованные исправления и проверка](docs/verification-audit-fixes-20261026/README.md), [ТЗ на звук](docs/SOUND_DESIGN_SPEC.md).

После `npm run setup` и `npm run setup:browser`: `npm run build`, затем `npm run test:audit:all`. Браузерный прогон требует свободных портов 18781/18782, использует временные данные и не обращается к AI. Для быстрой программной регрессии без Chromium — `npm run test:audit`. Обычная сборка сохраняет профиль запуска; новые Windows-комплекты формирует явный `ops/production-build/build.py --output НОВАЯ_ПАПКА`.


Операторские панели MAX/Стеллы и оригинальные музыка/эффекты: [инструкция](docs/OPERATOR_PANELS.md). Запуск без сцены — `apps/<программа>/Start-Admin.bat`.

Порядок внесения и доставки новых правок: [быстрые итерации](docs/STAND_FAST_ITERATION.md). По умолчанию работать только локально, без SSH и доставки. Обновлять production MAX и Стеллу только по конкретной просьбе пользователя; CHUWI не использовать. При нестабильном интернете передавать накопленный пакет изменений, без обязательного полного выпуска и загрузки через GitHub. [Аудит длительности предыдущей работы](docs/AUDIT_DELIVERY_TIME_20261027.md).

Для следующих обновлений повторно использовать [готовый установщик патчей](ops/production-build/deploy-sound/README.md): менять список файлов и базовую цепочку, не писать новый установщик под каждую правку.


Устойчивость production: [реализация и результаты проверки](docs/verification-runtime-resilience-20261027/README.md), [целевая архитектура](docs/PRODUCTION_RESILIENCE_ARCHITECTURE.md). Общие supervisor/API/worker-модули — `apps/STARTUP/tools/runtime-*`, после изменений — `npm run build:shared`. Точечные тесты: `npm run test:runtime`; реальная локальная проверка процессов: `node ops/production-build/runtime-resilience-integration.cjs`. Итерация установлена на обоих production-ПК: [RESILIENCE-20261027-1](docs/stand-patches/RESILIENCE-20261027-1/README.md); API/админки работают, ранее остановленные сцены не запускались.
