# MAX: экспорт финальной карты по Auto Layout — 03.10.2026

Задача: читать текущий макет, не названия фреймов и не прежний каталог. Последовательность берётся из children Auto Layout; визуал экспортируется отдельно от всех текстовых слоёв справки.

## Выбранные готовые механизмы

- Figma Plugin API 1.0.0: exportAsync PNG/SVG/JSON_REST_V1 и Image.getBytesAsync выполняют сам экспорт и растеризацию; getStyledTextSegments читает текст и стили. API предоставляется Figma по условиям платформы, сторонняя библиотека растеризации не добавляется.
- Существующий MAX Material Collector / Frame Archive: последовательная очередь, localhost:47831, SHA-256 ACK, запись на диск и продолжение по проверенным файлам. Переиспользуется существующий код, новый сервер/ZIP/транспорт не пишется. Это внутренний код проекта; тесты не являются доказательством работы в пользовательском Figma-host.
- Официальный figma/plugin-samples (MIT, просмотр 03.10.2026): экспорт/UI-message примеры подтверждают нативный путь; код сторонних примеров не копируется. Общий сторонний exporter не знает семантики нашей карты. Специфическое сопоставление дерева — адаптер данных, не замена механизма экспорта.

По одному экрану, отмена после текущего вызова, повтор с дисковыми ACK; не обещаем отменять внутреннюю операцию Figma.

## Границы

Автоматически не распознаём семантику пиктограммы по пикселям: сохраняем её визуал, вложенный текст и индекс. Удалённые метаданные не заменяем угадыванием по имени. Неоднозначные визуалы перечисляются с nodeId; до исправления структуры они не экспортируются как готовые экраны и остаются пробелами в карте. Пустые/служебные состояния сохраняются как пробелы в карте. Скрытые слои исключаются. Все видимые тексты справки читаются в порядке дерева, даже если заголовок или имя слоя устарели. Макет read-only, исходные растры отдельно, без шрифтов/видео. Проверка реального файла — пользователем.

## Уточнение после реальной выгрузки: сводка аудита

03.10.2026 повторно сверена официальная документация [children](https://developers.figma.com/docs/plugins/api/properties/nodes-children/), Figma Plugin API1.0.0: существующая read-only иерархия остаётся источником порядка. Новая библиотека/экспортный механизм не вводятся: сводка — отображение уже собранного contentMap. Реальный опыт и ограничение эвристики зафиксированы в [аудите](../../artifacts/reports/max-content-export-audit-20261003.md): Auto Layout внутри редактируемого UI совпадает с внешней структурой. Адаптер исключает кандидатов с предком-миссией; названия не используются. Это проектное правило семантики, не возможность автоматического определения миссий со стороны Figma. Произвольные вложенные карты миссий не поддерживаются; верификация реальной страницы пользователем остаётся необходимой.

## Ограничение глубины по указанию пользователя

03.10.2026: документация children повторно проверена; Figma прямо предупреждает о стоимости полного рекурсивного обхода. Для известной структуры нужны только прямые children области экрана, а не поиск всех потомков даже через findAll. Нативные references и exportAsync остаются готовым механизмом чтения/экспорта; адаптер лишь устанавливает границу аудита. Полный обход ассетов и fingerprint остаются в существующем экспортном тракте для сохранения оригиналов и безопасного resume. Эффект на время реальной Figma не измерен; фактический дефект прежнего обхода описан в аудите выгрузки выше. [Проверка интеграции](../../artifacts/reports/max-content-export-shallow-20261003.md).

Уточнение структуры от пользователя 03.10.2026: в области экрана находятся текстовые слои, именованный блок «Действия внутри устройства» и оставшийся визуал. Применено точное исключение имени блока кнопок на первом уровне, без чтения его потомков. Это явный контракт исходного макета; остальные имена не используются для выбора контента. Сохраняется существующий native children/exportAsync, новая механика не вводится. Сопоставление N экранов/M визуалов — представление уже прочитанной карты, а не доказательство полноты. Проверка: artifacts/reports/max-content-export-visual-counts-20261003.md.

## Подготовка экспорта без блокирующего прохода — 03.10.2026

Пользовательский кадр: аудит завершён (103 визуала), статус «Экспорт: 103 визуалов», первый файл не подтверждён. Код показывает синхронную подготовку fingerprint всех кадров до stream-plan, с уступкой только каждые16 кадров. Это подтверждённое блокирующее место, но без live-профиля не доказано, что оно единственная причина наблюдения.

Источники: [Figma async tasks](https://developers.figma.com/docs/plugins/async-tasks/), [MDN Breaking down long tasks](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Performance/JavaScript#breaking_down_long_tasks). Применён существующий native setTimeout/pause в Figma Plugin API1.0.0: уступка event loop каждые64 обработанных слоя и между визуалами, проверка отмены. Новый scheduler или библиотека не создавались; существующий fingerprint разделён на итерации без изменения итоговой подписи. Native runtime API поставляется платформой; сторонний исходный код не копировался. Ограничение: один медленный getter или внутренний exportAsync этой уступкой не прерываются; фактическая скорость на файле пользователя ещё не измерена.
