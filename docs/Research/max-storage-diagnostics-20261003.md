# MAX: диагностика недоступного browser storage

03.10.2026. Узкая итерация: раскрыть исходную причину без смены хранилища или миграции.

- [MDN: квоты](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria): Web Storage ограничен, превышение вызывает QuotaExceededError; это не эквивалент запрету доступа.
- [MDN: определение доступности](https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API/Using_the_Web_Storage_API): присутствие localStorage не гарантирует успешную запись, частный режим и исчерпанная квота требуют различения.
- [Практический issue localForage #815](https://github.com/localForage/localForage/issues/815): ограничения хранения могут проявляться и при IndexedDB; молчаливая смена API не является доказанным исправлением.

В существующем SessionPort Error.cause уже сохраняет исходную ошибку браузера. Используется этот стандартный механизм ECMAScript, без новой библиотеки и без самописного обхода quota. Из цепочки выводятся только типы/коды исключений; содержимое сохранений не выводится. Реальная причина в отдельном браузере пользователя пока неизвестна. Переполнение воспроизведено тестом как одна возможная причина, не объявлено диагнозом.

Пакеты не добавлялись, лицензии не менялись. Возможная следующая работа определяется фактическим кодом ошибки, а не этим предположением. [Проверка](../../artifacts/reports/max-storage-diagnostics-20261003.md).
