## Вывод и исправление предыдущей рекомендации

Нужная анимация уже реализована автором в `demo/scene/flight.ts` и `choreography.ts`: пружинное появление из центра, мягкое покачивание, разлёт наружу и возврат к центру. Она работает на браузерном Web Animations API (WAAPI). Для её воспроизведения GSAP не требуется.

Предыдущее исследование сосредоточилось на renderer/core и внешних библиотеках и пропустило готовую хореографию демонстрационной сцены. В результате внедрённый веер по дугам, крупные одинаковые прямоугольники и неподвижная пауза отличаются от нужного образа. Предыдущая рекомендация GSAP для этого визуального приёма **отменена**. Код текущей локальной страницы ещё содержит отклонённую итерацию: этим исследованием он не изменяется.

## Как устроено движение

| Механизм исходника | Точное поведение | Значение для Стеллы |
| --- | --- | --- |
| `flyIn` | Из общего центра к месту плашки по вектору; scale 0.18→1. Пружина zeta=0.6, omega=11, около 9% перелёта с возвратом. 920 ms, шаг между плашками 48 ms | Маленькие теги раскрываются в пространстве и мягко садятся |
| Появление opacity | Независимый fade до 320 ms; одновременно с движением | Тег проявляется раньше завершения посадки |
| `startFloat` | Бесконечное слабое покачивание по двум осям. Период 2–6 s; стабильный seed, 24 шага keyframes. `translate` отделён от `transform` полёта | Во время чтения плашки сохраняют ощущение лёгкости |
| `flyOut`, режим out | Дальнейший разлёт от центра, scale 1→0.55, ускоряющий easing. 640 ms, шаг 28 ms. Opacity держится первые 35% нормального полёта, затем исчезает | Завершение ответа можно связать с разлётом тегов |
| Возврат center | Возвращение к общему центру, scale 1→0.18, 520 ms; в демо после 140 ms запускается новый вход | Подходит как образ обратного перехода |
| Reduced motion | Без перемещения/покачивания; вход fade 420 ms, выход fade 380 ms | Сохранить уже предусмотренный автором спокойный режим |

Пружина задана CSS `linear()` из 45 отсчётов; fallback — `cubic-bezier(0.34, 1.45, 0.64, 1)`. Это не произвольная кривая MotionPath. Координаты полёта выражены в `cqmin`, размеры — относительно короткой стороны контейнера, базовый референс 345 px. Авторская композиция — квадрат внутри сцены.

`Choreographer` ведёт состояния hidden → entering → idle → leaving. Перед входом есть 32 ms на привязку элементов. Порядок определяется `item.order`. `data-shown` управляет присутствием, `data-live` разрешает pointer-ввод после посадки конкретной плашки. Новая видимость во время перехода запоминается и применяется после его завершения. Повторные scene actions во время busy игнорируются. `dispose()` отменяет Animation и таймеры.

Демонстрационная кнопка done запускает выход, паузу 1200 ms и повторный вход. Это демонстрационный цикл; в Стелле его следует заменить переходом к следующему вопросу, сохранив само движение.

## Почему важна форма плашек

`TopicBubble` и `scene.css` дополняют механику движения:

- Ширина по тексту и padding, компактная высота, небольшое скругление; плашки разного размера.
- Красный градиент и синий градиент, мягкая тень/ореол, тонкий внутренний блик.
- Выбранная тема меняет красный на синий через слой с opacity за 350 ms; это семантика выбора, а не чередование цвета по индексу.
- Наведение/фокус увеличивают плашку до 1.07 за 200 ms и усиливают свет.
- Крупная primary-плашка, вторичная подпись и карточка с иллюстрацией используют ту же хореографию.
- Раскладка нерегулярная, вокруг композиционного центра, с отдельными координатами и порядком каждой плашки. Демо не раскладывает всё в одинаковую сетку 2×2.

Размеры и координаты демонстрации нельзя механически растянуть на всю длинную стелу: потребуется ограниченный контейнер в верхних 2/3 и проверка длинных русских метаданных. Предыдущие референсы больших кнопок ответов сохраняются; перенос компактного вида относится прежде всего к вылетающим метаданным.

## Как плашки связаны с LumiCells

`SceneBinder` в `demo/stand/scene-binding.tsx` связывает DOM-сцену и WebGL через callbacks, без React-перерисовки на каждом кадре:

- `bindElement(track: auto)`: цветной свет под плашкой, базовая сила 0.28, hover 0.7, colorMix 0.2, falloff 1.6.
- Начало входа включает свет и слабую волну из центра (strength 0.25). Посадка вызывает волну в месте плашки (0.3). Конец выхода отключает её свет.
- Click даёт `pulse` цвета плашки (strength 0.9, colorMix 0.6). Hover вызывает `lift` трёх клеток, radius 1.5.
- Смена выбранного цвета обновляет также цвет influence; заголовок получает собственную мягкую тень.
- `tracking.ts` обнаруживает живые WAAPI-анимации через `getAnimations()` и измеряет движущийся элемент. Законченные fill-forwards-анимации не считаются продолжающимся движением.

В авторском binder нет покадрового умножения света на opacity: свет включается/выключается по фазам полёта. Не следует выдавать поведение предыдущего GSAP-адаптера за поведение исходника.

Эффект done дополнительно увеличивает радиус sphere и даёт общую волну. **Возвращать видимое кольцо не нужно:** последний визуальный запрос пользователя его исключил. Полёты и локальные pulse/lift независимы от видимой сферы.

## Что переносить и что адаптировать

1. Взять авторские `flyIn`, `flyOut`, `springEasing`, `startFloat` с минимальными изменениями; сохранить происхождение файлов. Это код демо, а не экспорт `lumicells/core` и не отдельная npm-библиотека.
2. В следующей короткой итерации заменить отклонённую GSAP-анимацию первого ответа; использовать компактные плашки по тексту и свободную композицию с авторским пружинным появлением, покачиванием и разлётом. Цель — проверить именно авторский характер движения.
3. Сценарий, answer id, веса, metadata и публикацию событий оставить владельцу Prototype. Одно завершение анимации разрешает один переход; не переносить демонстрационный бесконечный цикл done.
4. Добавить адаптер паузы: у `Choreographer` нет публичного pause/resume; исходный stand pause замораживает поле через modulators и сам по себе не приостанавливает WAAPI и timeout хореографии. Стелле нужны согласованные pause/play для Animation и оставшегося ожидания.
5. Удалять анимации и bindings при уходе со страницы; учитывать отменённые finished promises. `settle()` уже подавляет onDone при cancel, но адаптер сценария не должен ждать такой callback как обычное завершение.
6. Длительность не форсировать под старый GSAP-рисунок. Для четырёх тегов авторский вход с задержкой привязки занимает примерно 1096 ms, выход — 724 ms. В окне 2300 ms останется около 480 ms общей паузы; достаточность чтения требует отдельной оценки. Нужный темп выбирать с учётом завершения анимаций и содержимого.

GSAP-зависимости можно убрать при замене их последнего использования; в этом исследовании package-lock и код не менялись. Авторская demo-сцена использует фиксированный каталог и квадратную раскладку: подключение `<DemoScene>` целиком не заменяет параметризованный адаптер вопросов Стеллы.

## Дополнение перед переносом — 03.10.2026

Готовый механизм: исходные flight.ts + Choreographer из LumiCells0.1.0, commit1007717. Локальный package.json указывает private=true, license=UNLICENSED; публичной MIT-лицензии не заявляем. Использование LumiCells коллеги прямо разрешено пользователем в AGENTS. Веб-доступ к репозиторию https://github.com/supsad/lumicells в этой проверке не сработал; ревизия и реальный авторский пример проверены по сохранённому комплекту, его SHA приведены выше. Механизм полёта переносится кодом автора, а не новой формулой.

Проверены [MDN Element.animate](https://developer.mozilla.org/en-US/docs/Web/API/Element/animate), [Animation.finished](https://developer.mozilla.org/en-US/docs/Web/API/Animation/finished), [pause](https://developer.mozilla.org/en-US/docs/Web/API/Animation/pause) и [cancel](https://developer.mozilla.org/en-US/docs/Web/API/Animation/cancel). animate возвращает Animation, finished завершается по фактическому окончанию; cancel отклоняет текущий finished с AbortError. Пауза WAAPI требует pause/play на объектах Animation, CSS animation-play-state недостаточно.

Реальный описанный опыт: [web-animations-js issue62](https://github.com/web-animations/web-animations-js/issues/62) сообщает о зависании finished при повторном проигрывании в polyfill (2016); это историческое ограничение polyfill, не доказанный дефект нынешнего Chromium. [W3C issue141](https://github.com/w3c/web-animations/issues/141) разбирает отклонение Promise при отмене и необходимость обработки. Для интеграции используем нативный WAAPI, свежие объекты анимаций каждого перехода, обработку отмены; polyfill не устанавливаем. Авторский DemoScene/SceneBinder служит проверенным примером использования именно LumiCells, независимых отчётов production-внедрения этой библиотеки не найдено.

Узкая адаптация Choreographer: одноразовый цикл вход→чтение→выход вместо демо-повтора; pause/play для его Animation. Ожидания переводятся с timeout на пустые WAAPI-эффекты, чтобы остаток времени сохранялся браузером вместе с полётами. Полёты, easing и float берутся без изменений из flight.ts. Окно чтения увеличивается до1200ms после посадки последнего тега; полный нормальный переход около3020ms. Это осознанная настройка сценарной выдержки, художественно ещё не утверждённая. Интеграцию следует проверить отдельно; новые unit-тесты не доказывают качество движения.
