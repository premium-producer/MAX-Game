# MAX v5 — захват видимой иконки и готовое сглаживание телефона

03.10.2026. Пользователь сообщает смещение вниз при начале drag и просит такое же движение, как у телефона. Эта итерация исправляет существующую интеграцию ввода; новый движок жестов или физики не вводится.

## Готовые механизмы и ограничения

- `maath@0.10.8`, MIT, уже закреплён в проекте. Реальный `easing.damp` выполняет расчёт X/Y и сохраняет скорость. Иконки при drag получают тот же `smoothTime=2/14` (~0,143 с), что телефон. Применимая версия, интеграция и лицензия разобраны в [исследовании v5](max-webgl-v5-bfm-theme-20261003.md). Установленные package.json и ESM easing проверены, CPU-тесты исполняют библиотеку. [Исторический исходник](https://github.com/pmndrs/maath/blob/90317077d86b6aca9a5a5708bd15007b4c89c7c9/packages/maath/src/easing.ts). При повторном веб-запросе этот URL недоступен; текущий main перенаправляет на другой пакет `math`, его API не переносится в установленную maath.
- Реальный описанный опыт: [issue 33](https://github.com/pmndrs/maath/issues/33). Автор наблюдает телепортацию с `easeInOutCubic` и непонимание аргумента easing. Сохраняем штатную decay-функцию maath, без своей tween easing. Это источник ограничения, а не доказательство исправления текущего браузерного кадра.
- Захват контакта остаётся готовым браузерным **Pointer Events / setPointerCapture**: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture), [обзор и отмена захвата](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events). Нативный API направляет последующие события владельцу до release/pointerup; сам не вычисляет положение объекта и смещение точки захвата. Не заменяем его собственным диспетчером. Нативный Web API не является дополнительной распространяемой npm-зависимостью.

## Вывод для текущего кода

Исследование готового damp не требует менять его формулу: дефект в преобразовании координат и действующей reveal-политике. Начальный центр следует брать из того же retained IconMotion, который даёт WebGL/DOM/mask кадр. Преобразование host-content → world является обратным существующему guidedIconGeometry, с cameraX и базовой поправкой +100 по Y, без добавления border/caption. Pointer delta сохраняет место захвата внутри плитки; абсолютная координата курсора не становится центром иконки.

Старый reveal clamp может принудительно переместить уже видимую иконку вне старых границ при первом pointermove. Для v5 свободный drag использует позицию захвата плюс delta, как телефон. Автоматическая раскладка остаётся CSS Flexbox, её gap400 и восстановление после действия не меняются.

Парение и изменение размера при hover не должны менять захваченную плитку. До преодоления существующего порога 7 логических пикселей сохраняются фактические центр/размер и скорость; model MOVE не выполняется. После порога X/Y фильтрует maath с параметрами телефона, декоративный bob отключён и размер захвата сохраняется. Release/cancel/lostpointercapture снимают это состояние без обнуления скорости; обычное парение возвращается по существующему motion clock. Это адаптация готовых механизмов к текущему renderer, без новой физической модели.

## Проверка и предел уверенности

[Техническая проверка](../../artifacts/reports/max-v5-drag-20261003.md): фактические main pointer handlers, retained frame projection и исполнение maath при 30/60/120 Гц. Браузерное hit-testing, LiDAR и ощущение движения не доказаны CPU-проверкой; приёмку выполняет пользователь. Новых вкладок, тяжёлого GPU-прогона, записи видео и изменения мастера нет.
