# MAX — разметка интерактивных зон на ассетах

Дата: 03.10.2026. Назначение: страница всех игровых ассетов, сгруппированных по миссиям и заданиям; пользователь отмечает область кнопки на изображении либо явно выбирает внешнюю кнопку. Исследование выбора механизма; фактическая приёмка интеграции хранится отдельно в `artifacts/reports/`.

## Выбранное готовое решение

`@annotorious/annotorious` **3.9.3**, лицензия **BSD-3-Clause**. Версия и лицензия проверены по установленному package.json; основной агент подтвердил registry exact-version и npm audit без обнаруженных уязвимостей. Не использовать плавающую версию CDN. Сохранить лицензию в комплекте страницы.

Библиотека реализует требуемое редактирование прямоугольников: выделение, перемещение, изменение размера, преобразование координат при масштабировании изображения, историю изменений. Код страницы отвечает только за каталог, связь с `actionId`, первоначальное размещение прямоугольника по клику, хранение и экспорт. Собственный редактор геометрии не нужен.

Для обычного ImageAnnotator установленный исходник `src/Annotorious.ts` создаёт **SVGAnnotationLayer**. Three.js, OpenSeadragon и игровой renderer для этой страницы не требуются. Все карточки — обычные изображения с отложенной загрузкой; одновременно работает один редактор в увеличенном просмотре. Это выбранная архитектура нагрузки, а не обещание измеренной производительности.

## Подтверждённый API

Источники: [ImageAnnotator](https://annotorious.dev/api-reference/image-annotator/), [руководство](https://annotorious.dev/guides/annotating-images/), [формат прямоугольника](https://annotorious.dev/api-reference/shape/), [события](https://annotorious.dev/api-reference/events/).

```js
import { createImageAnnotator } from '@annotorious/annotorious';
import '@annotorious/annotorious/annotorious.css';

const anno = createImageAnnotator(image, {
  drawingEnabled: false,
  autoSave: true,
  userSelectAction: 'EDIT'
});

const annotation = {
  id: actionId,
  bodies: [],
  target: { selector: {
    type: 'RECTANGLE',
    geometry: { x, y, w, h,
      bounds: { minX: x, minY: y, maxX: x + w, maxY: y + h }
    }
  } }
};
anno.addAnnotation(annotation);
anno.setSelected(actionId, true);
anno.on('updateAnnotation', (updated, previous) => { /* сохранить область */ });
```

- `drawingMode: 'click'` не означает добавление готовой области одним кликом: стандартное построение прямоугольника завершается вторым кликом. Для поставленной задачи первый клик создаёт небольшую начальную область через публичный `addAnnotation`; дальнейший resize/move выполняет библиотека.
- `selectionChanged` передаёт массив выбранных аннотаций; снятие выделения — пустой массив. `getAnnotations()` возвращает текущее содержимое. Программные изменения необходимо сохранять непосредственно в вызывающем коде, не полагаясь на события пользовательского редактирования.
- При `autoSave:true` событие изменения приходит после прекращения редактирования; это не собственное долговременное хранилище библиотеки. Для явного завершения редактора сначала снять выделение и прочитать актуальные аннотации.
- `destroy()` вызывается **до удаления DOM редактора**: реализация возвращает исходный img из wrapper через `container.parentNode`, освобождает компоненты и клавиатурные обработчики.

## Координаты и жизненный цикл

В установленном `src/annotation/utils/responsive.ts` SVG `viewBox` равен `0 0 naturalWidth naturalHeight`. Geometry хранится в пикселях исходного изображения, а не пикселях уменьшенной карточки. Начальная точка клика пересчитывается относительно фактического img: `(clientX - rect.left) * naturalWidth / rect.width` и аналогично Y. Область ограничивается размерами изображения; адаптер экспорта может нормализовать её для каталога. Использовать img без padding и без `object-fit` внутри несовпадающего по пропорциям прямоугольника.

Сначала открыть увеличенный просмотр и дождаться декодирования изображения, затем создать annotator. Это обеспечивает ненулевые natural-размеры и видимые измерения. При переключении ассета сохранить текущую разметку, уничтожить annotator, заменить изображение и создать новый экземпляр. Не пересоздавать весь редактор на каждый update.

## Реальный опыт и ограничения

- [Issue #599](https://github.com/annotorious/annotorious/issues/599): пользователь сообщил о сломанном drawing/tool switching после3.7.13 в Next.js/Webpack production; development работал. Это не подтверждённая ошибка vanilla/esbuild, но требует проверки именно собранной страницы, включая resize/move, а не только dev.
- [Issue #602](https://github.com/annotorious/annotorious/issues/602): в Angular наблюдались невидимые handles с радиусом0 до перезагрузки. Поэтому редактор создаётся на декодированном видимом изображении; обязательны проверка ручек и повторное открытие диалога. Причина issue не считается окончательно установленной.
- [Discussion #331](https://github.com/orgs/annotorious/discussions/331): автор подтверждает встроенные rectangle/polygon и несовместимость расширений2.x с3.x. Для MAX достаточно стандартного прямоугольника; React и плагины не добавляются.
- Заявления текущей документации могут опережать установленную версию. Например, нельзя основывать сохранение выбора на обещании diff-reconcile `setAnnotations`: во время активного редактирования достаточно точечных API.

## Проверка интеграции

Короткая проверка production-страницы: загрузка групп; клик на портретном и широком ассете; появление editable-области; перемещение и resize библиотечными ручками; закрытие/повторное открытие; перезагрузка и восстановление; экспорт. Проверить отсутствие потери координат при уменьшении изображения и отсутствие console errors. Результаты записывает основной агент в отчёт реализации. До этих проверок готовность библиотеки не равна готовности страницы.

## Сборка превью и фактическая интеграция

Превью создаёт готовый sharp **0.35.5**, Apache-2.0: [resize API](https://sharp.pixelplumbing.com/api-resize/) подтверждает `fit:inside` и `withoutEnlargement`, сохраняющие пропорции без обрезки. Он работает только при сборке. Хранение использует уже установленный idb **8.0.3**, ISC, поверх транзакций IndexedDB; [официальный репозиторий](https://github.com/jakearchibald/idb).

[Отчёт реальной проверки](../../artifacts/reports/max-asset-audit-20261003.md). Пользовательская приёмка и перенос разметки в игру остаются отдельными шагами.
