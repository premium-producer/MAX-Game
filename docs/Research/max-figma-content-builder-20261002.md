# MAX — компактная карта контента для будущего Figma-сборщика

Дата: 02.10.2026. Статус: описание и предложение для реализации; плагин не создан, Figma и игра не изменены.

**Последующее выполнение 02.10.2026:** по отдельному запросу пользователя создан [локальный плагин для всех миссий](../../artifacts/DESIGN/figma-plugins/max-content-builder/README.md), без MCP. [Техническая проверка](../../artifacts/reports/max-content-builder-20261002.md). Ниже сохранена исходная спецификация; фактические возможности и ограничения, включая ручное разрешение конфликтов ресурсов, перечислены в README плагина. Приёмка в Figma ожидается.

**Задача:** собрать все миссии так, чтобы рядом были видны иконка, последовательность её экранов и соответствующие инструкции. Текст редактируется прямо в Figma, ассет можно заменить, пробелы видны сразу. За основу берём присланную компоновку, без оформления игрового стенда.

## 1. Как устроен присланный файл

[Исходный макет, узел 1:10663](https://www.figma.com/design/N1Z1xwnG25QrCqrWEVREFk/?node-id=1-10663). Проверены дерево обеих страниц, тексты, Auto Layout и снимок основной миссии.

На **Page 1** один корневой фрейм «МИССИЯ 1 - стать блогером», 6926 × 3326. Это шаблон одной миссии, а не готовый комплект шести. На **Page 2** находятся отдельные пробы компоновки и копия блогера `2:12307` с теми же семью этапами; новых миссий там нет.

Иерархия основного фрейма:

```text
Миссия — горизонтальный Auto Layout
├── Игровая иконка MAX
├── Иконка_задание: канал
│   ├── Игровая иконка / название
│   └── Задание миссии — вертикальный список
│       ├── Этап: экран слева + инструкция справа
│       ├── Этап: экран слева + инструкция справа
│       └── Этап: экран слева + инструкция справа
├── Иконка_задание: общение с подписчиками — 2 этапа
└── Иконка_задание: статистика — 2 этапа
```

**Два направления чтения:** слева направо — возможности миссии; сверху вниз — экраны конкретного задания. Название возможности находится слева от её столбца экранов, на уровне первого этапа. Справка центрируется по вертикали относительно своего экрана.

| Элемент | Фактические параметры |
|---|---|
| Между блоками миссии | 225 px |
| Плашка игровой иконки | Ширина 512 px; высота по тексту: примерно 210 или 277 px |
| Между плашкой и столбцом этапов | 78 px |
| Между этапами по вертикали | 100 px |
| Карточка этапа | 1323 × 1042 px, внутренние отступы 60 px по бокам и 41 px сверху/снизу |
| Область экрана | 520 × 960 px |
| Между экраном и справкой | 48 px |
| Справка | Ширина 635 px, высота по содержимому; Inter Regular 32 px |
| Название игровой иконки | Inter Regular, примерно 55 px |

Это размеры **редакторской карты Figma**, не требование к масштабу игры или физическому экрану стенда.

### Что заполнено и что нельзя принять за готовый сценарий

| Блок | Узел | Фактическое наполнение |
|---|---|---|
| MAX | `1:10664` | Только текстовая плашка; графического знака внутри нет |
| Канал | `1:10666` | 3 этапа: «Чаты», «Начать общение», пустой экран |
| Общение с подписчиками | `2:5791` | 2 пустых экрана; обе инструкции — «текст» |
| Статистика | `2:6918` | 2 пустых экрана; обе инструкции — «текст» |

Всего 7 карточек этапов, из них 2 с интерфейсом. Плашки возможностей пока содержат названия, без пиктограмм. Заполненные интерфейсы — вложенные фреймы `1:47469` и `1:46967`, состоящие из текстов, экземпляров компонентов и изображений, а не единые PNG.

На втором экране канала уже стоит справка «Поздравляем! Задание выполнено, открываем следующую возможность», хотя в интерфейсе ещё предлагается создать канал. Это содержательное несоответствие: использовать геометрию шаблона, а инструкции и переходы брать из актуального каталога. Три карточки канала в примере не заменяют его полную публичную/приватную последовательность.

## 2. Что должен собирать плагин

Одна страница **«MAX · Контент миссий»**. На ней шесть отдельных секций миссий, одна под другой, с промежутком 240 px. Высоту каждой секции определяет самый длинный столбец. Внутри сохраняется авторская схема выше.

Для каждой миссии:

1. Название миссии, отметка «тест» при необходимости, краткая отметка о недостающих материалах.
2. Плашка MAX и блоки заданий слева направо в порядке каталога.
3. В каждом блоке — название и пиктограмма возможности, затем все её этапы сверху вниз.
4. Один этап — исходный экран и только относящаяся к нему инструкция справа по центру.
5. В конце миссии — отдельный компактный блок результата: финальный текст и соответствующий QR.

Белые рабочие карточки, простой текст, свободные отступы. Не добавлять фон стенда, неон, линки, анимации, повторяющиеся надписи «Возможности MAX», декоративные корпуса устройств и большие панели статусов. Начало с ладонью и раскладки вокруг/в линию не дублировать для каждой миссии в этой карте контента; это отдельная задача сборки игровых композиций.

Видимые названия — человеческие. Технические IDs хранятся в метаданных и доступны в панели выбранного элемента, не занимая место возле каждого экрана.

### Экраны, тексты и действия

- **Экран:** сохранять пропорции и полный кадр. Для телефона базовая область 520 × 960; горизонтальный PC-экран получает собственную широкую область по пропорциям ассета, увеличивая ширину блока. Не вписывать PC в узкий телефон и не обрезать важный интерфейс.
- **Редактируемый оригинал Figma:** при наличии сопоставленного исходного узла копировать его с вложенными слоями; не растрировать автоматически. Если доступен только PNG/SVG, использовать этот ресурс и честно сохранять ограничение его редактируемости.
- **Инструкция:** отдельный TextNode с автоматической высотой. Не запекать в картинку; не добавлять дублирующий заголовок. Если инструкция отсутствует по сценарию, справочную плашку не создавать.
- **Действие:** hotspot поверх нужной кнопки исходного экрана либо одна кнопка под изображением в области устройства. Варианты ответа допускают несколько кнопок. Справа — только информация. Hotspot можно выделить при редактировании, постоянные стрелки и счётчики не нужны.
- **Сюжет ID:** первый кадр с «Далее», второй — с действием соответствующего сюжета, например «Заселиться через ID». Надпись кнопки — отдельный редактируемый текст. Правка интерфейса в лапах Мишки остаётся отложенной.
- **Ветвления:** общее начало один раз, затем подписанные подстолбцы «Публичный» и «Приватный» внутри задания; общий последующий экран снова один раз. Порядок и объединение задаются переходами каталога, не сортировкой имён файлов. Это схема веток, а не требование пройти обе.
- **Пробел:** вместо пустого белого экрана — спокойная плашка «Нет материала: …» с конкретной причиной. Конфликтный ассет не выдавать за утверждённый. Такое состояние не означает выполнение задания.

## 3. Источник данных и связь с игрой

Плагин получает подготовленный пакет из общего каталога, а не извлекает сценарий из старой игровой страницы. Существующие источники:

- [Каталог миссий](../../artifacts/max-game/src/content/mission-catalog.mjs) и [канала](../../artifacts/max-game/src/content/channel-catalog.mjs): порядок, тексты, действия и переходы. Текущая ревизия — `missions-20261002-v2`.
- [Актуальная подборка ассетов](../../artifacts/max-game/design/assets-selection-20261002.json): соответствия ресурсов, размеры и происхождение. Не импортировать все 303 ресурса подряд: использовать выбранные для экранов и нужные иконки/QR.
- [Клиентские требования](../../apps/max-game/docs/MISSIONS.md): смысловые ограничения и отложенные исправления.

Минимальные данные привязки:

| Уровень | Что сохранять |
|---|---|
| Комплект | Версия формата и `contentRevision` |
| Миссия | `missionId`, название, порядок заданий, признак теста, результат/QR |
| Возможность | `taskId`, название, ресурс пиктограммы, начальный экран |
| Этап | `screenId`, `assetId`, тип устройства, инструкция, причина пробела |
| Действие | `actionId`, подпись, расположение / координаты hotspot, переход из каталога |
| Figma-привязка | Node ID, роль слоя, исходный Figma-узел при наличии, значения последней сборки |

Роль различает экран, инструкцию, название и действие. Один `taskId` может встречаться в разных миссиях: экземпляр определяется парой `missionId + taskId`, а экран — с добавлением `screenId`. Переименование слоёв не должно ломать привязки.

Пакет для нативного плагина должен содержать доступные ресурсы: подготовленные байты/изображения или сопоставленные узлы Figma. Абсолютные пути диска из локального реестра сами по себе недоступны плагину и не являются способом передачи ассетов.

## 4. Минимальная панель плагина и сохранность правок

Основная панель: **загрузить пакет → выбрать миссии (по умолчанию все) → «Собрать / обновить»**. Рядом одна команда **«Скачать правки JSON»**. Без настройки тем, анимаций и размеров стенда. Подробности выбранного элемента показывать только по необходимости.

Обновление ищет существующие блоки по IDs и меняет их на месте. Не пересоздавать страницу: так сохраняются ручные правки и привязки комментариев. Если и каталог, и пользователь изменили один текст/ассет после прошлой сборки, не перезаписывать молча: показать конфликт и оставить пользовательский вариант до выбора. Удалённые из сценария блоки вынести в явно помеченную область «Вне текущего сценария», а не уничтожать вместе с комментариями.

Экспорт — один JSON: ревизия исходного пакета, смысловые IDs, исходные и изменённые значения, Figma node IDs. Изменения внутренних слоёв интерфейса требуют отдельного экспорта ассета: текстовый JSON не содержит автоматически новую картинку. Для общего задания, изменённого по-разному в двух миссиях, отметить конфликт, не выбирать случайную копию.

Обратный перенос в игру — отдельное применение проверенных правок к общему каталогу. Перестановка карточек на холсте сама по себе не меняет правила прохождения. Плагин не записывает пользовательский игровой прогресс.

## 5. Готовность первой реализации

- Шесть миссий читаются по одной схеме: возможности по горизонтали, этапы по вертикали, справка справа по центру.
- Все достижимые экраны, обе ветки канала, сюжетные пары и QR присутствуют; нет пустых необъяснённых карточек.
- Тексты можно править без раскрытия дерева вложенного смартфона; исходные редактируемые экраны сохраняют слои.
- Длинный текст и PC-ассет расширяют карточку без наложения на соседей.
- Повторная сборка не создаёт дубликатов и не затирает ручные изменения; один JSON связывает правки с каталогом.

Первый шаг будущей разработки: собрать **блогера целиком** в этой структуре и проверить удобство правок с пользователем. После принятия шаблона применить тот же сборщик к остальным пяти миссиям.
