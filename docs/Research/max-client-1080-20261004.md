# MAX Full HD: опора на действующие механизмы

04.10.2026. Узкая задача — публикация уже существующей v5 на клиентском экране 1920×1080. Новый движок, storage, анимационные solver или backend не создаются.

- Three 0.185.1 / MIT: существующий renderer, OrthographicCamera и setDrawingBufferSize. [Официальная документация](https://threejs.org/docs/pages/WebGLRenderer.html). Локальный исходник node_modules/three/src/renderers/WebGLRenderer.js подтверждает изменение buffer + viewport; не требуется второй renderer. Виртуальная сцена и CSS fit уже используются игрой. Ограничение — браузерное масштабирование требуется проверять совместно с hitzones.
- Caddy 2.11.4 / Apache-2.0: готовый file_server, handle_path и TLS. [Документация file_server](https://caddyserver.com/docs/caddyfile/directives/file_server), [репозиторий](https://github.com/caddyserver/caddy). Используем действующий опыт проекта: scripts/activate-selectel.sh, прежний DF release20260930T073539Z и его HTTPS SHA-проверку. Новый маршрут и release/current повторяют этот механизм, не добавляют свой HTTP server или auth.
- Действующий WAAPI gradient controller и автономный LumiCells reference переиспользуются без нового алгоритма. Отдельный client presentation выключает только debug chrome; стендовый общий фон не зависит от этой публикации.

Фактический результат, размеры и ограничения CUA — [технический отчёт](../../artifacts/reports/max-client-1080-20261004.md). Это публикационный адаптер к существующим механизмам, не исследование новой игровой механики.
