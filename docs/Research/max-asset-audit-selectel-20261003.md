# MAX — публикация редактора разметки на Selectel

Дата: 03.10.2026. Исследование до интеграции; этот документ не подтверждает публикацию. Область: только asset-audit и его сохранения, без запуска или открытия наружу Stand Service.

## Подтверждено существующей реализацией

`artifacts/max-game/src/asset-audit/main.mjs` загружает каталог относительно страницы, а серверную разметку через абсолютные `/api/max-asset-audit` и `/api/state`. Простого статического переноса недостаточно: URL на Selectel находится под префиксом, а локальный API мастера на удалённой машине отсутствует. Оригиналы в каталоге связаны через `../assets/`; необходимо либо сохранить это отношение, либо сформировать отдельный каталог с корректными относительными ссылками.

`server-store.mjs` уже использует закреплённый `atomically@2.1.1` (MIT), валидацию текущего каталога, SHA-ревизию, последовательную обработку и compare-and-swap. Повторно использовать этот модуль. Политика доступа и HTTP-обвязка являются интеграцией; атомарную запись заново не реализовывать. [Исследование хранения](max-asset-audit-live-20261003.md).

В проекте есть рабочий образец Selectel-доставки: `artifacts/max-game/scripts/activate-selectel.sh`, [контракт MAX](../../apps/max-game/docs/DEPLOYMENT.md), [проверенный релиз](../../artifacts/reports/max-selectel-20260930T073539Z/README.md). Это подтверждает принятый release/current/SHA/validate/reload подход, но не доказывает наличие серверного хранилища редактора. Прежний статический root игры не заменять новым редактором.

## Готовые механизмы и реальные ограничения

**Caddy 2, Apache-2.0.** Использовать уже установленную версию, зафиксировав её в отчёте перед изменением. `handle_path` удаляет совпавший префикс; `reverse_proxy` передаёт запрос отдельному loopback-сервису. Документация прямо ссылается на реальный «subfolder problem»: абсолютные ссылки приложения обходят префикс. Поэтому frontend должен знать путь API, а не надеяться на случайное переписывание ответов прокси. [handle_path](https://caddyserver.com/docs/caddyfile/directives/handle_path), [reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy), [разбор пользователей Caddy](https://caddy.community/t/the-subfolder-problem-or-why-cant-i-reverse-proxy-my-app-into-a-subfolder/8575), [лицензия](https://raw.githubusercontent.com/caddyserver/caddy/master/LICENSE).

**Готовая защита Caddy basic_auth.** Защищает страницу и API и возвращает 401 до корректных данных доступа. Директива называется `basic_auth` с 2.8.0, до этого `basicauth`; конфигурация принимает хеш, не открытый пароль. Использовать HTTPS и существующую политику доступа данного проекта, если она есть. CSRF-токен, который любой посетитель получает через GET, не заменяет авторизацию редактора. [Официальная документация](https://caddyserver.com/docs/caddyfile/directives/basic_auth).

**atomically 2.1.1, MIT.** Реализует физическую замену/очередь/fsync; `conf@15.1.0` действительно применяет atomically как зависимость. Это опыт использования для конфигураций, не доказательство корректности нового сетевого API. Библиотека не является межпроцессным lock и не объединяет правки разных людей. Нужен единственный владелец файла; существующий CAS остаётся обязательным. [Репозиторий](https://github.com/fabiospampinato/atomically), [зависимости conf](https://raw.githubusercontent.com/sindresorhus/conf/main/package.json).

## Рекомендуемая минимальная интеграция

1. Вынести только адреса API в конфигурацию страницы/сборки. Локальный режим сохраняет текущие endpoints, опубликованный использует endpoints внутри своего URL-префикса. Учесть начальную загрузку, получение токена, сохранение и повтор подключения.
2. Выделенный небольшой процесс на `127.0.0.1` предоставляет только чтение/запись разметки и выдачу токена. Хранилище — существующий bundled createAssetAuditStore. Ни `/api/state` мастера, ни управление источниками, ни игровые сессии не проксировать.
3. Отдельный каталог releases/current для статических файлов и server bundle. Постоянный JSON расположен вне releases и вне публичного file_server root; деплой его не заменяет. По последующему явному указанию пользователя локальную разметку не переносить: первая публикация создаёт пустое хранилище, существующее облачное сохраняется.
4. Защита всего редактора и его API существующим Caddy, без собственных паролей в JS. Для мутаций сохраняются same-origin/CSRF и лимит тела, методы ограничены GET/POST. Ошибки не раскрывают файловые пути или секреты. Сервис не должен слушать публичный интерфейс.
5. Не менять существующую игру и чужие Caddy routes. Валидация конфигурации перед reload; сохранить previous и конкретный способ отката. Пользовательское содержимое откатом релиза не удаляется.

## Проверка и незакрытые ограничения

Требуется фактическая проверка: открытие защищённой страницы по конечному URL; изображения/стили по правильным путям; изменение и серверное подтверждение; reload из другого клиента; конфликт старой ревизии; отклонение неавторизованной записи и неверного origin; сохранность документа после перезапуска отдельного сервиса. Сверить SHA опубликованного пакета и повторно проверить доступность прежней игры. Эти результаты записывает основной агент в artifacts/reports/.

Локальные и облачные сохранения после публикации — два отдельных документа. Автоматической двусторонней синхронизации с локальным мастером нет; не обещать её пользователю. Выбор «активен/финальный» по-прежнему хранит настройку редактора, пока игровой потребитель отдельно не подключён. Не выдавать успешный деплой редактора за включение этих правил в прохождение миссий.
