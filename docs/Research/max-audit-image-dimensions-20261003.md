# MAX asset audit: размеры изображений и повторное использование IMG

Дата: 03.10.2026. Область: загрузка оригинала в редакторе разметки. Исследование выполнено независимо от проверки конкретного браузера пользователя; подтверждённый механизм ниже не означает, что его воспроизведение уже получено.

## Вывод

Наиболее предметная гипотеза — `decode()` на повторно используемом IMG завершается для предыдущего изображения, пока новый `src` ещё загружается. Это известная проблема совместимости, описанная авторами HTML Standard в [WHATWG HTML #7680](https://github.com/whatwg/html/issues/7680). Поэтому сравнение `naturalWidth/naturalHeight` с новым каталогом может выдавать ложное несовпадение. Существующий `epoch` защищает от устаревшего вызова редактора, но не от старого current request внутри нового вызова.

Готовый механизм платформы: отдельный `new Image()` для каждой загрузки, `src` → `await decode()` → проверка размеров → замена элемента в DOM. Именно такой способ замены изображений рекомендует [MDN decode()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode). Новый элемент не содержит предыдущего изображения. Существующую проверку размеров и epoch следует сохранить. Annotorious создавать на уже проверенном новом элементе; предыдущий экземпляр уничтожать до замены. Отдельный загрузчик изображений или собственный декодер не нужны.

## Источники, версии и ограничения

| Источник | Подтверждённое содержание | Применимость и предел |
|---|---|---|
| [WHATWG HTML issue #7680, открыт 04.03.2022](https://github.com/whatwg/html/issues/7680) | `decode()` ориентируется на current request, а изменение `src` может ещё находиться в pending request. Обсуждение отмечает несовпадение поведения реализаций. | Совпадает с повторным использованием одного IMG в редакторе. Не доказывает конкретную версию Firefox пользователя и не связывает сбой с масштабом страницы. |
| [MDN HTMLImageElement.decode](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode) | Отдельное изображение декодируется до вставки/замены; API доступен в основных браузерах с января 2020. | Использовать готовый browser API. Отмена/быстрый переход всё равно требуют проверки актуальности выбранного экрана. |
| [HTML Standard, decode](https://html.spec.whatwg.org/multipage/embedded-content.html#dom-img-decode) | Описывает current request и микрозадачу перед декодированием. | Пример `src` → `decode()` сам по себе не опровергает issue #7680: обсуждение прямо касается существующего элемента с уже готовым предыдущим изображением. |
| [MDN naturalWidth](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/naturalWidth) | Значение представляет intrinsic density-corrected CSS pixels, а не универсальную проверку PNG IHDR; браузерные преобразования возможны. | Не следует автоматически объяснять любое несовпадение browser zoom. Для текущих PNG нужны фактические reported/expected/currentSrc. |
| [Mozilla #1566316](https://bugzilla.mozilla.org/show_bug.cgi?id=1566316) | Историческая проблема размеров при orientation metadata, исправлена. | К локальному `296-13546.png` не применимо: eXIf отсутствует, IHDR 682×1792; pHYs одинаков по X/Y. |
| [Mozilla #1935269](https://bugzilla.mozilla.org/show_bug.cgi?id=1935269) | Несовпадение размеров dimensionless SVG. | К PNG ассетам не применимо; не основание менять каталог. |

Browser APIs не добавляют пакетной зависимости или лицензии. Используемая библиотека аннотаций — `@annotorious/annotorious` 3.9.3, BSD-3-Clause, [репозиторий](https://github.com/annotorious/annotorious). По установленному коду `dist/annotorious.es.js` её create/destroy оборачивают и возвращают переданный IMG, не заменяют `src` и не меняют `naturalWidth/Height`.

## Дополнительный установленный дефект состояния

В текущем `src/asset-audit/main.mjs` ошибка открытия пишется через общий `status()` и остаётся после успешного открытия следующего экрана. Поэтому текст ошибки может относиться к предыдущему экрану. Нужен отдельный статус загрузки изображения, очищаемый при новой загрузке/успехе, без стирания сообщения об ошибке сохранения.

## Проверка интеграции

До объявления причины подтверждённой: проверить переключение оригиналов разных размеров, быстрое Next/Previous и закрытие при загрузке; зафиксировать URL и natural/expected размеры. После исправления проверить сохранённую рамку, отсутствие ложных ошибок и консоль. Не менять облачную разметку или каталожные размеры ради устранения сообщения. В этой исследовательской задаче frontend, runtime, данные и F не изменялись; проверку исправленной сборки фиксирует интегратор отдельно в artifacts/reports/.
