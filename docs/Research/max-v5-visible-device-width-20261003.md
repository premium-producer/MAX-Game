# MAX v5 — раскладка по видимой ширине устройства

03.10.2026. Уточнение пользователя отменяет предварительное резервирование PC из предыдущей итерации: логотип MAX занимает полноценный узкий стартовый экран.

## Готовое решение и источники

Сохраняем уже интегрированный нативный CSS Flexbox: flex:none, реальные width ячеек, gap400px; отдельная библиотека и собственный решатель раскладки не нужны. [Документация MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Flexible_box_layout/Basic_concepts) описывает использование width как исходного размера flex-элемента и запрет роста/сжатия через flex:none. Это браузерный стандарт, отдельной поставляемой лицензии пакета нет.

Существующий V5DeviceMorph использует установленную maath0.10.8 (MIT) для damp, Three.js0.185.1 (MIT) остаётся renderer. [Репозиторий](https://github.com/pmndrs/maath), [реальный опыт issue33](https://github.com/pmndrs/maath/issues/33): произвольная inOut вместо damp easing вызывала телепортации. Интерполятор и его настройки не меняем. [Предыдущий ресерч](max-v5-phone-first-20261003.md) содержит остальной контекст интеграции.

## Применение и границы

Удалён startup.rowMetrics с будущей шириной. phoneLayout передаёт нативному измерителю текущие phoneMetrics/presentedDevice; ключ кэша уже учитывает ширину. Имеющийся callback morph.resize обновляет presentedDevice и цели ряда в том же цикле. Цели следуют краям оболочки, фактические иконки сохраняют штатную инерцию IconMotion. Высота800 и центр устройства сохраняются.

CPU проверяет реальные controller/backend/morph и контракт измеренных центров, но не запускает браузерный Flexbox или GPU. Визуальная плавность требует пользовательской оценки. [Фактическая проверка](../../artifacts/reports/max-v5-visible-device-width-20261003.md).
