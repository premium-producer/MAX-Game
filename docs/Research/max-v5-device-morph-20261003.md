# MAX v5: постоянная оболочка телефона и PC

Требование: одинаковая высота, гашение только содержимого, изменение ширины, появление нового содержимого после подготовки. Backend и фон не меняются.

## Проверенные источники и решение

- Установленный `maath@0.10.8`, MIT: установленный пакет и его easing `damp` и сохраняемая скорость. [Репозиторий](https://github.com/pmndrs/maath), [практическое обсуждение damp3, epsilon и smoothTime #33](https://github.com/pmndrs/maath/issues/33). Текущий upstream переименован в math; API новой ветки не переносится автоматически в установленную версию. Используем уже существующий адаптер V5MotionValue и фактический damp 0.10.8 для ширины и прозрачности, без своего интерполятора.
- `three@0.185.1`, MIT: [Object3D.scale](https://threejs.org/docs/pages/Object3D.html). Существующий renderer масштабирует сохранённую группу по DOM bounds; применяем этот механизм к ширине, высота постоянна. Во время движения не вызываем refreshPart: исключаем создание CanvasTexture для каждой промежуточной ширины. Обновление содержимого выполняется один раз при скрытом изображении.
- Существующее приложение подтверждает GPU upload отдельным gpuReadyKey. Это используется как граница появления после decode, а не предположение, что создание текстуры означает её готовность.

## Ограничения и интеграция

Готовые библиотеки реализуют damping и GPU transform; прикладной порядок out → resize → ready → in остаётся адаптером сценария. Логическая высота 800; PC сохраняет прежнюю пропорцию 688/560, ширина 982.857. Исходные изображения и проценты hotspots не изменяются. В промежуточных кадрах масштабируется имеющаяся текстура оболочки; радиусы и ореол по X временно растягиваются вместе с ней. Конечная оболочка перерисовывается в точных размерах. Художественная допустимость этого перехода требует пользовательской оценки, CPU-тест её не доказывает.
