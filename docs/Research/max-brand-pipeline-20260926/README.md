# Брендбук MAX: проверка экспорта и рабочий пайплайн

Дата: 26.09.2026. Основание — фактический пользовательский [экспорт MAX](../../../artifacts/DESIGN/figma-exports/MAX%20-%202026-09-26_17-35-42/), локальные шрифты и код экспортера. Это практическая проверка подхода из [исследования брендбуков и агентов с 23 внешними источниками](../brand-agent-research-20260926/README.md). Нового пользовательского исследования с участниками здесь не проводилось.

## Вывод

Экспорт пригоден для анализа и подготовки рабочих материалов. Все 40 выбранных фреймов завершены, все 1264 файла из серверного inventory совпадают по размеру и SHA-256. Полные SVG, тексты, координаты и исходные свойства позволяют восстановить недостающие отдельные ассеты. Повреждений сохранённых файлов не обнаружено.

Использовать весь экспорт как ежедневный контекст агента неудобно: 807 МиБ, 1091 SVG, атлас 51 МиБ и множество технических слоёв. Рабочая схема — неизменяемый экспорт → компактный индекс → проверенные правила и небольшой набор ассетов → задача вёрстки → проверка результата.

Схема проверена на реальном [пакете MAX](../../../artifacts/DESIGN/BRANDS/MAX/README.md): пять SVG, пять WOFF2, пять цветов, Main с тремя остановками, 41 правило с источниками, два проектных скилла и [HTML-образец](../../../artifacts/DESIGN/BRANDS/MAX/proof.html). Пакет около 0,55 МиБ, без копии тяжёлых PDF/атласа. Это полезный стартовый комплект, а не завершённая дизайн-система MAX.

### Предупреждения

52 предупреждения `asset-svg` распределены так: 2.1 — 1, 3.3 — 3, 3.5 — 2, 3.6 — 39, 4.2 — 6, 5.4 — 1. Сообщение: `Failed to export node. This node may not have any visible layers.`

Среди этих узлов 12 масок; остальные — отдельные векторы, фигуры, boolean-операции и один frame. Следовательно, одинаковая ошибка не доказывает потерю нужного логотипа и не должна останавливать весь экспорт. Но и считать все предупреждения безвредными нельзя: важность определяется ролью конкретного узла. Полные PDF/SVG/превью этих фреймов сохранены. Для отобранных ассетов проверены самостоятельные SVG и их отображение.

### PDF действительно полезен, но JSON лучше для правил

Все 40 PDF открываются, каждый содержит одну страницу 1920×1080. У пяти выборочно проверенных PDF (1.4, 2.2, 2.3, 4.1, 4.2) есть извлекаемый текст и шрифтовые объекты. Поэтому утверждение «весь текст превратился в контуры» к этому экспорту неприменимо.

Однако PDF-экстракция даёт разрывы слов наподобие «Моно хромный». Для анализа использовать оригинальные строки из texts.json/атласа; PDF оставлять для просмотра и обмена. Наличие текстовых объектов не гарантирует удобного редактирования страницы в любом PDF-редакторе. Редактирование PDF в стороннем приложении не проверялось.

Просмотрены превью всех 40 фреймов и рендер PDF страницы 1.4. Проверка SHA подтверждает сохранность выгруженного, а не визуальную идентичность живому Figma. Сопоставления каждого пикселя с исходным документом не проводилось.

## Что мешает работать напрямую

### 1. Выборка закончилась, брендбук — нет

Получены главы 1–5: логотип, цвет, графика, шрифт и вёрстка. В оглавлении перечислены также маскот (6.1–6.17) и 3D-графика (7.1–7.5), но их фреймов в выборке нет. Для этих задач потребуются дополнительные материалы. Нельзя ставить флаг «бренд полностью разобран» по одному `state=complete`.

### 2. Отдельные SVG не равны готовой библиотеке ассетов

Цельная группа основного логотипа называется `Max`. Эвристика экспортера по словам logo/логотип/icon/икон/brand/бренд её не выбирает. Получаются отдельный Icon и части надписи, а не удобный файл полного логотипа.

В пилоте три полных логотипа извлечены из групп Max/Max_2 полных SVG страниц. Сохранены контекст предков, clipPath, градиенты, фильтры и исходные координаты; viewBox взят из bounds узла. Два отдельных знака скопированы из готовых ассетов. Перерисовка не требовалась.

`id` внутри SVG — имя слоя, не надёжный Figma nodeId. В curation.json отдельно записаны frameId, nodeId и svgId, сопоставленные вручную. Для следующих экспортов нужна явная карта этих идентификаторов или возможность выбирать корни ассетов в плагине.

### 3. Брендбук содержит противоречия

| Место | Проблема | Решение пилота |
|---|---|---|
| 2.2, «Синий гигант» | HEX #471AFF; RGB 26 75 255 и Figma-заливка соответствуют примерно #1A4BFF | Правило conflict; синяя переменная и зависимые дополнительные градиенты не выпускаются |
| 1.4, охранное поле | В тексте X — высота знака, на схеме высота равна 8x | Не переносить множитель буквально; хранить конфликт и различать поле макета/логотипа |
| 2.3, Main | Видимая подпись указывает крайние цвета, но в заливке три stops | Сохранён средний #5B33FF на позиции 0,504807710647583 |
| 2.4–2.8, фоны | Main, Angular и Spotlight — разные конструкции | Линейный CSS Main не объявляется реализацией Angular |
| 2.8–2.9, запрет циана | Запрет связан с тёмным Spotlight; в других фирменных примерах циан присутствует | Не распространять запрет на всю палитру и все композиции |

RGB/HEX используются для веб-пилота. Печатная палитра, CMYK/Pantone/RAL и цветопроба не валидировались.

### 4. Примеры легко принять за правила

В атласе много Max Sans Medium, потому что этим начертанием оформлен сам гайд. Это не означает «весь продукт Medium». Текст предписывает Regular для больших объёмов информации, Medium для подзаголовков и DemiBold для заголовков.

Страницы «Ошибки» содержат намеренно неправильные композиции. SF Pro/Roboto встречаются в примерах интерфейсов и не становятся фирменными шрифтами. Формула размера CTA относится к коммуникационным макетам, а не к каждой кнопке мобильного приложения. Эти различия должны храниться в scope правил и учитываться скиллом.

### 5. Ссылки не содержат самих материалов

Есть ссылки на [логотипы](https://cloud.mail.ru/public/FuA3/dh3yNdtuy), [шрифты](https://cloud.mail.ru/public/PvJS/HQRTcJL9N), [анимации](https://cloud.mail.ru/public/EAM3/wg9qUK3YK), [AE-сборку](https://cloud.mail.ru/public/EWic/4HW7WCgiB) и компоненты вне выборки. Это ссылки из исходника, а не проверенные нами внешние наборы: веб-инструмент не смог открыть четыре Cloud Mail страницы. Это не доказательство, что ссылки не работают у пользователя.

Для пилота внешнее скачивание не понадобилось: локальная папка `BRANDS/Fonts/Max Sans` уже содержит шрифты, логотипы восстановлены из SVG. Анимации и AE-содержимое остаются за пределами пакета.

## Что готово и насколько сложно повторить

| Материал | Готовность | Что потребовалось |
|---|---|---|
| Тексты, страницы, ссылки | Готов компактный индекс | Автоматическая обработка JSON, проверка UTF-16 диапазонов |
| Три полных логотипа и два знака | Рабочие локальные SVG | Ручной выбор правильных вариантов; извлечение с зависимостями; короткий просмотр |
| Max Sans | Пять локальных WOFF2 и @font-face | Найти уже предоставленные файлы; сверить family/style/weight по TTF; сохранить происхождение |
| Палитра | Пять цветов готовы, один конфликт | Сверка подписей, RGB, заливок и ролей |
| Main | Три stops, CSS и структурированные токены | Проверка реальной заливки, направления и средней остановки |
| Правила | 39 подтверждённых источником + 2 конфликта | Семантическая ручная работа с текстом и схемами |
| Angular, Glass | Только разобранные требования | Нужен отдельный перенос эффектов и визуальное сравнение |
| Маскот, 3D, motion | Не готовы | Нет нужных глав/внешних исходников |
| Общий UI-kit | Не создавался | Брендбук коммуникаций не задаёт компоненты, состояния и адаптивность приложения |

Автоматизировать проверку файлов и повторную сборку просто. Самая существенная работа — отбор норм, определение их области действия и разбор противоречий. Пилот не даёт основания обещать «любой брендбук за пять минут»; трудоёмкость зависит от структуры следующего источника. Уже подготовленный пакет повторно собирается одной командой без повторного извлечения правил.

Для следующего бренда — соседний каталог с тем же минимальным контрактом; необязательные sections добавлять по реальной потребности. Оригиналы остаются отдельно, package ссылается на них проектным относительным путём и хешем. Для переноса **только рабочего набора** хватает MAX/assets и tokens плюс документация; для повторной проверки происхождения нужен исходный экспорт и указанные локальные источники шрифтов.

В приложении выбирать пакет явно, копировать нужные ресурсы штатной сборкой, фиксировать используемую версию. Не давать runtime читать весь архив и не делать глобальное правило «все экраны проекта оформлять MAX». Интеграция MAX в Viewer/Ribbon/Video Wall в этой задаче не выполнялась.

## Повторяемый процесс для следующих брендбуков

1. **Получить снимок.** Фреймы с понятным порядком и именами, export/atlas/texts, SVG/PNG, при необходимости PDF. Записать, какие разделы выбраны, и сохранить оригинал.
2. **Проверить транспорт и комплектность.** Инспектор сверяет файлы и индексы, затем агент сопоставляет оглавление с полученными разделами и разбирает warnings. Нулевая ошибка хешей не закрывает вопрос смысловой полноты.
3. **Построить навигацию.** Компактный source-index сначала, отдельная страница и её nodes только по запросу. Статический контактный лист полезен для первичного обзора; тяжёлые браузерные проходы не нужны.
4. **Извлечь требования с доказательствами.** Для каждого — scope, исходный узел, цитата, статус explicit/inferred/conflict через basis/status. Не смешивать правила бренда, решения текущего приложения и технические ограничения носителя.
5. **Подготовить ассеты и токены.** Сначала небольшой востребованный набор. Отдельно фиксировать ручное сопоставление SVG-групп, названия вариантов, допустимый фон и источники шрифтов. Противоречия исключать из готовых значений, не угадывать.
6. **Собрать и проверить.** Воспроизводимая сборка из curation, хеши, проверка ссылок и небольшой реальный образец. Проверить, что файл можно подключить в вёрстке и он не зависит от внешнего Temp/Downloads.
7. **Дать агенту процедуру.** Общий skill отвечает за ingest; брендовый — за выбор ресурсов, применение правил и review. Полные данные остаются в пакете, а не дублируются в длинном SKILL.md.
8. **Применить к отдельной задаче.** Агент читает только нужные правила/ассеты, делает вёрстку, проверяет источник спорных решений и сдаёт с указанием ограничений. Последующая художественная оценка относится к конкретному макету.
9. **Обновлять по изменившемуся источнику.** Новый экспорт — новая ревизия; сравнить затронутые правила/ассеты, затем обновить curation и пакет. Автоматический semantic diff и система релизов пока не реализованы.

Команды и способ просмотра приведены в [README MAX](../../../artifacts/DESIGN/BRANDS/MAX/README.md). `inspect_export.py` работает с Frame Archive schema v2. `prepare_brand.py` — ограниченный подготовщик текущей схемы, а не универсальный парсер любых PDF: он ожидает явные selections, HEX-подписи, шрифты и определённый тип градиента. Для другого устройства брендбука нужны соответствующие преобразования.

## Что улучшить в экспортере следующим

Приоритеты получены из этого примера; ниже предложения, а не уже внедрённые функции.

1. **Явный выбор корня ассета и карта nodeId → SVG.** Сохранять целый логотип/компонент независимо от названия Max/Brand/Logo. Иначе агент тратит время на восстановление групп.
2. **Компактный index рядом с полным atlas.** Страницы, заголовки, тексты, ссылки, warnings, font inventory; геометрию читать отдельно по фрейму. Пилот уже создаёт индекс после экспорта, сам плагин пока нет.
3. **Сводка полноты и зависимостей.** Выбранные разделы, ссылки на невошедшие nodes, внешние файлы, исходный file key/revision при доступности. Ссылку не отмечать как скачанный материал.
4. **Понятные предупреждения по роли узла.** Маска/внутренний слой/целый запрошенный ассет; рядом доступность полного SVG и действие для пользователя. Не приравнивать optional warning к неудаче всей страницы.
5. **Настраиваемый PDF.** Для анализа основными сделать JSON/SVG/preview; PDF оставлять опцией для архивного просмотра/передачи. В этом наборе на него приходится 80% места. Не превращать всё в растр ради размера и не тратить первую итерацию на дедупликацию 197 КиБ.

Сервер, продолжение очереди и UI экспортера в этой задаче не менялись. Проверен готовый результат, а не новый экспорт внутри Figma.

## Проверки и границы результата

[Технический отчёт](../../../artifacts/reports/max-brand-pilot-20260926/README.md) содержит audit JSON, PDF/font checks и итоговую верификацию. Проверены hashes, связи индексов, диапазоны rich text, PDF parsing, извлечение SVG, исходники правил, загрузка ресурсов в одной вкладке localhost и воспроизводимость сборки. Отрицательные тесты включают повреждение файла, незавершённый экспорт, потерю SVG definitions и внешнюю зависимость.

Готовность инструментов и пакета не означает готовности всех возможных MAX-макетов. Открыты: спорный синий и единица монохромного охранного поля; перенос Angular/Glass; недостающие главы/анимации; практическая проверка процедуры на втором бренде; интеграция в конкретное приложение.
