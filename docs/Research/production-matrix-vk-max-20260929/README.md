# Обновление production-матрицы: VK Видео + MAX

29.09.2026. [Клиентский оригинал](../../../artifacts/client-input/production-matrix-vk-max-20260929/README.md) · [сценарий обеих веток](STAND_SCENARIO.md) · [точное извлечение](source-data.json) · [сравнение данных](changes.json).

## Что изменилось

Добавлены **10 состояний MAX**, ID 21–30, строки Excel 23–32. Все 14 полей каждого из прежних ID 1–20, включая описания, триггеры, звук, владельцев и статусы, **совпадают** с предыдущей книгой. Удалённых состояний нет. Лист `Lists` также совпадает.

Теперь книга описывает две ветки:

- VK Видео: AI-стела → арка → Discovery → медиалента → стена VK Видео.
- MAX: диалог на стеле → пульсация → передача метаданных → персональная миссия на экране → игра → успех → предложение действовать в настоящем MAX → QR/выход.

Маршрут MAX через арку, Discovery или ленту **не задан**: строка 25 говорит о движении «по системе к экрану MAX». Нельзя автоматически запускать тот же художественный маршрут, что для VK Видео.

## Discovery и текущие решения

В E11/E12 по-прежнему написано про чёрную субстанцию/объект. Сохраняется прямое уточнение пользователя: **Discovery — существующая белая сущность проекта**. В рабочем сценарии образ белый; оригинальная книга и JSON извлечения дословные. Никакого нового экрана Discovery не добавляется.

Название `Personal Orbit` в строке 21 сохранено. Оно не отменяет последних указаний пользователя и [исследования idle / magnet / motion](../vk-video-flight-motion-20260929/README.md). Нужно согласовать художественный смысл состояния с актуальной разработкой, а не возвращать старую орбитальную раскладку по одному названию.

## Что добавляется к реализации

| Область | Необходимое дополнение | Граница текущих возможностей |
|---|---|---|
| Стела | Завершение MAX-анкеты, пульсация, выпуск метаданных одной сессии | Действующий прототип содержит ветку MAX, но [передача результата на стены не реализована](../../../apps/stella-prototype/docs/SERVICE.md); голос/фото не становятся рабочими от появления строки в матрице |
| Координатор | Различать продукт и целевую зону; передать и подтвердить MAX-пакет | Прочитанный `journey-model.js` содержит только маршрут VK Видео; нельзя направлять MAX-пакет в `video-wall-left` |
| Назначение миссии | Сопоставить ответы/результат стелы с существующим mission ID | Не задано, кто вычисляет миссию: стела или экран. Рекомендация — один авторитетный результат с версией правил, без двух независимых подборов |
| Экран MAX | Loading → Ready → Start поверх существующей игры, с входящим пакетом и владельцем | Игру/четыре клиентские миссии не нужно переписывать; [существующий путь](../../../apps/max-game/docs/JOURNEY.md) начинает с локального выбора |
| Финал | После завершения назначенной миссии показать подходящий Real MAX CTA и QR | Матрица описывает одну персональную миссию, а действующая инструкция игры описывает общий финал после четырёх. Режимы нужно явно разделить или согласовать изменение; автоматически отменять прежний нельзя |
| Зоны/посетители | Привязать пришедшую сессию к свободной зоне, определить очередь | В игре есть single/two; это не готовое сопоставление посетителя стелы с человеком у экрана |
| Реальное действие | Утвердить URL/deep link каждого QR, текст и критерий успеха | Изображение QR не подтверждает сканирование или выполнение действия в приложении. Нужен обратный сигнал, если сценарий должен реагировать на скан; иначе использовать согласованный таймаут |
| Эксплуатация | Изолированный reset зоны, таймауты, повтор передачи без дублей, журнал этапов | Правила сбоя/отказа и длительности новой ветки не определены в книге |

Координаты не изменились: MAX остаётся в правом регионе задней стены 4096×1280, global X=3072 по [проектной карте](../../PROJECT_PIXELMAP.md). Новых аппаратных поверхностей книга не вводит. Дополнительные состояния могут увеличить стоимость видео/эффектов, но по числу строк нельзя пересчитать GPU-нагрузку или гарантировать 60 FPS.

## Решения, нужные до интеграции MAX

1. Видимые поверхности маршрута Metadata Run: только стела/экран или также арка/лента; точки входа/выхода.
2. Источник назначения миссии и точное соответствие результатам текущей анкеты; формат пакета и привязка к зоне/посетителю.
3. Персональный режим завершается после одной миссии или пользователь продолжает все четыре; что остаётся в самостоятельном режиме игры.
4. Назначение QR/deep link для каждой миссии, кто предоставляет ссылки; нужен ли подтверждённый факт сканирования.
5. Базовое состояние после Exit, условия повторной игры, ожидание человека и таймауты освобождения зоны.
6. Референсы и длительности пульсации, передачи, Loading/Ready/Start, успеха и QR; звуковая маршрутизация.

Это разбор входящего обновления. Код, игровые настройки, runtime, TD и публикация не менялись. [Проверка](../../../artifacts/reports/production-matrix-vk-max-20260929/README.md).
