# Крупное кирпичное поле MAX: разбор референса и подборка шейдеров

**Статус:** предварительное прочтение статичного кадра от 01.10.2026, **отменено последующим уточнением пользователя**. Это не MAX-кирпичная кладка, а дополнительная форма движущихся линий по рядам сетки на всём стенде; действующий разбор — [бегущие линии по рядам LumiCells](../grid-row-streams-20261001.md). Предложение о MAX-only шейдере и рекомендации ниже оставлены только как история первой интерпретации, **не как план внедрения**. Рабочий рендер не менялся. Исходный PNG пользователя сохранён как [reference.png](reference.png), 538×533, SHA-256 `da4b9bdae7123aea4787c9b80b2955844431c38969b01f3f3c7c0fc30d43e50a`; один кадр не доказывает направление/скорость движения.

## Что видно в кадре

- Четыре горизонтальных ряда. Главные границы проходят примерно по Y=135, 270 и 405 px, то есть ряд занимает около четверти высоты.
- Вертикальные швы не образуют сквозных колонок: в верхнем ряду виден шов около X=90, в третьем около X=245; в двух остальных рядах шов вне кадра. Для воспроизведения нужен отдельный сдвиг и, возможно, отдельная ширина кирпича для каждого ряда.
- Прямоугольники прилегают друг к другу. Отдельного раствора, объёмной фаски, выраженного bloom или зазора между ними не видно. Резкая граница — часть композиции.
- Цвет **локален для кирпича**: на верхнем длинном участке фиолетовый темнеет к правому краю, на третьем правом участке яркий фиолетовый переходит в сине-фиолетовый, нижний участок синее слева и темнее справа. На стыках соседние градиенты могут резко менять направление и яркость. Это не один глобальный градиент, разрезанный линиями.
- Точки исходного PNG для ориентира: (20,60)≈`#7518F7`, (520,60)≈`#260E74`, (300,200)≈`#1D0B5B`, (260,330)≈`#692CFB`, (20,460)≈`#344CE0`. Это **цвета референса**, не утверждённые брендовые токены MAX.

## Рекомендуемая модель для нашего WebRender

Не переносить один готовый шейдер целиком: композиция референса проще и точнее собирается одним собственным GLSL-pass. Для каждого пикселя в **глобальной координате заднего полотна** вычислить `rowId = floor(y / rowHeight)`, затем `shiftedX = x + rowOffset[rowId] + rowMotion(rowId,time)`, `brickId = floor(shiftedX / brickWidth[rowId])`, `localUV = fract(...)`. Цветовые остановки, направление и центр градиента детерминированно задаются `brickId`/`rowId` и редактируемой MAX-палитрой; градиент вычисляется только из `localUV`. Сдвиг ряда меняет и геометрию, и его локальный UV совместно, поэтому градиент едет вместе с кирпичом. Прямые границы сглаживаются максимум на 1 физический пиксель; толстой обводки и зазора нет.

Для движения предложен **медленный независимый ход целых рядов по X**: чередующиеся направления, немного разные скорости и длины кирпичей, без деформации самих прямоугольников. Стартовый диапазон для пробы — около 0,5–1,5% ширины MAX-участка в секунду; это гипотеза для просмотра нескольких фаз, а не свойство статичного референса. Синусоидальное «качание» можно сравнить отдельно, но в точках разворота оно визуально останавливается. Слабое изменение внутреннего градиента — второй, опциональный канал движения; оно не должно заменять движение швов.

В существующей трёхступенчатой схеме разметка кирпичей и их движение относятся к модификатору/геометрии, размер/скорость/палитра — к управляемым параметрам, локальный градиент — к материалу. Действующие маски больших/малых LumiCells не следует тайно превращать в раскладку кирпичей. Чтобы сохранить контракт единого заднего экрана, MAX-вид нужно вычислять в общем домене до технического crop 3072/4096 и смешивать с нынешней VK Видео областью по существующему глобальному брендовому переходу, а не переключать материал ровно на X=3072. Это архитектурное предложение, не готовая функция.

**Минимальная следующая итерация для оценки:** отдельный режим в общем GPU-поле только для MAX-области, 4 ряда, независимые локальные двухцветные градиенты и движение швов; без bloom/фактуры/контента. Проверять полный MAX-участок, несколько соседних кирпичей, стык с VK Видео и 2–3 момента анимации. Техническая работоспособность — **не проверялась**; визуальная самопроверка реализации — **BLOCKED до прототипа**; утверждение пользователем — **ожидается**.
