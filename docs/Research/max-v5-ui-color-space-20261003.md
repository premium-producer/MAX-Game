# MAX v5: цвет UI при появлении справки

03.10.2026. Three.js 0.185.1, MIT; новый пакет не требуется.

## Подтверждённая основа

- [Three.js Color Management](https://threejs.org/manual/pages/color-management.html): ShaderMaterial обязан учитывать выходное цветовое пространство; штатный colorspace_fragment выбирает преобразование в зависимости от render destination. Промежуточные значения линейные, дисплейный вывод sRGB.
- [Реальный случай r177](https://discourse.threejs.org/t/color-management-with-shadermaterials/83893): при добавлении OutputPass автор наблюдал высветление бирюзового ShaderMaterial. Обсуждается необходимость штатных chunks для одинакового вывода напрямую и через render target. Версия отличается; API и GLSL-функции проверены в установленной 0.185.1.
- Исходник установленной Three: node_modules/three/src/renderers/shaders/ShaderChunk/colorspace_pars_fragment.glsl.js содержит sRGBTransferEOTF/OETF. Используются эти реализации, собственной формулы преобразования нет.

## Диагноз и решение

journey-webgl-ui.mjs формирует палитру surface fragment как дисплейный sRGB, но раньше выводил её без цвета-преобразования. JourneyContextGlass переключает UI на линейный RT, когда появляется instruction, затем преобразует композицию в sRGB. Результат — повторная интерпретация значений и высветление. Это совпадает с присланными таймерами и моментом появления справки.

Только для профиля v5: декодировать авторский результат встроенным sRGBTransferEOTF и применить colorspace_fragment. Прямой вывод сохраняет прежнюю палитру; промежуточный RT получает линейные значения. CanvasTexture/MeshBasicMaterial уже поддерживают этот контракт и не изменяются. Blur, alpha, анимация, фон и старые renderer-профили не перенастраиваются.

Ограничения: RGBA8 промежуточный буфер имеет конечную точность; полное совпадение каждого полупрозрачного края не обещается. Проверка реального перехода обязательна отдельно от проверки исходников и CPU. [Отчёт](../../artifacts/reports/max-v5-ui-color-space-20261003.md).
