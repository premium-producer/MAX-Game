## Суть

Общий смысл четырёх миссий — дать посетителю попробовать понятные жизненные сценарии MAX и увидеть пользу инструментов. Игровая мотивация — добиться личной цели: развить канал, воспользоваться ID, пообщаться или запустить продвижение бизнеса. Документ не задаёт спутниковую механику, пространственные связи, очки, таймер либо проигрыш.

Это позволяет трактовать замысел как интерактивное знакомство с продуктом через задания. «Познакомиться с функцией» само по себе ещё не определяет действие игрока: нужно решить, что посетитель делает руками, какой результат видит и по какому событию шаг считается выполненным.

Упоминания историй, ID, платформы и прочих возможностей фиксируют содержание клиентского материала; этот разбор не подтверждает их фактическую доступность, условия подключения или точные интерфейсы продукта на сегодня.

## Предложение игрового цикла, не требование клиента

Выбор миссии → короткая постановка цели → действие в учебном интерфейсе → понятная обратная связь → отметка шага → итог миссии и возможность попробовать следующую.

Например, для блогера можно предложить создание демонстрационного канала, выбор ответа подписчику и показ изменения статистики. Для бизнеса — выбор сферы, затем одного инструмента и демонстрация его результата. Конкретные действия, тексты, числа и последствия потребуют согласования. Это предложения для превращения сценарного текста в игру, не извлечённые из файла готовые правила.

Для выставочного MVP разумна локальная симуляция без реального аккаунта посетителя. Такой режим тоже нужно утвердить: документ не устанавливает, должны ли быть настоящие интеграции. Финальный экран может показывать достигнутую цель и изученные возможности; общий рейтинг или соревнование из источника не следуют.

## Связь с существующим MVP

Проверен текущий [missions.json](../../artifacts/max-game/public/config/missions.json): «ЕСТЬ ПИНГ!», «АРКТИКА НА СВЯЗИ», «СВЯЗЬ ДЛЯ БОЛЬШОЙ СТРАНЫ». Действия связаны с размещением оборудования и построением связного маршрута. [Локальный контекст](../../apps/max-game/docs/DEVELOPMENT.md) описывает состояние попытки, проверку связей и интеграцию в мастер.

Из действующей игры можно использовать оболочку, брендовые материалы, управление экранами и ввод с правой стены. Проверка соседства спутников не проверяет создание канала или подтверждение возраста: для клиентских сценариев нужны собственные действия, состояние шагов, ветвления и условия завершения. Простое переименование объектов не реализует описанный опыт.

Ранее пользователь выбрал космическую подачу. Новый файл сам по себе это решение не отменяет: космос может остаться визуальной метафорой. Но связь метафоры с четырьмя продуктовыми сценариями ещё предстоит спроектировать; клиентский документ её не объясняет. Приём источника и анализ не меняют текущий режим игры и архитектуру мастера.

## Что нужно определить перед реализацией

1. Конкретные действия посетителя в каждом шаге и наблюдаемый результат.
2. Состав обязательных шагов, варианты через «/», порядок примеров ID и возможность пройти несколько бизнес-веток.
3. Условия успеха, подсказки и повтор; нужны ли вообще ошибки, очки и ограничение времени.
4. Учебная симуляция или интеграция с реальным продуктом; утверждённые тексты и актуальные экраны MAX.
5. Длительность сессии, прерывание, возврат в меню и сброс для следующего посетителя.
6. Как сохранить выбранную космическую подачу так, чтобы действия объясняли возможности MAX.

Следующий полезный результат — таблица «шаг → действие → обратная связь → условие завершения» для одной выбранной миссии. Только после этого можно обоснованно переносить сценарии в конфиги и код. В этой итерации сохранён и разобран источник; сценарии и новая механика не внедрялись.
