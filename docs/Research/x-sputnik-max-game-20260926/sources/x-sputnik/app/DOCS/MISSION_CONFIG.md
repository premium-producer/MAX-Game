# Конфигурация миссий

> С 2026-09-05 активен **Mission System v2**. Точка входа — `public/config/missions/index.json`, общие настройки — `mission-system.json`, миссии — отдельные файлы. Актуальные поля, условия и редактор: [MISSION_ARCHITECTURE.md](MISSION_ARCHITECTURE.md). Описание ниже сохранено для legacy v1 и не является контрактом новой игры.

Единственный runtime-каталог миссий находится в [`public/config/missions.json`](../public/config/missions.json). Игра загружает его при старте, проверяет структуру и строит из него порядок прохождения, таймеры, цели, инвентарь, точки A/Б и карту выбора. Для добавления миссии не требуется создавать новое JavaScript-состояние.

Формальная JSON Schema для редакторов и CI: [`public/config/missions.schema.json`](../public/config/missions.schema.json).

## Поля миссии

Общие параметры оборудования хранятся в корне `missions.json`, в `objectSettings`, рядом с массивом `missions`. Они действуют во всех миссиях и сохраняются общей кнопкой редактора вместе с каталогом. Старые каталоги без блока автоматически получают прежние размеры и радиусы.

```json
"objectSettings": {
  "terminal": { "size": 1, "signalRadius": 0.46 },
  "satellite": { "size": 1, "signalRadius": 0.78, "radiusAtMinAltitude": 0.5, "radiusAtMaxAltitude": 1.2 },
  "gateway": { "size": 1, "signalRadius": 0.62 },
  "core": { "size": 1, "signalRadius": 0.56 },
  "internet": { "size": 1, "signalRadius": 0.5 },
  "endpoint:A": { "size": 1, "signalRadius": 6.5 },
  "endpoint:B": { "size": 1, "signalRadius": 6.5 }
}
```

`size` — множитель размера маркера: `1` — исходный, `1.5` — на 50% больше, `0.75` — на 25% меньше. Масштабируются иконка, ножка, платформа и область захвата; зона радиопокрытия не масштабируется. Географический якорь остаётся на прежнем месте. Размеры карточек инвентаря и слотов footer задаются интерфейсом, этот параметр относится к объектам на Земле.

`signalRadius` — радиус в единицах 3D-сцены (радиус Земли — `3`). Для спутника явные `radiusAtMinAltitude` и `radiusAtMaxAltitude` задают радиусы на высотах `0.34` и `1.4`. Между ними радиус вычисляется линейно; значение отсутствующей границы берётся из `signalRadius`. Можно задать рост или уменьшение радиуса с высотой. В рабочем JSON обе границы изначально равны `0.78`, чтобы сохранить существующий баланс; в примере выше показана растущая зависимость.

Радиусы A/Б проверяют достижимость первой/последней ноды при замыкании маршрута и в условиях цепочек с `endpoint:A/B`. Начальное значение `6.5` сохраняет прежнюю доступность конечных точек; уменьшение делает положение терминалов относительно A/Б значимым. Визуальные кольца основания A/Б остаются оформлением платформы, а не изображением зоны радиопокрытия. Наземный линк Б → A появляется после успешной сборки и не проверяется как радиоканал.

Изменения исходного JSON применяются после `npm run build` и обновления страницы. После редактирования файла обновите также открытую вкладку редактора, чтобы она прочитала актуальные параметры перед следующей записью.

### Объекты экрана выбора миссий

Самостоятельные 3D-объекты карты хранятся в `mission-system.json` в массиве `missionSelectObjects`, рядом с общим системным каталогом миссий. Они не входят в `objectTypes`, наборы оборудования или `objectSettings` и поэтому не наследуют игровые размеры, высотные ограничения и расчёт радиуса спутника.

Текущий `mission-hub-satellite` имеет `kind: "orbital-signal"`, ссылку на SVG из общего банка `icons`, географические `latitude/longitude/altitude`, собственные `size` и постоянный `signalRadius`. Его авторская позиция `68.25 / 175.35 / 1.4` выводит центр правее третьей карточки, сохраняя прежний экранный уровень в целевом ракурсе выбора миссий. `signalMode: "always"` включает синие волны при любом прогрессе, а `successWhen: "all-missions-completed"` переводит объект в зелёный state только после завершения всех миссий. Renderer создаёт его отдельной неинтерактивной фабрикой; `createNode`, drag, route и collision/coverage логика миссии не используются.

- `number` — уникальный положительный номер; миссии сортируются по нему.
- `id` — уникальный стабильный строковый идентификатор.
- `name` — название.
- `description` — текст задания на игровом экране.
- `timeSeconds` — длительность миссии в секундах.
- `mapPosition.latitude/longitude` — географическая точка WebGL-платформы миссии на поверхности Земли. От платформы вверх идёт экранно-вертикальная ножка к DOM-карточке; вся конструкция следует за Землёй при вращении, а размер карточки не сдвигает географический якорь.
- `endpoints` — словарь произвольного числа фиксированных точек миссии. `roles: ["start"]` включает точку в группу возможных начал, `roles: ["finish"]` — в группу завершений; обе роли допустимы одновременно. У пути `endpointSelection.from/to` выбирает область кандидатов: `specific` — только точка из `from/to`, `anyRole` — любая точка соответствующей роли. Отдельный `endpointSignals.from/to` задаёт их активацию: `nearest` оставляет только ближайшую к крайнему объекту маршрута точку, `parallel` разрешает сигнал от всех точек в радиусе. У каждой точки обязательна `icon` из банка `system.pointIcons`; также задаются широта/долгота, размер и радиус. Отдельные текстовые подписи точек не отображаются. Старые A/Б остаются обычными совместимыми ID и при загрузке мигрируют на банковские `point-a/point-b`, а не образуют второй тип сущности.
- `connectEndpointsOnComplete` — если `true`, после полной корректной сборки WebGL-маршрут получает зелёные линки `A → первая нода`, `последняя нода → Б` и наземное замыкание `Б → A`. В текущем каталоге это включено для миссий №1 и №3.
- `route` — единственная правильная последовательность объектов.
- `objectives` — подзадачи с машинно проверяемыми условиями.
- `successText` — сообщение после правильной сборки.
- `unlock.requiresCompleted` — номера миссий, которые нужно выполнить для разблокировки.

Статус не записывается в JSON как константа, потому что зависит от прогресса игрока. Runtime вычисляет одно из трёх значений:

- `locked` / «закрыта» — выполнены не все номера из `unlock.requiresCompleted`;
- `open` / «открыта» — зависимости выполнены, миссию можно запустить;
- `completed` / «выполнена» — номер миссии записан в прогресс текущей сессии.

Допустимые типы объектов: `terminal`, `satellite`, `gateway`, `core`, `internet`.

## Условия подзадач

- `{ "type": "placed", "object": "terminal", "count": 1 }` — размещено нужное количество объектов.
- `{ "type": "adjacent", "first": "terminal", "second": "satellite", "count": 1 }` — в текущей пространственной последовательности слева направо есть нужная соседняя пара. Последовательность пересчитывается после перемещения объектов и не зависит от порядка их добавления.
- `{ "type": "connectedSequence", "sequence": ["endpoint:A", "terminal", "satellite", "satellite", "satellite"] }` — непрерывная цепочка активных объектов в указанном порядке; все соседние объекты должны иметь допустимые линки с пересечением радиусов сигнала. Необязательная `endpoint:A` в начале закрепляет цепочку за левым краем маршрута, `endpoint:B` в конце — за правым. Концевые линки A/Б по-прежнему появляются после полной сборки; условие не требует их заранее. Для восточной части миссии 3: `["satellite", "satellite", "satellite", "terminal", "endpoint:B"]`. В редакторе это условие «Цепочка соединена»; состав вводится через запятую.
- `{ "type": "allPlaced" }` — размещены все элементы маршрута.
- `{ "type": "routeCorrect" }` — вся последовательность совпадает с `route`.
- `{ "type": "networkConnected" }` — правильная цепочка физически соединена пересекающимися зонами сигнала.

## Шаблон новой миссии

```json
{
  "number": 4,
  "id": "new-route",
  "name": "НОВЫЙ МАРШРУТ",
  "description": "Описание игровой задачи.",
  "timeSeconds": 180,
  "mapPosition": { "latitude": 61, "longitude": 90 },
  "endpoints": {
    "A": { "label": "A", "latitude": 60, "longitude": 40 },
    "B": { "label": "Б", "latitude": 65, "longitude": 150 }
  },
  "connectEndpointsOnComplete": true,
  "route": ["terminal", "satellite", "gateway", "core", "internet"],
  "objectives": [
    {
      "id": "place-terminal",
      "label": "размести терминал",
      "condition": { "type": "placed", "object": "terminal", "count": 1 }
    },
    {
      "id": "finish-network",
      "label": "собери связанную сеть",
      "condition": { "type": "networkConnected" }
    }
  ],
  "successText": "МАРШРУТ РАБОТАЕТ",
  "unlock": { "requiresCompleted": [3] }
}
```

После изменения выполнить `npm run check`, `npm test`, `npm run build` и `npm run portable:check`. Невалидный каталог не запускает игру и показывает понятную ошибку конфигурации.

## Допустимая поверхность оборудования

`system.objectTypes.<id>.placementSurface` задаёт `land`, `water` или `any`. Если поле отсутствует, parser подставляет `land` для ground и `any` для orbital. Банк объектов показывает поле «Допустимая поверхность»; сохранение/локализация сохраняют его. При смене поведения банк ставит соответствующее правило по умолчанию. Фиксированные endpoints и объекты меню этим полем не ограничиваются.

PLACE/MOVE проверяют нормализованные координаты якоря по отдельной CPU-маске. Непринятая операция оставляет состояние без изменений; preview не создаёт связи к запрещённому кандидату. Тестовый режим редактора использует те же правила. Подробности маски и ошибки после отката — [NEW-013](LAND_PLACEMENT_RESEARCH.md).
