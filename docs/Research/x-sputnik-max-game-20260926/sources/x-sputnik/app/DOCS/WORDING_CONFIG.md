# Единый wording и локализация

Весь текст, который видит игрок, хранится в одном runtime-документе: [`public/config/wording.json`](../public/config/wording.json). HTML, JavaScript и конфиги миссий больше не являются источниками отображаемых фраз: они обращаются к словарю по стабильным семантическим ключам.

Редакторский и типографический house style для RU/EN, включая висячие предлоги, неразрывные конструкции и переносы, зафиксирован в [`COPY_EDITING_AND_TYPOGRAPHY_RESEARCH.md`](./COPY_EDITING_AND_TYPOGRAPHY_RESEARCH.md). Согласованные термины хранятся рядом в [`COPY_GLOSSARY.json`](./COPY_GLOSSARY.json).

Формальная схема документа: [`public/config/wording.schema.json`](../public/config/wording.schema.json). Загрузчик и переводчик находятся в [`src/wording.mjs`](../src/wording.mjs).

## Формат

Каждый ключ содержит русскую и английскую фразу рядом:

```json
{
  "mission.restart": {
    "ru": "Начать миссию заново",
    "en": "Restart mission"
  }
}
```

Ключи организованы по областям интерфейса: `app.*`, `screens.*`, `onboarding.*`, `missionSelect.*`, `mission.*`, `popup.*`, `end.*`, `content.*` и `missions.*`. Названия миссий, задачи и сообщения feedback привязаны к стабильным ID сущностей, а не к их позиции в массиве.

Динамические значения задаются одинаковыми плейсхолдерами в обеих локалях:

```json
{
  "app.titleWithScreen": {
    "ru": "X-SPUTNIK — {screen}",
    "en": "X-SPUTNIK — {screen}"
  }
}
```

Загрузчик не запускает игру, если отсутствует одна из локалей, значение пустое, набор плейсхолдеров в RU и EN различается либо copy-lint находит объективную ошибку. Для HTML-разметки в словаре используются обычные переносы строк, которые runtime безопасно превращает в `<br />`; произвольный HTML в wording не нужен.

После подстановки плейсхолдеров переводчик запускает `formatTypography(text, language, profile)`. Он детерминированно связывает русские однобуквенные слова, знак `№`, проценты и единицы измерения, а также однозначные английские конструкции. URL, email, пути и code-like токены защищены от преобразований. Доступны профили `body`, `instruction`, `heading`, `button`, `badge` и `code`; если профиль явно не указан третьим аргументом `t()`, он определяется по семантическому ключу. Короткие инструкции, включая шаги онбординга и задачи миссий, используют `instruction`: он защищает также двухбуквенные служебные слова (`на`, `по`, `из`, `от` и другие), не склеивая ими длинные описания. Повторный запуск форматтера не меняет результат.

Команда `npm run copy:check` проверяет RU/EN, плейсхолдеры, пробелы, пунктуацию, `№`/`%`, HTML entities, HTML, парность скобок и кавычек, а также неизвестные статические ключи и встроенный русский player copy. Объективные нарушения завершают проверку с ошибкой; спорная длина или формулировка остаются warning и требуют решения редактора.

Player-компоненты используют классы `ui-copy-heading`, `ui-copy-body`, `ui-copy-instruction`, `ui-copy-button` и `ui-copy-badge`. Они задают `text-wrap`, перенос слов и hyphenation по типу поверхности. В режиме `?debug=1` runtime дополнительно измеряет реальные line boxes в Bureau и сообщает в консоль об overflow, висячем коротком слове или слишком короткой последней строке заголовка.

После первичного layout runtime также устраняет короткий «хвост» нового предложения в `body` и `instruction`. Если после точки на текущей визуальной строке помещается только одно или два слова следующего предложения, перед первым из них DOM-операцией вставляется безопасный перенос. При трёх и более словах строка не меняется. Правило опирается на реальные line boxes текущего компонента и не добавляет HTML в `wording.json`.

## Выбор языка

С 2026-09-08 по прямому запросу пользователя доступен только русский. Переключатель удалён из header; параметры `?lang=en` и сохранённый английский выбор игнорируются. Начальная загрузка и ошибка до получения словаря также русские. Статические надписи `data-boot-copy` / `data-boot-aria` в index.html должны совпадать с RU-значениями wording.json; это проверяет copy:check.

EN-словарь и код переключения сохранены для последующего включения; сейчас вход в переключение допускает только `ru`. Описание механизма ниже относится к сохранённой неактивной возможности.

Переключение применяется без перезагрузки и без пустой фазы: runtime сохраняет визуальную копию старых текстовых поверхностей, сразу подставляет новую локаль под ней и за `320–440 мс` выполняет одновременный crossfade со встречным сдвигом всего `3 px`. Это ровно вдвое дольше первоначального диапазона; при текущем `motion.microDurationMs = 220` фактическая длительность равна `378 мс`. Обе стороны и скользящий индикатор используют одну мягкую ease-in-out кривую `cubic-bezier(.42, 0, .2, 1)`. Суммарная непрозрачность интерфейса остаётся видимой на всём переходе; постоянные рамки, shell и WebGL вообще не исчезают. В активной миссии in-place обновляются также формулировки задач, названия оборудования, status feedback и открытый popup: cache-ключи учитывают локализованный текст отдельно от игрового прогресса. Один interrupt-safe owner последовательно обрабатывает быстрые повторные нажатия; placement, таймер, feedback-сессия, popup и WebGL-сцена не пересоздаются. При `prefers-reduced-motion` crossfade и движение индикатора отключаются. Выбор сохраняется для следующего запуска.

## Добавление текста

1. Добавить один новый семантический ключ в `wording.json` сразу с `ru` и `en`.
2. В интерфейсе вызвать `t("путь.к.ключу")`; для переносов — `wordingHtml("путь.к.ключу")`.
3. Для новой миссионной сущности использовать её ID в ветке `missions.<missionId>` или `content.*`.
4. Выполнить `npm run copy:check`, `npm test`, `npm run check`, `npm run build` и `npm run portable:check`.

Тесты проверяют полноту обеих локалей, наличие wording для всех текущих миссий, отсутствие встроенного русского текста в player runtime и существование всех статически указанных ключей `t(...)`.

Служебные страницы авторинга (`editor.html`, `earth.html`) пока остаются отдельными русскоязычными инструментами. Их подписи не показываются игроку и не входят в player wording-контракт.

## Полное и краткое описание миссии

С mission-descriptions-149 ключ `content.missions.<id>.description` задаёт полный текст справа в игровом поле; `summary` остаётся кратким описанием карточки в меню. В обоих случаях источником является wording.json. Переводы и переносы строк сохраняются при переключении языка. Короткая подпись с двоеточием в начале строки (например, «Задача:») выделяется безопасной разметкой после экранирования текста.
