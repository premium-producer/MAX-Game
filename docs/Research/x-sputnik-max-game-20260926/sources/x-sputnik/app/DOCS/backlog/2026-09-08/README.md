# Скриншоты и задачи итерации 2026-09-08

[Бэклог задач](../../BACKLOG_2026-09-08.md) · [Реестр скриншотов](SCREENSHOTS.md)

[Галерея всех страниц «Первого варианта правок» и «Финальных правок»](DOCUMENT_PAGES.md). Снимки страниц хранятся в той же папке screenshots и имеют общий REF-ID. Для них применяется имя `REF-NNN__2026-09-08__doc-first__page-001.png` либо `doc-final`; номер страницы относится к локальному рендеру. Это документационные ассеты, они не копируются в игровые public/dist.

Перед клиентской задачей смотреть страницы из её карточки и читать связанные комментарии Word в расшифровке: комментарии могут не быть видны на рендере. Старые скриншоты внутри документа не отменяют текстовую правку. Формальные названия документов — «Первый вариант правок» и «Финальные правки»; DOC06/DOC07 в именах извлечений оставлены как технические идентификаторы.

Пользователь присылает изображения в чат вместе с комментариями. Переименовывать файлы заранее и оформлять задачи ему не нужно: агент сохраняет вложения, распределяет замечания по задачам и добавляет ссылки.

## Хранение и имена

Оригинальные изображения находятся в `screenshots/`. Сохранять их без обрезки, перекодирования или удаления пользовательских пометок. Расширение должно соответствовать реальному формату файла.

Формат имени:

```text
REF-001__2026-09-08__mission-play__current.png
REF-002__2026-09-08__mission-play__target.jpg
REF-003__2026-09-08__cta__annotation.png
```

Это примеры имён, а не существующие референсы.

- `REF-001` — уникальный последовательный номер изображения внутри этой итерации; не переиспользуется и не меняется при переносе замечания в другую задачу.
- Дата — день получения изображения.
- Экран: `cta`, `onboarding`, `mission-select`, `mission-play`, `end`, `editor`, `objects`, `earth-editor`, `shared` или `unspecified`.
- Назначение: `current` — текущее состояние; `target` — желаемое; `annotation` — изображение с пометками; `result` — результат реализации; `reference` — дополнительный референс. Если назначение неясно, использовать `reference` и записать открытый вопрос.
- Оригинальное имя, язык, номер миссии и сборку, если они известны, сохранять в реестре. Не угадывать отсутствующие сведения.

Задачи используют независимые ID `NEW-001`, `NEW-002` и далее. Один скриншот может относиться к нескольким задачам; одна задача может ссылаться на несколько скриншотов. Файл при этом хранится один раз.

## Приём сообщения из чата

1. Посмотреть присланные изображения и прочитать комментарий.
2. Скопировать доступный оригинал вложения в screenshots с очередным REF-ID. Проверить наличие файла и открыть сохранённую копию.
3. Добавить запись в реестр: ссылка, дата, исходное имя, контекст, исходный комментарий, связанные NEW-ID. Для нескольких изображений явно сопоставить комментарии; неоднозначность записать вопросом.
4. Разделить независимые изменения на задачи; дополнения к существующей задаче добавить туда же, сохранив прежние комментарии и решения. Не создавать дубли.
5. В задаче дать прямые ссылки и встроенные превью, указать конкретную область изображения и требуемое изменение. Отделить наблюдаемое на скриншоте от интерпретации агента.
6. Кратко сообщить пользователю назначенные NEW-ID и REF-ID. Обновить журнал проекта.

Если вложение видно в чате, но его исходные байты или локальный файл недоступны, записать «ожидается файл», сохранить комментарий и попросить оригинал файлом либо в папку screenshots. Не создавать пустую картинку, не реконструировать её и не ставить ссылку на несуществующий файл. Задача без изображения не считается полностью оформленной, если это изображение необходимо для её реализации.

## Работа по задаче

Перед изменением кода прочитать карточку и открыть все актуальные связанные изображения инструментом просмотра. Записать в карточке просмотренные REF-ID и дату. При необходимости увеличивать нужную область для просмотра, сохраняя оригинал.

Во время реализации обращаться к изображениям при выборе геометрии, цвета, текста и поведения. Перед отчётом повторно сверить выполненные изменения с комментариями и актуальными референсами. Статичное изображение само по себе не задаёт тайминги и поведение анимации.

Результат проверки фиксировать честно: проверка кода/тестов, сравнение изображений или пользовательская приёмка. Если скриншота результата нет, не заявлять визуальное совпадение. Интерактивный browser QA выполняется только по явному запросу пользователя согласно правилам проекта.

Новый вариант получает новый REF-ID. Старый остаётся в реестре со статусом «заменён REF-…». Указывать замену только если новое сообщение действительно меняет требование, а не дополняет его.

**Комментарий пользователя · дата**
> Исходная формулировка из чата.

**Скриншоты**
- REF-001 — текущее состояние; область: …; [открыть](backlog/2026-09-08/screenshots/ИМЯ-ФАЙЛА.png).

![REF-001 — описание](backlog/2026-09-08/screenshots/ИМЯ-ФАЙЛА.png)

**Ожидаемое поведение / интерпретация**
…

**Критерии готовности**
- [ ] …

**Открытые вопросы и зависимости**
…

**Реализация и проверка**
- Референсы просмотрены: дата, REF-ID.
- Изменённые файлы / сборка: …
- Проверки и результат: …

Пути в шаблоне рассчитаны на основной файл бэклога. Заменять placeholders реальными файлами; до поступления вложений карточки и референсы не создавать.
