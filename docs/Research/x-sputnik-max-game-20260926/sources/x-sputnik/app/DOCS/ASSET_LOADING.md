# Стартовая подготовка ресурсов — NEW-001

Ресерч и реализация: 2026-09-08, сборка `startup-preparation-146`.

## Что выяснено до реализации

Скачивание файла не означает готовность к показу. `HTMLImageElement.decode()` ожидает декодирования изображения, `FontFaceSet.load()` принудительно загружает указанные начертания. Поэтому ожидание только сетевых запросов или шрифтов уже видимого CTA не покрывает остальные экраны. Источники: [MDN: decode](https://developer.mozilla.org/en-US/docs/Web/API/HTMLImageElement/decode), [MDN: FontFaceSet.load](https://developer.mozilla.org/en-US/docs/Web/API/FontFaceSet/load).

Three.js отдельно предлагает `initTexture()` для предварительной загрузки текстуры на GPU и `compileAsync()` для подготовки шейдеров, использующей KHR_parallel_shader_compile при наличии. LoadingManager отслеживает загрузчики, но не заменяет декодирование аудио/шрифтов и подготовку GPU. Источники: [WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html), [LoadingManager](https://threejs.org/docs/pages/LoadingManager.html).

Аудиофайлы можно заранее преобразовать в AudioBuffer через `decodeAudioData()`. Разрешение воспроизводить звук — отдельный этап: возобновление AudioContext остаётся на пользовательском жесте, а не становится условием готовности игры. Источники: [MDN: decodeAudioData](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext/decodeAudioData), [MDN: Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices).

Проверены API установленного `three` в node_modules, фактический код загрузчиков, каталог всех миссий, audio.json, CSS и сервер. До изменения:

- preloadAssets запускал Image-загрузки без ожидания; ссылки на изображения не удерживались.
- TextureLoader.load возвращал текстуры до завершения загрузки.
- Звук догружался по группам при переходах.
- SVG пользовательских иконок мог повторно разбираться после очистки кеша.
- Нет этапа подготовки шейдеров и постобработки.
- Локальный сервер выставляет `Cache-Control: no-store`. Простой предварительный fetch не гарантировал отсутствие повторного запроса из нового `<img>`.

## Выбранная схема

Существующие пять состояний игры сохранены. Загрузка — внешний стартовый барьер, без изменения reducer, миссий или таймеров.

1. Экран загрузки есть в исходном HTML, до исполнения bundle. Игровой stage — inert; горячие клавиши и audio unlock блокируются до готовности.
2. Загружаются и валидируются все конфигурации: индекс/система/файлы миссий, каркас, RU/EN-словарь и аудиоманифест.
3. Из каталога собирается уникальный набор иконок, UI-изображений и ресурсов Земли. Максимум четыре одновременных задания. Файлы скачиваются один раз; изображения декодируются и удерживаются в PreparedAssets, вместе с Blob URL для будущих DOM-элементов. SVG границы хранится текстом для геометрии, без ненужной растеризации второго полотна 6000×3000.
4. Ожидаются оба шрифта Bureau, затем все 21 AudioBuffer с максимум тремя одновременными заданиями. Autoplay не ожидается. При отсутствии Web Audio игра может работать без звука; повреждённый/недоступный файл требует повторной загрузки.
5. Создаётся общий renderer в приостановленном состоянии. Текстуры используют уже декодированные Image; все SVG-иконки, включая пользовательские, разбираются заранее в оба размера и сохраняются до завершения сессии.
6. initTexture загружает карты Земли; compileAsync готовит сцены Земли, bloom, композиции, occlusion и игровых объектов. Временные представители оборудования, точек, наземного маркера и линка готовят варианты материалов. Их материалы удерживаются, чтобы освобождение представителей не вытеснило программы из кеша Three.js.
7. Исполняются реальные проходы постобработки и первый кадр; WebGL fence асинхронно ожидает окончания отправленной работы. Временные объекты убираются из сцены до раскрытия игры. Они не участвуют в правилах и вводе.
8. Рендерится начальное состояние и запускается единственный существующий render loop. Открывается ввод. Последующие экраны используют те же Blob URL, AudioBuffer, текстуры и подготовленные иконки.

Прогресс — число завершённых заданий текущего этапа, а не выдуманный процент переданных байтов. До загрузки словаря — короткий английский fallback; затем выбранный RU/EN. Готовность не наступает при ошибке. Задания ограничены 60 секундами; активные задания дожидаются завершения перед очисткой. Кнопка RETRY перезагружает страницу, сбрасывая незавершённый runtime. На ошибке освобождаются подготовленные Blob URL, audio context и созданное поле.

Service Worker и постоянный отдельный кеш не добавлены: файлы небольшие, приложение работает и под вложенным URL, а кеш без согласованной стратегии версий создаёт риск смешать ресурсы разных редакций. HTTP-запросы подготовки используют revalidation; дальнейшее использование в сессии — из памяти.

## Объём и память

Инвентаризация реальных файлов через каталог, stat и ffprobe:

| Ресурсы | Количество | Размер |
| --- | ---: | ---: |
| Визуальные ресурсы, включая 9 иконок и 2 SVG-маски | 18 | ≈7.15 MiB исходных данных, включая inline SVG |
| Аудио WebM | 21 | ≈2.67 MiB |
| Bureau TTF | 2 | ≈0.35 MiB |

Каждая из пяти растровых карт Земли — 4096×2048; маска заливки — 6000×3000. Нижняя оценка декодированных RGBA-изображений этих карт — около 229 MiB. Текстуры GPU с текущими RGBA/R8 и mipmaps — около 204 MiB, без render targets, геометрии и внутренней памяти драйвера. Это расчёт форматов, не измерение RAM/VRAM процесса.

Все аудио вместе: 129.4 секунды; оценка Float32 PCM при 48 kHz с фактическим числом каналов — около 47.4 MiB. Реальная частота AudioContext может отличаться. Предзагрузка переносит эту стоимость на старт; качество и разрешение ресурсов не понижались.

## Проверки и ограничения

Автоматические тесты проверяют ограничение параллелизма, завершение активных заданий при ошибке, timeout/abort, ожидание decode, повторное использование Blob URL, полноту каталога ресурсов, отсутствие повторного аудиофетча между экранами, отсутствие требования audio unlock, ошибку файла/отсутствующий шрифт, GPU fence и входной барьер.

Для диагностики после старта доступен `window.__xSputnikStartup`: общее время, времена этапов и количество ресурсов. Данные появляются только при успешном запуске.

Интерактивный browser QA и профилирование по правилам проекта не выполнялись. Холодный старт, реальное время загрузки, пиковая память и кадры переходов проверяются на целевой машине пользователем. Новый загрузчик устраняет отложенные запросы текущих ассетов и подготавливает основные программы/проходы; он не обещает постоянные 60 FPS при любом железе, ресайзе, потере контекста или давлении на память. Динамические игровые экземпляры по-прежнему создаются штатным кодом. Новые внешние ресурсы нужно включать в collectAssetSources: неизвестный assetUrl вызывает явную ошибку вместо скрытой догрузки.

## Игровая маска поверхности — NEW-013

С `land-placement-151` стартовый этап config также загружает `Earth_Surface_4K.json` и `Earth_Surface_4K.bin`, проверяет формат/размер и SHA-256. Только затем `configurePlacementSurface` делает CPU-карту доступной reducer; отсутствующие или повреждённые данные блокируют запуск через существующий экран ошибки. Маска не GPU-текстура, не входит в PreparedAssets и не читается с canvas во время drag. Тест редактора использует тот же загрузчик. Обычная сборка копирует закреплённую маску, portable-check проверяет её целостность. Подготовка офлайн и принятые параметры — [NEW-013](LAND_PLACEMENT_RESEARCH.md).
