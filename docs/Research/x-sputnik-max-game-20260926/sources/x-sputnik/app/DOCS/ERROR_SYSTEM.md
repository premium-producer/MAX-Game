# Mission Feedback System

Дата: 2026-09-05. Успешные и ошибочные попапы, а также негативная окраска соединений являются данными конкретной миссии. Техническая диагностика движка не показывается игроку напрямую.

## Граница ответственности

- `mission-evaluation.mjs` определяет физическую сеть, выполнение задач и победу. Он не выбирает пользовательский текст.
- `mission-feedback.mjs` сопоставляет готовый `MissionEvaluation` с авторскими правилами `feedbackEvents` и создаёт смысловые события.
- `applyMissionFeedback()` накладывает красные состояния только на копию данных для рендера. Он не меняет `complete`, `objectives`, `bindings` или диагностику. Даже авторское негативное правило не красит односторонний узел: требуется два различных физических соседа, после чего красными становятся только линии, касающиеся этого окрашенного узла.
- `main.js` показывает уже готовое событие в существующем плавающем окне, сохраняет его drag/close/motion и задерживает ошибку на 220 мс, чтобы не мигать при кратком промежуточном состоянии.

Игровой попап намеренно одноуровневый: отображается только крупный `title`. Поля `eyebrow` и `message` старых JSON продолжают проходить parser/serializer для обратной совместимости, но форма редактора их скрывает, а runtime DOM не создаёт под них элементы.

## Формат миссии

```json
{
  "feedbackEvents": {
    "success": [
      {
        "id": "mission-complete",
        "eyebrow": "МИССИЯ №2 ВЫПОЛНЕНА",
        "title": "АРКТИКА ПОДКЛЮЧЕНА",
        "message": "Маршрут собран верно.",
        "condition": { "type": "missionComplete" },
        "action": "complete"
      }
    ],
    "error": [
      {
        "id": "satellite-too-high",
        "eyebrow": "ОШИБКА ОРБИТЫ",
        "title": "СПУТНИК СЛИШКОМ ВЫСОКО",
        "message": "Опусти спутник ниже допустимого уровня.",
        "condition": {
          "type": "altitude",
          "object": "satellite",
          "comparison": "above",
          "value": 1,
          "quantifier": "any"
        },
        "negativeConnections": "matched"
      }
    ]
  }
}
```

Порядок элементов массива задаёт приоритет. ID уникален среди обоих списков. В каждой миссии нужен хотя бы один финальный success с `missionComplete + complete`; промежуточные success используют `dismiss`. Список error может быть пустым.

## Условия

- `missionComplete` — вся миссия выполнена;
- `invalidConnection` — движок нашёл неправильный слот, конфликт ролей, неоднозначность или неправильный линк, причём существует хотя бы один затронутый узел с двумя физическими связями; одиночная или односторонняя установка не открывает попап;
- `objectiveComplete` + `objective` — выполнена именованная задача;
- `pathComplete` + `path` — выполнен именованный маршрут;
- `altitude` — оборудование указанного типа находится `above`/`below` порога; `quantifier` задаёт «хотя бы один» (`any`) или «все размещённые» (`all`).

Новый вид условия добавляется в валидатор `mission-system.mjs`, resolver `mission-feedback.mjs` и форму редактора. DOM-попап и WebGL-движок при этом не переписываются.

## Негативные соединения

- `none` — только попап;
- `invalid` — красные только реально неправильные связи;
- `matched` — красные объект(ы), найденные условием, и прилегающие связи;
- `all` — все узлы текущей сети, уже имеющие две физические связи, и прилегающие к ним линии красные; незамкнутые концы остаются нейтральными.

Событие показывается один раз за вход в миссию. Закрытие не отключает продолжающуюся визуальную индикацию. Сброс раскладки сохраняет историю показа; выход и новый вход создают новую сессию.

## Редактор

В инспекторе миссии есть отдельные списки «УСПЕШНЫЕ ПОПАПЫ» и «ПОПАПЫ ОШИБОК». Для каждого элемента редактируются ID, единственный крупный текст, условие, действие или режим негативных связей. Кнопки добавления создают новые правила; карточка удаляется своей кнопкой. Все изменения входят в общий undo/redo, черновик, проверку и «СОХРАНИТЬ ИЗМЕНЕНИЯ» с резервной копией.
