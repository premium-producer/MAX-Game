# X-SPUTNIK browser prototype

**Mission System v2:** [архитектура и руководство редактора](DOCS/MISSION_ARCHITECTURE.md). Игра читает `config/missions/index.json`, миссии — отдельные JSON, общие параметры — `config/mission-system.json`. Старый `missions.json` оставлен только для совместимости. Редактор: `START-EDITOR-WINDOWS.bat` → точки, маршруты/роли, условия, радиусы/размеры/высоты → тест сети → «Сохранить изменения» с backup.

**Банк объектов — отдельная страница:** `http://127.0.0.1:4174/object.html`. Три раздела: оборудование с одним видимым названием, SVG и физическими параметрами; неигровые SVG-иконки начальных и конечных точек без экранных подписей; именованные наборы оборудования с количествами. В редакторе миссий выбирается готовый набор и иконки точек. Исходные составы трёх миссий перенесены в «Набор 1/2/3» без изменения количества оборудования.

**Вид планеты — отдельная страница:** `http://127.0.0.1:4174/earth.html`. На ней собраны все цвета, texture-mask remap, поверхность, вода, облака, огни, контур, bloom, дымка и атмосфера. Изменения сразу применяются к тому же Three.js-renderer, shader и runtime-картам, что использует игра; сохранение атомарно обновляет только `rendering.earth` и создаёт отдельный backup.

Браузерный прототип интерактива «Космос на связи». Сцена имеет канонический размер `1920×1080` и масштабируется целиком под окно браузера без изменения пропорций. Игровое поле работает как единая WebGL-сцена на Three.js.

Фактические игровые правила и принятые решения ведутся в [`DOCS/GDD.md`](DOCS/GDD.md). Настройка и добавление миссий описаны в [`DOCS/MISSION_CONFIG.md`](DOCS/MISSION_CONFIG.md). Текущий статус, backlog и выполненные задачи — в [`DOCS/TODO.md`](DOCS/TODO.md).

## Перенос на другой компьютер

Папка `app/` самодостаточна. После актуальной сборки её можно целиком заархивировать, перенести на Windows x64, распаковать в любое место и запустить двойным кликом по `START-WINDOWS.bat`.

- системный Node.js и интернет не нужны: Windows-runtime лежит в `runtime/win-x64/`;
- все изображения, SVG, шрифты и карты Земли находятся внутри `public/` и `dist/`;
- абсолютных путей к этой рабочей машине в runtime-сборке нет;
- браузер откроется автоматически на локальном адресе; окно сервера нужно оставить открытым;
- чтобы остановить приложение, достаточно закрыть окно сервера.

Перед передачей архива на машине разработчика выполнить:

```powershell
npm run build
npm run portable:check
```

## Запуск для разработки

```powershell
npm run build
npm run dev
```

Открыть `http://127.0.0.1:4174`. Редактор миссий и ракурсов доступен по `http://127.0.0.1:4174/editor.html`, визуальный редактор планеты — по `http://127.0.0.1:4174/earth.html`. Для редакторов рекомендуется отдельный запуск через `START-EDITOR-WINDOWS.bat`: он гарантированно использует проектный writable-сервер, а не внешний статический preview. Оба Windows-launcher запускают сервер с наблюдением за его JS-модулями, поэтому после изменения backend-валидаторов процесс автоматически перезапускается и не остаётся на старой версии схемы.

## Редактор миссий

Редактор `editor.html` позволяет добавлять и дублировать миссии, расставлять произвольные фиксированные точки, собирать маршруты с ролями, настраивать задачи, зависимости, игровые ограничения orbit и per-state ракурсы. Цвета и FX Земли из него удалены: ими владеет `earth.html`. Миссии выбирают набор из отдельного банка `object.html`; последовательность задаётся независимо от состава набора. Иконки точек выбираются из отдельного раздела банка, A/Б не обязательны. Общие размеры, радиусы и высоты задаются у оборудования в банке; размер и базовый радиус можно применить сразу ко всему каталогу, а локальные переопределения оставить в миссии.

## Визуальный редактор планеты

`earth.html` показывает крупный live preview без отдельного или упрощённого renderer. Числовые параметры представлены синхронными slider/number-контролами, цвета — color-полями, а bloom имеет выбор `high / medium / off`. «Примесь исходного цвета» позволяет плавно вернуть реалистичные цвета diffuse-карты или смешать их с текущим стальным grade; рядом находится отдельная насыщенность исходника. Зависимые пороги автоматически удерживаются в корректном порядке и больше не создают блокирующую ошибку при сохранении. Параметры сгруппированы по поверхности и воде, России и контуру, городским огням, облакам, bloom/дымке/атмосфере; поиск фильтрует их по русскому названию или config-key. Ниже показаны все семь фактически используемых runtime-карт и масок со ссылками на исходники сборки.

Кнопка «Сохранить в игру» валидирует профиль общей схемой `ui-shell`, заменяет только `rendering.earth` в `public/config` и `dist/config`, сохраняет предыдущий файл в `backups/earth-style/<timestamp>-<id>/` и уведомляет открытую игру. Сохранение из редактора миссий, наоборот, всегда сохраняет текущий Earth-профиль с диска и не может затереть его данными старой вкладки.

Единая кнопка `СОХРАНИТЬ ИЗМЕНЕНИЯ` фиксирует текущий ракурс выбранного state, проверяет проект и записывает system (включая типы и SVG), индекс, миссии и `ui-shell.json` в исходные `public/config` и активные `dist/config`. Перед заменой прошлая версия набора сохраняется в `backups/editor/<timestamp>-<id>/`; скачивания в Downloads нет. После подтверждённой записи открытая игра получает уведомление новой ревизии и перезагружает конфиги.

Ракурс настраивается внутри отдельного адаптивного preview строго `16:9`, соответствующего логической сцене `1920×1080`. Preview использует реальные размеры и расположение header, frame, footer и inventory выбранного state из `ui-shell.json`, повторяет frame-mask, blur/dim и экранное смещение Земли. На `MISSION_SELECT` видны миссии, на `MISSION_PLAY` — A/Б выбранной миссии, в остальных states игровые маркеры скрыты.

В блоке ракурса доступны независимые числовые оси `X/Y/Z` без угловых ограничений и автоматической вертикальной компенсации, перенос камеры по `target X/Y/Z`, точный zoom `4–14` и FOV `15–100°`. ЛКМ вращает X/Y, `Alt+ЛКМ` или ПКМ — Z, `Shift+ЛКМ` двигает камеру в плоскости экрана, колесо меняет zoom; редакторский drag не имеет инерционного доводчика. `ЗАПОМНИТЬ РАКУРС` назначает всю композицию выбранному state, а `СОХРАНИТЬ РАКУРС НА ВСЕ ЭКРАНЫ` копирует её во все пять states. В игру изменения попадают после общей кнопки сохранения.

## Управление

- клик/касание по кнопкам макета — основной маршрут;
- drag по пустому пространству поля — повернуть Землю с инерцией в пределах, заданных для четырёх направлений в `ui-shell.json`; в последних 4° перед каждой границей сопротивление плавно нарастает;
- вертикальный поворот компенсирует положение Земли в кадре: drag вниз поднимает её, drag вверх опускает, удерживая российский сектор ближе к среднему центру рамки; компенсация продолжается во время инерции;
- в миссии: перетащить наземную карточку на видимую часть Земли, а спутник — в свободную видимую область над ней;
- во время переноса карточка наклоняется по направлению движения и слегка продолжает движение по инерции;
- после отпускания карточка превращается в круглый узел, а единственная нижняя очередь сортируется по текущей экранной позиции слева направо и остаётся центрированной; её блоки неподвижны, меняются фейдом только иконки;
- наземный узел поднимается над поверхностью: основание ложится касательно к сфере, а ножка и иконка всегда направлены вверх по экранной оси Y; Земля не срезает круг и волны;
- новый узел кратко находится в состоянии `DROP`, затем начинает отправлять синие импульсы;
- окно миссии соответствует handoff-макету: задачи собраны на общей вертикальной оси, выполненные пункты получают зелёную галочку, справа от таймера доступен компактный перезапуск, а полностью завершённая карточка получает зелёную рамку и флаг;
- переход от `DROP` к сигналу, смена цвета состояния и появление линий интерполируются плавно без пересоздания WebGL-ноды;
- у каждого типа элемента свой радиус волн; два активных узла могут получить линию только при пересечении их зон покрытия;
- нижняя цепочка всегда сортируется по текущей экранной позиции объектов слева направо, а не по очереди их добавления;
- связь возможна только с непосредственным соседом слева и непосредственным соседом справа и только при пересечении радиусов: объект получает зелёное или красное состояние лишь после физического соединения с обеих сторон; при одной стороне объект и линия остаются нейтральными, а линия наследует цвет только от окрашенного объекта, которого касается;
- в миссиях №1 и №3 полная корректная цепь получает зелёные линки от A к первой ноде, от последней ноды к Б и отдельное наземное замыкание `Б → A`; правило хранится в JSON миссии;
- неправильный узел открывает перетаскиваемое плавающее окно ошибки только после соединения с обеих сторон: одиночная установка не считается ошибкой; в error/success-попапе показывается только крупный заголовок, без служебной верхней строки и серого описания; успех содержит зелёную кнопку «ПРОДОЛЖИТЬ» без дублирующей нижней плашки;
- popup одного и того же ошибочного порядка типов показывается только один раз за текущий вход в миссию; повтор остаётся видим красными линками, но не открывает то же окно снова;
- когда рамка поджимается footer-ом, Земля следует за её центром немного вверх; в игре она также смещается влево с учётом правого инвентаря;
- без drag-and-drop: выбрать объект кликом, затем нажать в нужной точке поля;
- размещённый узел можно переместить по сфере, захватив за маяк, ножку или иконку; исходное смещение захвата сохраняется без прыжка к курсору; двойной клик удаляет ноду;
- drag за ядро спутника двигает его по сферической оболочке текущей высоты; отдельная ручка `↕` меняет только высоту, а колесо мыши во время переноса служит ускоренным способом её регулировки;
- во время drag спутника показываются его проекция на Землю и пунктирная линия высоты;
- высота спутника ограничена диапазоном `0.34–1.40`, Земля и безопасный отступ 4.5% блокируют скрытые и выходящие за кадр позиции;
- `Enter` или `Space` — следующий экран;
- `Esc` — назад;
- `R` — сброс к CTA;
- `F` — fullscreen;
- `?debug=1` — показать кликабельные зоны и панель переходов.

## Архитектура

- `public/config/missions/index.json`, `mission-system.json`, `missions/*.json` — активный переносимый Mission System v2; старый `missions.json` оставлен только для совместимости;
- `public/config/mission-v2.schema.json` и `mission-system.schema.json` — формальные схемы конфигурации;
- `editor.html` и `src/editor-*` — отдельный визуальный редактор миссий, точек, маршрутов, задач и per-state ракурсов;
- `earth.html` и `src/earth-editor-*` — отдельный live-редактор текстурной интерпретации, цветов и FX Земли;
- `src/editor-project-save.mjs` и локальный endpoint `/api/editor/save` — проверка, резервная копия и единая запись обоих игровых JSON;
- `src/mission-config.mjs` — загрузка, нормализация и строгая проверка каталога;
- `src/game-state.mjs` — пять состояний `CTA / онбординг / выбор / игра / финал` и вычисляемые статусы миссий `locked / open / completed`;
- `src/mission-game.mjs` — инвентарь, индивидуальные радиусы сигнала и проверка JSON-маршрутов/условий;
- `src/mission-feedback.mjs` — редактируемые success/error-события миссий, их условия, дедупликация и независимая визуальная проекция негативных соединений;
- `src/webgl-field.js` — Three.js-сцена, сфера Земли, WebGL-ноды, raycasting, камера, мягко ограниченное орбитальное управление и пространственные связи;
- `scripts/sync-assets.mjs` — синхронизация последнего завершённого WEB handoff v2;
- `scripts/build.mjs` — автономная сборка в `dist/` без внешних зависимостей;
- `scripts/check-portable.mjs` — проверка полного комплекта и отсутствия локальных абсолютных путей;
- `server.mjs` — минимальный локальный static server, привязанный к `127.0.0.1`.

Обычный `npm run build` использует только файлы внутри `app/` и не обращается к родительскому `workspace/`. Обновление из Figma выполняется отдельно командой `npm run build:refresh`; если исходного workspace рядом нет, уже скопированные ассеты в `public/` остаются рабочими.

Все пять экранов собираются нативно из DOM/CSS и WebGL без PNG-заглушек. Один WebGLRenderer, одна камера и одна Земля живут непрерывно от CTA до финала, поэтому поворот не сбрасывается между экранами. Интерфейс меняется поверх сцены; игровые ноды, endpoints и связи включаются только во время миссии. Позиции хранятся как широта, долгота и высота.

WebGLRenderer, камера и Земля создаются ровно один раз при запуске приложения. Игровые действия согласуют существующие ноды и связи по идентификаторам, не уничтожая их при смене состояния; это сохраняет drag-захват и непрерывность анимации. У наземной ноды маяк и кольца находятся на высоте 0.012 от физической сферы и ориентированы по касательной плоскости географического якоря. Ножка высотой 0.23 и ядро находятся в отдельном billboard-слое и сохраняют экранную вертикаль Y при любом наклоне поверхности. Спутник стартует на высоте 0.72; обычный drag пересекает луч курсора со сферой текущей высоты, а отдельный hit-target ручки изменяет только altitude в диапазоне 0.34–1.40. Из двух пересечений выбирается непрерывная видимая точка, поэтому спутник не телепортируется на скрытую сторону Земли. Для runtime используются локальные карты Земли 3072×1536, подготовленные из исходников 6K.

Начальный ракурс Земли калибруется по полному контуру России из `workspace/UI/dev/reference/EARTH_REF.png`, без искусственной привязки Урала к центру. Текущая итерация использует поворот глобуса `[0.38, -3.31, -0.02]`, сохраняя масштаб и положение камеры. Пределы OrbitControls и вертикальная центровка России находятся в `ui-shell.json` и редактируются в строке игровых ограничений `/editor.html`. Точка A привязана к Москве (`55.75, 37.62`), точка Б — к восточной части России (`58, 120`); их световые якоря лежат непосредственно на поверхности, а географические слои используют тот же поворот, что diffuse-карта и контур границы.
