# Инструкция визуальным агентам: маски, материалы и элементы стенда

Дата сверки: 03.10.2026. Это инструкция разработки компонентов в D, а не разрешение применять их к мастеру F. Общий порядок назначения, изоляции и передачи — [AGENT_INTEGRATION_GUIDE.md](AGENT_INTEGRATION_GUIDE.md); ограничения корневого AGENTS.md обязательны. Перед задачей прочитать свежий WORKLOG и фактический исходник: старые записи в документах описывают в том числе отменённые варианты.

## 1. Граница ответственности

Работать в назначенном worktree D, только в согласованном наборе файлов. F читать для сверки контрактов. Ни F `artifacts/local-master`, ни его БД, конфиги, TODO, процессы и рабочую страницу исполнитель визуала не изменяет. Интегратор мастера переносит и применяет компонент после проверки. Отдельная ветка сама по себе не изолирует TD, порты, GPU, пользовательские JSON и процессы.

Мастер определяет посетителя, результаты квиза, теги, пакет, очереди, сценарные команды и подтверждённые рубежи. Визуальный компонент отображает принятые данные, рассчитывает кадры, сообщает готовность и фактическое достижение рубежей. Он не выбирает темы заново, не создаёт второй пакет и не освобождает Стеллу по своему таймеру. В D допустим подписанный как fixture демонстрационный драйвер с синтетическими данными; это не второй мастер.

`local / production` — размещение исполнения; `TD / Native` — источник масок; `Vanilla / CUBES` — вид материала. Эти переключатели независимы. Переключение материала не меняет сценарий, идентичность элементов, топологию или время движения.

## 3. Разделение визуальных задач между агентами

| Исполнитель | Допустимый выделенный участок | Не менять одновременно с соседней задачей |
|---|---|---|
| Маски / Native | Назначенные модули генерации, профиль/схема, adapter-tests; согласованные изменения `cubes-surface-mask.js` | FieldPass, engine types, `surface-field.js`, общая нормализация и transport — только через единственного владельца |
| Материал / compositor | Конкретный pass CUBES/Vanilla, shared glow/background или adapter материала | Те же shared GLSL/FieldPass нельзя одновременно отдавать масочному агенту; входные физические поля не переопределять |
| Теги / передний контент | Согласованная группа `discovery-*`, `tag-*` либо `pixel-tags*` либо карточки | `composition.js`, worker, общие atlas и брендовые профили требуют явной передачи владения |
| Белая сущность | `white-entity-*` и изолированный fixture драйвер | Профиль Стеллы, worker и сценарные API не менять без владельцев; не объявлять sweep уже связанным с F |
| Ввод / силуэт / флюиды | Назначенный input-adapter и тесты, затем согласованный compositor | Не переписывать solver ради визуального эффекта; `shared-fluid`, `surface-field`, `server.mjs` — последовательная интеграция |
| TD | Ручная настройка источника оператором; задача TD-агенту только при отдельном поручении | Не менять несвязанные ноды, транспорт и синхронизацию ради backend-интеграции; отдельные TOX запрещены без нового указания |

Общие `worker.js`, `surface-field.js`, `server.mjs`, `main.cjs`, сборщики, `common-map.js`, общие vendor types/shaders и runtime JSON не выдаются двум исполнителям одновременно. Переданный файл не становится общим: текущий владелец сдаёт проверенную версию, следующий начинает с неё. Работа root другого чата не даёт право интеграции в F.

До каждого среза зафиксировать задачу, владельца, allowlist конкретных файлов, исходный commit/SHA, выделенные данные/порт, зависимость от контракта и точку проверки. Масочные и материальные агенты могут параллельно исследовать, но зависимые правки FieldPass выполняются последовательно.

## 4. Целевой контракт масок и ограничения текущего состояния

Авторитетное описание для переноса: [F MASKS_INTEGRATION_ARCHITECTURE](F:/project/VK_DigitalProducts_Stand/docs/MASKS_INTEGRATION_ARCHITECTURE.md). Это архитектура для реализации. `MaskFrame/v1`, новый visual API и applied ACK в ней не означают наличие этих интерфейсов в установленном мастере.

Каждый домен получает **шесть независимых сигналов**: `large.physical`, `large.color`, `large.morph`, `fine.physical`, `fine.color`, `fine.morph`.

- Physical — данные 0…1: присутствие, размер и связанное с размером Z через материал. Ноль выключает клетку полностью. RGB или morph не могут вернуть клетку с нулевым physical. Это не готовая экранная alpha и не замена всех параметров LumiCells прямым scale.
- Color — RGB с указанным пространством цвета; он не вычисляет размер. Scalar-данные не декодировать как sRGB; цвет преобразовывать в linear один раз.
- Morph — переход от исходного материала к белой округлой форме, независимо от размера/присутствия.
- Large/fine независимы. Текущий Native fallback частично использует дополнение large и не обеспечивает полный паритет color/morph. Его нельзя выдавать за завершённый Native-провайдер.

Существующий TD wire-контракт: MSK schema1, четыре атласа `VK-Control-MainLeft`, `MainRight`, `Ribbon`, `Arch`; страницы physical/RGB для двух решёток, physical RGBA=`physical,morph,physical,1`, morph capability bit0. Старый источник без capability имеет morph=0. Входной цвет premultiplied по RouteAdapter; не делать скрытый unpremultiply. Конкретные размеры/guard/header брать из `td-mask-sources.js`, не переписывать вручную в соседнем модуле. Native внутри renderer не обязан имитировать Spout-пакет.

Получатель валидирует целый кадр, размер/идентичность/свежесть и доступные каналы. Статичная маска не равна умершему источнику. В целевом F preferred/applied source раздельны; fallback в Native не меняет сессию и не сбрасывает её события. Возврат TD — явная команда начального профиля, без дребезга. Управление и синхронизация самих генераторов TD остаются ручными; агент принимает входы, не начинает ими командовать автоматически.

## 5. Поверхности, сетки и независимость визуальных слоёв

Исходная топология: арка 5120×512 (large80×8, fine160×16), лента10240×512 (160×8, 320×16), задняя стена7168×1280 (106×19, 212×38). Проверять версию manifest; центры/pitch/padding не выводить заново округлением.

Задняя стена — **один домен до crop**, стык X=3072. Noise, seed, clock, градиент, маски, силуэты и декоративные элементы продолжаются через стык. Не создавать локальный shader/палитру для технических `SCREEN_LEFT/RIGHT`. Локальный брендовый контент плавно исчезает до своей границы согласно [REAR_WALL](../apps/stand-service/docs/REAR_WALL.md). Нативные рабочие текстуры не уменьшать до1080p; browser preview проверяется отдельно от настоящего вывода.

Чёрно-белая маска не является визуальным объектом сцены. Отдельно различать клеточное поле, его материал CUBES, декоративные кубики без текста, текстовые теги, Discovery-баблы, карточки/видео, белую сущность, силуэт/флюиды, цветную подложку и glow. Белая сущность не равна morph всего фона; Discovery-тег не равен этой сущности.

Настройки: модификаторы → ручные параметры → визуализация; дополнительные заливки/compositing описывать отдельным профилем. Существующие параметры LumiCells сохранять, новые художественные величины выносить в версионированные defaults/профили. Не хранить скрытый художественный hardcode в мастере или новые authoritative настройки в localStorage. Активная сцена использует принятую версию профиля; live override требует отдельного контракта применения.

## 6. Белая сущность и временной контракт

Действующий D sweep — отдельный Engine на арке, свой envelope, `proceduralEnvelope:true`, `maskPair=[0,0,0,0]`, цикл reveal/hold/erase по длительностям. Общая карта не обязана показывать его: текущая фактическая страница — `/service/presentation.html?instance=vk-arch`. Распространение на ленту/стену и сценарная связь F пока не подтверждены.

Целевой adapter имеет hidden → reveal → hold → erase → hidden, управляет уже существующим механизмом анимации, сохраняет seed и начинает переход из текущей фазы. Отказ от фото или начало scanning приводят к принятому плану, уходу тегов и reveal. Первый реально нарисованный кадр reveal даёт `entity_reveal_presented`; мастер разрешает выпуск пакета. Полностью появившаяся последняя карточка даёт новый `ribbon_items_visible`, после которого сущность стирается. `entity_hidden` завершает сопровождение арки; `ribbon_center_crossed` освобождает Стеллу; `all_arrived` завершает доставку.

Это новые предлагаемые рубежи, не повод переименовать существующие receipts: текущий `emission_complete` означает начало последней карточки, а не окончание её появления. Timing и `revealEndMs` вводятся новой согласованной версией. Длина пакета и выбранный визуальный профиль определяют timing; нельзя зашить фиксированные2с hold или число карточек. Пустой слот ресурса может ехать и заполняться позже без смены itemId.

Кадровую анимацию ведёт готовый renderer/timeline. Мастер получает смысловые ACK и checkpoints, не кадры масок. `accepted` не равно `applied` или `presented`. Адаптер согласует command/scene/domain/sourceEpoch/profile/controlRevision/owner identity с реально принятым протоколом F; не присылает неподдерживаемые новые ACK в живой API. Проверять дубликаты, seek без повторных событий, pause/reload, stale owner и dispose. Постоянный domain clock не прекращается вместе с конечным package execution. Новую сущность нельзя запускать вторым независимым execution в нынешнем единственном slot мастера.

## 7. Силуэт и флюиды: требование замещения

После TD/Native используется один и тот же этап интерактивного замещения. Нужны независимые `I` (рисунок мелкой маски), `C` (coverage, включая чёрные отверстия), `L` (подавление крупных клеток):

`fineEffective = (1 − C) × fineBase + C × I`

`largeEffective = largeBase × (1 − L)`

Это семантика source-over замещения, а не разрешение писать свой compositor. При C=1/I=0 белый base должен стать чёрным; `C=I>0`, max/add и `base×I` неверны. Подавление применяют до тела/halo/bloom, по footprint клетки: экранный stencil не режет её пополам. Провайдерские исходные маски остаются неизменны.

Неподвижный человек сохраняет силуэт, но физический импульс создаёт измеренное движение; pointer — отдельный явный ввод. Фоновый шум не запускает локальные флюиды. Исходные SharedFluid/DepthFluid сохраняются. Полное восстановление физического solver/GPU/TD из seed/time не доказано; нужна поддерживаемая snapshot/replay либо согласованная политика восстановления. Готовый производительный механизм нового compositor и recovery пока пробел исследования — не объявлять решённым по unit-тестам.

Ни сборка, ни SHA сами по себе не подтверждают, что работающий worker загрузил новый код.

Короткая проверка во внутреннем браузере: действие, результат, переход/обновление, console errors на фактической странице. Проверить источник → bundle → runtime → HTTP SHA → worker/выход. Для цветов/материала приложить сопоставимый ROI реального кадра, параметры и время; превью не доказывает нативную детализацию/FPS/Spout. Для масок — отдельно 0, серый,1; независимость шести каналов; исчезновение клетки; TD-loss/Native; для интерактива — стоящий/движущийся силуэт, pointer и затухание; для rear — обе стороны стыка вместе.

Тяжёлые GPU/нагрузочные прогоны и запись видео не запускать без требуемого отдельного согласия. Технический PASS, визуальная самопроверка и утверждение пользователем — три разных статуса. Документальная задача не требует запуска шоу или браузера.

Пакет передачи интегратору содержит task/owner, commit либо SHA каждого файла и исходного baseline, точный allowlist/diff, upstream provenance/лицензии, зависимости, schema/profile/API versions, defaults и миграции, topology/seed/clock, список событий и timing, изолированные тесты/fixtures, source→runtime→HTTP доказательства, скриншоты с маршрутом/режимом, известные gaps и способ отката. Секреты, БД посетителей, mutable конфиги оператора и несвязанные runtime-файлы не включать. Неприменённый кандидат явно подписывать «не установлен». Следующая визуальная итерация — после кадра и отзыва пользователя.

## 9. Открытые границы на дату сверки

Полные Native six-channel parity, сохраняемый TD/Native selector с applied ACK, сценарный adapter белой сущности, replacement compositor, recovery физики, распределённый rear barrier и production output fencing ещё требуют реализации/проверки. D уже имеет полезные компоненты, но это не работающий полный тракт F. Не смешивать эту работу с кандидатами и параллельными исправлениями F; сначала получить у интегратора назначение одного малого среза и актуальную версию контракта.
