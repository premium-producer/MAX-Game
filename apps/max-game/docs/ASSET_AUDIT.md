## Текущий Selectel editor v3 — 04.10.2026

Открыть https://futuronika.pro/df/max-asset-audit/editor/ . Release20261004T065200Z, командное редактирование с блокировкой карточек. Инструкции v1/v2 ниже описывают предыдущую локальную версию; игровая страница8770 и F этой поставкой не изменены.

Карточка экрана закрепляется за открывшим её участником. Другие видят «СЕЙЧАС РЕДАКТИРУЕТСЯ» и не могут открыть её ни с каталога, ни через prev/next. Закрытие/переход сначала сохраняет правки, затем освобождает доступ. Heartbeat8с, TTL30с, список2с; при потере связи ввод отключается, локальную копию можно скачать. После обновления сервера или страницы карточку открывают заново. Все участники должны обновить страницу после установки этой версии.

GET /editor/api/max-asset-locks с X-MAX-Editor-Id возвращает screenId/owned/expiresAt безtoken. POST с CSRF/Origin: acquire/renew/release и screenId, для renew/release token. Запись дополнительно передаёт X-MAX-Card-Id/X-MAX-Lock-Token; чужая занятая карточка и истёкший grant дают423. Сервер проверяет merge/CAS/legacy и общие тексты/финалы в одной очереди с захватом. Verrou0.5.2 MemoryStore действует в единственном процессе; масштабирование требует общего driver. Блокировки не пишутся в JSON. [Ресерч](../../../docs/Research/max-card-locks-20261004.md), [приёмочная проверка](../../../artifacts/reports/max-card-locks-20261004.md).

В крупном окне список действий: «+ Зона на изображении», «+ Кнопка под экраном», «+ Автопереход». Зон/кнопок может быть несколько, таймер один; новый таймер выключен, задержка0.5секунды. Каждое действие имеет собственные включение, назначение внутри задания и удаление. Зоны можно двигать/растягивать; кнопкам редактируется текст. Справка экрана поддерживает свой текст/наследование/скрытие, ниже тексты задания/миссии. Галочка финального экрана меняет default новых действий; существующие назначения сохраняются. Защищённые бизнес-действия не позволяют произвольно менять исход.

Правки сохраняются автоматически; дождаться «Общая версия синхронизирована». Независимые изменения участников объединяются, общая версия проверяется каждые2с в видимой вкладке; во время ввода и перетаскивания её визуальное применение откладывается. Для одновременной правки одной зоны/кнопки показаны обе версии и явный выбор. Геометрия и назначение одной зоны сливаются только целиком. Undo — «Отменить правку» в шапке после закрытия окна — обращает собственную операцию, сохраняя независимые изменения команды. Новые поля пока не применяются в игру; FE-04/05 ожидают интеграции. Экспортschema3 содержит весь документ; импортv3 явно заменяет черновик после подтверждения, legacyimport меняет только переданные значения и сохраняет новыеv3 действия. Импорт/восстановление используют отдельный CAS-путь; это полная замена, не обычное командное редактирование.

POST /editor/api/max-asset-flow/merge принимает baseDocument и document без revision/envelope. fast-json-patch3.1.1 выполняет test/apply на атомарных сущностях с общей очередью записи. Конфликт409 возвращает текущий документ и спорные сущности; частичных записей нет. GET/POST max-asset-flow остаются для чтения/CAS-замены. У каждой загрузки редактора отдельный ключ аварийной копии в IndexedDB; прежние несохранённые копии не стираются и доступны для явного восстановления. SharedBasicAuth сохраняется, имён/курсоров участников и посимвольного редактирования здесь нет. [Ресерч](../../../docs/Research/max-team-editing-20261004.md), [проверки и публикация](../../../artifacts/reports/max-team-editing-20261004.md).

GET/POST /editor/api/max-asset-flow на Selectel. v3 хранится в data/flow-v3.json, legacy в data/annotations.json сохранён. Первое чтение мигрирует в памяти без записи; первый CASPOST создаёт v3, после этого старыйPOST409. Повреждённое хранилище не заменяется пустым. max-asset-flow-recovery-v3 — локальный резерв, старыеIDB не удаляются; восстановление всегда подтверждается, устаревшаяbaseRevision отмечается. ОшибкаGET блокирует редактирование до успешного повтора.

Deployment не переносит разметку; резервирует оба серверныхJSON перед переключением. Если v3 уже сохранён, rollback на legacywriter автоматически блокирует его запуск до согласования данных; JSON назад не восстанавливается. Auth сохраняется. [Проверка, SHA и ограничения](../../../artifacts/reports/max-flow-editor-v3-20261004.md).

Открыть: http://localhost:8770/max-game/asset-audit/

Страница показывает все 84 экрана действующего каталога: 4 миссии, 15 заданий. Декоративные иконки, логотипы и QR-ресурсы не являются экранами для разметки.

1. Превью и «Открыть крупно» только открывают экран, не меняя рамку. Для нового действия нажать «Разметить действие», затем указать кнопку на изображении. Для размеченного доступны «Показать действие» и «Разметить заново». В показанной рамке можно двигать ручки и саму зону; изменения сохраняются автоматически. Повторную разметку можно отменить до выбора нового места.
2. Если на экране несколько действий, выбрать каждое в списке. Для внешней кнопки использовать «Кнопка под устройством». Исходные зоны не считаются проверенными до явного подтверждения.
3. Каждое законченное изменение автоматически записывается в проект через Stand Service. Дождаться «Сохранено в проекте». «Скачать копию» — необязательный резерв, JSON не нужен для обычного сохранения.

На карточке и в редакторе есть «Экран активен» и «Назначить финальным экраном задания». Отключение сохраняет разметку, снимая назначенный финал. В задании можно назначить один финальный экран; последний активный экран нельзя отключить. Флажок финала — пользовательское назначение, а не отображение исходного `complete-task` в каталоге.

**Принятый экспорт от03.10.2026 применён к локальной MAX v5 (73действия/33настройки,70активных экранов). Новые правки редактора сохраняются отдельно и не меняют игру автоматически.** Применение требует отдельной проверки ветвлений и привязки каталога к версии игрового сохранения. Изменение исходов в активной сессии ломает воспроизведение её receipts. Назначенный финал в применённом каталоге завершает текущее задание после правильного действия, не всю миссию; неверный ответ не должен засчитываться.

«Отменить правку» отменяет последнюю операцию текущего сеанса. «Удалить разметку действия» удаляет отметку для выбранного действия и возвращает исходную настройку каталога. Импорт добавляет/заменяет записи из файла, не удаляя остальные отметки.

Редактор: Annotorious 3.9.3; координаты прямоугольников — пиксели оригинального изображения. Основное хранилище — `apps/stand-service/configs/max-asset-audit.json`. GET/POST `/api/max-asset-audit`, существующие Host/Origin/X-VK-Token проверки; сравнение ожидаемой ревизии и последовательная обработка, атомарная запись через atomically 2.1.1 с fsync. Конфликт вкладок не перезаписывает чужую версию. После сетевого сбоя есть автоматические повторы и ручной повтор; закрывать страницу до подтверждения записи не следует.

Прежняя IndexedDB `max-asset-audit-v1` читается для миграции, не очищается. При первом пустом сервере перенос автоматический; иначе доступно явное восстановление старого черновика. Новая `max-asset-audit-recovery-v2` хранит аварийную копию, когда браузер допускает запись. Она не заменяет серверное подтверждение. Прогресс игры не затрагивается.

Экспорт: `schemaVersion:2`, `contentRevision`, `exportedAt`, `records` для зон действий и `screens` для активности/финала. Сервер возвращает `revision` — SHA сохранённых байтов, POST требует `expectedRevision`. Импорт поддерживает прежнюю schema1, проверяет версию, идентичность ассета, действия и границы до записи. Пустой документ имеет revision `0` до первой записи; повреждённый/чужой документ не сбрасывается.

Сборка: `node artifacts/max-game/scripts/build-asset-audit.mjs`. Использует закреплённый `vendor/backend-figma-v2`, проверяет хеши ассетов существующего runtime, создаёт лёгкие WebP-превью через sharp. Также генерирует `artifacts/service/max-game/asset-audit-store.mjs` с серверной библиотекой; этот модуль доставляется штатным service slice/full builder. Новый серверный код требует штатного перезапуска мастера. Конфиги сохраняются сборкой. Это отдельная сборка; общая сборка игры её не заменяет.

[Исследование](../../../docs/Research/max-asset-annotation-20261003.md), [проверка](../../../artifacts/reports/max-asset-audit-20261003.md).
