# MAX — две презентационные миссии

29.09.2026 — вместо четырёх условных экранов demo-id теперь используется [общая последовательность из 13 клиентских экранов](DIGITAL_ID_SCREENS.md). Согласия Минцифры/MAX и подтверждение входа показаны отдельно; кнопка «Вернуться в MAX» удалена как отсутствующая в исходнике. После Госуслуг следует учебный ПИН, биометрия по выбору, затем готовый ID. Остальные части тестовых миссий сохранены.

Реализовано 29.09.2026. Открыть [клиентскую игру](http://localhost:8770/max-game/client/) → «Начать» → одна из двух карточек с пометкой «тест». В локальном мастере используется эта же редакция; ссылка «Игра MAX · полное качество» ведёт на неё. Исходная страница `/max-game/` сохраняет четыре основные миссии.

## Прохождение

Стела и переход от стелы к стенду — отдельная часть общего пути посетителя и не входят в игровую механику. Миссия начинается обычным узлом «Открыть MAX» с оригинальным логотипом.

Сначала посетитель собирает путь плюсами, затем нажимает «Продолжить» и выполняет задания у иконок по порядку. Предыдущий шаг должен быть завершён. Ответы, размещение и выбранный инструмент сохраняются отдельно для каждой миссии. Две дополнительные миссии не входят в обязательные четыре для общего финала.

| Миссия | Полный демонстрационный путь |
| --- | --- |
| Получение льготы · тест | Открыть MAX → создать учебный Цифровой ID → Госуслуги: два согласия и подтверждение входа → ПИН → выбор биометрии → готовый ID → продолжить игру → получить льготу в музее → предъявить ID → льготный билет → QR |
| Продвижение бизнеса · тест | Открыть MAX → создать учебный Цифровой ID → Госуслуги: два согласия и подтверждение входа → ПИН → выбор биометрии → готовый ID → продолжить игру → подключить бизнес-аккаунт → выбрать один инструмент → выполнить его действия → QR |

Инструменты бизнеса: канал (создать и запланировать пост), бот (запустить и принять учебный заказ), витрина (подключить и открыть для клиентов). Достаточно одного инструмента.

## Госуслуги и границы демо

В обоих треках показаны исходные экраны Госуслуг: согласия Минцифры/MAX и подтверждение входа. Затем интерфейс переходит к ПИН-коду в MAX. Текст прямо обозначает, что реальной авторизации и передачи персональных данных нет. Учебный ID не является документом.

Стела, анкета и переход к стенду не моделируются в игре. Связь оборудования, передача сессии и назначение посетителя относятся к отдельной интеграции. ID и Госуслуги в бизнес-треке добавлены для презентации по запросу пользователя; это не утверждение о реальном обязательном условии подключения бизнеса. Реальные аккаунты, льготные билеты и заказы не создаются. Новые видеоролики и точные экраны приложений не изготовлены: создание ID использует исходные PNG внутри игрового телефона; остальные задания используют текстовые демосцены.

## Финал

Каждая тестовая миссия заканчивается локальным матовым попапом с QR-кодом **https://max.ru/**. Адрес подтверждён пользователем. Под QR есть подпись официального сайта и отметка деморежима. События сканирования и автоматического завершения по скану нет.

PNG генерируется локально скриптом `artifacts/max-game/scripts/build-presentation-qr.py` (ReportLab + Pillow), M correction, 25×25 модулей, quiet zone 4, итог 396×396. Внешний QR-сервис не используется. Скрипт проверяет соответствие пикселей матрице кодировщика; сканирование телефоном отдельно не проверено.

## Реализация и проверка

Источник сценариев: `artifacts/max-game/src/journey-presentation.mjs`. Клиентский адаптер добавляет их к четырём основным миссиям. Сборщик включает их в WebGL-каталог: номера 5/6, узлы и топологии обязательны для `syncScene`. UI использует существующие переходы, сохранение прогресса и стеклянные попапы.
