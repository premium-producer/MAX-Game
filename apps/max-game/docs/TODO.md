## Правила ведения

1. Перед правкой выбрать одну текущую задачу и критерий результата. При необходимости разбить её на небольшие шаги здесь.
2. После каждой итерации обновить дату, статус, доказательства и оставшуюся работу. Историю изменения кода записать в WORKLOG.
3. Статусы: бэклог → к выполнению → в работе → технически проверено, ждёт приёмки → выполнено. Для блокировки указывать конкретную причину.
4. Переносить в выполненные после выполнения критериев. Изменение поведения требует пользовательского отзыва; число тестов и сборка его не заменяют.
5. Повторный дефект возвращает задачу в очередь с причиной. Историю и доказательства сохранять.
6. Следующая визуальная итерация — после обратной связи. Мастер и публикация — только по отдельному запросу.
