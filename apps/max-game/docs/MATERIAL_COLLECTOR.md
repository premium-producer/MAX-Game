# Сбор клиентских материалов Figma для MAX

Локальный плагин: [MAX — сборщик материалов клиента](../../../artifacts/DESIGN/figma-plugins/max-material-collector/README.md). Отдельный инструмент чтения клиентского файла; плагины переноса игровых экранов в Figma остаются отдельными.

Вход: выделенные области либо текущая страница Figma Design. По умолчанию структурный обход SECTION/GROUP → опциональные подсекции → FRAME/COMPONENT/INSTANCE. Фрейм экрана атомарен; подфреймы UI не выгружаются отдельно. Контейнер-FRAME с непосредственно вложенными нумерованными экранами раскрывается. Названия и пути сохраняются, размеры/заголовки рядом не влияют. Старый эвристический режим выбирается явно. Ручное назначение группе и исправления сохранены. Текущая страница/выделение фиксируются при скане; экспорт использует эти узлы даже при переключении страницы. Макет не изменяется.

Выход: одна датированная папка в artifacts/DESIGN/figma-exports/. export.json — журнал сохранения и проверок; catalog.json — schema=max-client-materials-catalog/v1 с путями файлов; texts.json, coverage.json, index.html — сводные материалы. В папках секций/подсекций каждый экран имеет PNG, миниатюру, screen.json, тексты и опциональные SVG/REST JSON/исходные растры. ZIP и общий бинарный пакет не создаются. Статус complete означает сохранение выбранной очереди, не полноту миссий. Поля containerPath/sectionPath, groupName, sequence, task, evidence, confidence, reviewed, manualTask, order сохраняются.

Один шаг может иметь несколько видов материала: видеокружок/голосовое сообщение — альтернативы сообщения; подтверждённое фото — общая подготовка ID. Пользователь подтвердил пять заданий общения. Бизнес имеет аккаунт/сферу и три альтернативные ветки. Количество экспортированных экранов не меняет игровой сценарий и не отменяет недостающие задания. Сцены отеля/музея/магазина по прежнему остаются заглушками «АНИМИРОВАНАЯ СЦЕНА ???» до отдельного поручения.

Сырые выгрузки хранить в artifacts/DESIGN/figma-exports/ локально. Не пересобирать игру и не отправлять материалы на Selectel автоматически: сначала редакторская сверка и отдельная интеграция. Наличие изображений в пакете не даёт основания добавлять новые задания или менять клиентские тексты.

[Обоснование подхода](../../../docs/Research/max-figma-material-collection-20260929.md). [Проверки](../../../artifacts/reports/max-material-collector-20260929/README.md).

## Структурный режим 29.09.2026

`scan.detection` принимает `structure` (по умолчанию) или `legacy`. `Collector.structured` группирует по реальным родительским ID, сортирует имена внутри группы с numeric collation (1, 2, 10), не использует пространственные заголовки. Имена `Серия - N (описание)` разбираются без потери исходного имени. `plan` сохраняет общий/ручной порядок, не перегруппировывает по назначенному заданию. `source.detection` и `ordering` объясняют происхождение порядка в пакете version=1; новые поля аддитивны.

Fingerprint включает родителей и детектор изменений прочитанных свойств дерева экрана: тексты, основные стили, изображения, геометрию и порядок узлов. Это ключ актуальности, не криптографическая проверка; SHA-256 применяется отдельно к передаче и сохранённым файлам. Изменение после скана блокирует экспорт и требует повторного чтения. Внешние изменения, не отражённые в прочитанных свойствах, требуют «Новой выгрузки». Имена контейнеров используются для папок без ID-префиксов; коллизии разрешаются суффиксом -2. unpack.mjs поддерживает старые пакеты, но не участвует в текущем UI.

## Серверная очередь · 29.09.2026

Start-Server.bat сборщика вызывает существующий launcher pdf-export. Общий сервер localhost:47831 получает capability max-materials-v1; прежние маршруты брендбуков сохранены. При первом обновлении требуется повторный импорт manifest.json для доступа к localhost. Пользовательские инструкции — в README плагина.

Контракт:

- POST /api/max/exports: source/options/frames/links/context/coverage/resume; возвращает id, outputPath, completed, token. Одинаковый план при resume=true находит прежнюю папку и перепроверяет каждый сохранённый файл; resume=false создаёт новую.
- PUT /api/max/exports/:id/screens/:screenId: JSON только одного экрана, Authorization: Bearer token, X-Frame-Archive: 1, X-Content-SHA256. Сервер проверяет SHA-256 тела, обязательные выбранные материалы, пишет во временную папку runtime, fsync и повторно читает каждый файл для проверки SHA-256. После переноса папки экрана и атомарной записи журнала отвечает verified/bytes/sha256/screenId. Повтор потерянного ACK безопасен.
- GET /api/max/exports/:id: подтверждённый прогресс. После перезапуска сервера клиент снова делает POST для получения token и продолжения.
- Figma runtime ожидает stream-ack после плана и каждого экрана. Следующий exportAsync не начинается до подтверждения сохранения. Ошибка/отмена прекращает очередь, не отменяя предыдущие подтверждения. UI считает SHA-256 встроенным кодом без зависимости от crypto.subtle.

Ключ продолжения включает область/план, настройки, порядок, назначения и fingerprint. Повторная ручная классификация должна совпадать с прежней для продолжения той же папки. Сводные файлы восстанавливаются из проверенных screen.json. Копии заменённых файлов и незавершённые staging находятся в artifacts/workspace/runtime/figma-pdf-export/max-materials/, не в папке экспорта. Сервер не удаляет исходные пользовательские выгрузки.

Обновление сервера защищает активные HTTP-операции MAX. Между загрузками процесс может штатно обновиться; тогда клиент останавливается, повторный запуск продолжает ту же очередь. Проверка: [отчёт](../../../artifacts/reports/max-material-server-20260929/README.md). Настоящий пользовательский Figma-host ещё не проверен.

## Ошибочный component set · 29.09.2026

Getter componentProperties может выбросить исключение даже при наличии свойства в API. Fingerprint перехватывает только чтение/сериализацию этого необязательного свойства и сохраняет стабильный маркер недоступности. readWarnings на экране содержит nodeId/nodeName/property/message; предупреждение видно в списке и попадает в screen.json/catalog.json. Здоровым экранам поле не добавляется, чтобы не менять ключ продолжения существующих выгрузок. Если getter начинает работать, fingerprint меняется и требуется повторный скан. Компоненты не отсоединяются и не исправляются в исходном макете. Реальный сбой обязательного PNG/REST/SVG не игнорируется: экран не получает подтверждение сервера.

## Финальная карта Auto Layout · 03.10.2026

Для карты Content Builder с клиентскими изменениями используйте отдельный [MAX Content Exporter](../../../artifacts/DESIGN/figma-plugins/max-content-exporter/README.md). Он переиспользует этот сервер/очередь, но порядок и назначение контента читает из вложенных Auto Layout и фактического текста, без классификации по именам фреймов. Старый режим Collector сохранён.

## Windows: временная блокировка журнала · 03.10.2026

Запись общих JSON использует atomically2.1.1 с fsync, очередью по пути и ограниченными повторами EPERM/EACCES/EBUSY (10с). Постоянная блокировка остаётся ошибкой, ACK не выдаётся. После ошибки нажмите «Экспортировать / продолжить»: подтверждённые файлы проверяются и пропускаются. Не удаляйте журнал/папку; новая выгрузка для продолжения не нужна. [Проверка реальной блокировкой](../../../artifacts/reports/figma-export-windows-write-20261003.md).

### Сводка MAX Content Exporter

После «Прочитать карту» выводятся миссии, количество заданий и количество экранов каждого задания. Иконки без экранов показаны отдельно, проблемные строки включаются в общий счёт с явной пометкой. Вложенные UI не должны становиться миссиями. Эта сводка описывает прочитанную карту до выбора экспортируемых визуалов; снятие флажков меняет очередь выгрузки, но не структуру источника.

Чтение карты Content Exporter выполняет поверхностный аудит: внутренний визуал задания — граница обхода, берутся только прямые дети области экрана. Полный fingerprint и чтение исходных изображений отложены до команды экспорта. Все вложенные тексты справки сохраняются. Обычный Collector не переключён на этот режим.

Уточнение 03.10.2026: в области экрана TEXT не считается визуалом; прямой фрейм «Действия внутри устройства» исключается как кнопки даже при отсутствии данных Builder. Оставшийся прямой визуал экспортируется целиком. В сводке заданий сопоставлены количество экранов и количество кандидатов-визуалов; пробелы/лишние визуалы не скрываются при равенстве сумм.

Подготовка Content Exporter показывает номер визуала и число проверенных слоёв. Глубокая проверка при экспорте уступает event loop каждые64 слоя и обрабатывает «Остановить». Подготовка не означает сохранение: дисковое подтверждение по-прежнему показывается отдельным счётчиком. Внутреннюю операцию Figma exportAsync невозможно прервать этим способом.
