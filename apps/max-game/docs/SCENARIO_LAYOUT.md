## Сценарии

- Блогер: MAX и три задачи по контуру квадрата/ромба. Сборка направляется в порядке канал → комментарии → статистика; новые ограничения выполнения заданий не добавлены.
- ID: MAX сверху, именованное место «Создать Цифровой ID» в центре; нажатие открывает пикер одной иконки. После постановки одновременно доступны три плюса. Пользователь назначает отель, льготу и возраст любым свободным местам. При выполнении создание ID остаётся обязательным prerequisite.
- Общение: MAX и пять задач на кольце. По одному следующему плюсу, выбор любой оставшейся задачи; выполнение независимо. Голосовое/кружок и стикер/реакция остаются альтернативами внутри задания.
- Бизнес: MAX, подключение аккаунта, один выбранный инструмент. Три бизнес-инструмента — варианты пикера, не три обязательных задания.

Путь по-прежнему сначала собирается полностью, затем «Продолжить» открывает этап заданий. Места сборки не открывают телефон. Задания, ответы, заглушки клиентских сцен и поведение попапов сохранены.

## Геометрия и состояние

`src/journey-topology.mjs` возвращает постоянные позиции по semantic ID и список доступных мест с `id`, `allowed`, `label`, `named`. `PICK` сохраняет `slot`, `PLACE` проверяет допустимость задания и занятость места, затем пишет необязательный `object.slot`. Для старых сохранений назначения детерминированно восстанавливаются из задач и их порядка; ответы и координаты playing не сбрасываются. Версия сохранений остаётся совместимой с v1. Старые программные PICK без slot поддержаны; игровой UI всегда передаёт slot.

Каждый плюс имеет отдельный motion ID `route-add:<slot>`. Позиции существующих узлов при достраивании неизменны. Анимация MAX сохраняет reveal240ms и hold500ms, затем летит к позиции шаблона. Следующие места ждут окончания intro. Выбор/перелёт/отмена используют существующий renderer и clock; библиотек и render targets не добавлено.

На невысоком host (<540 logical px) используются двухрядные варианты: блогер2×2, общение2×3, ID — MAX/создание наверху и три применения ниже. На просторной странице — ромб/кольцо/три уровня ID. Сохраняются UX1–1,8м и отдельная область движения0,8–2,2м. Минимально проверенные логические размеры:1712×405,816×405,1520×780,820×880. 816×405 проверен расчётом как запас переносимости, несколько игровых зон сейчас не включены.

Пикер дополнительно резервирует18px вокруг уже существующих защитных областей для роста иконки во время перелёта. `safeFlightPath` рассчитывает один раз путь вокруг расширенных прямоугольников (плитка/подпись/бейдж). Пружина проходит безопасные опорные точки с замедлением у поворотов. При отсутствии прохода постановка не выполняется, отображается подсказка; это не полноценный динамический solver. Во время сборки фоновые узлы неподвижны, кроме малого парения, покрытого запасом. Свободный drag доступен после сборки как прежде.

## Связи и мастер

Удалены ранний отказ chooseObject и подсказка «Выбери иконку с другой стороны». Выбор любой доступной иконки проходит прежнюю анимацию/однократный commit; расположение меню не определяет доступность. В крайнем fallback визуальное пересечение при перелёте допустимо, итоговые места и защита размещения меню сохранены. [Проверка](../../../artifacts/reports/max-picker-unblocked-20260929/README.md).

29.09.2026 — смена грани теперь анимирована через `TileEdgeMotion`: угол порта движется по кратчайшему пути вдоль текущего скруглённого контура. Critical spring omega14 сохраняет позицию и скорость при повторном выборе грани. Размер, центр и радиус берутся из текущей плитки, поэтому перенос самой иконки не получает дополнительного отставания. Нормаль и обе управляющие точки кривой следуют за портами. Один state на существующее ребро, тот же delta рендера, pause/reduced motion; новые ребра сразу появляются на своих гранях. Приоритет выбора сторон не изменён: отдельный вариант «по внешнему контуру схемы» отменён пользователем до реализации. [Проверка](../../../artifacts/reports/max-smooth-ports-20260929/README.md).

29.09.2026 — обе редакции Journey соединяют середины ближайших граней плиток (верх/право/низ/лево). Близость стороны оценивается до центра соседней плитки; допуск 8% меньшего размера удерживает выбранные стороны при парении. `tileEdgeCurve` получает текущие визуальные bounds, включая scale, перелёт и drag; `syncScene` переводит точки в плоскость WebGL. Кубическая кривая с выходящими наружу касательными и мягким прогибом для соосных плиток семплируется в существующие 80 точек. Пять волокон, 32 частицы, фазы, цвета и правила правильности сохранены. Новых render targets/RAF нет; сферические связи других режимов не изменены. Это локальный изгиб между парой плиток, не поиск пути вокруг всех подписей/других объектов. [Проверка](../../../artifacts/reports/max-edge-links-20260929/README.md).

В клиентской схеме связи определяются сценарием: ID→каждое применение, MAX→возможности общения, цепь блогера, MAX→аккаунт→инструмент. Перестановка/drag не превращает их в связи с ближайшими соседями. Дальность10 размеров плитки, мягкое затухание последних18%; фазы и стиль волокон прежние. Перелетающая иконка участвует до сохранения PLACE. В первой редакции сохранён nearestLinks/MST с дальностью7 плиток.

Worker мастера загружает `/max-game/client/?surface=right&service=1&layout=single`. Клиентская страница пока фиксирует single, включая входящее сообщение layoutMode; настройка текущего источника сохранена single. Операторский селект2зоны скрыт, ссылка «полное качество» ведёт в client. Для будущей многопользовательской разработки понадобятся явное назначение сессий посетителям, область каждой зоны и правила их жизненного цикла; общий storage/глобальный прогресс для разных людей недопустимы.
