# Figma-плагин текущего Guided Reveal

[Локальный плагин](../../../artifacts/DESIGN/figma-plugins/max-journey/README.md) устанавливается через manifest; готовый офлайн-runtime лежит в его `internal`. Текущий снимок30.09.2026:6 миссий,139 основных экранов,216 полных. Старый экспортёр сохранён в `artifacts/workspace/backups/max-figma-plugin-before-reveal-20260930`.

## Каталог

`catalog.mjs` использует настоящие clientContent, taskFor/tasksFor, RevealJourney и media registry. Снимок включает сериализованные данные и точные session/phase/elapsed/activeId; анимационные фазы устанавливаются только экспортёром. Через текущие переходы получаются ладонь, все узлы в burst, посадка в arrange, задания/ответы/ошибки/результаты и завершение. Все6 клиентских миссий, включая2 тестовые и3 бизнес-ветки, проверены CPU. Варианты формата и сферы сохраняются отдельно; дополнительные кадры каждой галереи входят в полный режим.

Три начальные композиции без подписей и связей. Снимок линии показывает весь путь: manualNodes и отдельная toolPosition бизнес-узла фиксируют координаты200+i×320, ширина max(1600,N×320+128). Это обзор экспорта, не изменение камеры/сохранения игры. Прочие состояния используют реальные размеры/позы контроллера при сцене1600×1000. Нет самостоятельной копии сценариев.

## Сборка и источник

`build.mjs` собирает `journey-guided-main.js` и все его зависимости через существующий esbuild. Встроены CSS circular/journey/guided/line/reveal, config/icons/brand, цифровой ID, клиентские медиа, сюжетные фото и шрифты. Канонический символ MAX взят из брендового пакета. `source-manifest.json` фиксирует SHA256 для 256 исходников/ассетов; `screen-inventory.json` перечисляет кадры без внутренних состояний.

Экспортные адаптеры применяются только в памяти сборщика. Live-исходники/runtime/прогресс игры, мастер и TD не изменяются. Проверяется единственное ожидаемое вхождение патча; Source adapter drift останавливает сборку. Адаптеры добавляют framebuffer capture, метаданные SVG/CanvasTexture, offline fetch/src/HTML, изолированное хранилище и фиксированное начальное зерно. Clock контроллера заморожен, foreground устанавливает позу штатным владельцем движения. После шрифтов и decode изображений ждём1700мс для установления позы, затем читаем base/full и отдельные слои. Сюжетные фото и SVG не перерисовываются.

Под Frost нижние объекты остаются в base PNG; содержимое route-phone извлекается отдельно, даже если на нижнем слое. SVG сохраняет UTF-8 и оригинальную геометрию. Скрытый полный PNG позволяет сверять реконструкцию. Редактируемый Max Sans включается только после проверки доступных начертаний, иначе строки остаются PNG.

## Протокол

UI→sandbox: start/screen/finish/cancel; ответы: started/screen-added/finished/error. По одному кадру с подтверждением, boot timeout60с. Созданные экраны сохраняются при остановке; переключение страницы не меняет страницу назначения. Каждая миссия — отдельная группа,3 колонки, общий шаг учитывает максимальную ширину выбранных кадров. Metadata содержит mission/kind/step/stage/branch/device/media/revision.

Проверки входа:1…450 кадров, ширина1600…3600, высота1000, максимум1200 слоёв, PNG<24M символов. Manifest: Figma Design, dynamic-page; единственный разрешённый сетевой домен — `https://api.figma.com` для чтения комментариев. Создание экранов остаётся офлайн. Установленному плагину сервер и Node не нужны.

## Экспорт клиентских комментариев · 01.10.2026

Тот же manifest id сохраняет доступ к приватным `max-source` существующих экранов. Отдельное действие читает выделенные фреймы/группы текущей страницы и получает все комментарии файла через `GET /v1/files/:key/comments`. Токен вводится только в UI, не передаётся sandbox и не сохраняется. Альтернатива — импорт массива комментариев или REST-ответа `{comments}`. Ссылка на файл обязательна: публичный Plugin API может не предоставлять fileKey. Если ключ доступен, несовпадение останавливает экспорт; иначе JSON содержит предупреждение, что ключ задан пользователем.

UI→sandbox: `review-init`, `review-export`, `review-cancel`; ответы: `review-init`, `review-result`, `review-error`. Параллельная генерация/экспорт блокируются. Отмена, смена страницы или удаление выбранного экрана не выдают устаревший результат. Чтение не меняет выделение, viewport или фреймы.

Единственный результат — `max-review.json`, schema=`max-review`, version=1. `screenMap` содержит Figma node id, имя, страницу, геометрию/матрицу, предков, видимость и исходную metadata. `commentMap` сохраняет оригинальные поля и нормализованную геометрию/association; `threads` связывает ответы с корнем. Все исходные комментарии, включая resolved, вне выделения и повреждённые ветки, остаются в файле; неоднозначные перечисляются в `unassignedCommentIds`. Экспортируются также использованные anchors, scope, warnings и summary.

Приоритет сопоставления: явная привязка к экрану/его потомку → геометрия контейнера → точка/область внутри экрана → ближайшие кандидаты. Повороты учитываются через absoluteTransform, тени не расширяют экран. Многозначные области сохраняют несколько экранов. Свободные абсолютные координаты без подтверждённой страницы имеют статус `unknown-page`; UI предоставляет явную опцию текущей страницы. Близость остаётся рекомендацией, не подтверждённой привязкой. Повторные семантические id не объединяют разные Figma node id.

Лимиты: 1000 экранов, 60 000 обходных узлов, 10 000 комментариев, 3000 anchors, входной JSON до 20 МБ, запрос до 45 секунд. Источник исследования — [сопоставление комментариев](../../../docs/Research/figma-comment-screen-matching-20261001.md); [проверка реализации](../../../artifacts/reports/max-figma-comments-20261001/README.md).
