Использовать одну активную вкладку. Для смены renderer закройте предыдущую, затем откройте другую: default sessionId `site-shared`, общий ключ `max-site-shared:v1:missions-20261002-v2`. Тип канала, screenId, ответы, scan, таймер и результаты восстанавливаются из общего SessionPort. После восстановления нажмите текущую иконку, повторное сканирование не нужно. `session=` выбирает явную другую сессию внутри того же профиля.

`?backend=server` использует общий HTTP/SSE SessionPort без fallback. API Stand Service пока выключен; эта итерация не создаёт конфиг, не активирует/не перезапускает мастер. При выключенном API отображается ошибка запуска, а не локальная игра. Исторические страницы без backend-параметра сохранены; их старые ключи не импортируются автоматически.

## Разделение обязанностей

Mission Core/каталог v2 — шесть миссий, 16 заданий, действия/инструкции/ассеты, подтверждение удержания, результат и прогресс. `webgl-session.mjs` — команды со source screen/revision, владельцы ввода, подписка, дедупликация и late-result guard. Общий Browser PersistencePort вынесен из Site в application.

`journey-shared-reveal.mjs` переиспользует RevealJourney для поз/движения. Не вызывает legacy ANSWER/restore/save или legacy semantic tick. Backend snapshot подтверждает scan и результат; визуальный clock сам их не засчитывает. Один существующий renderer/RAF, прежние материалы, связи, оболочка телефона/PC и переход содержимого. `journey-shared-ui.mjs` строит телефон/информационную плашку из descriptor, без правил перехода. Hotspots привязаны к пикселям исходного изображения. Информация справа без интерактива; пробелы явно показаны и не получают успешного зачёта.

При смене задания departing descriptor сохраняется до окончания phone-exit; новый экран и инструкция используют screenId. Старый кадр сохраняется до подготовки нового; предварительно декодируются первые ресурсы задач/prepareNext. GPU upload остаётся в прежнем renderer; технические CPU-проверки не подтверждают визуальную готовность GPU.

Координатные пространства Site и WebGL различаются. База WebGL хранится в том же backend под `renderer:webgl:<missionId>:<nodeId>`, Site-позиции сохранены. Временный сдвиг для телефона не записывается. Ядро проверяет принадлежность узла миссии; namespace позволяет последующим renderer иметь собственную базу. Перенос координат между разными пространствами без утверждённого mapping не выполняется.

## Сборка и проверка

После duplicate guard: `node artifacts/max-game/scripts/build-webgl-runtime.mjs`. Изолированно компилируется guided-app.js, обновляются общие ESM/ассеты, Site wrapper общего PersistencePort и исправленный Site polling. Стили, страницы, app.js и пользовательские данные не переписываются. Манифесты обоих комплектов обновляются; изменённые пользователем генерируемые файлы блокируют сборку.

Проверка пользователем: блогер → ладонь → плюс в телефоне → публичная ветка/ссылка; закрыть вкладку, продолжить через Site, затем вернуться в WebGL. Дополнительно: приватная ветка, ID и две сюжетные фотографии, бизнес в PC, раннее отпускание и рестарт. Сообщить о визуальных отклонениях скриншотом.
