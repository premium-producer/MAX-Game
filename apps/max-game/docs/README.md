# MAX — Космос на связи

27.09.2026 — версия 0.4: три независимых стеклянных круга на всей стене, один исходный WebGL renderer, локальные световые полосы поверх прежнего фона. circular-main.js / circle-model.mjs / circular.css активны; старые 16:9 и сдвиг отменены. [Текущий контракт](CLIENT_MISSIONS.md).

Для дальнейшей разработки: [полный локальный контекст, skills и инструменты](DEVELOPMENT.md). Обращение к внешнему X-Спутнику больше не требуется.

MVP 0.1.0, 26.09.2026. Космическая игра на механике X-Спутника: разместить оборудование, настроить спутники и собрать работающий маршрут. Выбор космической подачи подтверждён пользователем. Сценарии связи — игровые условности, а не описание инфраструктуры MAX.

## Запуск и управление

Самостоятельно: `apps/max-game/Start.bat` → http://localhost:8785/. Нужен Node.js 22+ и браузер с WebGL 2. Повторный запуск открывает уже работающий сервер игры; чужой процесс на этом порту не останавливается. Другой порт задаётся `MAX_GAME_PORT`. Остановка — Ctrl+C в консоли самостоятельного сервера.

В Stand Service игра является сервисом правого экрана `max-wall-right`, назначенного `SCREEN_RIGHT`. Пункт «Игра MAX» → `/service/presentation.html?instance=max-wall-right` показывает и управляет тем же источником. Полотно 4096 × 1280, интерактивное поле 16:9 ниже центра, сдвинуто вправо на 2/3 своей ширины. [Размеры, Spout, ввод и применение сборки](../../stand-service/docs/MAX_GAME.md). `/max-game/` доступен для самостоятельной сессии. В переносимом комплекте используется сервер мастера; отдельный Node.js для игры не нужен.

Выбрать устройство в правой панели, затем коснуться места на Земле. Переключатель в шапке меняет касание на перетаскивание. Узлы можно перемещать; у спутников меняется высота. Земля вращается, нижняя полоса показывает порядок маршрута. Условие победы проверяется автоматически. В шапке доступны звук, RU/EN и возврат; в миссии — повторный старт. При скрытии страницы таймер не списывает время, проверка устойчивого соединения сбрасывается.

| Миссия | Время | Задача |
|---|---:|---|
| Есть пинг! | 120 с | Терминал → спутник → шлюз → ЦОД → интернет |
| Арктика на связи | 150 с | Собрать маршрут с учётом высоты и зоны действия спутников |
| Связь для большой страны | 90 с | Соединить два терминала через спутники и ядро сети |

Миссии открываются последовательно. Навигация: старт → обучение → карта миссий → игра → карта/финал. В MVP нет серверного профиля игрока или общего сохранения прогресса между устройствами.

## Исходники и сборка

Править `artifacts/max-game/`, затем из этой папки:

```powershell
npm ci
npm run build
node --test --test-isolation=none test/*.test.mjs
```

`npm ci` нужен при отсутствии зависимостей. Эквивалент сборки из корня: `node artifacts/max-game/scripts/build.mjs`; Python-обёртка — `artifacts/web/tools/build_max_game.py`. Готовый runtime не требует npm, исходного X-Спутника или сети.

Three.js 0.185.1 и esbuild 0.28.2 зафиксированы lockfile. Three упакован в изолированный `app.js`; библиотеки других приложений не обновляются. Сборщик копирует только используемый комплект, сохраняет `docs/`, записывает SHA-256 в `build-manifest.json`, проверяет пользовательские изменения runtime перед перезаписью. `source-manifest.json` фиксирует входы JS-сборки. Удаление устаревших выходов требует отдельной миграции.

Для интеграции пересобирается Stand Service штатным `build_service.py`; полный переносимый комплект собирает `build_master_portable.py`, включая `apps/max-game/`. Игра включена в полный переносимый ZIP мастера; актуальную проверку смотреть в [отчёте интеграции](../../../artifacts/reports/max-right-service-20260927/README.md).

## Контракты

| Файл исходников | Назначение |
|---|---|
| `src/game-state.mjs` | Экраны, доступность миссий, общий переход состояния |
| `src/mission-game.mjs` | Состояние попытки, установка/перенос устройств, время |
| `src/mission-evaluation.mjs` | Условия победы, построение и проверка маршрута |
| `src/screen-connectivity.mjs`, `src/route-layout.mjs` | Связность проекций и согласованный порядок нижней полосы |
| `src/webgl-field.js` | Постоянная 3D-сцена, Земля, камера, оборудование и эффекты |
| `src/main.js` | DOM, ввод, синхронизация сцены и состояния |
| `src/styles.css`, `src/max-theme.css` | Исходная геометрия интерфейса и оформление MAX |
| `public/config/ui-shell.json` | Макет 1920×1080, камеры, параметры рендера |
| `public/config/missions/index.json` и три JSON рядом | Каталог, правила, начальные условия и контент миссий |
| `public/config/wording.json` | Общие тексты интерфейса |
| `public/brand/` | Локальный срез пакета MAX: SVG, шрифты, tokens |

Сохранять версии схем и согласованную revision каталога/миссий. Код редакторов X-Спутника сохранён локально в upstream, но редакторы не подключены к MAX: контент меняется в исходных JSON с последующей сборкой. Runtime JSON не являются общим хранилищем настроек мастера; пользовательские настройки мастера остаются в `apps/stand-service/configs/`.

Режим связи исходных миссий — hybrid: наземные пары проверяются в мировой геометрии, связи со спутниками — в экранной проекции. Поэтому положение камеры влияет на часть связей. Нижняя полоса и проверка победы используют общий порядок маршрута. Установка устройства не означает мгновенную победу: учитываются пробуждение, актуальность снимка сцены и устойчивость соединения.

## Бренд и границы MVP

Max Sans Regular 400 / Medium 500 / DemiBold 600, официальный монохромный белый логотип, проектная адаптация трёхточечного градиента и шесть цветов пользователя взяты из [пакета MAX](../../../artifacts/DESIGN/BRANDS/MAX/README.md). Фиолетовая Земля и голубые акценты — адаптация сцены, не официальный 3D-ассет бренда. Цвета ошибки/успеха также подчиняются шести HEX из project-palette.json: сторонние красный/зелёный исключены. Старые QR, логотипы и Bureau-шрифты исключены.

Самостоятельная сцена рассчитана на пропорциональное поле 16:9; на других пропорциях остаются поля. В сервисе правой стены прозрачное поле встроено в общий фон задней стены с боковыми подсказками. Буфер рендера ограничен 2 073 600 пикселями. Это ограничение нагрузки, не измеренная гарантия FPS. Короткая проверка браузера не заменяет приёмку на сенсорном экране и целевом GPU.

Реализованы фоновый worker, Spout, назначение правому экрану, WebRTC и pointer API. Пока отсутствуют NDI, аудио в видеопотоке и редактор миссий в мастере; открыты физическая touch-калибровка, проверка LED/приёмника и финальная брендовая/сценарная приёмка. Однопользовательская сессия сбрасывается при перезапуске worker.
