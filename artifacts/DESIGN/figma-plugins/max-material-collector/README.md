# MAX — сборщик материалов клиента

Локальный Figma Design plugin. Читает существующие секции и экраны; макет не меняет. Использует действующий сервер Frame Archive, как последняя выгрузка бренда VK.

## Запуск

1. Откройте **Start-Server.bat** в этой папке. Сервер запустится в фоне; повторный запуск проверяет существующий экземпляр. Состояние: http://localhost:47831. Нужен Node.js 22+.
2. В Figma один раз повторно импортируйте **manifest.json** через Plugins → Development → Import plugin from manifest: теперь плагину разрешено подключение к локальному серверу.
3. Откройте нужную страницу, выделите секции или выберите «Вся текущая страница». Нажмите «Найти экраны».
4. Проверьте список, назначения групп, порядок и опции PNG / структуры / растров / SVG. Имена и порядок меняются только в каталоге выгрузки.
5. Нажмите **«Экспортировать / продолжить»**. Под кнопкой показаны прогресс проверенных экранов и полный путь результата.

Экран экспортируется → передаётся → записывается → проверяется с диска → сервер подтверждает → начинается следующий. Плагин не собирает все картинки в памяти и не скачивает общий пакет.

## Одна папка с датой экспорта

```text
artifacts/DESIGN/figma-exports/2026-09-29_16-30-00/
  export.json
  catalog.json
  texts.json
  coverage.json
  index.html
  Комментарии/
    Ответы/
      Комментарий-—-1-(начало)/
        screen.png
        preview.png
        screen.json
        texts.json
        figma.json        (если включена структура)
        screen.svg        (если включён SVG)
        images/           (исходные растры экрана)
```

Время — начало выгрузки, местное время компьютера; при совпадении секунды добавляется -2. Имена секций/подсекций сохраняются, недопустимые для Windows символы очищаются. Исходные полные имена и ID остаются в JSON. ZIP, общий PDF и упакованный JSON с картинками не создаются. Сырые материалы остаются локально, в GitHub не публикуются.

При сбое снова нажмите **«Экспортировать / продолжить»**. После закрытия Figma заново прочитайте ту же область с теми же настройками и назначениями. Сервер найдёт прежнюю папку и проверит SHA-256 всех подтверждённых файлов: целые экраны пропустит, отсутствующие/повреждённые выгрузит повторно. Перезапуск сервера также поддерживается. Незавершённые служебные записи находятся в runtime сервера, вне папки результата.

**«Новая выгрузка»** всегда создаёт новую датированную папку. Изменение списка, содержимого распознаваемых слоёв, порядка, назначений или настроек также создаёт отдельный экспорт. Во время выгрузки макет лучше не редактировать. После внешнего изменения компонентов/переменных, которое не отражается в прочитанных свойствах, используйте «Новую выгрузку».

Каталог сохраняет тексты/стили, связи прототипа, исходные изображения, структуру и назначение экранов. Наличие материалов не доказывает полноту клиентского сценария. Если текст — часть картинки или кривых, он не извлекается автоматически. Шрифты, видео и реальные анимации не выгружаются.

## Структура и порядок

- Основной режим — **«По секциям и именам фреймов»**. Поддерживает `SECTION → FRAME` и `SECTION → SECTION → FRAME`, а также группы-контейнеры. Подсекция, оформленная фреймом, распознаётся по непосредственно вложенным нумерованным экранам. Именованный экран экспортируется целиком; его вложенные UI-фреймы не становятся отдельными скриншотами.
- Полные имена сохраняются. Из `Комментарий — 2 (фокус инпута)` в каталог отдельно попадают серия `Комментарий`, номер `2`, описание `фокус инпута`. Поддерживаются дефис и короткое/длинное тире.
- Группы следуют структуре слоёв; внутри группы имена сортируются с числовым порядком: 1, 2, 10. Координаты на холсте не определяют последовательность. Порядок можно поправить вручную. Переходы прототипа хранятся отдельно.
- Группы определяются ID контейнеров и показывают полный путь `Секция / Подсекция`. Одинаково названные подсекции не сливаются. Выбор родительской секции и её дочернего фрейма не дублирует экспорт.
- Пропорции и размеры экрана не используются для угадывания. Назначение задания берётся только из названий экрана и родителей; неизвестное остаётся неназначенным и доступно для экспорта. Тексты рядом с экраном не влияют на этот режим.
- JSON сохраняет `containerPath`, `sectionPath`, `groupName`, `sequence`, исходные ID/имена. Сервер создаёт соответствующие папки контейнеров с читаемыми русскими именами, PNG/SVG/JSON каждого экрана. Исходные имена полностью остаются в метаданных; имена файлов очищаются для Windows.
- **«Старый макет · поиск по виду и заголовкам»** оставлен отдельным режимом для прежних неструктурированных страниц. Только там действуют поиск портретных экранов, близлежащих заголовков и геометрический порядок.

## Ограничения и разработка

Только текущая страница; остальные страницы выгружаются отдельно. Скан: до 30 000 видимых слоёв и 500 экранов, максимум 12 000 слоёв в одном экране. PNG 1×/2×, сторона до 4096 px. Полезные данные ограничены 200 МБ на один экран; HTTP-запрос — 300 МБ с учётом base64. Общего лимита на всю очередь нет. REST JSON может содержать ссылки на внешние компоненты/переменные; результат не является автономным .fig-файлом.

```powershell
node artifacts/DESIGN/figma-plugins/max-material-collector/build.mjs
node --test --test-isolation=none artifacts/DESIGN/figma-plugins/max-material-collector/collector.test.mjs artifacts/DESIGN/figma-plugins/max-material-collector/server.test.mjs
```

Исходники: core.cjs, runtime.js, ui.template.html, server-client.js, server-store.mjs. Сборка создаёт code.js и ui.html, используя проверенный SHA-256 из Frame Archive. Сервер и launcher общие с pdf-export; не переносите одну папку MAX без соседнего pdf-export. unpack.mjs оставлен только для ранее сохранённых пакетов; текущая выгрузка его не использует.
