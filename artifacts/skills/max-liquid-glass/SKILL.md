# Liquid Glass MAX

29.09.2026 — новое указание пользователя: плохой Frost исправить или заменить blur. Активен `overlapping-mip-blur-v2`: четыре перекрывающиеся mip-выборки без преломления под матовыми контролами. Общий BACKDROP_BLUR_GLSL для фона/волокон/UI, LOD≤5 и footprint≤56native px; сохранять premultiplied alpha, исходные bounds и резкий foreground. Это заменяет исторические требования9taps/LOD4 и refraction кнопок ниже. Числа Figma сохраняются как исходные, новая калибровка записывается отдельно. Без новых RT/проходов/RAF. Снижение числа выборок не выдавать за измеренный рост FPS.

28.09.2026 — «Миссия выполнена» — локальный матовый WebGL-попап поверх поля. `.field-success` включён в foreground layer1 и маску JourneyContextGlass; UI под ним размывается существующим RT, фон/волокна получают context Frost36px. Плавное появление420ms и парение±2px используют прежний clock, reduced-motion даёт неподвижный результат. Остальные игровые объекты приглушаются до45%; подпись объекта, чья плитка перекрыта попапом, скрывается целиком. Нет общего затемнения фона. Кнопка «К миссиям / К финалу» остаётся резкой. Контролы имеют явный приоритет button→popup→world, обе оптические маски выбирают первый покрывающий слой, а не минимальное SDF-расстояние. Полный рефакторинг фильтров всех task-попапов этой правкой не заявляется.

28.09.2026 — контекст задания: выбранная плитка остаётся единственным видимым экземпляром и фиксирует текущую позу; скрывается только её подпись. Остальные узлы плавно приглушаются до45%, фон не затемняется. Карточка раскрывается вокруг исходной плитки, скрытый task-icon служит только layout-якорем. objectContextPresence общий для foreground и оптики. Карточка сильнее матовая:36logical px (WEB-калибровка поверх референса Frost56.25). JourneyContextGlass размывает реальный UI под ней/телефоном: один переиспользуемый RGBA8 mipmapped RT, прогретый вместе с шейдером при загрузке в существующем renderer; без открытого задания дополнительного прохода нет. Sharp popup рисуется после фильтра, выбранная плитка — последним слоем. Профили — glass-profiles.json/contextCard. Не считать blur только фоновых волн достаточным: соседние глифы/текст тоже обязаны попасть под Frost. Дополнительный RT разрешён для этой композиции, не создавать RT на каждый объект.

Начать с [glass-profiles.json](../../DESIGN/BRANDS/MAX/glass-profiles.json): это источник параметров двух пользовательских референсов Figma. Числа Refraction/Frost/Depth не являются документированными единицами WebGL. Не менять профиль ради настройки картинки: калибровку записывать отдельно в webCalibration и синхронизировать с `max-panel-optics.js` тестом. Палитра и scope — [max-brand](../max-brand/SKILL.md).

Целевой результат — [референс матовой карточки](../../max-game/incoming/glass-frost-target-20260928.png). [Отклонение](../../max-game/incoming/glass-frost-rejected-20260928.png): резкая световая связь пересекает лицо иконки; это ошибка порядка слоёв, не недостаток внешнего glow.

1. Перечислить содержимое за стеклом. В MAX это градиентные течения **и связи с их bloom**, а не только текстура фона. Размытие должно смягчать тонкую линию до цветового пятна под всей иконкой. Белый знак, текст и badge рисовать после оптики резкими. Не оставлять sharp core поверх Frost и не скрывать дефект непрозрачной фиолетовой заливкой.
2. Большая панель преломляет реальный фон; кнопка имеет собственные матовость и фаску. Нужны скруглённый SDF, конечная фаска уже радиуса, устойчивые нормали, ограниченное смещение. Не добавлять хроматическую дисперсию, цветные контуры, толстый neon rim или блики под читаемым текстом.
3. Использовать существующий Three.js renderer. В Journey активная цепь: фон → clear-panel + frosted controls; отдельно premultiplied linear fibers+bloom → Frost по тем же bounds → резкие UI-глифы. В Stand Service слои в разных контекстах: оба фильтруются одинаковой маской, без CPU-копирования между ними. При изменении слоёв проверить, что эта декомпозиция остаётся корректной.
4. `journey-fiber-glass.mjs` переиспользует HDR target `webgl-field.js`. Один mip-chain на кадр со связями; fullscreen-композиция заменяет прежний output pass. Девять выборок только внутри control footprint, с prefilter LOD. Нет буфера/рендера на каждую кнопку, `readPixels`, screenshot/canvas-upload в RAF, новых контекстов/RAF. Без связей HDR/bloom/Frost-проход пропускается. Геометрия/материалы переиспользуются и освобождаются при dispose.
5. В прозрачном target очищать RGB и alpha в ноль. Фильтровать premultiplied RGB и alpha вместе; перевод linear → sRGB делать один раз. Не читать из активного framebuffer. Не смешивать CSS blur и shader так, чтобы подложка рисовалась дважды.
6. Bounds, радиусы и scale должны совпадать у стены, волокон, движущихся иконок и hit-target, включая letterbox и two-zone. Стекло невидимых/перекрытых контролов не должно размывать связи. Сохранять `data-glass-revision`, максимум 20 форм, tile culling и halo64: суммарные offsets ≤56 native px.
7. Короткая проверка: тонкая яркая связь пересекает иконку; снаружи волокна различимы, внутри становятся широким мягким пятном, знак резкий. Также открыть меню/задание, сдвинуть узел, проверить консоль и фактический мастер/сайт по [vk-live-verification](../vk-live-verification/SKILL.md). Число тестов не доказывает визуальное соответствие или FPS. Тяжёлую GPU-проверку согласовывать по AGENTS.
