# Единый запуск мастера

Для всех игр и экранных модулей один мастер. Каноническая инструкция — [STARTUP.md](../../../apps/stand-service/docs/STARTUP.md). Начать с последних записей WORKLOG: состав модулей мог измениться; не пересказывать старый статус как текущий.

## Команды

Из корня проекта в PowerShell:

```powershell
$env:VK_LAUNCH_NONINTERACTIVE = '1'
& ./apps/STARTUP/Check.bat
# Только если задача требует запуска:
& ./apps/STARTUP/Start.bat --no-open
# Только если задача требует остановки/перезапуска:
& ./apps/STARTUP/Stop.bat
```

Переменная отключает только pause консоли, а не проверки. Не запускать master через electron напрямую, сервер Node/Python, `npm start` отдельной игры или временный скрипт. Старые Stand Service Start/Stop и portable-корневые батники — совместимые делегаты тех же команд. `start.mjs` — внутренняя реализация, а не альтернативная инструкция запуска.

В ограниченном Windows sandbox агента запуск Electron может аварийно завершиться: `FATAL mojo ... platform_channel.cc`, `Access is denied (0x5)`, `spawn EPERM`; пользователь видит окно Breakpoint `0x80000003`. Для этой рабочей среды это подтверждено логами 29.09.2026. При запуске мастера через агент использовать штатный запрос `require_escalated` для того же Start.bat, сохраняя механизм проверки разрешений; не повторять известный нерабочий sandbox-запуск. Это не требование запускать приложение от администратора и не повод отключать Chromium sandbox/антивирус. После ошибки сначала проверить offline/живой мастер и хвост лога, затем повторить штатную команду с разрешённым доступом. Другие причины `0x80000003` без диагностики к этому случаю не приравнивать.

Стандарт с 30.09.2026 по последнему указанию пользователя: `Start.bat` запускает облегчённый `dev` по умолчанию; `StartDemo.bat` или `SwitchToDemo.bat` включают нативный `run` **только по явному запросу пользователя**. `SwitchToDevelopment.bat` штатно возвращает dev. Адрес `http://localhost:8770`; не переопределять порт и не подменять localhost на 127.0.0.1. В dev сохранённые разрешения и назначения остаются для показа, фактический рендер временно уменьшен и Spout по умолчанию выключен. LAN-agent — отдельная задача. Не включать отключённое автоматически.

## Проверка

После изменения/восстановления файлов, перед сборкой и запуском выполнить `python artifacts/web/tools/check_project_duplicates.py`. При найденных копиях `(2)` не выбирать версию по имени/дате: сравнить изменения и подтверждённые хэши, сохранить обе стороны в `artifacts/workspace/backups/`, согласовать исходники и пересобрать runtime штатными сборщиками. Новые текущие изменения могут быть новее копии. STOP и read-only Check допустимы при обнаруженных копиях; не блокировать безопасную остановку. Перед стартом сохранить таблицу source/runtime/HTTP и затем сверить generation. `codeRevision` текущей версии — время запуска, не fingerprint содержания.

1. `Check.bat` ничего не запускает. Проверяет projectId/nodeId этой копии, текущий режим, наличие включённых источников, состояние running, продвижение program и включённых выходов между двумя снимками одной generation. В показе Spout должен быть sending и registered; в разработке он по умолчанию выключен. Код 0 — эти проверки прошли; ненулевой — читать конкретную причину. Результат без токенов: `artifacts/workspace/runtime/master-startup-check.json`, время checkedAt обязательно сверять с текущим запуском.
2. `Start.bat` переиспользует подходящий мастер, затем выполняет ту же проверку. Не перезапускает источники ради проверки. Если порт занят другой копией, режим отличается или готовность не достигнута, остановиться и диагностировать; не taskkill, не обходить проверку свободным портом. Штатный stop/start своей копии допустим, когда задача включает её перезапуск. После Stop дождаться подтверждённого offline; если остановка не удалась, не продолжать новым запуском.
3. Если цель — применить изменённый код, сначала штатные сборки, затем [vk-live-verification](../vk-live-verification/SKILL.md). Успешный повторный Start не загружает новую сборку в старые процессы. Перезапуск только затронутых источников предпочтительнее полного; серверные изменения требуют stop/start по этому стандарту.
4. Одна короткая браузерная проверка фактического мастера/потребителя: ошибки консоли и видимый результат. Не создавать дополнительные игровые процессы ради проверки. Тяжёлые прогоны — только по правилам AGENTS, запись видео запрещена без указания.
5. При работе с TD читать Envoy skills, обнаружить живой экземпляр/сеть. Проверить эффективный Masterurl=localhost:8770, Autosync, live_poll, connection_note, surface_status, ошибки и внутренний out1. Локальные legacy-адреса нормализуются скриптом assets/scripts/live_surfaces.py. Для текущего стенда ожидается 6 поверхностей от 5 источников, обе ленты используют один источник; сверять с актуальными assignments. Снять малый кадр фактического out1; для зависшего изображения сравнить два кадра через реальное продвижение времени. Если TD недоступен, сообщить «выходы мастера проверены, приём TD не проверен». Не запускать/закрывать TD автоматически и не менять сцену ради статуса.

## Результат

Отдельно сообщать: мастер доступен; источники/Spout передают; приём TD/изображение подтверждены или нет. Готовность запуска не означает достижение 60 FPS. Не печатать/сохранять полный `/api/state` с csrf. При изменениях — запись WORKLOG с фактическими проверками и ограничениями.
