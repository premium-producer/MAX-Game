# Непрерывное движение MAX

29.09.2026 — последнее уточнение пользователя **заменяет прежнее скрытие при любом движении**: гасить пути только при замене уже выбранной иконки или обмене шагов/слотов. Обычный MOVE, полёт новой иконки, REVEAL и перестроение позиций при добавлении сохраняют видимые связи; порты/кривые следуют текущим позам через TileEdgeMotion. Открытие селектора ничего не гасит. `changesExistingRoute` сравнивает назначения существующих узлов; `RouteReconnect` включает прежний fade-out/freeze/reveal только при их изменении. Не использовать общий connectionsMoving как условие suspendedScopes.

Политика интерактивной динамики MAX — [max-interaction-motion](../../max-game/skills/max-interaction-motion/SKILL.md). 29.09.2026: нажатия при переходе идут через JourneyIntent (один последний запрос на зону, контекст привязан к исходному state); повтор ANSWER при смене контента только подтверждается. CLOSE прерывает вход popup с текущими presence/velocity, отменяя старый commit. Поле остаётся интерактивным, глобальный inert не применять вместо политики ввода. Связи коротко затухают с **замороженной** геометрией; новый порт разрешён только при opacity0, затем мягкое появление после покоя иконок. Это уточняет мгновенное скрытие в старой записи ниже; перетаскивание не ждёт затухания. Параметры переходов — TRANSITION_MOTION.

Не возвращать чтение DOM bounds после transform как источник движения. ## Владение движением

- Состояние x/y/size/radius и скорости принадлежит паре «host зоны + step id», не DOM-узлу. При menu → placing → field передавать то же состояние. Ретаргетить цель, не начинать каждый сегмент с нулевой скоростью.
- Опорная точка — центр tile. Подпись с несколькими строками не меняет pivot. Геометрия, input и optical masks получают одну позу в одном prepare до расчёта связей/рендера.
- Не завершать перелёт только по timeout. Проверять малую ошибку и скорость; commit ровно один после финального видимого кадра. Отменённый callback не может поставить объект после закрытия меню, смены миссии, layout или паузы.
- Размер, скругление, блик, caption и badge — часть перехода. Не обнулять hover/glow при новом владельце. Текущий caption скрывается на перелёте и проявляется после handoff, чтобы его перевёрстка не прыгала. Сохранять правило CTA пустого поля.
- Drag меняет целевую позицию и сохраняет semantic progress только при отпускании. Отмена возвращает цель, не коммитит. Не пересоздавать DOM/геометрию всего поля после MOVE.

28.09.2026 — после посадки подпись и badge раскрываются раздельно: label omega10/задержка40мс, badge omega8/задержка110мс. До90% яркости примерно430/600мс. Не возвращать общий быстрый effect20 для этих элементов. Видимость хранить в общем motion-state, не CSS transition/таймере; при восстановлении готового объекта не проигрывать раскрытие заново. Reduced motion пропускает задержки.

## Расчёт и ресурсы

Текущий адаптер использует closed-form critical spring с сохранением velocity, не Euler и не постоянный lerp-коэффициент за кадр. Сравнивать30/60/120Hz для постоянной цели; не обещать точное равенство при движущейся цели или паузе. Reduced motion и пауза обязательны. Не добавлять второй RAF/ticker к Three-loop без явного согласования clock/порядка.

Математика движения сама по себе не требует RT/blur/readback. SVG-геометрия кэшируется, текстовые textures обновляются только при изменении layout. Общий фон/блики/Frost не заменять другой графикой ради анимации. Для стекла читать [max-liquid-glass](../max-liquid-glass/SKILL.md).

## Проверка

Сначала отделить C0-скачок позиции/размера от C1-сброса скорости, layout-скачка подписи, дрожания shader bounds и просадки кадра. Аудит конкретной реализации — artifacts/reports; сравнение подходов — docs/Research.

Проверять: выбор во время движения, обычная посадка, отмена, повторный выбор, края поля, две независимые зоны, drag/release, восстановление, reduced motion. CPU-инварианты: state identity и скорость до/после handoff, конечные значения при большом delta, отсутствие лишнего commit. Затем короткая проверка одной вкладкой по [vk-live-verification](../vk-live-verification/SKILL.md). Не выдавать статический скриншот за доказательство качества движения или короткую проверку за60FPS benchmark. Тяжёлые прогоны/видео — только при отдельном разрешении пользователя.
