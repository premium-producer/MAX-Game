# MAX — сверка плана и проверка этапа 3

02.10.2026. [Контракт реализации](../../apps/max-game/docs/SHARED_BACKEND.md), [архитектура](../../docs/Research/max-game-shared-backend-20261002.md).

Этапы 1–2 повторно сопоставлены с планом. Исправлены два пропуска: answer=null обходил validation; freezeTaskCatalog пропускал вложенные изменяемые поля при уже frozen верхнем объекте. Добавлены отдельные проверки обоих случаев.

Реализован Application/SessionPort: создание/чтение сессии, очередь команд, подписки, lifecycle close, обязательный PersistencePort и явно выбранный memory profile для headless-логики. Snapshot содержит актуальный state и общий ViewDescriptor без outcome/markup, receipts остаются внутри владельца. Есть отдельный пустой раздел layouts; API редактирования ручных поз ещё не реализован и относится к этапу 9.

PASS: 82/82 CPU-проверки, около 0,06 с: 26 каталог, 39 kernel, 17 Application. Для нового слоя проверены одновременные разные/одинаковые команды, актуальный snapshot вместе с историческим receipt, ожидание commit, сбой до записи, потеря ответа после записи, восстановление Application на том же store, CAS conflict, неверный ACK store, sync/async ошибки слушателей, независимость сессий и захват команды до ожидания, закрытие во время записи/подписки, повреждённый state, public annotations и недоступность кнопок completed, immutable snapshots/catalog registration и чистые импорты.

PASS: node --check шести затронутых source/test модулей, duplicate guard и diff --check. Браузерный entrypoint не изменён, runtime build не запускался. Мастер/текущая игра/публикация/пользовательские сохранения не затронуты. Отдельный визуальный стенд не создавался.

Memory profile не является долговременным backend: повторное использование объекта store проверяет контракт восстановления, завершение процесса теряет данные. Следующий этап — реальный SQLite worker после проверки совместимости хоста; HTTP API, leases, timer/scan, все миссии и миграция остаются открытыми. Наличие отдельных CPU-модулей не означает подключения текущего пользовательского экрана к новой логике.
