# MAX v5: STORAGE_UNAVAILABLE — первая диагностическая итерация

03.10.2026. Пользователь подтвердил сбой в отдельном браузере. Доступные инструменту браузеры: внутренний Codex и MCP Apps; отдельный браузер недоступен. Внутренний профиль открывает сохранённое меню без STORAGE_UNAVAILABLE.

## Изменение

Стартовая ошибка теперь показывает безопасную цепочку кодов Error.cause, различает quota / access denied / неверный формат. Диагностика выведена из масштабируемой arena поверх сетки, чтобы код читался в wall и lidar. Нет удаления ключей, сброса миссий, миграции, нового хранилища или fallback в память.

## Проверки

- 2 теста PASS. На реальном установленном V5 Session Application воспроизведён QuotaExceededError при ownership commit; наружу приходит STORAGE_UNAVAILABLE с исходным cause. Последние сохранённые байты неизменны.
- SecurityError/SyntaxError различаются, неизвестный payload не выводится, цикл cause не зацикливает форматирование.
- Syntax двух исходников, duplicate guard PASS; scoped build28/198, HTTP28/source198 SHA PASS.
- Короткий запуск актуальной страницы во внутреннем браузере. У пользователя это другой storage origin profile, поэтому успешный внутренний запуск не доказывает исправление его сбоя.

## Открыто

Сбой пользователя пока НЕ исправлен и его причина НЕ подтверждена. Нужен код после обновления страницы `?backend=local&layout=lidar&v=storage-diagnostic-1`. Далее — одна адресная правка с сохранением прогресса. UI ошибки проверен тестом форматирования; живую ошибку отдельного браузера инструмент не видит.
