# MAX — техническая проверка локального Figma-сборщика

## Дополнение: лимит pluginData

Полный JSON дерева исходного интерфейса мог превышать 100 КБ на запись. Заменён на компактный отпечаток fp1; старые baseline мигрируют, отсутствующие после сбоя восстанавливаются с пометкой baselineRecovered. В модель API добавлен жёсткий лимит 100000 байт, регрессия большого экрана из 300 текстовых слоёв проверяет размер отпечатка, обнаружение правки, восстановление и миграцию. Все 7 CPU-тестов PASS (~2.9 с), синтаксис/сборка/duplicate guard PASS. Реальный редактор по-прежнему проверяет пользователь.

## Дополнение: текущая страница

По пользовательской проверке выявлен лимит Starter при createPage. Создание страниц убрано; результат размещается справа на текущей странице. Дополнительный CPU-тест проверяет три уже существующие страницы, запрет createPage, смену страницы во время сборки, сохранение существующих объектов и ручной позиции контейнера. Все 6 тестов PASS (~2.7 с), сборка/syntax/duplicate guard PASS. Повторная проверка в редакторе ожидается. Прежнее описание отдельной страницы ниже относится к первой версии.

02.10.2026. [Комплект и запуск](../DESIGN/figma-plugins/max-content-builder/README.md). [Основа компоновки](../../docs/Research/max-figma-content-builder-20261002.md).

Создан отдельный локальный плагин из текущего каталога: 6 миссий, 16 заданий, 65 уникальных экранов, 60 оригинальных ресурсов (23 971 668 байт до base64). Все ресурсы встроены; manifest запрещает сеть. MCP не использовался. Игра, мастер, прежние плагины и Figma-файл не изменялись.

- Duplicate guard: PASS.
- Сборка: PASS; SHA всех 60 файлов совпали с каталогом.
- Синтаксис runtime и готового code.js: PASS.
- CPU-модель Plugin API: 5 тестов PASS, около 2.2 секунды. Сверены все пары missionId/screenId, обе ветки, 6 миссий, горизонтальные и вертикальные Auto Layout, центровка справки, PC-область, явные пробелы; повторная сборка без новых узлов; сохранение пользовательской инструкции и JSON; отмена с последующим завершением; ошибка шрифта без изменения документа; offline-комплект.
- Первый запуск Node test runner с изоляцией не смог создать дочерний процесс (spawn EPERM); выполнен штатный повтор с `--test-isolation=none`.

## Граница проверки

Модель API не подтверждает реальную геометрию, производительность импорта, доступность Inter или работу клонирования исходных компонентов в редакторе. Реальный Figma не запускался по рабочему процессу пользователя. Копирование двух известных исходных интерфейсов имеет безопасный fallback на встроенные PNG. Содержимое PNG не объявляется редактируемым текстом.

Ручные изменения сохраняются. Новая версия изображения, конфликтующая с существующим, не заменяется автоматически; требуется ручное решение. JSON содержит карту/значения/признаки изменений, но не новые байты заменённых изображений и не комментарии. Задания с пробелами остаются помеченными, новые ассеты не выдумывались.

## Проверка пользователем

1. Импортировать manifest, собрать все миссии. Убедиться, что появилась отдельная страница; исходная не затронута.
2. У блогера проверить обе приватности; у бизнеса — широкие экраны; у ID — по две фотографии на ситуацию.
3. Удлинить инструкцию. Справка должна вырасти и остаться по центру высоты этапа, соседние этапы сдвинуться через Auto Layout.
4. Повторить сборку: текст сохранён, новых копий нет. Скачать JSON и проверить изменённую инструкцию.
