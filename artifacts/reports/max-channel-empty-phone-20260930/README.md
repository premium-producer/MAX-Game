# Пустой телефон на первом шаге «Стать блогером»

30.09.2026. Пользователь показал пустую фиолетовую рамку при таймере2:46: связь «Канал → телефон» и справка «Чаты» видны, внутренний экран отсутствует. Предыдущий отчёт о готовности телефона был слишком широким: успешная проверка другого кадра и `img.complete/naturalWidth` не доказывали сборку первого WebGL-экрана блогера.

## Исправление

`syncLinePhone` ждёт `decode()` всех изображений активного кадра и выдаёт отдельный `mediaReadyKey`. WebGL-адаптер не кэширует телефонное изображение до декодирования, а после сборки `.demo-app` и видимых image-материалов отмечает `gpuReadyKey` только после первого рендера. `phone-enter` проявляет рамку, когда оба ключа совпали с `sceneVersion`. Подготовка экрана не останавливает trace связи. Уже открытый телефон не гасится при смене этапа.

## Проверка

- Duplicate guard PASS; `node --check` обоих изменённых JS PASS; 42/42 целевых CPU-теста; штатная сборка MAX326 файлов/91 модуль; `check-local` PASS.
- При браузерном размере присланного кадра1948×1177 запущен первый шаг блогера с чистым review-прогрессом. На таймере2:48 DOM-изображение кадра чатов декодировано (`naturalWidth=360`, `gpuDecoded=true`), `mediaReadyKey=gpuReadyKey=sceneVersion`, внутренняя чёрная область с чатами, «+» и справка видны одновременно. При промежуточной пробе поймана и исправлена ошибка области видимости callback `failed`; проверка затем повторена на новой сборке.
- Источник `max-wall-right` перезапущен локально; generation `bd9485f6-884c-4562-8002-ca651bd04a28`, `running`, кадры продвигаются, `error=null`. `Check.bat` PASS в dev; presentation показал поток меню. Лог браузера содержал ошибку промежуточной пробы до исправления, нового повторения в итоговой прямой странице не наблюдалось.

Визуальная самопроверка конкретного кадра PASS. Одна короткая проверка не является статистической гарантией от всех редких сбоев и не заменяет художественное утверждение пользователем. TD/Spout в dev отключены; публикации не было.
