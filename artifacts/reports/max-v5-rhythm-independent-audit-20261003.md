# MAX v5 — независимая проверка ритма, 03.10.2026

Статус: read-only аудит исходников до правки текущей итерации. Браузер, GPU и сервер не запускались. Оценка художественной плавности остаётся у пользователя.

## Подтверждённые причины

- `journey-guided-reveal.mjs:155–164`: arrange сначала ведёт к compact layout и затем к обычному ряду. `V5RevealJourney.pose` до `spread` использует этот путь, а при trace начинает применять отдельный Flexbox-ряд с устройством. Это две разные конечные раскладки, а не просто задержка загрузки.
- `journey-webgl-ui.mjs:557`: видимые координаты дополнительно догоняют уже меняющуюся во времени цель arrange через `V5MotionValue` с omega 6.5. Номинальные 0.85 секунды arrange не равны времени видимой посадки. Камера отдельно движется с omega 7.5.
- `journey-v5-inertia.mjs`: автоматические иконки 6.5, drag и телефон 14. `journey-guided-main.js:394–402`: phonePresence 8, камера 7.5. `journey-v5-route-layout.mjs`: handoff links 12. `journey-v5-device-morph.mjs`: содержимое 24/20, ширина 10. Эти разные частоты объясняют заметную разницу темпа.
- Начальный trace длится фиксированные 1.2 секунды (`REVEAL_TIMING.trace`), следующий trace в handoff — около 0.675 секунды до своего критерия покоя. Одинаковое визуальное действие имеет разные clocks/критерии.
- `foreground.isSettled` ждёт connectionsMoving; тот требует ошибку <2 px, скорость <4 px/s и ещё 0.12 секунды устойчивости. Камера, width и phone применяют намного более строгие критерии. Хвост после визуально завершённого перемещения может задерживать следующую фазу.
- Появление popup запускается только после alpha телефона >0.55; popup имеет свой transition. Это намеренное смещение, но оно дополнительно растягивает составное появление. Убирать задержку без проверки пустого содержимого нельзя.

## Предложение для текущей малой итерации

1. Резервировать окончательную раскладку телефона уже при выходе из круга. Цели на границе arrange→trace должны совпадать. Не добавлять вторую предварительную раскладку и новый animation engine.
2. Вынести v5-only токены: автоматическое движение и камера omega10; drag14 сохранить; presence/link12; content14; width10. Это рекомендация для интеграционной проверки, а не утверждённый художественный результат. Не менять общие константы старых редакций.
3. Начальный trace и handoff trace согласовать по одной фазе или длительности; не оставлять два независимых 1.2/0.675с поведения.
4. Применить один критерий для единичной прозрачности. Для ширины рассмотреть rest0.5px/3px/s вместо0.05/0.2: текущий невидимый хвост занимает около0.6с после99%. Проверить финальный остаточный сдвиг перед snap. Не подменять readiness одним таймером.

Используется уже установленный готовый damping maath 0.10.8 (MIT). Обоснование и исходные ссылки: [исследование handoff](../../docs/Research/max-v5-task-handoff-20261003.md), [исследование morph](../../docs/Research/max-v5-device-morph-20261003.md). Нового математического механизма аудит не предлагает.

## Риски и приёмка

- Сохранять current pose/velocity при новой цели; не seed/recreate в середине arrange.
- Не менять drag14 вслед за travel: рука требует более короткого отклика, чем автоматическая перестройка.
- Не снимать decode/GPU guards, token/epoch отмену, backend ready gates ради ускорения.
- Проверить 30/60/120Гц, скрытие страницы, reduced motion, ранний/повторный контакт, restore, handoff и финал QR. Автоматический тест не доказывает приятный ритм.
- Пользователь должен проверить один старт до телефона и один межзаданный handoff. Видео и нагрузочный прогон не выполнялись.

## Повторная независимая проверка после правки

Проверены новые `V5_MOTION` и их wiring: travel10, drag14, presence12, trace0.65s, popup0.45/0.45s, resize rest0.5px/3px/s. `V5RevealJourney.spread` теперь включается в arrange и `pose` сразу отдаёт Flexbox-ряд с телефоном; на границах arrange→trace→phone-enter→task цели остаются одинаковыми. `focusCurrent` уже в arrange выбирает цель камеры с устройством.

Влияния на прежние редакции в просмотренных изменениях не обнаружено: `JourneyTransition` принимает необязательный timing, по умолчанию прежний; `IconMotion.presenceOmega` по умолчанию null с прежними константами; `SharedRevealJourney` использует прежний REVEAL_TIMING без v5 override; maath alpha/label/badge включается через v5 adapter.

Замечания, переданные основному агенту для решения в интеграции:

- Из-за presence12 вместо24/20 простой crossfade без изменения ширины стал медленнее: приблизительно1.27с вместо0.76с до критериев покоя. Ритм согласован, но это осознанный tradeoff; окончательное восприятие требует пользователя.
- Popup exit0.45s может предварительно задерживать handoff unlink, потому что `foreground.busy(host,true)` приостановит контроллер до конца косметического ухода справки. Ранее этот барьер был0.16s. Проверить возможность не блокировать handoff исключительно локальным popup-fade, сохранив content/scene барьеры.
- Существующие до правки pause-различия: main palmPresence, popup transitions, instruction motion и IconMotion получают dt без v5 pause-gate, тогда как morph останавливается. В аудите не утверждается полное покрытие browser hidden/pause.
- Существующее до правки начальное phone-enter использует декодированный phoneReady в settled; явный GPU deviceReady проверяется в handoff. Это не новая регрессия, но различие нельзя скрывать утверждением одинакового readiness всех путей.
