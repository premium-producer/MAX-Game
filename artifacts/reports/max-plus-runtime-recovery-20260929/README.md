# MAX — повторное исправление плюса и уменьшение крупной редакции

29.09.2026. Повторный пользовательский снимок показывал финальную статистику поверх MAX.

## Причины и исправления

Основной `journey-main.js` не содержал импорта/вызова slot-placement, в large-blocks стоял масштаб 3; согласованная реализация оставалась в локальных копиях `(2)`. Пофайлово сверены различия и восстановлены соответствующие исходники и тесты, а не весь проект. Копии оставлены; предыдущее состояние основных сохранено в `artifacts/workspace/backups/max-slot-recovery-20260929`. Причина внешнего расхождения не установлена.

Проверка check-local теперь требует, чтобы алгоритм поиска слота действительно присутствовал в source-manifest. Старый согласованный по хэшам bundle без этого модуля больше не проходит проверку.

Браузерный проход большого поля выявил дополнительную проблему: суммарная рамка обычного профиля съедала свободный ряд. Крупные контролы используют padding/gap 2px, начальные крайние позиции учитывают эту рамку. Добавлен тест размещения всех исходных слотов, включая шесть узлов общения.

Последнее указание пользователя уменьшило крупные элементы в 1,5 раза. Теперь `LARGE_BLOCK_SCALE=2.5/1.5`, плитки 180px вместо 270px, варианты выбора/подписи/управление масштабируются вместе, окна вписываются отдельно. Обычная клиентская версия остаётся 108px.

## Проверка итоговой сборки

- 293/293 CPU-теста passed: [лог](tests.log). Syntax проверен для восстановленных JS; check-local pass; сборка 207 файлов / 85 модулей.
- HTTP и runtime app.js SHA256: `07295CA80191B5844C336E06F002CB43B3CA2669D23EED75226FBABC52FD26B5`.
- Одна вкладка, `/max-game/large-blocks/`, 1280×720. Сборка блогера до финальной статистики; затем новая сборка ×1,67 и перенос MAX на центр финального плюса. Получен отдельный плюс в свободном месте. DOM-проверка пересечения плитки и подписи плюса со всеми установленными плитками/подписями: пустой список. Реальный CSS tile 180px, caption font 38.3333px. [Геометрия и консоль](browser.json).
- Check.bat после окончательного обновления: 5 источников running / Spout sending; MAX 25.7 FPS в коротком снимке. Это не проверка производительности.
- Перезапущен только MAX worker; общая оптика/палитра rear не изменялась этой задачей. TD status вернул connected=true, но instance reachable=false; новый приём TD не подтверждён. Отдельного полного браузерного прохождения остальных миссий не было, для них проверен алгоритм.

Без публикации, видео, тяжёлого GPU-прогона и изменения TD-патча. Художественная приёмка пользователем остаётся открытой.

Финальная повторная check-local после документирования обнаружила изменение общего `artifacts/service/public/rear-wall-style.js` относительно manifest. Эта задача его не редактировала; повторная сборка с непроверенным внешним изменением не выполнялась. 54 собственных скомпилированных исходника MAX повторно совпали. Поздняя HTTP-проверка получила connection refused: мастер стал недоступен после успешной браузерной проверки. Указанные выше HTTP/pass относятся к моменту сборки; полный текущий source/runtime parity общего проекта уже не подтверждён.

Финальный HTTP снова доступен и совпадает с указанным SHA256 runtime. Расхождение общего исходника rear-wall-style.js остаётся отдельно от проверенной сборки MAX.
