## Результат

Открытая карточка экрана получает исключительный доступ. У остальных участников оранжевая рамка, отметка «СЕЙЧАС РЕДАКТИРУЕТСЯ» и недоступные кнопки открытия. Другие карточки доступны. Prev/next также проходят серверный захват. Сначала сохраняются правки текущей карточки, затем освобождается доступ; несохранённые изменения не отбрасываются молча.

Verrou0.5.2/MemoryStore,30сTTL, heartbeat8с, список занятости2с. При потере связи форма перестаёт принимать ввод, поздний ответ не восстанавливает доступ. Экспорт копии остаётся внутри модального окна. При аварийном закрытии доступ освобождается по TTL, при штатном — после сохранения. Server restart аннулирует токены без записи в JSON. Политика ограничена одним Node-процессом, не несколькими репликами. [Ресерч с ограничением готового driver и регрессией](../../docs/Research/max-card-locks-20261004.md).

GET/POST /editor/api/max-asset-locks. CSRF/Origin/BasicAuth сохранены. Публичный список не отдаёт capability; randomBytes32token обязателен для занятой карточки, даже при совпадающем clientId. Проверка прав выполняется в общей очереди записи. Merge/CAS/legacy API не обходят чужую блокировку; shared help/final проверяют затронутую область. JSON/schema3 не менялись.
