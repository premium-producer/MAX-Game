# MAX v5 — исправление Unprepared MAX image

03.10.2026. Пользователь прислал ошибку запуска на `icon-glyphs/max-icon.channel.svg`.

Причина в интеграции preload и GPU warmup: первый batch содержит все четыре состояния каждой иконки одновременно. `takeImage` переносил единственный подготовленный HTMLImageElement в первый узел; второй потребитель того же URL получал false из-за isConnected. Это ошибочно трактовалось как незагруженный ассет. Предыдущие тесты проверяли отсутствие кражи живого DOM-узла, но не весь путь многократного использования SVG в одном batch.

Исправлено только использование подготовленного изображения: `getImage` возвращает общий decoded source; реальный `image()` renderer передаёт его в Canvas drawImage. Элемент разметки продолжает задавать размеры, материал и владельца ввода. Warmup проверяет наличие source, не пересаживает его в DOM. Отсутствующие ресурсы по-прежнему вызывают явную ошибку. Исходные SVG, backend, миссии, градиенты и движение не изменялись этим исправлением.

PASS12 CPU: регрессия вызывает реальную функцию image() с восемью одновременными потребителями одного SVG (четыре статуса в двух миссиях), одним запросом/декодированием и уже подключённым source; все восемь получают правильный источник без изменения DOM. Также загрузка/отмена и прохождение готового backend. Canvas host в CPU-тесте инструментирован; это не доказательство GPU-отрисовки.

Syntax, duplicate guard и scoped build PASS. HTTP28/28 и193 source SHA совпали; [машинный отчёт](max-v5-svg-warmup-20261003.json). Параллельные изменения исходников сохранены. Мастер не перезапускался, browser/GPU не запускались. Пользовательская проверка: загрузка до меню → выбор миссии → удержание ладони.
