# Проверка Figma-плагина MAX 28 сентября 2026

## Исправление offsetLeft

Пользователь получил `Cannot read properties of null (reading 'offsetLeft')`. Единственное такое чтение в игровом исходнике — fieldRect. Экспортёр очищал host и вызывал arrangeRoute раньше render, поэтому .playfield отсутствовал. Восстановление изменено на: снимок без task/picker → render → fit → arrangeRoute → восстановление picker/render → восстановление task/renderTask. Это также сохраняет picker, который штатный fit закрывает.

После пересборки 13 тестов проходят. Новый тест выполняет настоящий bridge и DOM-зависимые функции раскладки из игры для 48 компактных снимков (24 × 2 редакции), с моделями DOM, Canvas и WebGL; проверяет сохранение requested picker/task. Это CPU-регрессия, не визуальная или GPU-проверка. Новый результат в Figma ещё не подтверждён.


## Проверка сокращённого режима

Сборка и 12 CPU-тестов проходят. Для обеих редакций проверены ровно 24 снимка, 4 группы по 6, порядок состояний, первый MAX, picker, один поставленный смысловой объект, полное поле и открытое первое задание. Бизнес представлен веткой канала. Это проверка каталога и кода; рендер нового набора в настоящем Figma ещё не подтверждён.


## Изменение назначения страницы

По запросу пользователя новая страница больше не создаётся. Обновлённый sandbox-тест подтверждает добавление слоёв на исходную страницу, отступ 240 px от существующего объекта, сохранение этого объекта и отсутствие принудительного перехода после ручной смены страницы/отмены. Сборка, 10 тестов и проверка синтаксиса проходят. Проверка в реальном Figma остаётся открытой.


## Исправление после пользовательского запуска

Импорт плагина подтверждён скриншотом пользователя; после «Собрать экраны» результата не было. Скриншот показывает не загруженное превью и недоступные в видимой части окна действия. Ограничен размер превью, оно скрыто до onload; footer со статусом и прогрессом остаётся видимым. Убрана зависимость приёма sandbox-ответов от WindowProxy родителя — такой же дефект ранее исправлялся в Frame Archive. Добавлены явный сигнал готовности игры и ранняя передача JS/CSP/boot-ошибок. Отмена больше не скрывает сообщение об ошибке.

После исправления сборка и 10 CPU-тестов проходят. Три новых проверки моделируют реальный relayed/null-source ответ Figma, последовательность ready → start → screen → ack → finish, отказ boot без создания пустой страницы и обработку preview. Это подтверждение поведения кода в тестовой модели; точная причина зависания в пользовательской Figma без её сообщения об ошибке окончательно не установлена. Базовая браузерная проверка остаётся заблокирована прежним запретом file:-предпросмотра; обход не выполнялся. Новый одиночный экспорт в настоящем редакторе и визуальная сверка остаются открытыми.


Результат: [локальный плагин](../../DESIGN/figma-plugins/max-journey/README.md), подготовленный из текущих исходников обеих редакций игры. Готовый UI примерно 2,53 MB; 187 клиентских и 208 текущих состояний, 96 исходников/ассетов в SHA-манифесте.

## Выполнено

- Сверены реальные `journey-main`, reducer, задачи обеих редакций, WebGL foreground, фон/стекло, CSS, брендовые SVG/WOFF2.
- Сборка esbuild прошла. Требовала расширенного выполнения дочернего процесса после sandbox EPERM; изменения ограничены каталогом плагина.
- `node --check` новых JS/MJS пройден; оба скрипта встроенного игрового HTML и UI дополнительно разбираются Node VM.
- 7 Node-тестов проходят: все этапы всех миссий/бизнес-веток и общий финал в обеих редакциях; зависимости и альтернативные форматы; независимость состояний; автономные ресурсы и отказ внешнему URL; создание страницы/слоёв и сохранение результата при отмене в тестовой модели Plugin API.
- Проверено, что необходимые planar-ассеты присутствуют: mono logo, endpoint A/Б и встроенные data-SVG; исходный знак MAX добавлен из брендового пакета.
- Тест выявил и помог исправить подстановку `$&` при упаковке JS через String.replace; упаковка теперь использует callback, встроенный bundle корректно парсится.
- Адаптер не изменяет файлы игры; native SVG используется без перерисовки. Max Sans не заменяется случайным шрифтом. Применены max-brand: исходные логотипы, роли 400/500/600 и действующая игровая палитра.

## Не подтверждено

- Figma account-library create отклонён инструментом: `You don't seem to have permission to do that`. Предоставлен локальный manifest-плагин вместо ссылки на несуществующий опубликованный плагин.
- Встроенный браузер запретил `file:` для локального UI. Обход политики не выполнялся. Визуальная проверка автономного WebGL-экспортера в браузере и импорт в реальный редактор Figma не выполнены.
- Тестовая модель Figma API не подтверждает точность импорта SVG, политику iframe/CSP реального клиента или метрики нативного текста. Полное визуальное совпадение раздельных слоёв нужно проверить первым одиночным экраном; полный PNG-эталон предусмотрен для сравнения.
- Не запускались мастер, отдельный сервер, запись видео или тяжёлый GPU-прогон сотен кадров. Нагрузка и художественная приёмка остаются открытыми.

## Область изменения

Только новый плагин, его документация, ссылки общих документов и WORKLOG. Игра/её опубликованные редакции и существующий PDF-export не изменены. Коммит, push и публикация на Selectel не выполнялись.
