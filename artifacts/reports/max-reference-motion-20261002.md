# MAX reference: аудит движения, 02.10.2026

Область: `/max-game/webgl-reference/?backend=local&layout=wall`. Проверен код пути controller → targets → IconMotion → scenePose → WebGL/DOM/links. Браузерный обход не выполнялся по указанию пользователя.

## Найдено и изменено

- `SharedRevealJourney.tick` ожидал `settled` после burst и arrange. В reference это связывало очередность с малой скоростью всех пружин и камеры. Reference снимает это ожидание у двух декоративных стадий; старые адаптеры сохраняют поведение.
- Trace шёл1.2с перед началом phone-enter. В reference устройство появляется уже в trace; input задачи открывается только после readiness и входа. Media-load не превращается в принятый ответ.
- Старая слабая bob-анимация зависит от held/expanded. Новый drift4×6px следует общему frame clock независимо от фазы и выбранности. При drag управление остаётся у указателя; reduced motion отключает drift, hidden/service pause останавливают его clock.
- Раскладка проверяла только конечный горизонтальный промежуток. Новый чистый модуль `journey-reference-motion.mjs` выбирает ближайшее свободное место для фактических прямоугольников каждого кадра. Плитка и полная видимая подпись образуют защищённый bounds; телефон и ладонь — препятствия. Порядок владельцев стабилен, запас18px. Предыдущая поправка затухает, препятствуя мгновенному возврату после освобождения места. Справочный popup намеренно не участвует.
- WebGL, DOM transform и опубликованные optical bounds получают одну исправленную позу. Правила/прогресс и saved layout не изменяются; новый RAF/GPU pass отсутствует.

## Проверка

21/21 CPU: непрерывный drift30/60/120Hz, отсутствие пересечений в плотных движущихся fixtures с520px PC, reduced motion, переход без rest, readiness/drag/pause, прежние шесть миссий/restart/restore. Синтаксис основных модулей, duplicate guard и сборка PASS. HTML/guided-app.js на localhost:8770 возвращают200 и совпадают с runtime. Эти проверки подтверждают математику, а не FPS и не художественный результат.

## Пользовательская проверка

Перезагрузить новую страницу. Начать миссию с Цифровым ID, удержать ладонь, посмотреть круг → ряд → телефон. Проверить движение выбранной и остальных плиток, завершение задания, перетаскивание плитки к телефону и соседней плитке. Оценить отсутствие визуальных наложений и резких обходов. Непрерывность маршрута около плотных препятствий и фактическое измерение длинных подписей требуют этой визуальной оценки; она пока не выполнена.

## Коррекция по кадру старта

Пользователь показал смещение ладони вниз. В prepare обнаружен двойной учёт palm: препятствие из прошлого DOM rect и movable motion owner (data-route-next). Это создавало самоотталкивание; прежний набор проверял независимые объекты и не покрывал одну сущность в двух ролях. Добавлен fixed-owner в общей функции, renderer передаёт единственную текущую запись ладони. Для неё отключены correction carry и дополнительный drift.5/5 профильных тестов PASS; новый тест проходит удержание и рождение иконки при порядке icon-before-palm на30/60/120Hz. Фактический браузерный запуск отклонён auto-review по сохранённому пользовательскому ограничению. Новый кадр после исправления ещё не получен.
