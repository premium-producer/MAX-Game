# MAX — проверка этапа 2: чистое игровое ядро

02.10.2026. [Реализация/контракт](../../apps/max-game/docs/SHARED_BACKEND.md), [архитектура](../../docs/Research/max-game-shared-backend-20261002.md).

Добавлены общий GameCommand и Game Core. Ядро получает каталог аргументом, не импортирует канал, Site или WebGL. Канал используется как первый проверочный сценарий. Реализованы immutable GameState и отдельные receipts, приём ACT по текущему контексту/screen/revision, именованные ответы, явное завершение, идемпотентные повторы и проверка нового сохранённого формата.

PASS: 63/63 CPU-проверки ядра и каталога (39 новых), около 0,05 с. Проверены:

- приватная/публичная ветки, выбор на том же экране и возвращение к старой ссылке;
- created без зачёта до команды завершения; одно событие TASK_COMPLETED;
- повтор принятой команды после следующего действия и после JSON restore возвращает исходный reply без effects/изменения актуального state;
- повтор commandId с изменёнными данными, старый screen/revision, другая session/mission/task и недоступные действия;
- запрет передавать next state/answers/completed, неправильные типы/версии команд;
- восстановление каждого промежуточного экрана, сохранение типа канала и отказ на выдуманных ответах, отсутствующих/переставленных подтверждениях и изменённых правилах;
- отсутствие подстановки ответов из числовых legacy stages, независимость сессий, immutable state и чистые импорты;
- применение того же kernel к другому переданному каталогу/начальному экрану.

Это первый срез ядра одного активного задания, не общий сервер шести миссий. Очередь сессии, подписки, транзакционный commit, API, timer/scan и оркестрация миссии — следующие этапы. Проверка receipts при restore означает согласованность нового формата, не криптографическое доказательство пользовательских действий.

Синтаксис двух source-модулей и теста, duplicate guard и diff --check пройдены. Браузерный entrypoint не менялся, сборка runtime не запускалась. Текущая игра, мастер, пользовательские сохранения и публикация не затронуты. Отдельный визуальный стенд не создаётся: по последнему указанию пользователя сначала развиваются logic/backend.
