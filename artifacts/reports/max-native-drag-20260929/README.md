# MAX: запрет нативного браузерного drag — 29.09.2026

У всех четырёх шаблонов img (логотипы, экран ID, QR) задан draggable=false. Capture-обработчик dragstart на document отменяет HTML drag, включая динамические картинки/ссылки/выделение, не отменяя pointerdown/click игрового ввода. Общий CSS обеих редакций запрещает user-drag изображений, ссылок, SVG/canvas и draggable-элементов; user-select выключен вне полей ввода/contenteditable.

Проверено: syntax трёх изменённых JS; [243/243 CPU-теста](tests.log); build206/76; check-local pass. В одной вкладке захват прямо за изображение MAX переместил целый объект, затем объект возвращён. DOM подтверждает draggable=false и computed -webkit-user-drag:none у игрового логотипа и нового логотипа в попапе. Открытие задания с клавиатуры работает, console без warning/error. [Снимок после переноса](drag-logo.png).

Перезапущен только MAX, Check.bat pass, JS/CSS по HTTP совпадают с runtime, остальные поколения сохранены: [метаданные](runtime.json). В той же вкладке проверен стартовый экран фактического presentation-потока.

Только локально. Другие приложения стенда, Selectel и Git не изменялись. Полный проход всех заданий, физический touch/TD и художественная приёмка не проверены; видео/тяжёлых GPU-тестов не было.
