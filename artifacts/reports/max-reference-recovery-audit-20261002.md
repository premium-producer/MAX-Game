# Технический аудит восстановления MAX reference — 02.10.2026

**Статус: версия не принята, исправность старта не подтверждена.** Этот аудит не является выпуском исправления.

Область: третья WebGL-визуализация `/max-game/webgl-reference/?backend=local&layout=wall`, её общий Guided adapter, подготовка кадра, ввод и переходы. Общие backend-сценарии проверены CPU-набором; полная приёмка Site, legacy, GPU, всех экранов и стенда здесь не выполнялась. После текущего сообщения пользователя код игры и runtime не изменялись. Мастер не переключался.

## Почему прежние проверки пропустили поломку

1. Тест ограничителя принимал готовые прямоугольники; он не выполнял сбор владельцев из DOM и `prepare`. Поэтому двойной учёт ладони не попадал в тест.
2. Отсутствие пересечений проверялось независимо в каждом кадре. Расстояние между последовательными кадрами, сохранение скорости и непрерывность пути не проверялись. Телепортация проходила как правильный результат.
3. Тест контроллера передавал `settled` извне, но не проверял вычисление этого признака в реальном adapter. Успешные тесты ядра не подтверждали готовность телефона к нажатию.
4. Одновременно изменились phase-gates, момент появления устройства, парение и collision projection. Не было одного воспроизводимого стартового сценария и зафиксированного критерия до правки.
5. Сборка и совпадение HTTP подтверждали доставку файлов; пользовательская приёмка оставалась открытой. Формулировки «исправил» преждевременно распространяли технический результат на поведение игры.

## Проверено сейчас

- 75/75 существующих профильных CPU-тестов проходят. Это подтверждает сохранённые инварианты, но **не снимает MR-01…MR-06**.
- Контрпримеры MR-02/MR-03 воспроизводятся на текущих исходниках без браузера и без изменения пользовательского прогресса.
- [Скрипт диагностики](max-reference-audit-probes-20261002.mjs), [числа](max-reference-audit-probes-20261002.json), [лог тестов](max-reference-audit-tests-20261002.txt).
- Визуальная проверка после последней правки: **не выполнена**. Известен пользовательский кадр предыдущего дефекта и сообщение о текущей поломке. Нового разрешения после отказа auto-review на браузер не получено; обход не выполнялся.
- Производительность GPU, отсутствие ошибок WebGL и фактическое совпадение hit-target: **не подтверждены** этой проверкой.

## Решение по восстановлению

Не наращивать эвристики поверх solver и не объявлять старую сборку рабочим fallback без проверки. Сначала воспроизвести MR-01 через ту же функцию подготовки кадра, которой пользуется renderer; затем исправлять её по одному дефекту. Требование отсутствия наложений сохраняется, поэтому просто выключить ограничитель и назвать игру исправленной нельзя.

Целевая граница ответственности: backend → presentation targets → один frame coordinator (pose/velocity/presence/constraints) → WebGL, hit-target, links. Это **предложенное направление**, не уже реализованный рефакторинг. Извлечение frame coordinator сначала без изменения поведения; только затем замена collision projection на непрерывный маршрут/упреждающее освобождение места. Справочный popup остаётся разрешённым исключением.

Порядок работ и единственный список статусов: [общий бэклог](../../docs/BACKLOG.md#max-reference-recovery). Повторяемый чек-лист: [локальный контракт разработки](../../apps/max-game/docs/DEVELOPMENT.md#reference-change-gate). Отдельный новый бэклог приложения не создаётся.
