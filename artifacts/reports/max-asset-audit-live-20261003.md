# MAX — серверное сохранение разметки и свойства экранов

03.10.2026. Страница: http://localhost:8770/max-game/asset-audit/

## Собрано

- Запись завершённых правок в `apps/stand-service/configs/max-asset-audit.json` через GET/POST `/api/max-asset-audit`; отдельная конфигурация без мутаций игровой сессии.
- Готовая atomically 2.1.1 реализует запись/замену/fsync/Windows retry. Сервер валидирует schema2, идентификаторы и размеры, сериализует проверку ревизии и запись. Чужая ревизия получает409. Повреждённый файл не перезаписывается.
- UI сохраняет после изменения рамки, её положения/размера и флажков; подтверждает сохранение только после ответа сервера. Локальная IDB остаётся аварийным черновиком; экспорт необязательный.
- «Экран активен» и «Назначить финальным экраном задания» на карточке и в редакторе. Единственный назначенный финал на задание; отключение снимает финал, все экраны задания отключить нельзя. Разметка отключённого экрана сохраняется. Есть отмена и фильтры.
- Старые browser-only отметки сохранены; первый пустой сервер принимает их автоматически, иначе предлагается явное восстановление. Поддержан импорт schema1.

## Проверено

- Три субагента: исследование готового хранения; независимые тесты и аудит backend; реализация UI. Разделены владельцы файлов.
- 18 CPU-тестов PASS: исходные9 и9 серверных. Реальная запись atomically, чтение новым экземпляром, конкурентная старая ревизия, отказ диска, повреждённый файл, миграция, идентичность ассетов, ограничения финала/активности, субпиксельная рамка.
- Отдельный HTTP-тест штатного createStandService с фиктивными workers PASS: GET, запрет без токена/с чужим Origin, POST, повторное чтение с диска,409. Никаких игровых окон/нагрузки. Sandbox запрещал запуск read-only GPU telemetry; после разрешённого запуска тест прошёл. Вариант Node `--test-force-exit` вызвал Windows handle assertion после PASS; обычное завершение повторно PASS с exit0.
- Syntax/duplicate guard PASS. MAX audit90 файлов, service slice только server.mjs и сгенерированный max-game/asset-audit-store.mjs; переносимый ZIP не обновлялся.
- Независимый review нашёл и исправлены: потеря пустого dirty-документа при offline restore; округление слишком маленькой рамки до0 с последующей невозможностью чтения файла. Второй случай покрыт реальной записью/повторным чтением.

## Применение и ограничения

**Рабочий API ещё не активирован.** На момент проверки localhost8770 работал в run с пятью источниками. Новый route требует перезапуска общего мастера. У пользователя запрошено подтверждение краткого Stop → Start с сохранением режима; до ответа перезапуск не выполнялся. Финальная браузерная проверка autosave/reload/флагов на рабочем API ожидает этого шага. Предыдущая проверка страницы не считается подтверждением нового API.

**Настройки пока не изменяют прохождение.** Это явно указано в UI. Игра восстанавливает сохранение переисполнением receipts против конкретного каталога. Независимая проверка в памяти: подмена первого navigate на complete-task под старой ревизией даёт INVALID_SAVED_MISSION. Для следующей короткой итерации необходимы закреплённый каталог активного запуска, проверка отключаемых ветвлений и согласование вложенного channel coreCatalog. Ошибочные ответы не должны завершать задание, пустое задание не считается выполненным. Финал означает конец текущего задания после правильного действия, не конец всей миссии.
