# MAX — согласование динамики и состояний, 29.09.2026

Исправления логической части [аудита плавности](../max-motion-audit-20260929.md), после [сохранения сцены и подготовленного кадра](../max-retained-scene-20260929/README.md). Производительность не является предметом этой правки.

## Изменено

- Убран общий ранний отказ activate по busy и inert всей зоны. Один JourneyIntent на зону сохраняет последний запрос; контекст привязан к исходному state, навигация имеет приоритет. Короткий статус подтверждает ввод. Reset/branches и выбор иконки также используют очередь.
- Повтор ANSWER при принятом ответе подтверждается без применения к следующему этапу. Закрытие очищает очередь, отменяет переход контента и прерывает вход popup из текущего значения/скорости. Старый callback не выполняется после отмены. Обычные переходы сохраняют прежнюю хореографию, прерывание использует существующую аналитическую пружину.
- При отмене перелёта выбранная иконка удерживает текущую позу до ухода picker; посадочный callback удаляется. Уведомление повторного ввода обновляется без удаления/нового входа владельца.
- Связи гаснут на замороженной геометрии вместо мгновенного исчезновения. Даже короткий drag пересекает нулевую opacity перед пересчётом портов. Новая геометрия проявляется после окончания движения; перетаскивание не ждёт анимацию. Удаляемые пары и reduced motion учтены.
- Тогда был создан общий Motion Skill; позже пользователь уточнил его область действия, и он перенесён в [MAX interaction motion](../../max-game/skills/max-interaction-motion/SKILL.md). Обновлены документы и контракт разработки MAX. Общие параметры переходов собраны в TRANSITION_MOTION.

## Проверено

- `node --check` восьми изменённых исходников; 280/280 Node-тестов. Новые сценарии: последний запрос навигации, устаревший контекст, повтор ответа, отмена callback, непрерывность value/velocity, короткий drag/повторный захват при 30/60/120 Hz, reduced motion. [Лог](tests.log).
- Штатная сборка MAX: 206 runtime-файлов, 82 модуля. `check-local.mjs` сразу после сборки: pass. HTTP bundle совпадает с runtime. Только локальный MAX worker перезапущен; Check.bat: running/Spout sending. [Runtime](runtime.json). При финальном повторе check-local выявлено изменение `../service/public/rear-wall-style.js` после сборки (20:10 против сборки20:09). Полная сверка manifest: это единственное расхождение исходников, runtimeMismatches=[]; все motion-исходники соответствуют проверенной сборке. [Снимок сверки](snapshot-check.json). Параллельный общий фон не включён повторной сборкой в этот проверенный результат.
- Одна вкладка client: открытие/быстрое закрытие/повторное открытие канала; двойное нажатие «Создать канал» дало строго «Шаг 2 из 3» и статус «Ответ принят»; выбор доступа и закрытие; свободный перенос канала. После покоя moving=false, три связи, popup/очереди нет, console error/warn отсутствуют.
- В общении: BEGIN_ROUTE, picker, выбор видеозвонка и «Назад» во время перелёта — picker ушёл, остался только MAX; повторный выбор успешно завершён (ровно MAX+call, picker0). Проверены восстановление управления и отсутствие поздней отменённой посадки.
- В той же вкладке открыт реальный presentation мастера: running, корректное начальное изображение. [Поле](field.png), [мастер](master.png). Снимки подтверждают композицию; непрерывность математических переходов проверяют тесты, а не статичные изображения.
- Skill проверен вручную: YAML name/description, имя каталога, относительные ссылки, отсутствие scaffold placeholders. Bundled quick_validate не запустился из-за отсутствия PyYAML; зависимости не устанавливались.

## Ограничения

Полная художественная приёмка динамики остаётся пользователю. Тяжёлые тесты, видеозапись и GPU-профилирование не запускались. Check показал MAX23.4FPS, это не устранено и не относится к выполненной задаче согласованности. Приём в TD не проверен. Остальные приложения не переписывались: общий skill регулирует их дальнейшие изменения. Selectel и Git-публикации не выполнялись.
