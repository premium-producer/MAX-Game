# MAX v5: восстановление запуска после quota localStorage

03.10.2026. Пользовательским скриншотом подтверждён QuotaExceededError в отдельном браузере. Предыдущий диагностический этап установил причину; настоящее изменение устраняет зависимость записи v5 от localStorage.

## Реализовано

Локальный v5 SessionPort подключён к createIndexedDBPersistence через idb 8.0.3 ISC. Native readwrite transaction сравнивает version и атомарно записывает record; ответ только после tx.done. Lazy import точной старой записи, повторная проверка внутри транзакции, старый профиль только читается. Backend, каталог и ответы прежние; библиотека тестирования fake-indexeddb не входит в runtime. [Исследование и ограничения](../../docs/Research/max-indexeddb-local-profile-20261003.md).

## Техническая проверка — PASS

Независимый субагент создал и проверил 9 интеграционных тестов. Root выполнил вместе с diagnostic/layout restore: 12/12 PASS.

- Переполненный legacy store: setItem запрещён, import и ownership recovery продолжаются, старые байты неизменны.
- CAS двух соединений даёт одного победителя; конфликт create/import не перезаписывает запись.
- Неуспешный structured clone откатывает запись; повреждённый legacy не заменяется новым прогрессом.
- Разные профили и сессии изолированы.
- Настоящий v5 backend сохраняет public-link, ответы, layouts, receipt history; после холодного открытия повтор команд не даёт нового зачёта.
- Syntax изменённых JS, duplicate guard PASS.
- Build 28 файлов / 200 входных модулей; SHA28 HTTP и SHA200 исходников соответствует build.json. ISC notice включён в комплект.

## Короткая браузерная проверка — PASS

Одна вкладка внутреннего браузера, действующий URL `http://localhost:8770/max-game/webgl-v5/?backend=local&layout=lidar&v=indexeddb-1`. До обновления: восстановленная миссия блогера, «Канал / Продолжить задание». После обновления: те же узлы/статус, DOM dataset sessionStorage=indexeddb, assetPreparation=ready. Перезагрузка повторно восстановила этот статус, ошибок хранения нет. [Снимок после перезагрузки](max-indexeddb-local-profile-20261003.png).

Сохранена отдельная прежняя ошибка ожидания живой маски фона. Фон не изменялся. Прогресс не сбрасывался, миссия не проходилась заново. Полная миграция ответов/повторов дополнительно проверена CPU через установленный backend.

## Пользовательская приёмка — ожидается

Отдельный браузер пользователя инструменту недоступен; его накопившийся профиль не прочитан и не изменён вручную. Он перенесётся при следующем открытии обновлённой страницы. Старые вкладки v5 следует обновить, чтобы они не продолжали писать в прежний localStorage.

Оставшаяся архитектурная задача: ограничивать рост истории с доказуемыми checkpoints; обрезать receipts сейчас нельзя, поскольку restore проверяет историю replay. IndexedDB тоже имеет квоту/возможные отказы — при них стартовая диагностика сохраняется, fallback или очистки нет. Публикации, перезапуска мастера, видео и тяжёлых GPU-тестов не было.
