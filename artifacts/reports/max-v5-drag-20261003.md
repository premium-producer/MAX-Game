# MAX v5 — исправление захвата иконок

03.10.2026. [Исследование готовых механизмов](../../docs/Research/max-v5-drag-anchor-20261003.md).

## Установленные причины в реализации

1. V5 использовал reveal clamp на первом движении. Для допустимой видимой позиции worldY=-600 и deltaY=8 при hostHeight952 старый код подставляет -348 вместо -592: скачок цели244px. Это CPU-контрпример; точное положение иконки пользователя не измерялось.
2. Начальная точка пересчитывалась через tile bounds и host border box, хотя retained motion использует host content coordinates. Caption/hover/рамка не должны менять исходную точку drag.
3. Порог7px ещё не достигнут, но idle bob и hover продолжали менять видимую иконку. При drag использовалась скорость38 вместо телефонной14.

## Правка

Только v5 вызывает captureObject/releaseCapturedObject. Они работают с текущим владельцем IconMotion и его фактическими X/Y/size; отдельная DOM-поза не вычисляется. До порога движение/размер захваченной плитки сохраняются; при drag bob отключён, size остаётся прежним. Pointer delta учитывает масштаб arena; прежний clamp в v5 пропущен. X/Y используют реальный maath.damp с параметром телефона14. При отпускании/отмене сохранённая скорость не обнуляется. Камера фиксирует текущую цель при drag, как при перетаскивании телефона. Иконки после ответа по-прежнему возвращаются в ряд с gap400, телефон сохраняет anchor. Backend, ассеты, фон и прежние runtime не менялись этой правкой.
