# MAX — аудит разделения логики и визуализации

02.10.2026. Проверка фактических исходников. Новая архитектура пока **не реализована**. [Архитектурное решение](../../docs/Research/max-game-shared-backend-20261002.md).

## Область и метод

Сопоставлены текущая `site-game` и последняя WebGL-редакция `guided-reveal`; базовые/client/guided/line редакции рассмотрены как сохранённые исторические сценарии. Прочитаны модели, входы, задания, media, сохранения и сборщики. Выполнены чистые Node-пробы и 82 профильных CPU-теста. Браузер, GPU, мастер, пользовательские сохранения и серверные конфиги не менялись. Исторические жалобы на пустой телефон не считаются повторно воспроизведёнными этим аудитом.

## Риски и конкретные доказательства

1. **P0 при объединении: несовместимые идентификаторы и этапы.** Legacy миссии `digital-id/demo-benefit/demo-business`; site `id/benefit-test/business-test`. Legacy задания имеют id, site маршрут пока массив подписей и numeric index. Перевод нужен по смысловому id и версии сценария, а не по порядку элементов. [Legacy](../max-game/public/config/client-missions.json), [site](../max-game/public/site-game/model.mjs).
2. **P0 при миграции: восстановление может додумывать ответы.** `restoreSession` берёт done из stage и подставляет допустимый/правильный ответ, когда исходного ответа нет. Чистая проба `{channel, stage:3, answers:[]}` дала `done:true, answers:[0,0,0]`. Это поведение текущего восстановителя, не доказательство повреждения реальных сохранений. Новое ядро не должно использовать его как свидетельство выполнения новой цепочки. [Код](../max-game/src/journey-state.mjs#L108).
3. **P1: правила миссий уже различаются с принятой новой картой.** Legacy выбирает голосовое *или* видео; новый контракт требует голосовое → видео. В обеих старых бизнес-моделях остаются прежние шаги аккаунта/ID. Это расхождение контента/правил, не тема или shader. [Клиентские задачи](../max-game/src/journey-client.mjs), [тестовые миссии](../max-game/src/journey-presentation.mjs), [карта](../max-game/design/site-game-content-map-20261002.md).
4. **P1: domain и presentation смешаны.** RevealJourney содержит проверки ответов, timer, позиции, раскладку телефона и ожидание settled в одном наследуемом классе. Site app содержит DOM, FSM, persist, links и callback завершения канала. ChannelTransition хранит и смысловой screen/type, и decode/transition phase. Эти границы требуется разделить, а не импортировать целый renderer в общую модель. [Reveal](../max-game/src/journey-guided-reveal.mjs), [site app](../max-game/public/site-game/app.mjs), [channel](../max-game/public/site-game/channel-task.mjs).
5. **P1: библиотека заданий не чистая.** journey-media включает семантический выбор, `new Image`, устройство по первому кадру, HTML-генерацию и галерею. Поэтому она не подходит как backend-каталог без извлечения данных. [Код](../max-game/src/journey-media.mjs).
6. **P1: stage и gallery index не равны.** Legacy специально не считает перелистывание ответом; site экраны канала являются шагами действия. Автоматическое сопоставление счётчиков добавит лишние действия либо ранний зачёт.
7. **P1: поведение зависит от подготовленного кадра, но это не право на зачёт.** В legacy mediaReady и gpuReady уже разделены. Общий протокол должен сохранить различие между готовностью содержимого/рендера, доступностью ввода и подтверждением ответа. Нельзя возвращать проверку «есть DOM/texture → задание выполнено». [Вход](../max-game/src/journey-guided-main.js), [WebGL UI](../max-game/src/journey-webgl-ui.mjs).
8. **P2: скопированные motion-модули и отдельные токены.** Site использует копии journey-motion/links и отдельный site-reveal-motion; CPU-сравнения уже проверяют часть равенства, но новые изменения требуют синхронного сопровождения. Будущий общий presentation-runtime заменит эти копии импортами одного исходника; исторические страницы можно оставить зафиксированными.
9. **P2: покрытие не равно количеству картинок.** Legacy вычисляет coverage по media; site пишет coverage в menu шаблоне. Ни один вариант нельзя принять как общий актуальный каталог без сверки с картой. Public 91612/91637 имеются; 99940 — настройки бота, а не товарная витрина. Отсутствующий сюжет/задание должен иметь семантический статус gap и пропуск без зачёта.
10. **P2: скрытое отличие timer.** Legacy уменьшает remaining при active tick и сохраняет время; site считает от performance.now-sessionAt и не сохраняет его. Общий timer обязан иметь одну политику pause/menu/reload независимо от скина.

## Сервер и инструментальная проверка

`artifacts/service/server.mjs` обслуживает `/max-game/` как статический каталог. Существующий `/api/journey` обслуживает маршрут VK Видео; использовать его для прогресса MAX нельзя. Отдельного MAX session/command API в просмотренном сервере нет. `main.cjs` запускает сервер внутри Electron, поэтому shell Node и production host не тождественны.

На shell Node **v25.9.0** импорт `node:sqlite` успешен, `DatabaseSync` доступен. Это не подтверждает его доступность в упакованном Electron. Официальная документация отмечает синхронность этого API и статус release candidate; соответствующий gate внесён в решение. Зависимости не устанавливались, SQLite-файл не создавался.

Пройдено **82/82** CPU-теста: `journey-guided-reveal.test.mjs`, `journey-guided.test.mjs`, `journey-id.test.mjs`, `channel-task.test.mjs`; около 0,12 с длительности тестового набора. Они подтверждают существующие контроллеры, а не совместимость нового backend — такой реализации ещё нет. Отдельная read-only проба RevealJourney дала phase=burst, scanned=true и четыре узла блогера после 0,8 с. Сохранения пользователя не читались и не записывались.

## Вывод

Выделять общий backend через контракты, постепенно заменяя владельцев логики. Сохранять проверенные primitives reducer/guards/motion, но не переносить наследование UI-контроллеров целиком. Первый вертикальный срез — один каталог канала, один engine/session и два адаптера этого задания; после него переносить остальные миссии по одной. [Границы, API, хранение, миграция и критерии](../../docs/Research/max-game-shared-backend-20261002.md).
