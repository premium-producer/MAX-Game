# MAX: общее поле стекла под масками — проверка 27.09.2026

## Реализовано и доставлено

В мастере три сферы в координатах стены заменили повторение линз внутри каждой панели. glassLayers выдаёт одинаковые значения в two/single при одинаковом времени; никакой panel-owner не используется. Центры возле границ общей композиции: (2410,200), (3260,1216), (4024,270), радиусы570/810/515, небольшой общий дрейф. Средняя сфера пересекает промежуток между двумя масками. За пределами игровых панелей сферы скрыты; панельные тени/glow сохранены.

Усилены нормаль, преломление, светлая/тёмная фаска. Широкие движущиеся отражения аналитического студийного окружения используют только cyan/violet MAX. Это screen-space refraction и художественная модель отражений, не трассировка 3D и не официальный Apple-компонент. Белые glints маскируются под меню, foreground резкий. Пауза и reduced motion используют прежний контракт времени. Пикселизации нет.

Сокращены texture lookups внутри маски с6 до2; убран5-tap blur гладкого фона. Полезные crop тайлов вне панели с224px запасом тени выводятся сразу в GPUAtlas, без glass pass. В4096×1280 работают4 из6 стеклянных проходов. Прежний дополнительный reusable HalfFloat RT остаётся один (~20.05MiB), новых контекстов/буферов/readback не добавлено. Фоновый тайлинг и DOF не менялись.

Изменены три public-модуля Service и профильный тест. Выборочный build_service_public.py доставил их в apps/stand-service с обновлением manifest; portable ZIP не пересобирался. Игровой foreground и standalone CSS fallback не изменялись; вне Service эта итерация оптики не применяется.

## Подтверждение

- `node --check` трёх изменённых JS прошёл.
- 8 профильных service/geometry/input тестов и110 Ribbon тестов прошли, логи рядом. Новый тест фиксирует идентичность поля между раскладками, ещё один — сохранение масок/теней при пропуске тайлов. Первоначальная проверка отсечения выявила использование padded renderRect вместо полезного crop; это исправлено до доставки, повторный прогон зелёный.
- `http-checks.json`: HTTP/source SHA всех трёх модулей совпали.
- `before.json` / `after.json`: перезапущен только max-wall-right, generation остальных четырёх неизменны. Все пять running, error=null. Перезапуск MAX сбрасывал память его игровых сессий.
- Штатный Check.bat прошёл, все пять Spout sending. TD-приём не проверялся.
- В одной существующей presentation-вкладке проверены two→single→two: широкая зона раскрывает общую композицию, в квадратах видны разные части, вне них сфер нет. Сферы заметнее на фоне; пропорции и меню сохранены. Warn/error консоли пусты. Финальный режим two; снимки обоих режимов рядом.

## Ограничения

Исследование и сравнение готовых решений: [docs/Research/max-liquid-glass-20260927.md](../../../docs/Research/max-liquid-glass-20260927.md). Применены max.glass.limit, max.glass.dispersion, max.glass.highlights и проектная палитра. Сторонних пакетов не установлено, внешнего кода не скопировано.

Краткий Check после обновления: MAX15FPS, остальные25–37FPS; до изменения — MAX25.6, остальные54–57. Условия общего стенда/клиентов не зафиксированы, падение затронуло и неизменённые источники. Причинный вывод о стоимости стекла или ускорении из этого делать нельзя. Число проходов/lookup сокращено по коду, GPU A/B не проведён, цель60FPS не принята. Художественную оценку и аппаратную приёмку выполняет пользователь. Длительных GPU-тестов, видео, повторной проверки3D/TD не было. Git stage/commit/push не выполнялись.
