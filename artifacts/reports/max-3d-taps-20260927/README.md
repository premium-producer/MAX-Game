# MAX: показ и нажатия на 3D-стенде, 27.09.2026

Причина: Viewer уже назначал VideoTexture MAX правой стене, но не имел обработчика игрового ввода. В предыдущем контракте упоминание ввода из 3D было преждевременным: тогда проверялся только presentation. Теперь добавлена и проверена реальная цепочка Viewer → UV → pointer API → действующий игровой worker.

## Реализация и проверки

- `screen-pointer.js`: ближайшая видимая грань, material index, UV-transform отображаемой текстуры, down/move/up/cancel, временная блокировка OrbitControls, отмена при смене контекста. Камера фокусируется по позиции и нормали игровой зоны на изогнутой стене.
- 130/130 Node-тестов: 5 новых проверок UV/окклюзии/ракурса/тапа/жеста, существующие проверки камеры и ориентации, Ribbon и MAX input. `tests.txt`. Синтаксис трёх изменённых JS и diff-check прошли.
- Пользователь отдельно разрешил короткую проверку одной вкладки 3D; нагрузочный прогон и запись видео не выполнялись.
- Реальный адрес: http://localhost:8770/viewer/show/. На SCREEN_RIGHT видна игра действующего `max-wall-right`, WebRTC 1920×600. Нажатие на игровую кнопку дало UV≈(0,384916; 0,696979), phase=up и перевело старт в обучение «Три шага к связи». Камера осталась неподвижной. Консоль без warn/error.
- [Снимок после тапа](live-3d-tap.jpg), DOM-диагностика потока и события — `browser.json`. Это работающий мастер, не fixture или отдельная копия игры. Перезапускать источники не потребовалось.

Проверено отображение и один реальный тап; прохождение миссий и реальные drag-действия в браузере не выполнялись. Жизненный цикл drag/cancel проверен CPU-тестами. Физические LED, touch-контроллер и длительная устойчивость остаются вне этой проверки. Самостоятельный Viewer на другом порту не получает сервисную игру — использовать маршрут мастера. Оформление и правила бренда не менялись.

[Действующая инструкция](../../../apps/stand-viewer/docs/MAX_INTERACTION.md).

Viewer и общий переносимый ZIP обновлены штатными сборщиками: 604 файла / 431 991 947 байт, CRC/SHA pass. HTTP-хеши изменённых модулей совпали с runtime. Все пять источников running без ошибок и с прежними generation (`service.json`).
