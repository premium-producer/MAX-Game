# Пустой телефон MAX на локальном стенде

30.09.2026. Проверка присланного кадра, где рамка телефона в миссии «Цифровой ID» видна, а экран внутри пустой.

## Установлено

- Источник `max-wall-right` работал без ошибки и продолжал отдавать кадры. SVG первого экрана ID присутствует в runtime; в прямой сервисной странице он декодировался (`naturalWidth=360`) и отрисовывался.
- На фактическом WebRTC-потоке источника и в 3D-просмотрщике экран ID удалось увидеть. Поэтому постоянную потерю контента на этапе передачи в мастер/просмотрщик проверка не подтвердила.
- В коде телефонная оболочка получала целевую видимость по фазе `phone-enter` без проверки загрузки вложенного изображения. WebGL-адаптер пропускал ещё не загруженный `img`, поэтому при задержке загрузки мог показать пустую рамку.

## Исправление

`phoneContentReady()` удерживает телефон скрытым и не завершает `phone-enter`, пока изображения текущего кадра не декодированы. После готовности используется прежняя анимация входа. При ошибке изображения вместо пустого устройства появляется явное сообщение. Состояние задания, ответы и медиафайлы не меняются.

## Проверка

- Guard копий: PASS; `node --check`: PASS; Guided Reveal CPU: 24/24; MAX build: 326 файлов/91 модуль; `check-local`: PASS.
- Локальный источник перезапущен из интерфейса мастера: generation сменился, `running`, кадры продвигаются, `error=null`. `Check.bat`: PASS в dev.
- В одном браузерном сеансе проверены прямая страница игры, предпросмотр источника и 3D-стенд: содержимое ID видно внутри телефона после загрузки.

Присланную длительную пустоту воспроизвести не удалось, поэтому точную причину того конкретного кадра нельзя отличить от задержки изображения или прежнего состояния процесса. Текущая защита устраняет подтверждённый кодом сценарий пустой оболочки. Физический приём TD/Spout не проверялся: локальный мастер работает в dev с отключённым Spout. Публикации не было.
